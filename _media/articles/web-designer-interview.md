フリーランスのWebデザイナーの面談でよく聞かれるのは、**作品ごとに自分が担った範囲、目的をどう確かめて形にしたか、修正の指示にどう向き合ったか、実装の担当者にどう渡したか**の4つです。面談官は、見た目の好みより「この人に任せたら、目的に沿って作り切り、チームの手を止めずに渡してくれるか」を確かめようとしています。

答えるときは、模範解答を覚えるより、ポートフォリオの中から説明の軸になる作品を2〜3つ選び、どの質問にもそこから答えられるようにしておくのが近道です。面談全般の答え方の型は[業務委託の面談でよく聞かれる質問と答え方](/media/interview-questions/)で解説しているので、この記事ではWebデザイナーの面談に固有の質問に絞ります。

## Webデザイナーの面談で面談官が見ていること

面談に出てくるのは、制作会社のディレクターやデザインの責任者、事業会社のマーケティングや制作の担当者であることが多くあります。作品はスキルシートやポートフォリオで事前に見ているため、面談では**作品の裏にある判断と進め方**を聞いています。

面談官が知りたいのは、おおむね次の3点です。

1. **任せられる範囲**：どの工程を、どこまで自分の判断で進めてきたか
2. **チームでの進め方**：確認や修正、実装への受け渡しを滞らせずに回せるか
3. **現場との相性**：使うツール、データの作り方、連絡の速さが自社のやり方に合うか

以下の質問は、この3点のどれかを確かめるためのものです。質問の意図が分かれば、答えの中心に何を置くかも決まります。

## よく聞かれる質問と答え方の考え方

ここで示す答えの例は、組み立て方を伝えるための**架空の例**です。そのまま使うのではなく、ご自身の経験に置き換えて準備してください。

### 1. 「この作品で、あなたが担当した範囲を教えてください」

最もよく聞かれる質問です。確かめたいのは、作品の出来と本人の力量を切り分けることです。構成、デザインの方向性、下層ページへの展開、画像の加工、実装など、工程ごとに**自分がしたこと・ほかの人がしたこと**を分けて話します。

架空の例：「構成案はディレクターが作り、トップと主要な下層ページのデザイン、部品の決まりづくりを私が担当しました。実装は別のコーダーです」

チームで作った作品を自分一人の成果のように話すと、掘り下げられたときに答えに詰まります。担当の線を最初に引くことで、後の質問との食い違いを防げます。

### 2. 「このデザインにした理由は何ですか」

見た目の説明ではなく、**目的と相手からデザインを決めた筋道**を聞く質問です。「誰に向けたページで、何をしてもらいたかったか」「そのために何を目立たせ、何を控えたか」の順で話すと伝わります。色や書体の好みだけで答えると、目的を考えずに作る人だと受け取られやすくなります。

### 3. 「依頼の目的があいまいなとき、どうしていましたか」

指示の少ない現場でも作業を前に進められるかを確かめる質問です。作り始める前に何を聞き返したか、聞き返せないときに仮の前提を置いてどう確認したかを話します。方向性の段階で一度見せて、ずれを早めに直した場面があれば、それが答えの中心になります。

### 4. 「修正の指示が、あなたの考えと違ったときはどうしましたか」

修正への向き合い方は、チームとの相性を見る材料です。面談官は、指示どおりに直すか反論するかより、**目的に照らして代わりの案を出せるか、決める人に判断を返せるか**を見ています。複数の確認者から食い違う指示が来たときに、どう整理したかも話せると、進め方の力が伝わります。

### 5. 「実装の担当者には、どのように渡していましたか」

デザインデータの作り方と、受け渡しの丁寧さを確かめる質問です。部品の使い回し、余白や文字の大きさの決まり、画面幅ごとの見え方、動きの意図をどう残したかを話します。実装後に表示を確かめ、ずれを直してもらった経験があれば添えます。コーディングもできる場合は、どこまで自分で組めるかを正確に伝えます。

### 6. 「普段使っているツールと、データの作り方を教えてください」

ツールの名前を並べるより、**どう使っていたか**が聞かれています。部品や色の決まりをデータの中でどう整理していたか、ほかのデザイナーと同じデータを触るときの決まりをどう守っていたかを話すと、現場に入ったときの姿が想像しやすくなります。現場で使うツールが自分の経験と違う場合は、近いツールでの経験と、慣れるまでの見込みを正直に伝えます。

### 7. 「公開した後の数値や反応を見たことはありますか」

LPや広告、事業会社の案件でよく聞かれます。数値の分析を自分で担った経験がなくても、**数値を受けて何を直したか**を話せれば十分です。比べた案、変えた箇所、結果の受け止め方を順に話します。具体的な数値は守秘の対象になっていることが多いので、伏せたまま傾向で伝えましょう。

### 8. 「写真やフォント、生成AIの扱いはどうしていましたか」

素材の権利への意識を確かめる質問です。写真やイラストの利用条件の確かめ方、フォントのライセンスの扱い、生成AIを使ってよいかを発注元とどう決めていたかを話します。生成AIの扱いは現場ごとに方針が違うため、「使ってよい範囲を先に確かめてから使う」という姿勢を示すのが無難です。契約での扱いは[生成AIの利用と業務委託契約](/media/ai-riyou-keiyaku/)で整理しています。

:::view
Webデザイナーの案件をご紹介していると、面談で評価されやすいのは、作品の見栄えより「担当した範囲」と「その形にした理由」を短く話せる方です。反対に、作品を順番に見せながら見た目の説明だけが続くと、判断の中身が伝わらず、見送られやすい傾向があります。修正で方向が変わった作品でも、何を受けてどう直したかを話せれば、経験として受け止められることが多くあります。
:::

## 準備は「説明の軸になる作品」を2〜3つに絞る

上の質問は数が多く見えますが、答えの材料は共通しています。準備は次の手順で進めると効率的です。

1. **作品を選ぶ**：新しく作ったサイト、改善を続けたLPやバナー、修正で大きく方向が変わった案件など、性質の違う作品を2〜3つ選ぶ
2. **作品ごとにメモをつくる**：目的と相手、担当した範囲、決めたこと、修正の経緯、実装への渡し方、公開後の結果を書き出す
3. **担当範囲をそろえる**：スキルシート、ポートフォリオ、口頭の説明で、担当した工程が同じになるようにする
4. **画面共有の準備をする**：オンラインの面談では、見せる順番に作品を並べ、拡大しても見やすい形で開けるようにしておく
5. **1分版と3分版をつくる**：最初は1分で概要を話し、掘り下げられたら詳しく話せるようにする

スキルシートとの一致は特に大切です。面談官はシートとポートフォリオを見ながら質問するため、話と書面がずれると、どちらも信用されにくくなります。シートの書き方は[Webデザイナーのスキルシートの記事](/media/web-designer-skillsheet/)、オンラインの面談の注意点は[オンライン面談の記事](/media/online-interview/)で解説しています。

:::caution
面談で見せる作品は、公開してよいと許可を得たものに限ります。公開前のデザイン、社内向けの画面、前の発注元が実績の公開を認めていない作品は、画面共有でも見せないようにしましょう。見せられない作品は、媒体の種類と目的、担当した範囲を言葉で説明すれば足ります。考え方は[スキルシートに書いてよいこと・いけないこと](/media/confidentiality-in-skillsheet/)が参考になります。
:::

## 面談の相手によって重心が変わる

Webデザイナーの面談は、相手によって聞かれる内容の重心が変わります。

| 面談の相手 | 重く見られやすい点 |
|---|---|
| 制作会社のディレクター | 担当範囲、修正への向き合い方、締め切りと並行作業の進め方 |
| 制作会社のデザイン責任者 | デザインの判断の理由、部品や決まりの作り方、データの丁寧さ |
| 事業会社のマーケティング・制作の担当者 | 依頼の受け方、公開後の数値の見方、社内の確認への対応 |
| 発注元の経営者（直接の依頼） | 聞き取りの進め方、公開までの段取り、公開後の更新の扱い |

制作会社のチームに入る案件で、制作会社と発注元の両方と話すこともあります。その場合、制作会社との面談ではデータの作り方や進め方、発注元との面談では目的の理解や過去の媒体の話に重心を置くと、限られた時間を有効に使えます。

## Webデザイナーならではの逆質問

面談の終わりには、こちらから質問できる時間があります。逆質問は、印象づくりより**参画後のずれを防ぐ確認**に使います。Webデザイナーの案件では、次の点を聞いておくと判断がしやすくなります。

- 依頼が来る経路と、デザインを最終的に決める人
- 確認の回数と、修正の指示がまとめて届くか、個別に届くか
- 使うデザインツールと、既存のデザインの決まりや部品の有無
- 実装の担当と、デザインどおりに組まれたかを確かめる工程の有無
- 制作物を自分の実績として公開してよいか、その条件

一般的な逆質問の考え方は[業務委託の面談で聞いておくべき逆質問](/media/reverse-questions/)にまとめています。逆質問で聞いた内容は、契約前の確認にもそのまま使えます。案件を選ぶときの確認点は[Webデザイナーの案件の選び方](/media/web-designer-anken-erabi/)で整理しています。

:::view
当社では、経歴をご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。Webデザイナーの面談では、案件票だけでは分からない確認の流れや実績公開の条件について、面談の前に確認しておきたい点があれば、ご質問いただければ確認します。面談後に参画を迷う点が出てきた場合も、早めにご相談ください。
:::

:::point
- Webデザイナーの面談では、担当範囲、デザインの理由、目的の確かめ方、修正と受け渡しの進め方がよく聞かれる
- 答えは「目的と相手→担当した範囲→決めたこと→修正の経緯→結果」の順で組み立てる
- 準備は説明の軸になる作品を2〜3つに絞り、スキルシートとポートフォリオの内容をそろえる
- 逆質問では、決める人、確認の流れ、ツールと既存の決まり、実績公開の条件を確かめる
:::

## よくある質問

### ポートフォリオに載せられる作品が少ないのですが、面談で不利になりますか？

数よりも、1つの作品をどこまで説明できるかが見られます。公開できない作品は、媒体の種類と目的、担当した範囲を言葉で伝えれば経験として受け止めてもらえます。載せられる作品を増やしたい場合は、今後の案件で実績公開の条件を先に確かめておきましょう。

### コーディングができないことは、正直に伝えたほうがよいですか？

伝えたほうがよいです。できないことをあいまいにすると、参画後に役割のずれが起きます。そのうえで、実装の担当者に渡すときに何を残していたか、実装後の表示をどう確かめていたかを話すと、受け渡しの力が伝わります。

### 面談でその場でデザインの意見を求められたら、どう答えればよいですか？

発注元の今のサイトについて意見を求められることがあります。限られた情報で断定するより、「目的と相手がこうであれば、ここを見直す余地がある」と前提を添えて話すほうが信頼されます。批判の言い方にならないよう、良い点を先に挙げることも大切です。
