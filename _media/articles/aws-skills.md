AWSエンジニアのフリーランス案件では、**設計・構築・運用のうちどこを自分で担えるか、ネットワークとセキュリティの基礎、IaC（コードによる構築）や自動化の経験**が中心に見られます。AWS認定資格は知識の裏付けになりますが、案件ではそれ以上に、実際の環境で何を作り、どう運用してきたかが問われます。

この記事では、案件で求められやすいスキルを分野ごとに整理し、AWS認定の位置づけと、スキルシートや面談での経験の伝え方を解説します。

## AWSエンジニアの案件の主な種類

AWSの案件は、扱うテーマと工程によっていくつかの型に分かれます。

| 案件の型 | 主な業務 | 特に見られる経験 |
|---|---|---|
| 新規構築 | 新しいサービスやシステムの基盤を設計・構築する | アーキテクチャ設計、IaC |
| オンプレミスからの移行 | 既存のサーバーやシステムをAWSへ移す | 現行調査、移行計画、ネットワーク |
| 運用・改善 | 監視、障害対応、コストや性能の改善 | 監視設計、自動化、トラブル対応 |
| SRE・DevOps | 信頼性の向上、CI/CDやデプロイの仕組みづくり | コンテナ、パイプライン、可観測性 |
| セキュリティ・ガバナンス | 複数アカウントの管理、権限設計、統制の仕組みづくり | IAM設計、ログ管理、ポリシー |
| データ基盤 | データの収集・保存・分析の基盤づくり | データ関連サービス、パイプライン |

どの型の経験を持っているかで、参画できる案件が変わります。運用の経験が長い人と、設計から構築を担ってきた人では、案件側が期待する役割も違います。

## 案件でよく求められるスキル

### 主要なサービスを組み合わせて設計する力

AWSには多くのサービスがありますが、案件で中心になるのは、コンピューティング（EC2、Lambda、コンテナのサービスなど）、ストレージ（S3など）、データベース（RDSなど）、ネットワーク（VPC、ロードバランサー、DNSなど）、権限管理（IAM）、監視（CloudWatchなど）です。個々のサービスを知っているだけでなく、要件に合わせて組み合わせ、構成を説明できることが求められます。

設計の考え方の土台として、AWSは「Well-Architected Framework」を公開しています。運用上の優秀性、セキュリティ、信頼性、パフォーマンス効率、コスト最適化、持続可能性の6つの柱で構成されており、設計を見直すときの観点として案件でも話題になります。

### ネットワークとセキュリティの基礎

クラウドの案件でも、ネットワークの基礎（IPアドレスの設計、ルーティング、名前解決、通信の暗号化）は欠かせません。オンプレミスとの接続、複数のVPCの接続など、ネットワークの設計で詰まりやすい部分を経験していると、移行や大規模な構築の案件で頼りにされます。

セキュリティでは、IAMによる権限の最小化、ログの取得と保管、暗号化、複数アカウントでの統制など、設計の段階から組み込む経験が評価されます。

### IaCと自動化

手作業での構築ではなく、Terraform、AWS CloudFormation、AWS CDKなどを使って、環境をコードで管理する経験は、多くの案件で求められます。あわせて、GitHub ActionsなどでのCI/CD、スクリプトによる運用作業の自動化ができると、運用改善やSREの案件にも参画しやすくなります。

### コンテナとサーバーレス

Dockerを使ったコンテナの運用や、Amazon ECS・Amazon EKSでの構築、Lambdaを中心としたサーバーレスの構成は、Webサービス系の案件でよく求められます。どちらの構成で、どの規模のシステムを扱ったかを説明できるようにしておきましょう。

### 運用とトラブル対応

監視の設計、アラートの調整、障害時の原因調査と再発防止、コストの見直しなど、運用の経験は案件で重視されます。特に、障害対応で原因を切り分け、対策まで進めた経験は、面談で具体的に話すと評価されやすい部分です。

:::view
AWSの案件をご紹介していると、「どのサービスを使ったか」だけでなく、「なぜその構成にしたのか」を説明できる方ほど、面談で評価されやすい傾向があります。たとえば、可用性とコストのどちらを優先したか、運用の手間をどう減らしたかといった判断の理由です。サービス名を並べるだけのスキルシートでは、経験の深さが伝わりにくくなります。当社では、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをご案内しています。
:::

## AWS認定資格の位置づけ

AWSは、レベルと分野ごとに認定資格を用意しています。2026年10月時点の公式の試験一覧では、次のような区分があります。

| レベル | 主な認定 |
|---|---|
| Foundational | AWS Certified Cloud Practitioner、AWS Certified AI Practitioner |
| Associate | Solutions Architect、Developer、CloudOps Engineer、Data Engineer、Machine Learning Engineer（いずれも Associate） |
| Professional | AWS Certified Solutions Architect - Professional など |
| Specialty | AWS Certified Security - Specialty、AWS Certified Advanced Networking - Specialty（2026年12月31日に廃止予定） |

認定の名称や区分は見直されることがあるため、受験の前にAWSの公式サイトで最新の内容をご確認ください。

### 認定には有効期間がある

AWS認定は、更新の手続きをしないと失効します。公式サイトでは、最新の試験やより上位の試験に合格するなどの方法で更新すると、有効期間が3年延びると案内されています。また、有効期限の90日前以内で、AWS Skill Builderの有料プランに加入している場合は、1年延長する「維持」の方法もあります。スキルシートに認定を書くときは、有効期限も確かめておきましょう。

### 案件での見られ方

認定は、AWSの知識を体系的に持っていることの裏付けになり、書類の段階で目に留まりやすくなります。ただし、認定だけで参画が決まることは多くありません。Professionalや、セキュリティなどの専門分野の認定を持っていても、実務でその知識を使った経験とあわせて説明できることが大切です。

:::caution
認定の数が多くても、実務の経験が運用の定型作業だけの場合、設計や構築を求める案件では評価が分かれます。認定で学んだ内容を、検証環境や今の案件の改善などで実際に使った経験として話せるようにしておくと、面談での説得力が増します。
:::

## 工程によって参画できる案件が変わる

AWSの案件は、担った工程によって求められる経験が違います。

1. **要件定義・設計**：非機能要件（可用性、性能、セキュリティ、コスト）を整理し、構成を決める
2. **構築**：IaCで環境を作り、テストする
3. **移行**：現行の調査、移行計画、切り替えの準備と実施
4. **運用・改善**：監視、障害対応、コストや性能の改善、自動化

運用から入った人も、改善の提案や自動化に取り組むことで、構築や設計の経験を少しずつ積めます。上流の工程に入るための考え方は[上流工程の案件に入るために必要な経験](/media/upper-process/)にまとめています。

## スキルシートと面談で伝えたいこと

AWSのスキルシートでは、プロジェクトごとに次の点を書くと、経験の中身が伝わります。

- システムの概要と規模（利用者数やアカウント数など、伏せられる範囲で）
- 使ったサービスと構成の特徴
- 担当した工程と役割
- IaCやCI/CDなど、使ったツール
- 工夫した点と結果（可用性の向上、コストの見直し、作業の自動化など）

面談では、構成図を描くように口頭で説明できると、理解の深さが伝わります。書き方は[AWSのスキルシートの書き方](/media/aws-skillsheet/)で解説しています。

:::view
クラウドの案件は、オンプレミスのインフラやネットワークの経験がある方が、AWSの経験を足して参画されることも多い分野です。当社では、経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せて提案しています。AWSの経験年数が短い方でも、インフラ全体の経験とあわせて整理すると、ご案内できる案件の幅が広がることがあります。
:::

:::point
- AWSの案件では、設計・構築・運用のどこを担えるか、ネットワークとセキュリティの基礎、IaCと自動化の経験が見られる
- AWS認定は知識の裏付けになるが、実務での経験とあわせて説明することが大切
- 構成を選んだ理由や工夫を説明できると、経験の深さが伝わる
:::

## よくある質問

### AWS認定がないとフリーランスの案件は受けられませんか？

認定がなくても参画できる案件は多くあります。案件では、実際の環境での設計・構築・運用の経験が重視されます。ただ、認定は知識の範囲を示す材料になり、書類の段階で目に留まりやすくなるため、経験の整理とあわせて取得を考えるのもよい方法です。

### オンプレミスのインフラ経験はAWSの案件で生かせますか？

生かせます。ネットワーク、サーバー、ストレージ、セキュリティの基礎は、クラウドでも同じように必要です。特にオンプレミスからAWSへの移行案件では、現行の環境を理解できる人が求められます。AWSでの構築経験を少しずつ足していくと、参画できる案件が広がります。

### AzureやGoogle Cloudの経験も必要ですか？

AWSだけの経験で参画できる案件も多くあります。一方、複数のクラウドを使い分ける会社の案件では、ほかのクラウドの経験が評価されることがあります。違いは[Azureエンジニアのスキルの記事](/media/azure-skills/)や[GCPエンジニアのスキルの記事](/media/gcp-skills/)もあわせてご覧ください。
