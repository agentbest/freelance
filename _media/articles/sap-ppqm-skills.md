SAP PP/QMのフリーランス案件では、**品目・部品表・作業手順のマスタ、所要量の計算（MRP）、製造指図の実行、検査の計画と検査ロット・使用決定といった機能の設定を自分で組んだ経験と、計画や検査の結果がおかしいときにマスタと設定から原因を追える力**が見られます。工場の流れを知っていることは前提で、そのうえで「どの設定を、なぜそう組んだか」を説明できるかが、任される範囲を分けます。

この記事では、PPとQMで案件によく出る分野ごとに問われる設定と論点を整理し、経験の段階ごとに求められる水準を示します。工場の流れに沿った経験の棚卸しや独立の手順は[SAP PP/QMコンサルがフリーランスになるには](/media/sap-ppqm-how-to/)で扱っています。

## PPのマスタ：計画と指図の土台

PPの不具合の多くは、マスタの持ち方に原因があります。案件では、次のマスタをどう設計したかがよく聞かれます。

| マスタ | 問われやすい設定・論点 | 説明できると強いこと |
|---|---|---|
| 品目（計画の項目） | MRPタイプ、ロットサイズ、調達タイプ、リードタイム | 品目群ごとに計画の方法を分けた理由 |
| 部品表（BOM） | 用途、代替の部品表、有効期間 | 設計変更を部品表にどう反映させたか |
| 作業区 | 能力、標準値、原価との結びつき | 作業区の単位をどう決め、原価の担当とどう合わせたか |
| 作業手順・マスタレシピ | 工程の順序、標準時間、部品の割り当て | 工程ごとに実績を上げるかどうかの判断 |
| 製造バージョン | 部品表と作業手順の組み合わせ | 同じ品目を複数のラインで作るときの扱い |

マスタの設計は、計画、指図、原価のすべてに効きます。「この項目を変えると、どこに影響が出るか」を説明できると、設計の工程から任されやすくなります。

## PPの計画：MRPと生産方式

計画の分野では、MRPの設定だけでなく、生産方式との組み合わせが問われます。

- **計画の戦略**：見込みで作るのか、受注に結びつけて作るのか。需要の見込みと実際の受注をどう相殺するか
- **所要量の計算の結果**：計画手配と購買依頼がどう作られ、計画担当者がどの画面で確かめ、どう直していたか
- **能力の確認**：作業区の能力を超えたときに、計画をどう組み替えたか
- **計画の単位**：工場ごとか、MRPの範囲を分けるか

MRPの面談では、「計画結果が多すぎる・少なすぎると言われたら、どこから調べますか」という問いがよく出ます。品目の計画の項目、部品表の有効期間、在庫や発注済みの数量の扱いを順に確かめる手順を、自分の言葉で話せるようにしておきましょう。

## PPの製造の実行：指図から入庫まで

| 分野 | 問われやすい設定・論点 | 説明できると強いこと |
|---|---|---|
| 製造指図 | 指図タイプ、リリースの条件、部品の在庫確認 | 計画手配から指図への変換を誰がいつ行う運用にしたか |
| 部品の出庫 | 手での出庫か、実績と同時の自動出庫か | 現場の運用とシステムの在庫を合わせる工夫 |
| 実績確認 | 工程ごとの実績、仕損の扱い | 実績の上げ方を工場の担当とどう決めたか |
| 入庫と完了 | 入庫の方法、指図の完了と原価の決済 | 指図の差異が原価のどこに出るかを説明できるか |
| プロセス指図 | 配合、ロット、工程の指示 | 化学・食品などでのロットと記録の扱い |
| 繰返製造 | 期間ごとの計画と実績の計上 | 指図を使わない形を選んだ理由 |

指図の決済は、COとのつなぎ目です。PPの担当でも、指図の実績からどんな原価が集計され、計画との差異がどう扱われるかを説明できると、統合テストで頼られます。

## QMの計画：何を、いつ、どう検査するか

QMは、SAP Learningの学習コース「Configuring SAP S/4HANA Quality Management」（2026年10月時点で確認）でも、検査の基礎データ、検査計画、結果の記録と使用決定、品質通知、QMの費用の記録といった単位で構成されています。案件でも、この流れに沿って経験が確かめられます。

| 分野 | 問われやすい設定・論点 | 説明できると強いこと |
|---|---|---|
| 検査の基礎データ | 検査特性、サンプリングの方法、検査の緩め・厳しめの切り替え | 品質保証部門の検査基準をどう設定に写したか |
| 検査計画 | 品目ごとの検査計画、作業手順への検査の組み込み | 受入・工程内・出荷前のどこで検査するかの判断 |
| 検査の起こし方 | 入庫や指図のどの取引で検査ロットを作るか | 検査ロットが作られないときの原因の調べ方 |

## QMの実行：結果、判定、不良の処理

- **結果の記録**：検査員が入力する画面と項目、検査機器からの取り込み
- **使用決定**：合格・不合格の判定と、それに応じた在庫の区分の変更（利用可能、保留、廃棄など）
- **品質通知**：購買、製造、販売の各場面で起きた不良を記録し、原因と処置を追う流れ
- **ロットの追跡**：MMのロット（バッチ）管理と組み合わせ、どの材料がどの製品に使われたかを追えるようにする

使用決定で在庫がどう動くかは、MMと製造の両方に効く論点です。QMの担当でも、在庫の区分が変わったときに出荷や次の工程がどう止まるかを説明できると、チームの中での役割が広がります。在庫と購買の側の設定は[SD/MMで求められるスキル](/media/sap-sdmm-skills/)で扱っています。

:::view
PP/QMの案件紹介の現場では、面談で「検査ロットが作られなかった」「計画手配が二重に出た」といった不具合を、どこから調べて原因にたどり着いたかを問われる場面をよく見ます。評価されやすいのは、品目マスタの設定、検査計画、取引の種類を一つずつ確かめた手順を順に話せる方です。設定を担当した経験があっても、原因の調べ方を説明できないと、保守や統合テストの局面で任せられるかが伝わりにくくなります。
:::

## 経験の段階ごとに求められる水準

同じ分野でも、経験の段階によって求められることが変わります。

| 段階 | PPで求められること | QMで求められること |
|---|---|---|
| 設定を担う段階 | 設計書にそってマスタと指図の設定を行い、単体テストで確かめる | 検査特性や検査計画を登録し、検査ロットが作られることを確かめる |
| 流れを任される段階 | 生産方式に合わせて計画と指図の設計を決め、統合テストを回す | 検査の段階と判定の運用を品質保証部門と決め、不良の処理まで設計する |
| 工場全体を見る段階 | 複数工場の共通の型を作り、原価・購買・販売とのつなぎ目を決める | 品質の記録と追跡の要求を整理し、MESや検査機器との連携を含めて設計する |

自分の段階を確かめ、次の段階で求められることを一つずつ経験に加えていくと、任される範囲を広げやすくなります。

## 設定の外で求められる技術的なスキル

1. **追加開発の仕様を書く力**：帳票（作業指示書、現品票、検査成績書など）や入力のチェックを、開発者が迷わない粒度で書けるか
2. **データを調べる力**：指図や検査ロットのデータを照会し、件数や状態の偏りを確かめられるか
3. **工場のシステムとの連携を読む力**：MESや検査機器との間で、指図・実績・検査結果のどの項目がどう対応しているかを読み解けるか
4. **テストを設計する力**：計画から製造、検査、入庫、原価の決済までを通すシナリオを作り、仕損や不合格などの例外を漏らさないか

S/4HANAへの移行案件で問われる論点は[S/4HANA移行のスキル](/media/s4hana-skills/)、製造業の業務知識は[製造業の業務知識の記事](/media/ind-seizou-chishiki/)をご覧ください。

## 認定資格との関係

SAPはPPに対応する認定として「SAP Certified - SAP S/4HANA Cloud Private Edition, Production Planning and Manufacturing」（試験コード C_TS422）を用意しています。2026年10月時点のSAP Learningのページでは、出題範囲はマスタの管理、計画、設定、製造の実行の4つで、製造の実行の比重が大きく示されています。案件では認定より実務の設定経験が重視されます。認定が効く場面や維持の仕組みは[SAP認定コンサルタントの記事](/media/cert-sap/)で解説しています。

:::caution
「PP/QM担当」とまとめて書くだけでは、どの分野を深く扱ったかが伝わりません。保守で問い合わせに答えていた期間と、導入で設定を組んだ期間が混ざっていると、設計から任せる案件に紹介されて、参画後に負担が大きくなることがあります。分野ごとに「設定を組んだ」「設定を直した」「使い方を知っている」を分けて整理しておきましょう。
:::

:::view
当社では、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをご案内しています。ご経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せて提案しています。PP/QMの案件は、同じモジュールでも生産方式や検査の段階によって求められる分野が違うため、上の表の分野の単位で経験を書き出しておくことをおすすめします。
:::

:::point
- PPではマスタ・MRP・指図の実行、QMでは検査計画・検査ロット・使用決定・品質通知の設定の深さが問われる
- 計画結果や検査ロットの不具合をマスタと設定から追う手順を話せると、保守やテストの局面でも任されやすい
- 経験の段階ごとに、設定→流れの設計→工場全体と、求められる水準が上がる
:::

## よくある質問

### PPとQMのどちらか一方の経験だけでも案件はありますか？

あります。案件の募集は、PPまたはQMのどちらかを主に担う形のものも多くあります。そのうえで、入庫や工程の中の検査、使用決定による在庫の動きなど、つなぎ目の論点を説明できると、参画できる案件が広がります。

### ABAPの知識は必要ですか？

プログラムを書くことを求める案件は多くありませんが、帳票や連携の仕様を書くとき、不具合の原因を調べるときに、プログラムの動きを読める知識があると役立ちます。開発者と話すときの共通の言葉として、基本的な仕組みを知っておくとよいでしょう。

### 原価計算の知識はどこまで必要ですか？

PP/QMの担当として原価の設定を行うことは多くありませんが、指図の実績からどんな原価が集計され、差異がどこに出るかの流れは理解しておくと、COの担当との会話がかみ合います。経理部門との確認の場で、製造の側から説明できる範囲を持っておくと頼られやすくなります。
