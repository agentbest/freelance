C#エンジニアがフリーランスになるには、**業務アプリやWebシステムの開発経験に加えて、どの.NET環境で、どんな種類のアプリを作ってきたかを具体的に説明できること**が必要です。C#の案件はWindowsの業務アプリ、ASP.NET CoreのWeb、装置と連携する制御系など幅が広く、同じC#でも求められる経験がかなり違うためです。

独立の準備は、経験の棚卸し、得意な領域の絞り込み、足りない経験の補強、手続きとお金の準備の順に進めます。この記事では、C#ならではの「領域の違い」を中心に整理します。

## C#の案件は領域によって別の仕事になる

C#のフリーランス案件は、主に次のような領域に分かれます。応募の前に、自分の経験がどこに当てはまるかを確かめておくと、面談での話がかみ合いやすくなります。

| 領域 | 主な仕事 | 特に見られる経験 |
|---|---|---|
| Windowsの業務アプリ | WinForms・WPFで社内システムの画面を作る | 画面設計、帳票、データベースとの連携 |
| Webシステム | ASP.NET CoreでWebアプリやAPIを作る | API設計、認証、Entity Frameworkなどでのデータアクセス |
| 古い環境からの移行 | .NET Frameworkのアプリを新しい.NETに移す | 両方の違いの理解、使えなくなる機能の置き換え |
| 製造・制御系 | 装置や計測機器とつながるアプリを作る | 通信、マルチスレッド、現地での動作確認 |
| クラウド | Azure上でアプリを動かし、運用する | App Service・Functionsなどの利用、CI/CD |

業務アプリと製造・制御系は、発注元の業務や装置を理解することが前提になり、経験のある分野から選ぶと立ち上がりが楽になります。Unityを使うゲームやXRの開発もC#ですが、求められる経験は別物と考えたほうが安全です。

## 独立前に積んでおきたい経験

### 新しい.NETでの開発と移行

Microsoftのサポートポリシーによると、.NETには3年サポートのLTS（偶数の版）と、2年サポートのSTS（奇数の版）があります。2026年10月時点では、.NET 10がLTSとして2028年11月14日まで、.NET 8（LTS）と.NET 9（STS）はどちらも2026年11月10日までがサポートの期限とされています。

期限が来るたびに、運用中のシステムでは版を上げる作業が発生します。さらに、古い.NET Frameworkで作られた業務アプリを新しい.NETに移す案件もあります。会社員のうちに、次のような作業に関わっておくと説明しやすくなります。

- プロジェクトの形式や参照しているライブラリの更新
- 新しい.NETで使えない機能の置き換え
- 移行後に動作が変わっていないかを確かめるテスト

### データベースとSQL

C#の業務案件では、SQL Serverなどのデータベースを扱うことがほとんどです。Entity Frameworkを使う場合でも、発行されるSQLを確かめ、遅い処理を直せるかが問われます。ストアドプロシージャが多い古いシステムでは、SQLを読む力がそのまま作業の速さにつながります。

### 設計書とテスト

業務系の案件では、詳細設計書やテスト仕様書を書く工程が含まれることが多くあります。実装だけでなく、設計書を起こした経験、単体テストを自動化した経験（xUnit・NUnit・MSTestなど）があると、入れる案件の工程が広がります。

:::view
C#の案件をご紹介していると、「C#の経験◯年」とまとめて書かれた経歴では、どの案件に合うかが判断しにくいことがあります。面談で評価されやすいのは、WinFormsかWebか、.NET Frameworkか新しい.NETかを分けて書き、移行や性能改善で自分が判断した点を話せる方です。面談の前に、領域と環境を整理しておくことをおすすめします。
:::

## 出身によって補う経験が違う

| 出身 | 強みになりやすい経験 | 独立前に補っておきたいこと |
|---|---|---|
| SIer・受託開発 | 業務アプリの設計、帳票、工程管理 | ASP.NET Core、Gitでのレビュー運用、クラウド |
| 製造業・組込み寄り | 装置との通信、マルチスレッド、現地対応 | Webの基本、チームでのソース管理 |
| Web系 | ASP.NET Core、API設計、Azure、CI/CD | 業務システムの進め方、設計書の作成 |

製造・制御系の経験は、扱える人が限られるため、業界の知識とあわせて強みになります。一方で、現地での作業が前提の案件も多いため、リモートを希望する方は条件をよく確かめましょう。リモートの傾向は[C#のリモート案件の記事](/media/csharp-remote/)で解説しています。

## 独立までの進め方

### 1. 領域と環境を分けて棚卸しする

関わったシステムごとに、期間、業界、チームの人数、担当工程、アプリの種類（Windows・Web・制御系など）、.NETの版、データベースを書き出します。Javaの業務システムと同じように工程の書き分けも大切です。進め方の近い[Javaエンジニアがフリーランスになるには](/media/java-how-to/)も参考になります。

### 2. 応募する領域を一つ選ぶ

C#は領域が広いため、すべてに応募すると経歴が散らばって見えます。最初は、経験の長い領域を一つ選び、その中で案件を探すと面談で説明しやすくなります。必要なスキルの全体像は[C#の案件で求められるスキルの記事](/media/csharp-skills/)にまとめています。

### 3. スキルシートと希望条件を整える

スキルシートでは、システムごとに領域・環境・工程を表で示します。書き方は[C#のスキルシートの記事](/media/csharp-skillsheet/)と[スキルシートの基本](/media/skillsheet-basics/)をご覧ください。稼働日数、出社できる日数、報酬の下限も先に決めておきます。報酬の決まり方は[C#の報酬の記事](/media/csharp-rate/)で扱っています。

### 4. 案件を探して面談を受ける

フリーランスエージェント（案件紹介サービス）、知人の紹介、発注元との直接契約などの方法があります。使い方は[フリーランスエージェントの使い方](/media/agent-how-to-use/)で解説しています。

## 面談でよく問われること

1. **作ってきたアプリの種類**：Windowsアプリ、Web、制御系のどれで、どの程度の規模か
2. **.NETの版と移行**：使ってきた版、移行で詰まった点と直し方
3. **データベース**：SQLの書き方、性能の問題をどう調べたか
4. **非同期処理**：async/awaitを使った処理や、画面が固まる問題への対応
5. **稼働の条件**：開始時期、稼働日数、出社や現地作業の可否

Azureを使う案件では、クラウドの運用経験も聞かれます。クラウド側の準備は[Azureエンジニアがフリーランスになるには](/media/azure-how-to/)も参考にしてください。

:::caution
移行や改修の案件では、請負契約で「動くものの完成」を約束する形になっていることがあります。古いシステムは仕様書が残っていないことも多く、想定外の作業が増えても報酬が変わらないと負担が大きくなります。契約の形と、作業が増えたときの扱いは、参画前に確認しましょう。違いは[準委任契約と請負契約の違い](/media/junin-vs-ukeoi/)で解説しています。
:::

## 独立前後の手続きと契約

会社を辞めて独立する場合は、次の手続きが必要です（2026年10月時点の公的な案内による）。

| 手続き | 期限・内容 | 窓口 |
|---|---|---|
| 国民年金への切り替え | 退職日の翌日から14日以内 | 住所地の市区町村 |
| 健康保険の切り替え | 国民健康保険への加入か、任意継続を選ぶ | 市区町村・加入していた健康保険 |
| 開業届 | 事業を始めた年分の確定申告期限まで | 納税地の税務署 |
| 青色申告承認申請書 | 1月16日以後に開業した場合は開業日から2か月以内 | 納税地の税務署 |

手順の全体は[会社員からフリーランスになる手順](/media/quit-company-steps/)、開業届は[開業届の出し方](/media/kaigyo-todoke/)で解説しています。税金や保険の判断に迷う場合は、税理士や窓口にご相談ください。

2024年11月に施行されたフリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容・報酬の額・支払期日などを書面やメールなどで明示することとされています。現地作業の有無や担当する工程が、面談の内容と合っているかを確かめましょう。

:::view
当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、業務の範囲・報酬・支払期日・契約期間は個別契約に書いてお渡ししています。経歴は、ご了承いただいた案件にだけ、氏名・連絡先を伏せて提案しています。出社や現地作業の頻度など、C#の案件で差が出やすい条件は、ご紹介を受ける前に確かめておくことをおすすめします。
:::

:::point
- C#の独立では、どの領域（業務アプリ・Web・制御系など）で、どの.NET環境の経験があるかを分けて示す
- .NETにはサポートの期限があり、移行の経験は説明しやすい実績になる
- SQLと設計書の経験があると、入れる工程が広がる
- 請負の移行案件は、作業が増えたときの扱いを参画前に確かめる
:::

## よくある質問

### .NET Frameworkの経験しかなくても独立できますか？

.NET Frameworkで業務アプリを作ってきた経験は、保守や移行の案件で生かせます。ただ、新しく始まる開発は新しい.NETで進むことが多いため、独立前に個人の学習や社内の案件で触れておくと、参画できる案件が広がります。

### Unityの経験は業務系のC#案件で評価されますか？

C#の文法やオブジェクト指向の理解は共通しているため、基礎の力としては伝えられます。ただ、業務系の案件では、データベースや設計書、業務の進め方の経験が求められます。業務系に移りたい場合は、その部分を補う必要があります。

### 現地作業のある案件は避けたほうがよいですか？

一概には言えません。製造・制御系では、装置のある現場での確認が欠かせないことがあります。頻度や交通費の扱いを確かめたうえで、生活と合うかで判断してください。最初の案件の選び方は[最初の案件の記事](/media/first-project/)も参考になります。
