生成AIエンジニアのフリーランス案件の報酬は、**試作で終わる案件か本番で使い続ける案件か、回答の品質を評価する仕組みまで作るか、既存の業務システムとつなぐか、入力してよい情報や権限の設計まで担うか、業務部門への定着まで関わるか、稼働日数、商流**で決まります。生成AIエンジニアの単価について公的な統計はなく、案件ごとに大きく変わります。

生成AIは新しい分野のため、経験者が少ない時期には条件が上がりやすい面があります。ただ、APIを呼んで動く試作を作るだけなら、できる人は増えていきます。単価を保ち、上げていくには、「動くものを作れる」から「業務で使える品質にして、使われ続ける状態にできる」へ、示せる経験を移していくことが大切です。

## 報酬の差は「試作のあと」をどこまで担うかで生まれる

生成AIの案件は、同じ「社内文書の検索と回答（RAG）」でも、どこまで任されるかで責任の重さが大きく違います。

| 担う範囲 | 主な仕事 | 報酬への影響 |
|---|---|---|
| 試作・検証 | APIとプロンプトで動くものを作り、使えそうかを見せる | 期間が短く、できる人が増えている |
| 品質の評価と改善 | 評価データを作り、検索やプロンプトの改善を数字で示す | 改善を説明できる人が限られ、評価されやすい |
| 本番の開発 | 認証、権限、ログ、既存システムとの連携を作り込む | ソフトウェア開発の力が問われ、担える人が限られる |
| 運用と統制 | 利用料の管理、誤回答への対応、利用ルールの運用 | 継続しやすく、責任の重さが条件に表れる |
| 導入の企画 | 使いどころの整理、費用の見積もり、社内への説明 | 業務部門や経営層と話せる人が少なく、条件が上がりやすい |

案件の型と独立の準備は[生成AIエンジニアがフリーランスになるには](/media/genai-how-to/)、技術の中身は[生成AIエンジニアのスキルの記事](/media/genai-skills/)で解説しています。この記事では、それが報酬にどう表れるかに絞って説明します。

## 報酬を左右する主な要素

### 1. 品質を評価する仕組みを持っているか

もっとも差がつくのは、回答が良くなったか悪くなったかを、感覚ではなく評価の仕組みで示せるかどうかです。評価の仕組みがない案件では、改善のたびに「前より良くなった気がする」で判断が止まります。評価の仕組みを作れる人は、改善の方向を決める役として任されやすくなります。

### 2. 既存のシステムとつなげるか

チャット画面だけで完結する試作と、社内の認証、文書管理、業務システムとつなぐ開発では、作業の量も、障害が起きたときの影響も違います。バックエンドの開発経験がある人は、この部分で強みを出しやすくなります。開発言語の経験の生かし方は[Pythonエンジニアの報酬の記事](/media/python-rate/)も参考になります。

### 3. 情報の扱いと権限の設計

社員が見てよい文書だけを検索の対象にする、個人情報を入力させない、外部の操作をモデルに任せる範囲を絞る、といった設計は、事故が起きたときの影響が大きい部分です。この設計まで任される場合は、責任の範囲が広がった分を条件に反映させる材料になります。

### 4. 業務への定着まで関わるか

作った仕組みが使われるかどうかは、業務部門の理解にかかっています。利用者の声を集めて直す、使い方の説明会を開く、社内ルールの案を作る、といった役割まで担う人は、開発だけの人より長く任されやすくなります。

### 5. 稼働日数と期間

生成AIの案件は、数週間から数か月の短い検証が多い一方、本番に進むと改善と運用が続きます。短い案件が続くと、案件と案件の間に空白が生まれやすくなります。空白を短くする準備は[案件が途切れたときにやることの記事](/media/no-project-gap/)にまとめています。

:::view
生成AIの案件をご紹介していると、面談で差がつきやすいのは、使ったモデルの名前より「評価の基準をどう決め、どこまで改善できたか」を話せるかどうかです。試作の経験が中心の方も、利用者の反応をもとに直した点や、費用を見積もった経験を整理すると、本番の開発の案件まで候補に入りやすくなります。当社では、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをご案内しています。
:::

## 技術の新しさは、条件の理由として長続きしない

生成AIの分野では、新しいモデルや機能が次々に出ます。経験者が少ない時期は、新しい技術を使えること自体が条件の理由になりますが、その理由は時間とともに薄れます。

- **プロンプトの調整**：モデルの性能が上がると、細かい調整の価値が下がることがある
- **特定のフレームワークの知識**：入れ替わりが速く、知識の寿命が短い
- **試作の速さ**：道具が整うほど、誰でも速く作れるようになる

一方で、評価の作り方、情報と権限の設計、費用の見積もり、業務部門との合意の取り方は、道具が変わっても求められます。単価を保つには、新しい道具を追いながら、こうした「道具が変わっても残る経験」を積み増していくことが大切です。

## 業務の削減効果に連動した報酬の注意

生成AIの導入では、「問い合わせ対応の時間が◯割減ったら成功報酬を払う」といった、業務の削減効果に連動した報酬を提案されることがあります。次の点を確かめずに受けるのは避けましょう。

1. **削減の効果を左右するのは誰か**：仕組みが使われるかどうかは、利用者の数や業務の進め方の変更に左右され、自分では動かせない
2. **比べる前と後が決まっているか**：導入前の作業時間を測っていないと、効果を示せない
3. **回答の正しさを約束していないか**：回答の品質は、入力や文書の中身で変わる。正答率を報酬の条件にすると、文書の質の問題まで背負うことになる
4. **作業への報酬が確保されているか**：連動する部分は上乗せにとどめ、作業そのものは準委任で支払われる形にする

契約の形の違いは[準委任契約と請負契約の違い](/media/junin-vs-ukeoi/)で解説しています。

:::caution
モデルのAPIの利用料は、使った量に応じて増えます。検証の段階で評価を繰り返すと、想定より費用がかさむことがあります。自分のアカウントで払い、報酬に含める形にすると、評価を重ねるほど手元に残る額が減ります。利用料は発注元のアカウントで払う形を基本にし、立て替える場合は上限と精算の方法を取り決めてから始めましょう。
:::

## 同じ生成AI案件でも提示額が違う理由

- **検証か本番か**：検証は区切りが早く、本番は責任と期間が長い
- **開発と企画のどちらが中心か**：手を動かす開発と、使いどころを決める企画では、向き合う相手が違う
- **社内の体制**：評価や運用の担当が社内にいるか、自分がすべてを担うか
- **契約までの経路**：事業会社と直接か、開発会社やコンサルティング会社を経由するか。詳しくは[商流の記事](/media/shoryu/)を参照

月額だけでなく、精算幅、稼働日数、契約期間、支払期日までそろえて比べましょう。全体像は[フリーランスの単価の決まり方](/media/rate-mechanism/)でまとめています。

## 交渉で示せる材料

| 材料 | 例 |
|---|---|
| 品質の改善 | 評価データでの正しい回答の割合や、根拠を示せない回答の割合が改善した |
| 費用の管理 | モデルの使い分けやキャッシュで、利用料の伸びを抑えた |
| 利用の広がり | 利用者や利用部門が増え、問い合わせの対応時間が減った |
| 役割の広がり | 試作から本番の設計、利用ルールの案づくりまで任されるようになった |

検証から本番へ進むときは、担う範囲が大きく変わるため、条件の見直しを相談しやすい時期です。伝え方は[単価交渉の記事](/media/rate-negotiation/)、面談での見せ方は[生成AIエンジニアのスキルシートの記事](/media/genai-skillsheet/)をご覧ください。

:::view
生成AIの案件は、検証の結果を見て、範囲や期間が途中で変わることがよくあります。当社がご案内する案件では、業務の範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。フリーランス法でも、発注側は業務の内容・報酬の額・支払期日などを書面やメールで明示することとされています。利用料の負担や、検証から本番への切り替わりで気になる点は、ご質問いただければ確認します。
:::

:::point
- 生成AIエンジニアの報酬は、試作か本番か、評価の仕組み、システム連携、情報と権限の設計、業務への定着、稼働条件、商流で決まり、案件ごとに大きく変わる
- 技術の新しさは条件の理由として長続きしない。評価・統制・費用・合意づくりの経験を積み増す
- 削減効果に連動した報酬は、効果の測り方と作業への報酬を先に決め、正答率は約束しない
:::

## よくある質問

### 生成AIエンジニアの単価の相場はいくらですか？

生成AIエンジニアの単価について公的な統計はなく、担う範囲、システム連携の有無、業界、稼働日数、商流によって大きく変わります。分野が新しく、案件の中身の幅も広いため、相場の数字より、ご自身の経験が試作・評価・本番・運用・企画のどこに当てはまるかを整理するほうが判断の材料になります。

### 機械学習の経験があると報酬は上がりますか？

評価の考え方やデータの扱いに慣れている点は強みになります。ただ、生成AIの案件では、モデルの学習よりも、既存のモデルを業務に組み込み、品質と費用を管理する力が問われることが多くあります。モデルの学習や運用が中心の案件は、[機械学習エンジニアの報酬の記事](/media/ml-engineer-rate/)の考え方に近くなります。

### 短期の検証案件ばかりだと収入が不安定になりませんか？

短い案件が続くと、次の案件までの空白が生まれやすくなります。検証の段階から評価の仕組みを作っておくと、本番に進むときに続けて任されることがあります。終了時期が見えたら早めに次の案件を探し始め、本番の開発や運用の案件も候補に入れておくと、収入の波を小さくしやすくなります。
