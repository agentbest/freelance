ECサイト・Shopifyエンジニアのスキルシートは、**関わったストアごとに「設定で済ませたこと」「自分で作ったこと」「運用で対応したこと」を分けて書く**のが基本です。そのうえで、テーマ・アプリ・外部システム連携のどれを担ったかと、使ったAPIや仕組みがいつ時点のものかを添えます。Shopifyは管理画面の設定だけでできることが多いため、読み手はまず「この人はどこから先を自分で作れるのか」を探します。

スキルシート全体の構成は[スキルシートの基本](/media/skillsheet-basics/)、EC・通販の業務経験の書き方（事業の形や注文の流れのどこを担ったか）は[EC・通販業界の経験のスキルシートの記事](/media/ind-ec-skillsheet/)で解説しています。この記事では、ShopifyなどのカートやECサイトを作るエンジニアが迷いやすい部分に絞ります。

## 読み手がECエンジニアのシートで最初に確かめること

ECやShopifyの案件の担当者がシートを開いて最初に見るのは、おおむね次の4点です。

- 担った領域（ストア構築、テーマ開発、アプリ開発、外部システム連携、ヘッドレス）
- 使ったカートやプラットフォームと、Shopifyの場合はPlusかどうか
- 新規の構築か、運用中のストアの改善か、他の仕組みからの移行か
- 自分で書いたコードの範囲と、使った言語・API

どれも、案件の募集の書き方と対応しています。募集に「アプリ開発」「GraphQL」「Plus」などの言葉があれば、読み手はシートの中で同じ言葉を探します。

## 技術欄は「設定」「開発」「連携」を混ぜない

よくあるのが、技術欄に「Shopify、Liquid、JavaScript」とだけ書く形です。これでは、管理画面の設定が中心なのか、アプリまで作れるのかが分かりません。次のように分けると、読み手が判断しやすくなります。

| 欄 | 書く内容の例 |
|---|---|
| プラットフォーム | Shopify（Plus／Plus以外）、他のカート、ECパッケージ |
| テーマ | Liquid、セクション・ブロックの設計、JSONテンプレート、Theme Check |
| アプリ・API | GraphQL Admin API、Webhook、アプリの拡張、Shopify Functions、使った言語 |
| 連携先 | 受注管理、在庫、基幹、倉庫、CRM、メール配信（製品名は守秘義務の範囲で） |
| フロントエンド | ヘッドレスの場合のフレームワーク、計測と速度の改善の道具 |

既製のアプリの導入と設定の経験も、立派な経験です。ただ、**自分で作ったアプリと同じ欄に並べない**ようにしましょう。「導入・設定したアプリ」と「開発したアプリ」を分けて書くと、面談で深掘りされたときの食い違いを防げます。

### APIや仕組みの時点を添える

Shopifyは仕組みの入れ替わりが多いプラットフォームです。Shopify.devでは、REST Admin APIは2024年10月1日にレガシーとなり、2025年4月1日以降の新しい公開アプリはGraphQL Admin APIだけで作るよう案内されています。また、サンクスページと注文状況ページでのcheckout.liquidと追加スクリプトの提供は2025年8月28日に終わり、Shopifyのヘルプセンターでは、Shopify Scriptsは2026年6月30日に廃止され、Shopify Functionsへの移行が案内されています（いずれも2026年10月時点の公式ページの記載）。

そのため、「REST Admin APIで在庫連携（20XX年）」「checkout.liquidのカスタマイズをチェックアウトの拡張に置き換え」のように、**どの時点の仕組みで、何から何へ移したか**を書くと、経験の新しさと、移行の経験の両方が伝わります。

## ストアごとに「設定・開発・運用」を分ける

プロジェクト欄の担当内容は、次の3つに分けると読みやすくなります。

- **設定・構築**：商品・配送・決済・税の設定、テーマの選定、アプリの選定と導入、データの移行
- **開発**：テーマのセクションやブロック、アプリ、連携の処理、割引や配送の処理
- **運用**：公開後の改善、不具合の調査と修正、セールや繁忙期の対応、APIのバージョンの更新

同じストアで3つとも担当していた場合も、1行にまとめず分けて書きます。「構築から運用まで担当」と書くより、何を設定し、何を作り、何に対応したかが並んでいるほうが、読み手は自分の案件に近い経験を見つけやすくなります。

## 成果の書き方と守秘義務

ECは数字で成果が見えやすい分野ですが、売上や注文数、会員数は、ストアの特定につながりやすい情報です。具体的な数字が書けない場合は、次のように書きます。

1. **何を測ったか**：表示速度、カートから注文までの割合、問い合わせの件数など
2. **何を変えたか**：画像の扱いの見直し、アプリが足すスクリプトの整理、注文の手順の短縮など
3. **どう変わったか**：「表示がおおむね半分の時間に」「同じ問い合わせが出なくなった」など、相対的な表現や状態の変化

ブランド名、ストアのURL、取引先の名前は書かず、「アパレルのD2Cブランド」「食品の定期購入のストア」のように、業種と事業の形で書くのが無難です。判断に迷うときは[スキルシートと守秘義務の記事](/media/confidentiality-in-skillsheet/)をご覧ください。

:::view
ECやShopifyの案件をご紹介していると、面談で評価が安定しやすいのは、シートに書いた改善について「何を測り、何を変えたか」を順を追って話せる方です。数字を伏せていても、手順がはっきりしていれば経験の深さは伝わります。逆に「ストア構築を担当」とだけ書いた行は、どこまで自分で作ったかを面談で一から聞かれ、時間を取られがちです。
:::

## プロジェクト欄の記入例（架空）

次は、書き方の型を示すための**架空の例**です。実在の案件・企業・ストアではありません。ご自身の経験に置き換えてお使いください。

> **期間**：○年○月〜○年○月（1年程度）
> **案件概要**：アパレルのD2Cブランドの自社ECを、自社開発のカートからShopify（Plus）へ移行し、公開後の改善を担当
> **規模・立場**：EC事業部と制作会社を含む数名のチーム（自分は開発の担当）
> **設定・構築**：配送と税の設定、商品・会員データの移行の手順づくり、旧サイトのURLの転送の設定
> **開発**：運用担当が編集できるセクションを設計（Liquid、JSONテンプレート）。注文の作成のWebhookを受けて受注管理システムへ渡す連携をGraphQL Admin APIで実装。署名の検証、重複の除外、日次の照合の処理を入れた
> **運用**：セールの前の負荷の確認と当日の監視。APIのバージョンを四半期ごとに更新。Shopify Scriptsの割引の処理をShopify Functionsへ置き換え
> **工夫・成果**：照合の処理で、連携の漏れを公開後の早い段階で検知できるようにした。商品一覧の表示がおおむね半分の時間になった

この例のように「設定・構築」「開発」「運用」を分けると、テーマ中心の案件にも、連携中心の案件にも、読み手が合う経験を見つけられます。

## 制作の経験が多い場合のまとめ方

制作会社の出身で、多くのストアを短い期間で担当してきた方は、1件ずつ同じ分量で書くとシートが長くなります。「期間・件数・主な担当（テーマの改修が中心、うちアプリ開発は○件）」をまとめた行を作り、特に深く関わった2〜3件だけをくわしく書く形が向いています。作ったテーマやアプリのサンプルを公開している場合は、何を見てほしいかを一言添えてURLを載せます（[ポートフォリオとGitHubの記事](/media/portfolio-github/)）。

:::view
当社では、経歴はご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。ECの案件は、テーマ中心か、アプリや連携中心か、移行かで、読み手が見る行が違います。提出の前に、応募する案件に近い経験が上の方に来ているかを見直すことをおすすめします。書き方で迷う点があれば、ご質問いただければ確認します。
:::

:::caution
Plusの機能を使った経験は、Plusのストアで自分が担当した範囲だけを書きましょう。チームの別の人が作った処理や、検証用のストアで試しただけの機能を、実務の経験として書くと、面談で詳しく聞かれたときに説明が食い違います。学習中のものは分けて書くのが基本です。
:::

:::point
- ストアごとに「設定・構築」「開発」「運用」を分けて書く
- 導入・設定したアプリと、開発したアプリを同じ欄に並べない
- APIや仕組みは、いつ時点のものか、何から何へ移したかを書く
- 売上やブランド名は書かず、測ったこと・変えたこと・変化で成果を示す
:::

## よくある質問

### 管理画面の設定しか経験がありませんが、書いてよいですか？

書いてかまいません。設定の経験は、ストア構築や運用の案件で判断材料になります。ただ、開発の案件に応募するときは、設定の経験だけでは合わないことがあるため、学習中のテーマ開発やアプリ開発の取り組みを分けて書き添えると、伝わり方が変わります。

### Shopify以外のカートの経験はどう書けばよいですか？

プラットフォームの欄にカートの種類と期間を書き、担当内容は同じように「設定・構築」「開発」「運用」に分けます。Shopifyへの移行の案件では、移行元の仕組みを知っていることが判断材料になるため、データの持ち方や連携の方式まで書いておくと伝わりやすくなります。

### アプリの名前は書いてもよいですか？

公開されている既製のアプリの名前は、使った道具として書くことが多い情報です。ただ、組み合わせ次第でストアが特定されることもあるため、守秘義務の範囲を確かめてから書きましょう。自分で作った非公開のアプリは、名前ではなく機能で書きます。
