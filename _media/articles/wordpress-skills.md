WordPressのフリーランス案件で問われるのは、**WordPressの仕組みに沿ってPHPを書く力、ブロックエディタに合わせた開発の力、更新とセキュリティを守る保守の力、PHPの版の変化に合わせる力**の4つです。どれをどの深さで求めるかは案件によって違い、構築の案件では前の2つ、保守の案件では後の2つが重く見られます。

この記事では、分野ごとに案件で問われる中身を整理し、最後に経験の段階ごとに求められることをまとめます。

## 案件で問われるスキルの全体像

| 分野 | 案件で問われること |
|---|---|
| WordPressの仕組みとPHP | フック、テンプレート階層、投稿の取得、カスタム投稿タイプ、REST API |
| ブロックエディタ | 独自ブロックの開発、ブロックパターン、ブロックテーマとテーマの設定 |
| 保守運用とセキュリティ | 本体・プラグインの更新、入力と出力の安全な扱い、権限の管理、障害時の切り分け |
| PHPの版への対応 | 版を上げたときに動かなくなる箇所の把握と修正 |
| サーバーと表示速度 | キャッシュ、データベース、画像の扱い、サーバーの設定 |

デザインの作成やUIの設計は、WordPressエンジニアの案件ではデザイナーが担うことが多い分野です。デザインの側のスキルは[Webデザイナーのスキルの記事](/media/web-designer-skills/)で扱っています。

## WordPressの仕組みに沿ってPHPを書く力

WordPressの案件で最初に見られるのは、PHPそのものより、**WordPressの決まりに沿って書けるか**です。

- **フック（アクションとフィルター）**：本体やプラグインのファイルを直接書き換えず、決められた場所に処理を差し込めるか
- **テンプレート階層**：どのページでどのテンプレートが使われるかを理解し、必要な分だけ作れるか
- **投稿の取得**：一覧や絞り込みを、表示の遅さを招かずに書けるか
- **カスタム投稿タイプとカスタムフィールド**：入力する人が迷わない形でデータを設計できるか
- **REST API**：外部のサービスや画面のプログラムとデータをやり取りできるか

本体やプラグインのファイルを直接書き換えたサイトは、更新したときに変更が消えたり、更新できなくなったりします。フックを使って外側から変える書き方は、保守のしやすさにつながるため、面談でもよく確かめられます。PHPそのものの力については[PHPエンジニアのスキルの記事](/media/php-skills/)で扱っています。

## ブロックエディタに合わせた開発の力

WordPressの公式の開発者向けハンドブックでは、ブロックエディタはブロックという部品を組み合わせてコンテンツを作る仕組みで、さまざまな方法で拡張できる開発の基盤だと説明されています。ブロックの開発の基本としては、block.jsonでブロックを定義すること、JavaScriptで開発すること、編集画面ではブロックがReactのコンポーネントとして読み込まれることが示されています（2026年10月時点）。

案件で問われやすいのは次の点です。

- 既製のブロックとブロックパターンで足りるか、独自のブロックが要るかを判断できる
- 独自のブロックを、編集画面と公開画面の両方で正しく動くように作れる
- 入力する人が見た目を崩しにくいよう、使えるスタイルや設定を絞れる
- クラシックエディタで作られたサイトを、ブロックエディタに移す段取りを組める

2026年5月に公開されたWordPress 7.0では、PHPだけでサーバー側からブロックやパターンを作り、自動で登録できるようになったと公式のリリースの記事で説明されています。JavaScriptの開発に慣れていない方でもブロックに関われる場面は広がっていますが、独自の編集画面を作る案件では、JavaScriptとReactの経験が引き続き求められます。画面側の技術を深める場合は[Reactエンジニアのスキルの記事](/media/react-skills/)も参考になります。

:::view
WordPressの案件の面談では、「ブロックエディタに対応できます」という説明が、既製のブロックで組み立てられるという意味なのか、独自のブロックを作れるという意味なのか、はっきりしないことがよくあります。どちらの経験なのかを分けて話せるだけで、ご紹介できる案件の幅が変わります。作ったブロックがあれば、何のために作り、何を設定で絞ったかを説明できるよう準備しておくことをおすすめします。
:::

## 保守運用とセキュリティを守る力

WordPressの公式サイトでは、正式にサポートされるのは最新版だけで、古い版へのセキュリティ修正は好意として移植していると説明されています（2026年10月時点）。運用中のサイトでは、本体だけでなく、テーマとプラグインの更新も重なります。保守の案件で問われるのは次の力です。

- **更新の段取り**：検証環境での確認、バックアップ、問題が出たときの戻し方
- **入力と出力の安全な扱い**：受け取った値の検証と無害化、出力時のエスケープ、フォームの送信元の確認
- **権限の管理**：管理者のアカウントを増やしすぎず、役割に合った権限を設定する
- **障害の切り分け**：表示が崩れたときに、本体・テーマ・プラグイン・サーバーのどこが原因かを絞る
- **プラグインの選び方**：更新が続いているか、必要以上の機能を持っていないかを見て選ぶ

改ざんや不正アクセスの調査を本格的に担う場合は、WordPressの枠を超えたセキュリティの知識が必要になります。その分野に広げる場合は[セキュリティエンジニアのスキルの記事](/media/security-engineer-skills/)が参考になります。

## PHPの版に合わせる力

WordPressの開発者向けの資料によると、2026年10月時点で、WordPress 7.0と7.1が対応するPHPは7.4〜8.5、6.9は7.2〜8.5です。一方、PHPの公式サイトでサポートされているのは8.2〜8.5で、8.2のセキュリティサポートは2026年12月31日に終わります。

つまり、**WordPress本体が動く版と、PHPとしてサポートされている版は一致しません**。サーバーのPHPを上げたときに、古いテーマや更新の止まったプラグインが動かなくなることは珍しくありません。どの関数や書き方が問題になるかを調べ、テーマやプラグインを直すか置き換えるかを判断できることが、保守や移行の案件で求められます。

## 経験の段階ごとに求められること

| 段階 | 求められること |
|---|---|
| 構築を担う段階 | テーマの開発、カスタム投稿タイプの設計、既製ブロックとパターンでの組み立て |
| 機能を任される段階 | 独自ブロックとプラグインの開発、外部サービスとの連携、表示速度の改善 |
| サイトを任される段階 | 更新の計画、PHPの版の移行、障害時の判断、発注元への説明 |
| 複数のサイトや体制を見る段階 | 開発と公開の流れの整備、コードの規約、保守の範囲と手順の設計 |

どの段階でも、作ったものを次の人が直しやすいかを考える姿勢は共通して見られます。構築を担う段階では、既製品を使いこなす力に加えて、コードで直す力を少しずつ足すことが大切です。機能を任される段階では、作ったものが更新で壊れないかを考える習慣が評価されます。サイトを任される段階では、技術の判断を発注元の言葉で説明する力が問われます。

## 面談とスキルシートでの示し方

ここまでの分野のうち、どれが自分の強みかを一つ決めておくと、案件を選ぶときの軸になります。

スキルは、使った道具の名前より、**何を判断したか**で伝わります。フックで何を変えたか、独自ブロックで何を設定で絞ったか、PHPを上げたときに何が動かなくなり、どう直したかを書き出しておくと、面談でそのまま話せます。シートへの書き方は[WordPressエンジニアのスキルシートの記事](/media/wordpress-skillsheet/)で解説しています。

:::view
保守の案件で評価が安定しやすいのは、更新の手順を自分の言葉で説明できる方です。「バックアップを取ってから更新します」だけでなく、どこで確かめ、何が起きたら戻すかまで話せると、運用中のサイトを任せられる人だと伝わります。手順を書き出した資料があれば、面談の前に見直しておくことをおすすめします。
:::

:::point
- 問われるのは、WordPressの仕組みに沿ったPHP、ブロックエディタの開発、保守とセキュリティ、PHPの版への対応
- 本体やプラグインを直接書き換えず、フックで外側から変える書き方が保守のしやすさにつながる
- WordPressが動くPHPの版と、PHPとしてサポートされる版は一致しないため、版の移行を判断できる力が求められる
:::

## よくある質問

### ブロックエディタの開発にはReactの経験が必要ですか？

独自の編集画面を持つブロックを作る場合は、JavaScriptとReactの基本が求められます。2026年10月時点ではPHPだけでブロックやパターンを作る方法も用意されていますが、案件によって求める範囲が違うため、どちらの作り方を前提にしているかを面談で確かめることをおすすめします。

### クラシックエディタの経験しかありませんが、案件はありますか？

クラシックエディタで作られたサイトの保守や改修の案件はあります。ただ、新しく作る案件ではブロックエディタを前提にすることが多いため、既製ブロックでの組み立てと、独自ブロックの基本を手元で試しておくと選べる案件が広がります。

### 資格は取っておいたほうがよいですか？

WordPressの案件では、資格よりも作ったものや対応した経験が見られることがほとんどです。WordPressの開発や保守の力を直接示す公的な資格は多くないため、まずは、作ったプラグインやブロック、更新の手順など、説明できる材料をそろえることをおすすめします。
