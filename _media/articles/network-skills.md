ネットワークエンジニアのフリーランス案件では、**ルーティングとスイッチングの基礎を土台に、障害を層ごとに切り分ける力、ファイアウォールやVPNなどセキュリティ機器の設計、クラウドとの接続、設定の自動化**が見られます。機器の名前やコマンドを知っていることより、**通信が流れる経路を頭の中で描き、どこで何が起きているかを説明できるか**が評価の分かれ目になります。

独立の目安や在職中に積みたい実績、現地作業の契約上の注意は[ネットワークエンジニアがフリーランスになるには](/media/network-how-to/)で扱っています。この記事では、分野ごとに求められるスキルの中身と、その示し方を整理します。

## 分野ごとに求められるスキル

ネットワークの案件は、扱う範囲によって求められる知識が変わります。

| 分野 | 主な技術 | 案件で確認されること |
|---|---|---|
| 社内LAN・拠点間 | VLAN、スパニングツリー、OSPFなどの経路制御 | 冗長化の設計と、切り替わるときの動き |
| データセンター・回線 | BGP、回線の冗長化、負荷分散 | 経路の制御方針と、障害時の迂回の仕組み |
| セキュリティ | ファイアウォール、VPN、プロキシ | 通信の許可の考え方と、ルールの整理 |
| 無線 | 無線LANの設計、認証 | 電波の調査と、利用者の多い場所での設計 |
| クラウド接続 | 専用線やVPNでの接続、クラウド内の仮想ネットワーク | オンプレミスとの経路と名前解決 |
| 自動化 | Python、Ansible、APIを使った設定 | 手作業をどこまで減らし、誤りをどう防いだか |

すべての分野を深く経験している人は多くありません。案件では、**軸の分野でどこまで深く設計できるか**と、**周りの分野とつながる部分をどこまで理解しているか**の2つが見られます。たとえばクラウド接続の案件では、クラウドの知識だけでなく、社内側のルーターやファイアウォールの設定を読めることが前提になります。

## 案件で特に差がつくスキル

### 経路と冗長化を説明する力

ルーティングの案件で問われるのは、プロトコルの仕組みより、**「この経路が落ちたら、どこを通って、何秒で戻るか」を説明できるか**です。経路の優先度の決め方、片側が落ちたときに通信が戻る方向（行きと帰りで経路が違うと止まる通信がある）、冗長化した機器の切り替わりの条件などを、構成図を前に話せると、設計の経験が伝わります。

### 障害を層ごとに切り分ける力

運用・保守の案件では、障害の切り分けの手順がよく確認されます。物理層（ケーブル・光の強さ）、データリンク層（MACアドレスの学習・VLAN）、ネットワーク層（経路・ARP）、その上の名前解決やアプリまで、どの順で何を確かめるかを持っているかどうかです。

- パケットキャプチャを取り、どこで通信が止まっているかを特定した経験
- 機器のログと監視の数値を突き合わせて、原因の時間帯を絞り込んだ経験
- 「ネットワークが遅い」という申告を、回線・機器・アプリのどこの問題か切り分けた経験

ネットワークの障害は、ほかのチームから「ネットワークのせいでは」と言われて始まることが多い仕事です。**ネットワークに問題がないことを根拠を示して説明できる力**も、現場では頼りにされます。

:::view
ネットワークの案件をご紹介していると、面談で評価されやすいのは、扱った機器の台数より「障害のときに何から確かめたか」を順に話せる方です。手順が具体的だと、運用の経験が長い方でも、設計や改善の案件で話が通りやすくなります。スキルシートに対応した障害の例を一つ、切り分けの順番がわかる形で書いておくことをおすすめします。
:::

### セキュリティ機器のルールを整理する力

ファイアウォールの案件では、新しくルールを作るより、**長年の運用で増えたルールを整理する仕事**が多くあります。使われていないルールの洗い出し、許可が広すぎるルールの絞り込み、変更の申請と承認の流れづくりなどです。どの通信を誰の判断で許可しているかを記録に残した経験は、監査や統制が絡む案件で評価されます。

VPNやリモートアクセスの案件では、認証の方式、利用者が増えたときの処理能力、端末の状態を確かめる仕組みとの連携などが確認されます。セキュリティを軸にしたい場合は[セキュリティエンジニアのスキルの記事](/media/security-engineer-skills/)もあわせてご覧ください。

### クラウドとの接続を設計する力

クラウドの利用が広がり、オンプレミスのネットワークとクラウドをつなぐ案件が増えています。ここで求められるのは、クラウドの画面の操作より、**社内のアドレス設計と重ならないようにクラウド側のアドレスを決める力、経路をどちらからどう広告するかの判断、社内とクラウドの両方から名前解決できる仕組み**です。これらはオンプレミスの経験がそのまま生きる部分です。各クラウドの考え方の違いは、[AWS](/media/aws-skills/)、[Azure](/media/azure-skills/)、[GCP](/media/gcp-skills/)のスキルの記事で扱っています。

### 設定を自動化する力

設定の変更や情報の収集をPythonやAnsibleで自動にした経験は、規模の大きい環境の案件で評価されます。ただ、自動化の価値は「速くなった」だけではありません。**同じ手順を誰がやっても同じ結果になり、作業の誤りが減ること**のほうが、運用の現場では重く見られます。

- 機器の設定を定期的に取得し、前回との差分を確認できるようにした
- 変更の作業を、事前の確認・投入・事後の確認まで手順として自動にした
- 設定の雛形を作り、拠点ごとの値だけを差し替える形にした

## 資格の位置づけ

ネットワークの資格は、基礎の体系を示す材料になります。入口となるCCNAとIPAのネットワークスペシャリスト試験の概要は[ネットワークエンジニアがフリーランスになるには](/media/network-how-to/)で紹介しています。ここでは、もう一段深い専門性を示す資格を整理します（2026年10月時点の各公式サイトによる）。

| 資格 | 構成 | 有効期間など |
|---|---|---|
| CCNP Enterprise（Cisco） | コア試験（350-401 ENCOR）と、選択する専門試験1つ | 3年。継続教育のクレジットや再受験で更新 |
| Professional Cloud Network Engineer（Google Cloud） | VPCの設計と実装、ハイブリッド・マルチクラウドの接続、ネットワークのセキュリティなど | 推奨される経験は業界経験3年以上（Google Cloudでの設計・管理1年以上を含む） |

CCNP Enterpriseのコア試験は、IPv4とIPv6のデュアルスタックの構成、仮想化、インフラ、ネットワークの品質の確認、セキュリティ、自動化を扱います。専門試験は、高度な経路制御、SD-WAN、設計、自動化などから選ぶ形です。選んだ専門試験の分野が、そのまま自分の軸を示す材料になります。

なお、IPAのネットワークスペシャリスト試験は、現行の制度が2026年度で終わり、2027年度から新しい試験制度に移る予定と案内されています。これから受験を考える方は、IPAの最新の案内を必ずご確認ください。

:::caution
資格で学んだ知識は、特定の機器メーカーの操作に偏ることがあります。案件で使われる機器は現場ごとに違うため、コマンドの暗記より、仕組みを理解して別のメーカーの機器でも同じ設計を説明できるようにしておくと、応募できる案件の幅が狭まりにくくなります。
:::

## スキルシートと面談での示し方

ネットワークの経験は、機器名と台数を並べるより、**どういう構成の中で、どの工程を担い、何を判断したか**を書くと伝わります。

- 拠点間の経路を冗長化し、片側の障害時に通信が戻ることを試験で確かめた
- 増えすぎたファイアウォールのルールを洗い出し、利用部門と確認して整理した
- 社内とクラウドをつなぐ際、アドレスの重なりを避ける割り当てを決めた
- 機器の設定の取得と差分の確認を自動にし、変更作業の確認漏れを減らした

面談では、構成図を描きながら説明を求められることがあります。冗長化の仕組み、障害の切り分けの手順、セキュリティのルールの考え方は、口頭でも説明できるようにしておきましょう。書き方の詳細は[ネットワークエンジニアのスキルシートの書き方](/media/network-skillsheet/)、報酬との関係は[ネットワークエンジニアの報酬の記事](/media/network-rate/)をご覧ください。

:::view
当社では、取引先の会社の実態と支払条件を確かめた案件を扱っています。ネットワークの案件は、設計中心か、運用・保守中心か、現地作業がどれだけあるかで働き方が大きく変わります。ご自身のスキルの軸とあわせて、対応できる作業の場所と時間帯もはっきりさせておくと、合う案件を選びやすくなります。
:::

:::point
- ネットワークの案件では、経路と冗長化の説明、障害の切り分け、セキュリティ機器の整理、クラウド接続、自動化が見られる
- 機器の操作より、通信の流れを描いて説明できる力が評価の分かれ目になる
- 資格はCCNAやネットワークスペシャリストが入口、CCNPなどで専門分野を示せる
:::

## よくある質問

### 特定メーカーの機器しか扱ったことがありませんが不利ですか？

同じメーカーの機器を使う案件では強みになります。ほかのメーカーの案件に広げたい場合は、経路制御や冗長化の仕組みを理解したうえで、設定の書き方の違いを確かめておけば、説明できる範囲が広がります。

### プログラミングはどこまで必要ですか？

運用・保守や構築の案件では、必須でないことも多くあります。ただ、設定の取得や変更の自動化を求める案件は増えており、Pythonで機器から情報を集めて整理できる程度の力があると、評価される場面が増えます。

### クラウドの経験がなくてもクラウド接続の案件に入れますか？

社内側のネットワーク設計の経験があれば、接続の案件で生かせる部分は多くあります。クラウド内の仮想ネットワークの考え方や、アドレスと名前解決の設計の違いを学んでおくと、応募できる案件が広がります。
