AWS認定ソリューションアーキテクト–アソシエイト（以下、SAA）は、**持っていなくても参画できるAWS案件が多い一方で、運用中心の経歴から設計に広げたいときや、AWSの経験年数が短いときの書類選考では裏付けとして効きます**。評価を分けるのは、試験で問われる「要件に合わせて構成を選ぶ力」を、実際の案件でどう使ったかを説明できるかどうかです。

この記事では、2026年10月時点のAWSの公式ページをもとに、試験の範囲と有効期間を確かめたうえで、SAAが効く場面と効きにくい場面、実務経験との組み合わせ方、スキルシートへの書き方を整理します。AWSの案件で求められるスキル全体は[AWSエンジニアのスキルの記事](/media/aws-skills/)、職種として取る資格の選び方は[AWSエンジニアの資格の記事](/media/aws-shikaku/)で扱っています。

## SAAの試験で問われる範囲と有効期間

SAAは、Amazon Web Services（AWS）が実施する認定で、ソリューションアーキテクトの役割を担う人を対象にしています。試験ガイドでは、AWS Well-Architected Frameworkにもとづいて設計する力を確かめる試験と説明されています。

| 項目 | 内容（2026年10月時点の公式ページによる） |
|---|---|
| 実施 | Amazon Web Services |
| 試験 | SAA-C03。130分、65問（択一・複数選択）。採点対象は50問で、残り15問は採点されない |
| 推奨される経験 | AWSを使ったクラウドの設計の実務経験1年以上 |
| 出題分野と比率 | セキュアな設計30%、弾力性のある設計26%、高性能な設計24%、コストを最適化した設計20% |
| 合否 | 100〜1,000のスコアで、720以上が合格 |
| 受験方法 | テストセンターまたはオンライン監督付き。日本語で受験できる |
| 有効期間 | 3年間 |

推奨される経験は受験の条件ではありません。ただ、「1年以上の設計経験」が想定されている点は、案件側がSAAをどう読むかにもつながります。

### 有効期間と更新の方法

SAAの有効期間は3年間です。公式ページでは、期限が切れる前に最新版のSAAに合格するか、上位のソリューションアーキテクト–プロフェッショナルに合格すると更新されると案内されています。更新すると、そこから3年間有効になります。

このほか、AWS Skill Builderの有料プランに加入していて、有効期限の90日前以内であれば、所定の学習を終えることで1年延長する「維持」の方法もあります。どの方法を選んだかで次の期限が変わるため、スキルシートには認定の管理画面で確かめた期限を書きます。

## SAAがなくても入れる案件が多い理由

AWSの案件で面談の中心になるのは、どの規模の環境で、設計・構築・移行・運用のどこを担ったかです。発注側は、決まった構成を運用する人を探しているのか、構成を決める人を探しているのかで、確かめる経験が変わります。どちらの場合も、実際の環境での経験があれば、SAAを持っていなくても参画が決まることは珍しくありません。

反対に、SAAを持っていても、実務の経験がAWSの画面での定型作業に限られていると、設計を任せる案件では評価が分かれます。SAAは「設計の基本を体系的に学んだ」ことの証明であって、「設計を任された」ことの証明ではないためです。

## SAAが効きやすい場面

### 運用から設計・構築に広げたいとき

監視や障害対応の経験が中心の人が、構築や設計の案件に応募するとき、SAAは「構成を選ぶ観点を一通り学んでいる」ことを示す材料になります。試験の4分野は、セキュリティ、可用性、性能、コストと、設計で天秤にかける観点そのものです。運用の中で可用性やコストの改善に関わった経験と並べると、設計に近い経験として読まれやすくなります。

### オンプレミスのインフラ経験にAWSを足すとき

ネットワークやサーバーの経験が長く、AWSの実務がまだ短い人にも効きます。インフラの基礎は経歴で伝わっても、AWSのサービスの組み合わせ方をどこまで理解しているかは経歴だけでは分かりにくいからです。移行案件では、現行の環境を読める人がAWSの構成も理解していることが求められます。

### 書類選考で歓迎条件に名前があるとき

案件票の歓迎条件に「AWS認定（アソシエイト以上）」のように書かれている場合は、書類の段階で目に留まりやすくなります。案件票の読み方は[案件票の読み方の記事](/media/project-info-read/)で解説しています。

## SAAだけでは効きにくい場面

- **上流の設計を主導する役割**：複数のアカウントや組織全体の構成を決める案件では、上位のプロフェッショナルの認定や、実際に設計を主導した経験が見られます。プロフェッショナルは、AWSでの設計と実装の経験2年以上が推奨されています
- **特定の分野を深く問う案件**：セキュリティやネットワーク、データ基盤などは、分野ごとの経験が先に見られます。セキュリティ寄りの案件は[AWS認定セキュリティの記事](/media/cert-aws-security/)をご覧ください
- **IaCやCI/CDが前提の案件**：SAAの範囲は構成の選び方が中心で、TerraformなどでのIaCの経験は別に問われます。IaCの資格は[Terraform Associateの記事](/media/cert-terraform/)で扱っています

:::view
案件紹介の現場では、SAAをお持ちの方の中でも、試験の観点を自分の経験に当てはめて話せる方は面談が早く進む傾向があります。たとえば「可用性を上げるためにマルチAZにしたが、コストとの兼ね合いで一部は単一構成にした」のように、判断の理由まで話せる方です。反対に、認定名だけが並び、担った工程の説明が短い経歴では、発注側が任せる範囲を判断しにくくなります。SAAを取ったら、試験の4つの観点で自分の経験を一度書き出してみることをおすすめします。
:::

## 実務経験との組み合わせ方

SAAを経験の裏付けとして使うには、試験の分野と自分の経験を対応させておくと説明しやすくなります。

| 試験の分野 | 結びつけやすい実務の経験 |
|---|---|
| セキュアな設計 | IAMの権限の整理、セキュリティグループの見直し、暗号化の設定 |
| 弾力性のある設計 | マルチAZ構成、バックアップと復旧の手順づくり、障害時の切り替え |
| 高性能な設計 | 負荷に合わせた構成の見直し、キャッシュの導入、データベースの性能改善 |
| コストを最適化した設計 | 使っていない資源の整理、料金プランの見直し、ストレージの階層化 |

すべての分野で経験がそろっている必要はありません。経験の薄い分野は、検証環境で構成を作って確かめておくと、面談で「試験で学んだ」だけで終わらずに話せます。検証環境での経験は、実務とは分けて書きます。

上流の工程に広げる考え方は[上流工程の案件に入るための記事](/media/upper-process/)にまとめています。

## スキルシートでの書き方

資格欄には、正式名称、取得年月、有効期限をそろえて書きます。

> 例：AWS Certified Solutions Architect - Associate（20XX年X月取得、有効期限20XX年X月）

あわせて、SAAで学んだ観点を使った案件があれば、経歴欄のその案件に「可用性とコストの比較をもとに構成案を作成」のように一言添えます。資格欄と経歴欄がつながると、認定が実務に生きていることが伝わります。期限が切れたものは有効な認定と分けて「取得歴」として書きます。AWSのスキルシート全体の書き方は[AWSのスキルシートの記事](/media/aws-skillsheet/)で紹介しています。

:::caution
SAAの試験ガイドは改訂されることがあります。古い版の問題集だけで準備すると、出題の範囲や対象のサービスとずれるおそれがあります。受験の前に、公式の試験ガイドで対象のサービスと範囲外のサービスの一覧を必ずご確認ください。
:::

## 案件と並行して準備するときの進め方

1. **試験ガイドで4分野と対象サービスを確かめる**：自分の経験で説明できる分野と、説明できない分野に分けます
2. **説明できない分野を検証環境で作る**：構成を作り、なぜその構成にしたかを短く書き残します。面談の材料にもなります
3. **受験の時期を案件の繁忙期と重ねない**：本番切り替えや障害対応が多い時期を避けて日程を決めます

学習の時間の作り方は[学習時間の作り方の記事](/media/benkyo-jikan/)をご覧ください。

:::view
当社では、案件をご案内するときに、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをお出ししています。SAAを取得したあとに設計寄りの案件へ広げたい場合は、経歴のどの部分が設計の経験として読めるかを事前に整理しておくと、ご案内できる案件の幅を考えやすくなります。案件票にある認定の条件が必須か歓迎かが分かりにくいときは、ご質問いただければ確認します。
:::

:::point
- SAAがなくても参画できるAWS案件は多く、面談の中心は担った工程と判断の経験
- 効きやすいのは、運用から設計への拡大、オンプレミス経験にAWSを足すとき、歓迎条件に名前があるとき
- 有効期間は3年。最新版の試験やプロフェッショナルの合格で更新でき、Skill Builderでの1年延長もある
- 試験の4分野と自分の経験を対応させ、資格欄と経歴欄をつなげて書く
:::

## よくある質問

### クラウドプラクティショナーを先に取るべきですか？

AWSの公式ページでは、ITの経験がまったくない人にはクラウドプラクティショナーを先に取ることが推奨されています。インフラや開発の実務経験がある人は、SAAから受けても問題ありません。案件の面談では、基礎の認定よりも実務とSAA以上の認定の組み合わせが見られる傾向があります。

### SAAとプロフェッショナルのどちらを目指すべきですか？

設計を主導する役割を狙うならプロフェッショナルが目標になりますが、推奨される経験は2年以上と重くなります。設計の経験がまだ短い場合は、SAAで観点を固め、案件で設計に関わる経験を積んでから進むと、学習を実務に結びつけやすくなります。プロフェッショナルに合格するとSAAも更新されます。

### SAAを取れば単価は上がりますか？

SAAを取っただけで報酬が上がるとは限りません。報酬は担う役割や案件の需要、稼働日数などで決まり、案件によって大きく変わります。SAAをきっかけに設計の工程を担えるようになれば、選べる案件が変わることはあります。
