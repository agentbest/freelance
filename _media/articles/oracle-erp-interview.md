Oracle ERPコンサルのフリーランス面談でよく聞かれるのは、**どの製品とリリースで、どの領域を、どの工程まで担ったか、標準機能で足りない要件をどう扱ったか、データ移行と更新・パッチにどう関わったか**です。面談官は知識の量より、「この人にこの領域を任せたら、利用部門と話して設定まで進められるか」を確かめようとしています。

答えるときは、模範解答を覚えるより、自分のプロジェクトから「判断の場面」を3つほど選び、どの質問にもそこから答えられるように準備しておくのが近道です。面談全般の答え方は[業務委託の面談でよく聞かれる質問と答え方](/media/interview-questions/)で解説しているので、この記事ではOracle ERPの面談に固有の質問に絞ります。

## Oracle ERPの面談で面談官が見ていること

面談に出てくるのは、導入を担う会社の領域リードやPM、発注元の情報システム部門の担当者であることが多く、本人もOracle ERPに触れてきた人です。そのため、画面や機能の名前を並べても、すぐに「それはどの業務のために、どう設定したのか」と掘り下げられます。

面談官が知りたいのは、おおむね次の3点です。

1. **経験の範囲**：製品・リリース・領域・工程のどこを、どの深さで担ったか
2. **判断の仕方**：利用部門の要望と標準機能がぶつかったときに、何を見て何を決めたか
3. **一緒に働けるか**：利用部門や開発者、他の領域の担当とのやり取りが、自社のやり方に合うか

以下の質問は、この3点のどれかを確かめるためのものです。質問の意図が分かれば、答えの中心に何を置くかも決まります。

## よく聞かれる質問と答え方の考え方

ここで示す答えの例は、組み立て方を伝えるための**架空の例**です。そのまま使うのではなく、ご自身の経験に置き換えて準備してください。

### 1. 「直近のプロジェクトの製品と、担当した領域を教えてください」

確かめたいのは経験の範囲です。製品（FusionかEBSか）、EBSならリリース、業種、プロジェクトの種類（導入・運用・保守・移行）、担当領域、自分の役割を短く伝えます。**製品とリリースを最初に言う**だけで、後の質問との食い違いが起きにくくなります。

架空の例：「製造業のFusion Cloud ERPの新規導入で、買掛金と支払の領域を担当しました。要件定義から本番稼働後の最初の締めまで関わり、設定は自分で行っています」

### 2. 「その領域で、自分で設定したものと、設計だけ担ったものを分けてください」

経験の深さを測る質問です。設定を自分で行ったもの、設計書を書いて他の人が設定したもの、レビューだけしたものを分けて話します。全部を「担当しました」とまとめると、掘り下げられたときに答えに詰まります。

### 3. 「標準機能で足りなかった要件を、どう扱いましたか」

Oracle ERPの面談で最もよく掘り下げられる質問です。次の順番で組み立てると伝わりやすくなります。

- どんな業務の要望だったか
- 標準機能のどこまでで受けられ、どこが足りなかったか
- 選択肢（運用を変える、設定の工夫で補う、アドオンや外部の仕組みで補う）をどう並べたか
- なぜそれを選び、誰と合意したか
- 結果と、次に生かしたこと

「アドオンを作りました」だけで終わると、判断の中身が見えません。**作らずに済ませた例**や、業務側の運用を変えてもらった例を話せると、標準機能を前提にした考え方が伝わります。

### 4. 「データ移行には、どこまで関わりましたか」

移行の対象の決め方、データの整え方、取り込みの方法、エラーの読み方、残高や件数の照合のどこまで担ったかを話します。移行のリハーサルを何度回し、何が起きて何を直したかを話せると、本番切替の場面を想像してもらいやすくなります。

### 5. 「Fusionの四半期アップデートに、どう対応していましたか」

Fusionの運用経験を確かめる質問です。Fusionは四半期ごとに更新が入り、2026年10月時点ではOracleの案内ページに「26D」の新機能資料が掲載されています。新機能資料を読んで影響を洗い出し、使う機能を利用部門と決め、テスト環境で業務を流して結果を記録した、という流れのうち、自分がどこを担ったかを話します。Oracleのドキュメントでも、テスト環境は本番に同じメンテナンスを当てる前の検証に使うと説明されており、**検証の段取りを自分で組んだ経験**は評価されやすい材料です。

### 6. 「EBSのアドオンや既存の設定を、どう読み解きましたか」

EBSの保守や移行の案件で聞かれます。資料が少ない環境で、設定、アドオン、データのどれが原因かを切り分けた経験を話します。SQLで本番データを確かめた、PL/SQLの処理を追った、といった技術の深さは、どこまで自分でできるかを正直に伝えます。EBSは2026年10月時点でも12.2系の新しいリリースが提供されており、担当した環境のリリースを答えられることも前提として見られます。

### 7. 「隣の領域とのつなぎ目で、困ったことはありますか」

財務と調達、受注と入金のように、領域の境目の理解を確かめる質問です。請求書の照合、仕訳の連携、入金の消込などで起きた問題と、他の領域の担当とどう解決したかを話します。つなぎ目を説明できる人は、領域のリードを任されやすくなります。

### 8. 「利用部門から無理な要望が出たとき、どう伝えましたか」

やり取りの相性を確かめる質問です。画面や設定の名前ではなく、業務の手順がどう変わるかで説明したか、決める人を誰にしたか、を話します。断った話より、**代わりの案を示して合意した話**のほうが伝わります。

:::view
Oracle ERPの案件をご紹介していると、面談で評価されやすいのは、設定した画面の名前を並べる方より、「どの業務を、標準機能のどこで受け、足りない部分をどう補ったか」を順に話せる方です。反対に、FusionとEBSの経験が混ざったまま話してしまい、どの経験がどの製品のものか伝わらないと、経験の厚さが正しく受け取られにくい傾向があります。プロジェクトごとに製品とリリースを最初に言う習慣をつけることをおすすめします。
:::

## 準備は「製品・領域・判断の場面」をそろえる

上の質問は数が多く見えますが、答えの材料は共通しています。準備は次の手順で進めると効率的です。

1. **プロジェクトごとの1行をつくる**：製品とリリース、業種、プロジェクトの種類、領域、役割を1行で言えるようにする
2. **判断の場面を3つ選ぶ**：標準機能とのギャップ、データ移行、更新やパッチの対応など、性質の違う場面を選ぶ
3. **場面ごとにメモをつくる**：要望、選択肢、選んだ理由、合意の相手、結果、学びを書き出す
4. **技術の深さを言葉にする**：SQL、データの取り込み、レポートの作成などを、どこまで自分でできるかで整理する
5. **スキルシートと照らし合わせる**：シートの記載と話の内容が一致しているかを確かめる

面談官はシートを見ながら質問するため、話とシートがずれると、どちらも信用されにくくなります。書き方は[Oracle ERPコンサルのスキルシートの記事](/media/oracle-erp-skillsheet/)、冒頭の自己紹介の組み立て方は[面談の自己紹介の記事](/media/self-introduction/)で解説しています。

:::caution
面談では、前の案件の発注元の社名、アドオンの具体的な仕様、勘定科目の体系、取引の金額などを話してしまいがちです。ERPのコンサルは会社の会計や取引の情報に深く触れる立場なので、話の具体性と守秘のバランスが問われます。社名は業種と規模に置き換え、仕様は「何のための仕組みだったか」の水準で話しましょう。考え方は[スキルシートに書いてよいこと・いけないこと](/media/confidentiality-in-skillsheet/)が参考になります。
:::

## 面談の相手によって重心が変わる

| 面談の相手 | 重く見られやすい点 |
|---|---|
| 導入を担う会社の領域リード・PM | 設定の深さ、つなぎ目の理解、チームでの動き方 |
| 発注元の情報システム部門 | 運用や更新の経験、利用部門とのやり取り、問い合わせの切り分け |
| 発注元の利用部門（経理・購買など） | 業務の理解、説明の分かりやすさ |

導入を担う会社と発注元の両方と面談することもあります。その場合、前者では設定と工程の深さ、後者では業務の理解と説明の仕方に重心を置くと、限られた時間を有効に使えます。英語での面談や、海外拠点の担当者が同席する場合は、[英語を使うプロジェクトの記事](/media/eigo-project/)も参考になります。希望の金額を聞かれたときの答え方は[面談で希望単価を聞かれたときの答え方](/media/mensetsu-tanka/)で整理しています。

## Oracle ERPならではの逆質問

逆質問は、印象づくりより**参画後のずれを防ぐ確認**に使います。Oracle ERPの案件では、次の点を聞いておくと判断がしやすくなります。

- 対象の製品とリリース、担当する領域の範囲
- プロジェクトの今の局面（要件定義、設定、テスト、運用など）と、次の区切り
- 自分で設定まで行う想定か、設計とレビューが中心か
- データ移行や帳票、連携の作業を誰が担うか
- 四半期アップデートの検証や締めの時期の稼働の見込み
- 現地に出る場面と頻度

一般的な逆質問の考え方は[業務委託の面談で聞いておくべき逆質問](/media/reverse-questions/)にまとめています。逆質問で聞いた内容は、契約前の確認にもそのまま使えます。案件を選ぶときの確認点は[Oracle ERP案件の選び方](/media/oracle-erp-anken-erabi/)で整理しています。

:::view
当社では、ご経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。Oracle ERPの案件は、同じ「財務」の募集でも、求める領域や製品、自分で設定まで行うかどうかが案件ごとに違います。面談の前に確かめておきたい点があれば、ご質問いただければ確認します。
:::

:::point
- Oracle ERPの面談では、製品とリリース、領域と工程、標準機能とのギャップの扱い、データ移行、更新やパッチへの対応がよく聞かれる
- 答えは「要望→標準機能でどこまで→選択肢→選んだ理由→合意→結果」の順で組み立てる
- 準備はプロジェクトごとの1行と判断の場面3つをそろえ、スキルシートと内容を一致させる
- 逆質問では、製品と領域の範囲、局面、設定まで行うか、移行や連携の分担、繁忙期の稼働を確かめる
:::

## よくある質問

### EBSの経験しかありませんが、Fusionの案件の面談ではどう話せばよいですか？

同じ領域の業務の流れと、EBSで担った設定や移行の経験を中心に話します。そのうえで、Fusionの考え方をどこまで学んだかを、実務の経験と分けて伝えます。触れていないことを触れたように話すと、掘り下げられたときに答えに詰まるため、学んだ範囲を正確に伝えることが大切です。

### 技術的な質問にどこまで答えられればよいですか？

機能コンサルの案件でも、データの取り込み、レポート、SQLなどについて聞かれることがあります。すべてに答えられる必要はなく、自分でできる範囲と、開発者に任せてきた範囲をはっきり分けて話せれば十分です。できないことを曖昧にするより、正直に伝えたほうが役割の調整がしやすくなります。

### 面談でうまく答えられなかった質問があったら、どうすればよいですか？

面談の後、案件を紹介してくれた担当者に、答えきれなかった点と補足したい内容を伝えるのが一つの方法です。次の面談に向けては、その質問を判断の場面のメモに加えておくと、準備が厚くなります。SAPの面談と比べたい場合は[SAP FI/COコンサルの面談の記事](/media/sap-fico-interview/)も参考になります。
