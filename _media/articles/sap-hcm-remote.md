SAP HCM・SuccessFactorsコンサルのフリーランスは、**設定、設計書の作成、テストを中心にリモートで働ける案件があります**。特にクラウドのSuccessFactorsは、インターネット経由で設定画面に入れるため、作業そのものは場所を選びにくい仕事です。

一方で、人事部門と制度を詰める要件定義、給与の並行稼働の差異確認、本番切替の前後は、出社が求められやすい場面です。さらに人事・給与の案件は、**従業員の個人情報やマイナンバーを扱うため、データに触れる作業の場所や端末が細かく決められ、それによってリモートの範囲が変わる**のがこの職種の特徴です。この記事では、リモートで進めやすい仕事・しにくい仕事を分け、案件の探し方と参画前の確認点を整理します。

## 作業ごとに見たリモートとの相性

| 作業 | リモートとの相性 | 理由 |
|---|---|---|
| SuccessFactorsの画面からの設定 | 進めやすい | クラウドのため接続できれば作業が完結する |
| オンプレミスHCMの設定 | 条件しだい | 社内ネットワークへの接続の方法と、本番データへの距離で決まる |
| 機能設計書・連携の仕様書の作成 | 進めやすい | 文書で受け渡しができる |
| ダミーデータでの単体テスト・結合テスト | 進めやすい | 結果を記録して共有できる |
| 等級・手当・休暇などの制度を詰める要件定義 | 現地が選ばれやすい | 人事部門の複数の担当者の合意が要り、規程の原本を見ながら話すことが多い |
| 本番に近いデータでの移行リハーサル・給与の並行稼働 | 現地が選ばれやすい | 実データを扱うため、作業場所や端末が限定されやすい |
| 本番切替と稼働直後の締め | 現地が選ばれやすい | 給与の締め日に合わせて判断が要り、問い合わせが集中する |

大まかには、ダミーデータで済む作業ほどリモートで進めやすく、**本物の従業員データに近づくほど現地や指定の環境での作業が増える**、という傾向があります。

## 人事・給与ならではの「データ」と「時期」の制約

### 個人情報の扱いが作業場所を決める

人事・給与の仕組みには、氏名や住所に加えて、給与の額、評価、家族、健康に関わる情報、マイナンバーなどが入っています。発注側の企業は、こうしたデータを外部の人に扱わせる場合、社内の規程に沿って作業場所や端末を決めます。

マイナンバーについて、個人情報保護委員会のガイドラインは、給与や社会保険の事務を委託する側に、委託先が自らと同等の安全管理措置を講じるよう「必要かつ適切な監督」を求めています。また、委託を受けた側が再委託できるのは、委託者の許諾を得た場合に限るとされています。こうした決まりがあるため、マイナンバーを含むデータに触れる作業は、貸与端末や仮想デスクトップに限る、本番データは特定の部屋でしか扱わない、といった条件が付くことがあります。

### 給与の暦が出社の時期を決める

人事・給与の案件では、出社が増える時期が給与の暦に引っ張られます。毎月の給与の締め日、賞与の支給、年末調整、新年度の組織改編や昇格の反映は、運用の負荷が高い時期です。移行プロジェクトでも、切替は給与の締めの合間に置かれることが多く、その前後は現地に詰める体制が組まれやすくなります。参画の前に、稼働予定日が給与の暦のどこに当たるかを確かめておくと、出社が増える時期を見通せます。

### オンプレミスとクラウドで接続の条件が違う

オンプレミスのHCMは発注側の社内ネットワークの中にあるため、VPNや仮想デスクトップを通じた接続の許可が出るかどうかで、リモートの可否が決まります。長く運用されてきた環境では、外部からの接続の手順が整っておらず、保守の案件でも出社が前提になっていることがあります。

SuccessFactorsは、インターネット経由で接続できる一方、接続できる場所や端末を発注側の設定で絞っていることがあります。どちらの場合も、「接続できるか」と「その環境で本番データを見てよいか」は別の問題です。設定の作業はリモートでも、本番データの確認だけは指定の場所で、という分け方をする発注側もあります。

:::view
人事・給与の案件をご紹介していると、「設定と設計は基本リモートで、要件定義の会議と並行稼働・切替の時期だけ出社」という形の案件がよく見られます。一方で、本番データを扱う工程では、作業場所が発注側の拠点に限られる案件もあります。当社では、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをご案内しています。リモートの範囲は工程ごとに変わることがあるため、どの工程で出社があるかまで確かめることをおすすめします。
:::

## リモートで信頼を得る進め方

人事・給与の仕事では、「数字が合っていること」と「データを正しく扱っていること」の両方が信頼になります。リモートでは、それを相手が確かめられる形で共有することが大切です。

- **テストはダミーデータを基本にする**：実在の従業員のデータを使う必要があるテストは、指定された環境と手順に限る
- **画面の共有と資料に気をつける**：会議で画面を共有するときは、個人の給与や評価が映らない画面を選ぶ。資料に貼る画面は、個人が特定されないよう伏せる
- **設定の変更を記録に残す**：どの設定を、どの理由で、いつ変えたかを一覧にし、権限の変更も含めて説明できるようにする
- **差異の説明を先回りする**：並行稼働で旧と新の金額が違うときは、理由（端数の扱い、遡及の範囲など）を短く書いて報告する

SuccessFactorsは、SAP Learningの説明でも更新が頻繁なクラウドの仕組みとされています。新しいリリースで画面や機能が変わったときに、影響を短くまとめて共有できると、リモートでも頼られる存在になります。求められるスキルの全体像は[スキルの記事](/media/sap-hcm-skills/)で解説しています。

:::caution
人事・給与のデータを、私物の端末や個人のクラウドストレージに保存するのは避けましょう。テストの結果や移行のデータを手元にコピーすると、漏えいの原因になるうえ、契約違反を問われることもあります。自宅で作業する場合は、家族やほかの人に画面が見えない場所を確保してください。在宅での情報管理は[在宅で働くときの情報セキュリティ](/media/home-security/)、委託先として求められることは[業務で個人情報を扱うときの契約と注意点](/media/kojin-joho-itaku/)で解説しています。
:::

## リモートの案件の探し方

人事・給与のリモート案件を探すときは、「フルリモート」の言葉だけで絞るより、工程とデータの扱いで見るほうが合う案件を見つけやすくなります。

1. **工程で選ぶ**：設計・設定・テストが中心の工程は、リモートの比重が高くなりやすい。要件定義の初期や切替前後は出社が増えやすい
2. **製品で選ぶ**：SuccessFactorsの機能追加や改善の案件は、接続の面でリモートと相性がよい。オンプレミスの保守は、接続方式しだいで条件が分かれる
3. **扱うデータで選ぶ**：給与や移行のように実データに近い作業ほど、作業場所の決まりが厳しくなりやすい。採用や評価の設定など、テスト環境で完結しやすい作業は比較的リモートにしやすい
4. **契約の経路を確かめる**：導入パートナーの下に複数の会社が入る構成では、個人情報の再委託の許諾の扱いが関わるため、どの立場で参画するかを確かめておく

フルリモートで働くときの全般的な注意点は[フルリモートの記事](/media/full-remote/)、常駐の案件との比べ方は[常駐の記事](/media/jochu/)にまとめています。

## 参画前に確かめること

1. **出社が必要な工程と頻度**：要件定義、移行リハーサル、並行稼働、本番切替、稼働後の初回の締めのそれぞれで出社があるか
2. **扱うデータの範囲**：本番データに触れるか、触れる場合はどの環境・どの場所か。マイナンバーの項目を見る権限が付くか
3. **接続と端末**：貸与端末か私物か、仮想デスクトップ経由か。私物の場合に使ってよいソフトと保存先
4. **個人情報の取扱いの条項**：守秘義務、再委託、データの返却と廃棄、事故が起きたときの報告の手順
5. **時間外の稼働**：給与の締め日や切替の週末に作業が入るか、その場合の稼働の数え方

秘密保持の条項の読み方は[秘密保持契約（NDA）の記事](/media/nda/)をご覧ください。フリーランス法では、発注側は業務を委託したときに、給付の内容・報酬の額・支払期日などを書面やメールで明示することが求められています。

:::view
当社がご案内する案件では、業務の範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。人事・給与の案件は、参画後に「並行稼働の期間だけ出社が増える」「本番データを扱う作業が加わる」といった変化が起きることがあります。条件が変わりそうなときは、個別契約の業務範囲と照らし合わせ、早めにご相談ください。
:::

:::point
- 設定・設計・ダミーデータでのテストはリモートで進めやすく、実データに近い作業ほど出社や指定環境が増える
- マイナンバーの委託・再委託の決まりや発注側の規程が、作業場所と端末の条件を左右する
- 出社が増えるのは給与の締め日、年末調整、新年度、本番切替の前後。参画前に暦と工程を確かめる
:::

## よくある質問

### SuccessFactorsの案件ならフルリモートで働けますか？

設定や機能追加の案件では、フルリモートに近い形の案件もあります。ただ、新規導入の要件定義や、給与・移行のように実データを扱う工程が含まれる場合は、出社や指定の環境での作業が求められることがあります。工程ごとの出社の有無を確かめてから判断しましょう。

### 自宅で従業員データを扱ってもよいですか？

発注側の規程と契約で決まります。多くの場合、貸与端末や仮想デスクトップなど指定の環境に限って扱うことになります。私物の端末へのダウンロードや保存は避け、判断に迷うときは作業の前に発注側の担当者に確認しましょう。

### 地方に住んでいても人事・給与の案件に参画できますか？

リモート中心の案件であれば参画できることがあります。ただし、切替や並行稼働の時期に出社が求められる場合は、移動の時間と費用を含めて見通しを立てておく必要があります。交通費や宿泊費の扱いは、契約の前に確かめておきましょう。
