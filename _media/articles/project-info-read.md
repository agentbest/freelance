案件票の**必須スキルは「満たしていないと書類選考で外れやすい条件」、歓迎スキルは「あると有利で、現場が困っていることの手がかり」**として読みます。稼働条件は、日数・時間・場所・期間・開始日に分けて一つずつ確かめます。そして、案件票に**書かれていない項目**を見つけ、応募の前に質問するところまでが、案件票の読み方です。

案件票は、限られた行数で案件を説明する資料です。書いてある言葉の意味と、書かれていない部分の両方を読むと、応募するかどうかを判断しやすくなります。

## 案件票の主な項目と読むときの視点

案件票の形式は案件や紹介元によって違いますが、おおむね次のような項目が並びます。

| 項目 | 読むときの視点 |
|---|---|
| 案件名 | 業界とシステムの種類の大づかみ。中身は業務内容で判断する |
| 業務内容 | 担当する工程と役割。動詞に注目する |
| 必須スキル | 書類選考の足切りの条件。「すべて」か「いずれか」か |
| 歓迎スキル | あると有利な経験。現場の課題を映していることが多い |
| 求める人物像 | 現場が困っていること、前任者との違い |
| 稼働条件 | 日数・時間・精算幅。日数と時間を分けて読む |
| 勤務地・働き方 | リモートの割合、出社の頻度と場所 |
| 期間・開始日 | 最初の契約期間と、長期の見込みかどうか |
| 金額 | 誰が受け取る額か、税の扱い、精算の有無 |
| 面談 | 回数と、誰が出てくるか |

ここからは、読み違いが起きやすい項目を順に見ていきます。

## 業務内容は「動詞」で読む

業務内容の欄は、名詞よりも**動詞**に注目すると、任される役割が分かりやすくなります。

- 「設計・開発」と「設計を担当し、開発メンバーへの指示を行う」は、同じ工程でも役割が違う
- 「PMOとして支援」は、資料作成が中心のこともあれば、課題の管理や会議の進行まで含むこともある
- 「保守運用」は、障害対応が中心か、小さな改修が中心かで中身が大きく違う

「支援」「推進」「担当」など幅のある言葉が使われているときは、具体的に何をするのかを質問の候補にします。

## 必須スキルの読み方

### 「すべて」か「いずれか」かを見る

必須スキルが箇条書きで並んでいる場合、すべてを満たす必要があるのか、いずれかを満たせばよいのかで、応募できるかが変わります。案件票に書かれていなければ、確かめる価値があります。

### 年数は「実務で使った期間」の目安

「◯◯の経験3年以上」のような年数は、多くの場合、実務でその技術や業務を担った期間の目安です。学習の期間や、少し触れただけの期間は含めにくいと考えておきます。年数はあくまで目安で、担当した内容の深さで補えることもあります。

### 満たしていない必須スキルがあるとき

必須スキルを一つ満たしていない場合でも、応募できることはあります。ただし、書類の段階で見送られる可能性が高くなります。応募する場合は、近い経験（似た技術、同じ役割の別の領域）を具体的に示し、足りない部分をどう補うかを添えます。経験の浅い領域への応募の考え方は[未経験の領域の記事](/media/mikeiken/)をご覧ください。

:::view
案件紹介の現場で見る傾向として、面談で評価されやすいのは、案件票の業務内容の言葉に沿って、自分の経験を当てはめて話せる方です。必須スキルの一つひとつに「どの案件で、何をしたか」を対応させてスキルシートを整えておくと、書類でも面談でも伝わりやすくなります。当社では、先に稼働日数・リモート・希望金額を伺い、合う案件だけをご案内しています。案件票の必須スキルの読み方で迷う場合は、ご質問いただければ確認します。
:::

## 歓迎スキルと人物像は「現場の課題」として読む

歓迎スキルは、満たさなくても応募できる項目です。ただ、歓迎スキルには、**現場が今困っていること**が表れていることがよくあります。

- 歓迎スキルに「テスト自動化の経験」があれば、テストに手が回っていない可能性がある
- 「顧客折衝の経験」があれば、開発者が要件の確認まで担う場面がある
- 「チームリードの経験」があれば、将来は取りまとめを任せたい意図がある

求める人物像の欄も同じです。「自走できる方」は、細かく指示を出す余裕がない体制であることを示している場合があります。「コミュニケーションを大切にする方」は、関係者が多い、または調整が多い現場であることを示している場合があります。

歓迎スキルに当てはまる経験があれば、スキルシートや面談で前に出します。当てはまらなくても、その課題にどう関われるかを考えておくと、面談で話す材料になります。

## 稼働条件は5つに分けて読む

稼働条件は、まとめて書かれていることが多い欄ですが、次の5つに分けて読むと読み違いが減ります。

1. **日数**：週何日か。曜日の指定はあるか
2. **時間**：1日の稼働時間、コアタイム、始業・終業の時刻
3. **精算**：月の稼働時間の幅と、超過・控除の扱い
4. **場所**：フルリモートか、出社があるか。出社の頻度と場所
5. **期間と開始日**：最初の契約期間、長期の見込み、開始の希望日

「週3日〜」「リモート併用」のような書き方は、幅がある分、自分の希望とずれることがあります。たとえば「リモート併用」は、週1日の出社の場合もあれば、週の半分以上が出社の場合もあります。稼働日数の読み方は[稼働率の記事](/media/kado-ritsu/)、精算の仕組みは[精算幅の記事](/media/seisan-haba/)で解説しています。

## 金額の欄で確かめること

金額の欄では、数字そのものより、**何の金額か**を確かめます。

- 自分が受け取る額か、それ以外の額も含んでいるか
- 消費税を含むか含まないか（[税込・税抜の記事](/media/tax-included/)）
- 月額か、時間あたりか。精算の対象になるか
- 「スキル見合い」「〜」と幅がある場合、何によって決まるか

金額の水準は案件によって大きく変わります。一つの案件票の金額だけで判断せず、業務内容や稼働条件とあわせて比べます。

## 案件票によく出る言葉の読み方

案件票には、幅のある言葉がよく使われます。代表的なものと、確かめたい点を挙げます。

| 言葉 | よくある意味 | 確かめたい点 |
|---|---|---|
| 上流工程から | 要件定義や基本設計から関わる | どの工程まで担当するか。下流の作業も含むか |
| リードポジション | 技術の判断やメンバーの取りまとめを任される | 何人くらいの取りまとめか。手を動かす割合 |
| 立ち上げフェーズ | 仕組みや体制がまだ固まっていない | 決まっていることと、これから決めること |
| 即戦力 | 立ち上がりの期間を短く見込んでいる | 最初の数週間で求められること |
| 長期想定 | 更新が続く見込みがある | 最初の契約期間と、見込みの根拠 |

言葉の意味は現場によって違います。表の意味に当てはまらないこともあるため、気になった言葉は質問の候補に入れておきます。

## 案件票に書かれていないことを見つける

案件票を読んだら、**書かれていない項目**を書き出します。よく抜けているのは次のような点です。

- チームの人数と、同じ役割の人の有無
- 増員か、前任者との交代か
- 開発環境や使うツール、端末の貸与の有無
- 契約の相手と、発注元の先に何社が入っているか（[商流の記事](/media/shoryu/)）
- 準委任か請負か（[準委任と請負の記事](/media/junin-vs-ukeoi/)）

これらは、応募の前に担当者に聞けることと、面談で現場に聞くことに分かれます。分け方は[面談前のチェックリスト](/media/check-before-interview/)にまとめています。

:::caution
案件票の内容は、募集を出した時点の情報です。面談の段階で、業務内容や開始日、稼働条件が変わっていることがあります。案件票を読んで応募したあとも、面談で聞いた内容と案件票の違いはそのままにせず、参画の合意の前に確かめてください。最終的な条件は、契約の書面で受け取る内容で確かめます。
:::

## 読み終えたら、応募するかを決める

案件票を読み終えたら、次の順で判断します。

1. 自分の「譲れない条件」を満たしているか
2. 必須スキルに、自分の経験を一つずつ対応させられるか
3. 歓迎スキルや人物像から読み取れる課題に、関われそうか
4. 書かれていない項目のうち、応募前に確かめたいことは何か

4で挙げた項目は、応募の意思を伝えるときにあわせて質問します。条件を満たした案件同士を比べる観点は[案件の選び方の記事](/media/project-selection/)で解説しています。

:::view
案件票は行数が限られているため、取引先の事情や体制までは書き切れないことがあります。当社では、取引先の会社の実態と支払条件を確かめた案件を扱っています。案件票で分からない点を応募の前に質問しておくと、応募後の行き違いを減らせます。「この言葉は何を指すのか」といった細かな点でも、ご質問いただければ確認します。
:::

:::point
- 業務内容は動詞で読み、任される役割を確かめる
- 必須スキルは「すべて」か「いずれか」か、年数は実務の期間の目安として読む
- 歓迎スキルと人物像は、現場の課題を映す手がかりとして読む
- 稼働条件は日数・時間・精算・場所・期間に分け、書かれていない項目は応募前に質問する
:::

## よくある質問

### 必須スキルを一つだけ満たしていません。応募してもよいですか？

応募することはできますが、書類の段階で見送られる可能性は高くなります。近い経験を具体的に示し、足りない部分をどう補うかを添えると、検討してもらえることがあります。ほかの項目で強みがあるかもあわせて考えます。

### 必須スキルの年数が少し足りません。

年数は目安として書かれていることが多く、担当した内容の深さで補える場合があります。その期間に何を担当し、どの程度の規模だったかを具体的に書くと、年数だけでは伝わらない経験を示せます。

### 案件票に書かれた条件は、面談後に変わることがありますか？

変わることがあります。案件票は募集を出した時点の情報で、プロジェクトの状況によって業務内容や開始日、稼働条件が変わることがあります。面談で聞いた内容が案件票と違う場合は、参画の合意の前に担当者と確かめてください。
