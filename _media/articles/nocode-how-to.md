ノーコード・ローコード開発者としてフリーランスになるには、**業務を聞き取ってアプリとデータの形に落とし込み、現場で使われ続ける状態まで運んだ経験**が必要です。ツールの操作を覚えただけでは、業務委託の案件で任される範囲が狭くなります。

独立の準備では、まず自分が扱うツールの種類と、作ってきたものの性格（社内の業務アプリか、社外向けのサービスか）をはっきりさせ、その範囲で「作る前」と「作った後」を説明できる実績を整えることから始めます。Power Platform や RPA を中心にする場合は、それぞれの職種の記事をご覧ください。

## 独立の前に確かめたい経験の目安

業務委託の案件では、教えてもらいながら覚える前提で参画することは多くありません。次の表は、独立を考える段階で振り返っておきたい経験の目安です。年数ではなく、何をやり切ったかで見ます。

| 段階 | やってきたこと | 業務委託で入りやすい役割 |
|---|---|---|
| 構築を担える | 指示された仕様どおりに、画面・項目・一覧・通知・承認の流れを設定した | 構築の担当、既存アプリの改修 |
| 設計から担える | 業務を聞き取り、アプリの分け方、データの持ち方、権限を自分で決めた | 一つの部署の業務アプリづくりを任される |
| 拡張まで担える | 標準の機能で足りない部分を、プラグイン・コード・API連携で補った | 連携や拡張を含む案件、他の作り手の支援 |
| 広げる側に立てる | 複数の部署にまたがる環境を整理し、作成や変更のルールを整えた | 社内展開の支援、内製化の伴走 |

「構築を担える」段階でも参画できる案件はありますが、独立後に案件を選べる幅を考えると、少なくとも一つの業務について、聞き取りから運用の開始まで自分で通した経験があると安心です。社内の情報システム部門や業務部門で、ツールの管理者として社内のアプリを任されてきた経験は、そのまま説明の材料になります。

## ツールの種類ごとに、独立前に押さえたいこと

扱うツールの種類によって、独立前に意識して積んでおきたい経験が少しずつ違います。どのツールが良いかではなく、それぞれの案件で何が前提になるかとして整理します。

### 業務アプリ型（kintone、AppSheet など）

kintone は、プログラミングの知識がなくても業務アプリを作れるサービスとして公式に紹介されています（2026年10月時点）。AppSheet は、Google スプレッドシートやデータベースなどのデータにつないでアプリを作るノーコードの基盤と説明されています。

この種類の案件では、社内の業務をそのままアプリにするのではなく、手順を整理し直す提案が求められます。独立前に、申請や承認、案件の進み具合の管理など、複数の人が関わる業務をアプリにした経験を作っておくと説明しやすくなります。kintone の場合は、開発者向けサイトで JavaScript API や REST API、プラグインの作り方が公開されているので、拡張の入口に触れておくと、案件の話題に出たときに対応しやすくなります。

### データベース型（Claris FileMaker など）

データの構造と、処理の流れ（スクリプト）を一体で作る案件が中心です。テーブルの分け方やリレーションの考え方、運用中のデータを壊さずに改修する手順を説明できることが前提になります。長く使われてきたシステムの改修を引き継ぐ案件もあるため、他人が作った仕組みを読み解いた経験も役立ちます。

### Webアプリ型（Bubble など）

社外向けのサービスや会員サイトなど、利用者が社外にいる案件が多くなります。画面とデータに加えて、ログイン、権限、決済や外部サービスとの連携、公開後の不具合対応まで一通り担うことがあります。独立前に、要件の聞き取りから公開、公開後の改善まで一通り経験しておくと、発注側が安心して任せやすくなります。

:::view
ノーコード・ローコードの案件の面談では、「作ったアプリは今も使われていますか」と問われる場面をよく見ます。評価されやすいのは、作った数より、利用が広がった理由や、使われなくなったアプリをどう見直したかを具体的に話せる方です。社内で管理者を務めてきた方は、問い合わせへの対応や、社内の作り手からの質問に答えてきた経験も、そのまま強みとして伝えられる傾向があります。
:::

## 独立前に積んでおきたい実績

会社員のうちに次の経験を意識して積んでおくと、独立後に説明できる材料が増えます。

1. **変える前の業務を整理した経験**：紙やスプレッドシートでの管理、転記の手間、確認の手順などを、比べられる形で書き出した経験
2. **業務部門と一緒に決めた経験**：現場の担当者に試してもらい、意見を受けて画面や手順を直した経験
3. **作らない判断をした経験**：アプリにするより手順を変えたほうがよいと判断した、範囲を絞った経験
4. **引き継げる状態にした経験**：設計の記録、操作の手順書、管理者向けのメモなど、自分がいなくても回る状態を整えた経験

ノーコード・ローコードの案件では、発注側が最終的に自分たちで直せる状態を望んでいることが多くあります。4の経験は、独立後の評価に直結しやすい部分です。

## 独立までの進め方

### 1. 扱うツールの種類と案件の性格を決める

業務アプリ型・データベース型・Webアプリ型のどれを軸にするか、社内向けと社外向けのどちらを主に受けるかを決めます。複数のツールを使える場合も、軸を一つ決めて、ほかは補助として伝えるほうが、相手が役割を想像しやすくなります。

### 2. 実績を言語化し、スキルシートを用意する

取り組みごとに「どんな業務だったか」「何をアプリにし、何を変えたか」「どこまで担ったか」「その後どう使われているか」を書き出します。書き方は[ノーコード・ローコード開発者のスキルシートの記事](/media/nocode-skillsheet/)で解説しています。

### 3. 契約の形と条件を決める

この分野の案件は、アプリを作って納める請負と、稼働時間で報酬が決まる準委任の両方があります。完成の定義や修正の範囲の扱いが違うため、[準委任契約と請負契約の違い](/media/junin-vs-ukeoi/)を読んでおくと、案件を比べやすくなります。あわせて、稼働日数、出社の頻度、希望する報酬の下限を決めておきましょう。報酬の考え方は[ノーコード・ローコード開発者の報酬の記事](/media/nocode-rate/)にまとめています。

### 4. 手続きを済ませる

開業届や、退職後の健康保険・年金・住民税の切り替えなどの一般的な手続きは、[会社員からフリーランスになる手順](/media/quit-company-steps/)と[開業届の出し方](/media/kaigyo-todoke/)で順を追って解説しています。会社員のまま副業として受け始める場合は、[副業で業務委託案件を受けるときの注意点](/media/fukugyo-gyomu-itaku/)もご覧ください。

:::caution
勤務先で作ったアプリの画面やデータ構造を、独立後の実績として画像やファイルのまま持ち出すのは避けましょう。画面には顧客名や社内の情報が映り込みやすく、守秘の約束に触れるおそれがあります。実績は、業務の種類、アプリの数や利用者の規模、担った工程といった形で、言葉に置き換えて伝えるのが安全です。考え方は[スキルシートに書いてよいこと・いけないこと](/media/confidentiality-in-skillsheet/)をご覧ください。
:::

## 面談で問われやすいこと

ノーコード・ローコードの面談では、次のような質問がよく出ます。

- どんな業務を、どの種類のツールでアプリにしたか
- 業務の聞き取りから運用の開始まで、どこを自分で担ったか
- 標準の機能で足りなかったとき、どう対応したか
- 作ったアプリを、現場の担当者が自分で直せるようにしたか
- 権限や個人情報を含むデータを、どう扱ったか

正解を出すことより、判断の理由を筋道立てて話せるかが見られます。面談全体の流れは[業務委託の面談でよく聞かれる質問](/media/interview-questions/)で解説しています。

フリーランス法では、発注側は業務を委託したときに、業務の内容、報酬の額、支払期日などを書面またはメールなどで直ちに明示する必要があります（公正取引委員会の案内による）。「業務改善の支援」のように範囲があいまいになりやすい案件こそ、明示された内容を読み、分からない点を参画前に確かめておくことが大切です。個別の契約の判断に迷う場合は、専門家にご相談ください。

:::view
当社では、稼働日数・リモートの可否・希望金額を先に伺い、合う案件だけをご案内しています。契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡しし、ご経歴はご了承いただいた案件にだけ、氏名・連絡先を伏せてご提案します。独立の時期や、どの段階の経験で参画できそうかを知りたい場合は、早めにご相談ください。
:::

:::point
- 独立には、業務を聞き取り、アプリとデータに落とし込み、使われる状態まで運んだ経験が必要
- 扱うツールの種類と、社内向けか社外向けかで、前提になる経験が変わる
- 引き継げる状態を整えた経験は、評価につながりやすい
- 勤務先で作ったアプリの画面は持ち出さず、実績は言葉に置き換えて伝える
:::

## よくある質問

### 独学でノーコードツールを覚えただけで独立できますか？

業務委託の案件では、実際の業務をアプリにした経験が問われることが多く、学習だけで参画できる案件は限られます。まず社内の業務や副業の小さな案件で、聞き取りから運用の開始までを一通り経験し、その結果を説明できるようにしておくことをおすすめします。

### プログラミングの経験は必要ですか？

標準の機能だけで組む案件もあり、必須ではありません。ただ、拡張や外部連携を含む案件では、JavaScript や API の基本が分かっていると任される範囲が広がります。どこまで身につけるかは、[スキルの記事](/media/nocode-skills/)を参考に、軸にするツールと案件の性格に合わせて決めるのが現実的です。

### 最初の案件はどう選べばよいですか？

最初は、これまで扱ったツールの種類と近い業務の案件を選ぶと、立ち上がりで苦労しにくくなります。担当範囲、契約の形、ツールの契約の名義を確かめてから決めましょう。考え方は[独立後の最初の案件の選び方](/media/first-project/)で解説しています。
