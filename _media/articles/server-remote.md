サーバーエンジニアのフリーランスは、**設計書や手順書の作成、踏み台サーバーなどを経由した構築・運用、自動化のコードの作成ではリモートで働ける案件があります**。一方で、物理サーバーの設置や配線、部品の交換、外部から接続できない本番環境での作業は、現地に行くことが前提です。

リモートの可否は、職種よりも「どの工程か」「サーバーがどこにあり、どこから触れるか」で決まります。この記事では、リモートで進めやすい仕事としにくい仕事、案件の探し方、参画前に確かめたい点を整理します。

## リモートで進めやすい仕事・しにくい仕事

| 仕事 | リモートの傾向 | 理由 |
|---|---|---|
| 設計書・パラメータシートの作成 | 進めやすい | 打ち合わせと資料作成が中心 |
| 構築手順書・試験項目の作成 | 進めやすい | 検証環境があれば手元で確かめられる |
| 自動化のコードの作成・修正 | 進めやすい | コードの管理と検証環境での試験で進められる |
| 踏み台経由の構築・設定変更 | 案件による | 接続の方式と、発注元のセキュリティ方針しだい |
| 運用・保守（定型作業） | 案件による | 遠隔から操作できる環境が用意されているか |
| 障害対応 | 案件による | 遠隔で直せる範囲と、駆けつけが要る範囲がある |
| 物理サーバーの設置・配線・部品交換 | 現地が前提 | 機器に手で触れる必要がある |
| 閉じた本番環境での作業 | 現地が前提 | 外部からの接続が認められていない |

### 進めやすいのは「書く」「コードにする」仕事

設計書や手順書、試験項目の作成は、打ち合わせをオンラインで行えれば、場所を選ばずに進められます。構築や設定変更をAnsibleなどのコードで管理する現場では、コードの作成とレビューをリモートで行い、本番への反映だけを決められた手順で行う形もあります。監視の設定の見直しや、運用手順書の整備のように、本番の設定に直接触れない改善の仕事も、リモートで任されやすい仕事です。こうした仕事は成果が書類やコードとして残るため、離れた場所からでも進み具合を共有しやすいという利点があります。

### 案件によるのは「どこから触れるか」

本番サーバーへの接続を、VPNや仮想デスクトップ、踏み台サーバー経由で認めている現場では、構築や運用もリモートで進められます。ただ、金融や公共、医療などの分野では、本番環境への接続を特定の場所の端末に限っていることがあります。リモートの案件でも「本番作業の日だけ出社」という形はよくあります。

### 現地が前提なのは「機器に触れる」仕事

オンプレミスの物理サーバーを扱う案件では、データセンターでの設置、配線、ディスクや電源の交換が発生します。サーバーの更改やデータセンターの移転の時期は、現地の作業が集中しやすくなります。

:::view
サーバーの案件をご紹介していると、「フルリモート」と書かれた案件でも、参画直後の数週間や、本番の切り替えの日は出社を求められる例がよくあります。面談では、リモートの可否を一言で聞くより、「どの作業を、どの場所から、どの端末で行うか」を具体的に確かめておくと、参画後の行き違いを防げます。出社の頻度と場所は、条件として最初に伝えておくことをおすすめします。
:::

## リモート案件を探すときの見方

### 工程とサーバーの置き場所で絞る

リモートの案件を探すときは、「リモート可」の表示だけでなく、工程とサーバーの置き場所を見ます。設計や自動化が中心の案件、クラウド上のサーバーを扱う案件、移行の計画づくりの案件は、リモートで進めやすい傾向があります。物理サーバーの保守や、データセンターの運用が中心の案件は、出社や現地作業の比重が高くなります。

### 「一部リモート」の中身を確かめる

「一部リモート」「週◯日出社」と書かれた案件は、どの作業が出社の対象なのかで負担が変わります。打ち合わせのための出社なのか、本番作業のための出社なのかを確かめましょう。常駐の働き方は[常駐の記事](/media/jochu/)、地方からの参画の考え方は[地方在住のフリーランスの記事](/media/chiho/)で扱っています。

### 稼働日数と組み合わせて考える

週3〜4日の稼働を希望する場合、障害時の待機や夜間作業がある運用の案件とは合いにくいことがあります。稼働日数を抑えたい場合は、設計や自動化、移行の計画など、時間の区切りがつけやすい仕事を中心に探すと見つけやすくなります。

## 参画前に確かめたいこと

| 確かめること | 見ておきたい点 |
|---|---|
| 接続の方式 | VPN、仮想デスクトップ、踏み台サーバーのどれか。自分の端末で接続してよいか |
| 端末の扱い | 発注元から端末が貸与されるか。私物の端末を使う場合のルール |
| 本番作業の場所 | 本番環境への作業もリモートで行えるか、特定の場所に限られるか |
| 夜間作業の場所 | 夜間のメンテナンスを自宅から行えるか、現地に行く必要があるか |
| 障害時の駆けつけ | 現地に駆けつける必要があるか。その場合の移動時間と交通費の扱い |
| 出社の頻度 | 定例の出社日、立ち上げ時期の出社、作業日の出社 |

接続の方式や端末の扱いは、発注元のセキュリティの方針で決まります。総務省は、テレワークを行う組織向けに、セキュリティ対策の考え方と対策例をまとめた「テレワークセキュリティガイドライン」を公表しています（2026年10月時点の最新版は第5版）。発注元がこうした指針をもとにルールを決めている場合、自宅の通信環境や端末の管理について確認を求められることがあります。

:::caution
サーバーの管理者権限を持ったまま自宅から接続する働き方では、端末の紛失や、家族との共用、公衆無線LANからの接続が大きなリスクになります。発注元の定めたルールを守るのはもちろん、作業用の端末を他の用途と分け、画面ロックやディスクの暗号化を設定しておきましょう。ルールが示されていない場合は、参画前に確かめてください。
:::

## リモートで信頼されるための進め方

リモートで本番サーバーを触る仕事では、相手から作業が見えにくい分、作業の前後を見える形にすることが信頼につながります。

1. 作業の前に、手順と影響範囲、戻し方を共有して承認を得る
2. 作業の開始と終了を、決められた連絡手段で知らせる
3. 実行したコマンドや変更した設定を記録に残す
4. 想定と違う結果が出たら、作業を止めて報告する

こうした進め方ができる人は、リモートで任せられる範囲が広がりやすくなります。

## 自宅から本番作業をするための備え

リモートで本番サーバーの作業や夜間のメンテナンスを担う場合、自宅の環境そのものが作業の品質に関わります。参画が決まる前に、次の点を見直しておくと安心です。

| 備え | 理由 |
|---|---|
| 回線が切れたときの代わりの手段 | 設定の途中で接続が切れると、サーバーが中途半端な状態で残るおそれがある |
| 作業中に途切れない作業の仕方 | 長い処理は、接続が切れても止まらない方法で実行できるようにしておく |
| 発注元との連絡手段の確認 | 夜間に想定外のことが起きたとき、誰にどの手段で連絡するか |
| 作業の時間の記録 | 夜間や休日の作業時間を、精算や条件の見直しの材料として残す |

特に夜間の切り替えでは、自宅の回線や端末の不具合が、そのまま作業の中断につながります。発注元が代わりの接続手段を用意しているか、中断したときに現地の担当者に引き継げるかも、あわせて確かめておきましょう。待機や夜間作業の報酬の扱いは[サーバーエンジニアの報酬の記事](/media/server-rate/)で整理しています。

## クラウドへの移行の案件はリモートと相性がよい

オンプレミスからクラウドへの移行の案件は、移行元の調査、移行方式の検討、移行先の構築の多くをリモートで進めやすい仕事です。ただ、移行元のサーバーが閉じた環境にある場合、調査や切り替えの日だけは現地での作業になることがあります。移行の案件では、移行元と移行先のそれぞれについて、どこから触れるかを分けて確かめておくと、出社の見込みを立てやすくなります。現地作業や交通費の扱いは[交通費の記事](/media/transportation-fee/)、ネットワークの領域でのリモートの傾向は[ネットワークエンジニアのリモート案件の記事](/media/network-remote/)も参考になります。

:::view
当社では、案件をご案内する前に稼働日数・リモートの希望・ご希望の金額を伺い、その条件に合う案件だけをお出ししています。業務の範囲・報酬・支払期日・契約期間は個別契約に書いてお渡ししています。サーバーの案件では、本番作業や夜間作業の場所、障害時の駆けつけの有無で働き方が大きく変わります。気になる点は、面談の前にご質問ください。
:::

:::point
- 設計書・手順書の作成、自動化のコード、踏み台経由の作業はリモートで進めやすい
- 物理サーバーの設置や部品交換、外部から接続できない本番環境での作業は現地が前提
- 案件を探すときは「リモート可」の表示より、工程とサーバーの置き場所を見る
- 接続の方式、端末の扱い、本番作業と夜間作業の場所、駆けつけの有無を参画前に確かめる
:::

## よくある質問

### サーバーエンジニアでフルリモートの案件はありますか？

設計や自動化、クラウド上のサーバーの構築・運用など、フルリモートで進められる案件もあります。ただ、参画直後や本番の切り替えの日だけ出社を求められることもあるため、「どの作業を、どこから行うか」を具体的に確かめることが大切です。

### オンプレミスの経験しかありませんが、リモートの案件に入れますか？

オンプレミスでも、遠隔から操作できる環境が整っている現場では、リモートで構築や運用を進められます。設計書や手順書の作成、自動化の経験があると、リモートで任せられる範囲を広げやすくなります。

### 障害対応がある案件でもリモートで働けますか？

遠隔で直せる範囲の障害であれば、自宅から対応できる案件もあります。物理的な故障の場合は現地の担当者や保守会社が対応する分担になっていることもあります。駆けつけが必要かどうかと、その場合の扱いを参画前に確かめておきましょう。
