Flutterエンジニアがフリーランスになるには、**Dartで画面と機能を作れることに加えて、iOSとAndroidの両方のストアにアプリを出し、ネイティブ側の設定や連携まで自分で扱った経験**が必要です。Flutterの案件は少人数で両方のOSを担うことが多く、「Flutterの中だけでは解決しない問題」に対応できるかが見られます。

独立の準備は、経験の棚卸し、ネイティブ側の知識の補強、開発環境とお金の準備、最初の案件選びの順に進めます。この記事では、Flutterならではの事情に絞って説明します。

## Flutterの案件で多い現場

Flutterは、一つのコードからiOS・Androidのアプリを作れるため、限られた人数で両方を出したい企業に選ばれています。Flutterの公式ドキュメントでは、モバイルに加えてWeb、Windows・macOS・Linuxのデスクトップも配布先として挙げられています（2026年10月時点）。ただ、業務委託の案件はモバイルアプリが中心です。

| 現場の型 | 主な仕事 | 特に見られる経験 |
|---|---|---|
| 新規アプリの立ち上げ | 少人数で設計から両ストアへの公開までを担う | 状態管理の選定、ストア申請、API設計への参加 |
| 運用中アプリの機能追加 | 公開済みのアプリに機能を足し、不具合を直す | 既存コードの読解、OSの更新への対応 |
| ネイティブアプリからの置き換え | SwiftやKotlinで作ったアプリをFlutterに移す | 両方のOSの仕組みの理解、段階的な移行 |
| 既存アプリへの部分導入 | ネイティブのアプリの一部の画面をFlutterで作る | ネイティブとFlutterの橋渡し、ビルドの設定 |
| 受託開発 | 発注元のアプリを仕様に沿って作る | 見積もり、納品の範囲、公開後の保守の取り決め |

Flutterは新規の立ち上げで選ばれることも多く、その場合は一人で任される範囲が広くなりがちです。そのため、画面を作れるだけでなく、公開までの流れを一通り知っていることが求められます。

## 独立前に積んでおきたい経験

### 両方のストアへの公開

FlutterでもiOSとAndroidのストアには別々に申請します。iOS向けのビルドや申請にはMacとAppleの開発者向けの登録が、Androidの公開にはGoogle Playの要件への対応が必要です。たとえばGoogle Playでは、2026年8月31日以降、新しいアプリとアプリの更新は、多くの場合Android 16（APIレベル36）以上を対象にする必要があるとされています（2026年10月時点のAndroid Developersの案内）。

両方のストアで審査の指摘に対応した経験や、証明書や署名の設定でつまずいて解決した経験は、面談で話題にしやすい実績です。

### ネイティブ側の設定と連携

Flutterのアプリでも、プッシュ通知、決済、カメラ、位置情報などでは、iOSとAndroidそれぞれの設定や権限の扱いが関わります。Flutterのパッケージでまかなえない機能は、Platform Channelなどを使ってSwiftやKotlinのコードとつなぎます。ネイティブのコードを読んで直せると、詰まったときに頼られる人になります。ネイティブ側の準備は[iOSエンジニアがフリーランスになるには](/media/ios-how-to/)と[Androidエンジニアがフリーランスになるには](/media/android-how-to/)も参考になります。

### 状態管理と設計の判断

Flutterでは、Riverpod・Provider・Blocなど、状態管理の方法が複数あります。名前を挙げるより、「なぜその方法を選んだか」「画面が増えたときに何に困ったか」を説明できることが大切です。パッケージの更新で動かなくなったときの対応や、使っていたパッケージの開発が止まったときの判断も、運用の経験として伝えられます。

### テストと配布の自動化

ウィジェットのテストや結合テストを書いた経験、両方のOS向けのビルドと配布を自動化した経験は、少人数のチームで特に評価されます。手作業のリリースは、担当者が抜けると止まりやすいためです。

:::view
Flutterの案件をご紹介していると、面談で評価されやすいのは、画面を作った経験に加えて「Flutterの外側で起きた問題」をどう解決したかを話せる方です。ストアの審査、証明書や署名の設定、ネイティブの権限まわりなど、自分で調べて直した経験を具体的に説明できると、少人数のチームでも任せやすい人として見てもらえます。面談の前に、担当した画面と、公開までに関わった範囲を整理しておくことをおすすめします。
:::

## Flutterから始めた人とネイティブから来た人の違い

Flutterエンジニアの経歴は、Flutterから開発を始めた方と、SwiftやKotlinのネイティブ開発から移った方に分かれます。

| 出身 | 強みになりやすい経験 | 独立前に補っておきたいこと |
|---|---|---|
| Flutterから始めた | Dartでの画面開発、状態管理、両OSへの同時対応 | ネイティブのコードを読む力、OSごとの設定や権限 |
| ネイティブから移った | OSの仕組み、ストア対応、ネイティブ連携 | Flutterらしい設計、状態管理の使い分け |
| Webのフロントエンドから移った | 画面の組み立て、APIとの連携 | モバイル特有の制約（通信の切れ方、端末の違い） |

どの出身でも、足りない部分を一つ選んで実務で補っておくと、面談で説明しやすくなります。

## 独立までの進め方

### 1. アプリごとに経験を書き出す

関わったアプリごとに、期間、チームの人数、担当した機能、状態管理の方法、ネイティブ連携の有無、どちらのストアに何回公開したかを書き出します。書き方は[Flutterのスキルシートの記事](/media/flutter-skillsheet/)と[スキルシートの基本](/media/skillsheet-basics/)をご覧ください。

### 2. 開発環境を用意する

iOS向けのビルドにはMacが必要になるため、貸与がない案件では自分で用意することになります。検証用の端末も、両方のOSで揃えておくと確認が早くなります。参画先によっては私物の機器を使えないこともあるため、貸与か持ち込みかは面談で確かめましょう。

### 3. 希望する条件を決める

稼働日数、リモートか出社か、報酬の下限を決めておきます。リモートの傾向は[Flutterのリモート案件の記事](/media/flutter-remote/)、報酬の決まり方は[Flutterの報酬の記事](/media/flutter-rate/)、求められるスキルは[Flutterの案件で求められるスキルの記事](/media/flutter-skills/)にまとめています。

### 4. 案件を探して面談を受ける

フリーランスエージェント（案件紹介サービス）、知人の紹介、発注元との直接契約などの方法があります。使い方は[フリーランスエージェントの使い方](/media/agent-how-to-use/)で解説しています。

## 面談で聞かれやすいこと

1. **アプリの規模と構成**：画面の数、状態管理の方法、ディレクトリの分け方
2. **ネイティブ連携**：Flutterだけで足りなかった機能と、その対応
3. **ストア対応**：両方のストアで受けた指摘と直し方
4. **性能**：動きが重い画面をどう調べ、どう直したか
5. **チームでの進め方**：デザイナーやサーバー側との仕様のすり合わせ

:::caution
立ち上げの案件では、「アプリを公開するまで」を一式で請け負う形になっていることがあります。ストアの審査で何度も指摘を受けた場合や、OSの更新への対応をどこまで含むかで、負担が大きく変わります。契約の形と範囲は参画前に確かめましょう。違いは[準委任契約と請負契約の違い](/media/junin-vs-ukeoi/)で解説しています。
:::

## 独立前後の手続きと契約

退職して独立する場合は、健康保険と年金の切り替えに加え、開業届を出します。開業届の提出期限は、国税庁の案内では事業を始めた年分の確定申告期限までです。青色申告をする場合は、1月16日以後に開業したなら開業日から2か月以内に承認申請書を出します（2026年10月時点）。手順の全体は[会社員からフリーランスになる手順](/media/quit-company-steps/)、開業届は[開業届の出し方](/media/kaigyo-todoke/)で解説しています。税金の判断に迷う場合は、税理士にご相談ください。

2024年11月に施行されたフリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容・報酬の額・支払期日などを書面やメールなどで明示することとされています。両方のストアへの申請を含むか、公開後の保守をどうするかを確かめておきましょう。

:::view
当社では、案件をご案内する前に、稼働日数・リモートの希望・希望金額を伺い、合う案件だけをお出ししています。経歴は、ご了承いただいた案件にだけ、氏名・連絡先を伏せて提案し、業務の範囲・報酬・支払期日・契約期間は個別契約に書いてお渡ししています。開発機の貸与やストア申請の範囲など、Flutterの案件で差が出やすい点は、面談の前に整理しておくことをおすすめします。
:::

:::point
- Flutterで独立するには、Dartでの開発に加え、両方のストアへの公開とネイティブ側の対応の経験が大切
- 状態管理は名前より、選んだ理由と困った点を説明できるようにする
- iOS向けのビルドにはMacが要るため、開発環境の貸与の有無を確かめる
- 公開まで一式で請け負う案件は、審査やOS更新への対応の範囲を参画前に確認する
:::

## よくある質問

### Flutterの経験だけで独立できますか？

Flutterだけの経験で参画している方もいます。ただ、ネイティブ側の設定や連携で詰まったときに自分で解決できるかを聞かれることが多いため、SwiftやKotlinのコードを読める程度の理解はつけておくと安心です。

### Flutterの案件はネイティブより少ないですか？

案件の数は時期や地域によって変わり、一概には言えません。Flutterの案件は新規の立ち上げや少人数のチームが多い傾向があり、ネイティブの案件とは求められる役割が違います。両方に応募できるよう、ネイティブの経験も整理しておくと選択肢が広がります。

### 最初の案件は新規開発と運用中のアプリのどちらがよいですか？

新規開発は任される範囲が広く、判断を一人で求められる場面が多くなります。運用中のアプリは、既存の設計に沿って進められるため、独立して最初の案件として入りやすい傾向があります。選び方は[最初の案件の記事](/media/first-project/)も参考にしてください。
