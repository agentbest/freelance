Javaエンジニアのフリーランス案件では、**Spring Bootを使った開発を土台に、データベースとSQL、テストの自動化、バッチ処理、性能の調査、バージョン移行の経験**が見られます。言語の知識そのものより、業務システムやWebサービスを動かし続けるための周辺の技術をどこまで扱えるかで、参画できる案件の幅が変わります。

この記事では、Javaの案件で問われやすい技術を分野ごとに整理し、2026年10月時点のJavaとSpringの前提、経験の示し方を解説します。担当工程の整理や独立の手順は[Javaエンジニアがフリーランスになるには](/media/java-how-to/)で扱っています。

## 2026年10月時点のJavaとSpringの前提

案件の要件を読むときは、Javaとフレームワークの世代を押さえておく必要があります。

OpenJDKのプロジェクトページでは、JDK 21（2023年9月19日に一般提供）とJDK 25（2025年9月16日に一般提供）は、多くのベンダーから長期サポート（LTS）版として提供されるとされています。JDK 21では、軽量なスレッドである仮想スレッド（JEP 444）や、switchでのパターンマッチング（JEP 441）などが正式な機能になりました。

Spring Bootの公式ドキュメント（2026年10月時点で安定版とされる4.1系）では、動かすにはJava 17以上が必要とされています。新しい案件ではJava 17以降が前提になりやすく、古い環境の案件では、Java 8や11からの移行が仕事の中心になることがあります。

また、Java EEの流れをくむ仕様は、現在はJakarta EEとして提供されています。公式サイトでは、Jakarta EE 9は、新しい名前空間への移行を試すための基盤と位置づけられており、古いアプリケーションを新しい環境に移すときは、パッケージ名の変更に伴う修正が発生します。

| 技術 | 案件で見られやすい点 |
|---|---|
| Javaのバージョン | 17・21・25のどれで開発したか。8や11からの移行の経験 |
| Spring Boot | 2系から3系以降への移行、設定の考え方、自動設定の理解 |
| Jakarta EE / Java EE | アプリケーションサーバー上の開発、名前空間の移行 |
| ビルド | MavenかGradleか、依存関係の管理、複数モジュールの構成 |

## Spring Bootで見られる深さ

Javaの案件の多くは、Spring Bootでの開発経験を求めます。面談で差がつくのは、画面やAPIを作ったことがあるかより、次のような点を説明できるかです。

- **DI（依存性の注入）とBeanの扱い**：クラスの責任の分け方、テストしやすい作りにするための工夫
- **トランザクションの範囲**：どこからどこまでを一つの処理として扱うか。例外が起きたときにどこまで戻るか
- **設定と環境の切り替え**：開発・検証・本番で設定をどう分け、秘密の情報をどう扱ったか
- **Spring Securityでの認証と認可**：ログインの方式、権限による画面やAPIの制御
- **非同期・並列の処理**：重い処理を分ける方法と、その際のスレッドの扱い

特にトランザクションの範囲は、業務システムでは不具合に直結しやすい論点です。「なぜそこで区切ったか」を業務の言葉で説明できると、設計に関われる人として伝わります。

## データベースとSQLの力

Javaの業務システムでは、データベースとのやり取りが処理の中心になることが多く、SQLの力が評価を左右します。

| 分野 | 見られやすい経験 |
|---|---|
| SQLの記述 | 結合や集計を含むSQLを自分で書き、結果の正しさを確かめられるか |
| 実行計画 | 遅いSQLの実行計画を読み、インデックスの追加や書き換えで改善した経験 |
| データアクセスの方式 | JPA（Hibernate）、MyBatis、JDBCの使い分けと、それぞれの注意点 |
| 排他の制御 | 同時に更新されるデータの扱い。楽観ロック・悲観ロックの選び方 |
| データベースの種類 | Oracle、PostgreSQL、MySQLなど。方言の違いを踏まえた書き方 |

JPAを使う案件では、意図しない大量のSQLが発行される問題（いわゆるN+1）に気づいて直した経験など、ORMの便利さの裏側を理解しているかが問われることがあります。

:::view
Javaの案件紹介の現場では、面談で「遅かった処理を、どう調べて、どう直したか」と問われる場面をよく見ます。評価されやすいのは、ログや実行計画、プロファイラの結果から原因を絞り、SQLの書き換えやキャッシュの導入など、選んだ対策の理由まで話せる方です。機能を作った経験だけを並べるより、問題を解いた経験を一つ深く話せるほうが、任せられる範囲が伝わりやすくなります。
:::

## テストの自動化と品質

フリーランスの案件では、自分が書いたコードの品質を自分で示すことが求められます。

- **単体テスト**：JUnitでのテストの書き方、Mockitoなどでの依存の差し替え、テストしやすい設計
- **結合テスト**：Spring Bootのテストの仕組みを使い、データベースや外部APIとつないだ確認。コンテナでテスト用のデータベースを立てる方法
- **静的解析とレビュー**：コードの規約のチェック、プルリクエストでのレビューの受け方と出し方
- **CI**：テストを自動で回し、壊れたら気づける仕組み

業務システムの案件では、テスト仕様書を作り、結果を記録する進め方も多く残っています。自動テストの経験と、ドキュメントでテストを管理する経験の両方があると、どちらの文化の現場にも入りやすくなります。

## バッチ処理と夜間の運用

金融・公共・流通などの業務システムでは、夜間に大量のデータを処理するバッチが重要な役割を持ちます。Spring Batchなどでのバッチの開発経験に加えて、次のような点が見られます。

1. **処理件数と時間の見積もり**：決められた時間の中で終わるかを、データ量から見積もる
2. **途中で失敗したときの再実行**：どこから再開できるか、二重に処理されないか
3. **ジョブの順番と依存関係**：前のジョブが終わらないと始められない処理の組み立て
4. **運用の担当者への引き継ぎ**：異常時の連絡の流れと、確認の手順

Web系の開発から業務システムの案件に移る場合、このバッチと夜間の運用の考え方が、最初につまずきやすい部分です。

## 性能とJVMの理解

性能の問題を調べられる人は、どの案件でも頼りにされます。Javaでは、アプリケーションのコードだけでなく、JVMの動きの理解が求められます。

- **メモリとGC**：ヒープの大きさの設定、GCのログの読み方、メモリ不足の原因の調べ方
- **スレッド**：スレッドダンプを取り、処理が止まっている箇所を見つける
- **プロファイリング**：どのメソッドに時間がかかっているかを測る
- **仮想スレッドの使いどころ**：待ち時間の多い処理での効果と、従来のスレッドとの違い

本番環境で起きた性能の障害を調べ、原因と対策をまとめた経験は、面談で具体的に話す価値があります。

:::caution
新しいバージョンの機能を使った経験は評価されやすい一方で、案件によっては、古いバージョンや独自のフレームワークで動いているシステムの保守が中心のこともあります。新しい技術だけを強みとして伝えると、合わない案件を紹介されることがあります。保守してきた環境の世代も、経験として正直に書いておきましょう。
:::

## APIとクラウドの経験

Webサービスや、システム間の連携が多い案件では、REST APIの設計と、クラウドの上での開発・運用の経験が求められます。

API設計では、リソースの切り方、エラーの返し方、バージョンの管理、ドキュメントの整備（OpenAPIなど）を説明できると評価されます。クラウドでは、コンテナでのデプロイ、マネージドのデータベース、ログと監視の仕組みに触れた経験があると、参画できる案件が広がります。クラウドの側のスキルは[AWSエンジニアのスキル](/media/aws-skills/)もあわせてご覧ください。

## バージョン移行の経験を整理する

古いJavaやSpringからの移行は、案件として一定の需要があります。移行の経験は、次の観点で整理しておくと、深さが伝わります。

1. 移行前と移行後のバージョン（Java、Spring、アプリケーションサーバー）
2. 影響の調査の方法（依存ライブラリの洗い出し、非推奨のAPIの確認）
3. 名前空間の変更や、廃止された機能への対応
4. テストでどう確かめたか、移行後に起きた問題とその対処

## よくある質問

### Java 8の経験しかないと案件に参画できませんか？

参画できる案件はあります。古いバージョンで動くシステムの保守や、移行の案件では、旧環境の知識が求められます。一方で、新しい案件ではJava 17以降が前提になりやすいため、新しいバージョンの主な変更点を学び、検証の環境で動かしておくと、選べる案件が広がります。

### Kotlinの経験はJavaの案件で評価されますか？

評価されることがあります。KotlinはJavaと同じJVMの上で動き、Springでも使えるため、Javaの案件と重なる部分があります。ただし、案件の多くはJavaで書くことを前提にしているため、Javaでの開発経験もあわせて伝えることが大切です。

### 資格はどのくらい重視されますか？

資格を条件にしている案件は多くありません。Javaの資格は、言語の知識を体系的に持っていることの裏付けになりますが、案件では実際のシステムでの開発経験のほうが重視されます。資格で学んだ内容を、どの案件で生かしたかまで話せると伝わりやすくなります。
