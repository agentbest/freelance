TypeScriptエンジニアがフリーランスで働くのに、**資格は必須ではありません**。TypeScriptの案件は、どの層（画面・サーバー・両方）で使い、型によって何を防いできたかで参画が決まります。そもそもTypeScriptそのものを対象にした、広く使われている公式の認定資格はありません。

一方で、資格が効く場面はあります。実務の年数が短いとき、公共系や大手企業の案件で体制を説明するとき、クラウドやセキュリティまで任される案件に広げたいときです。この記事では、TypeScriptエンジニアにとって評価されやすい資格と効きにくい資格を分け、実務とどう組み合わせると効くかを整理します。資格全般の考え方は[資格はフリーランスの案件獲得に役立つ？](/media/shikaku/)で解説しています。

## 資格がなくてもTypeScript案件に入れる理由

TypeScriptの力量は、コードを見れば確かめられます。面談に出てくるテックリードは、型の付け方やanyの扱い、既存のコードを改善した経験を聞けば、チームに合うかを判断できると考えています。技術課題や公開リポジトリで、実際のコードを見られることもあります。

そのため、案件票の必須条件に資格の名前が入ることはほとんどありません。並ぶのは「TypeScriptでの開発経験」「Reactでの開発経験」「Node.jsでのAPI開発経験」のような実務の条件です。資格がないことを理由に応募をあきらめる必要はなく、まずは[TypeScriptのスキルシート](/media/typescript-skillsheet/)で型の取り組みを伝わる形にすることが先です。

### Node.jsの認定試験は終了している

JavaScriptの実行環境であるNode.jsには、OpenJS財団とThe Linux Foundationによる認定試験がありました。ただし、The Linux Foundationの案内によると、OpenJS Node.js Application Developer（JSNAD）の試験は2025年9月30日で終了しています（2026年10月時点）。過去に取得した人はスキルシートに書いて構いませんが、これから取る資格の候補にはなりません。

## 資格が効く4つの場面

| 場面 | 資格が効く理由 |
|---|---|
| 実務の年数が短いとき | 基礎の知識を体系的に学んでいることの裏付けになる |
| 公共系・大手企業の案件 | 体制表や提案書に要員の資格を書く慣習があり、発注元が説明に使いやすい |
| クラウドまで任される案件 | サーバーやデプロイの話についていけることの裏付けになる |
| 書類で比べられる段階 | 候補者が並んだとき、経験の幅を短く伝える材料になる |

どの場面でも、資格は判断の後押しにはなりますが、それだけで決まることはありません。TypeScriptの案件では、**資格は実務の説明を補強する材料**と考えるのが現実的です。

:::view
TypeScriptの案件をご紹介していると、面談で評価が分かれるのは資格の有無より、型を使って何を防いだかを具体的に話せるかどうかです。一方で、Node.jsでサーバー側の案件に広げたい方が、クラウドの認定資格を持っていると、書類の段階で「インフラの話も通じそうだ」と受け止められやすい傾向があります。資格は、広げたい方向を示す材料として選ぶことをおすすめします。
:::

## TypeScriptエンジニアにとって評価されやすい資格

### 基本情報技術者試験・応用情報技術者試験（IPA）

国内でITの基礎知識を示す国家試験です。IPAは、基本情報技術者試験の対象者を、ITを活用したサービスや製品、システム、ソフトウェアを作る人材に必要な基本的知識・技能をもち、実践的な活用能力を身に付けた者としています。実務の年数が短い時期に、アルゴリズムやデータベース、ネットワーク、セキュリティを一通り学んだことの裏付けになります。

IPAの案内では、現行の試験制度は2026年度の試験の実施をもって終わり、2027年度から新しい制度に移る予定です（2026年10月時点）。基本情報技術者試験は新制度でも続く予定とされていますが、詳細は変わる可能性があります。効く場面や準備は[基本情報技術者試験の記事](/media/cert-ipa-fe/)と[応用情報技術者試験の記事](/media/cert-ipa-ap/)で解説しています。

### クラウドの認定資格

Node.jsでAPIやサーバーレスの処理を書く案件では、クラウドの知識が問われることがあります。Amazon Web Servicesの案内によると、AWS Certified Developer - Associateは、ITやクラウドの開発者の職務にある人を対象とし、1年以上の実務経験が推奨され、認定の有効期間は3年です（2026年10月時点）。アプリケーションの開発とデプロイに近い内容のため、TypeScriptでサーバー側を書く人と相性のよい資格です。設計まで広げたい場合は[AWS認定ソリューションアーキテクトの記事](/media/cert-aws-saa/)も参考になります。

### 情報処理安全確保支援士（IPA）

認証やセッション、外部からの入力を扱う画面やAPIでは、セキュリティの知識が評価されます。決済や個人情報を扱うサービスの案件で、入力の検証やエラーの扱いを任されるときに、知識の裏付けになります。詳しくは[情報処理安全確保支援士の記事](/media/cert-ipa-sc/)をご覧ください。

### テストの資格

テストの設計や品質の仕組みづくりまで任される案件では、テストの用語や考え方を共通の言葉で話せることが役立ちます。型チェックとテストで品質を支える役割に広げたいときに検討する価値があります。詳しくは[JSTQB認定テスト技術者の記事](/media/cert-jstqb/)をご覧ください。

## TypeScript案件では効きにくい資格

次のような資格は、持っていて損はないものの、TypeScript案件の評価にはつながりにくい傾向があります。

- **TypeScriptやJavaScriptの民間の検定**：知名度が限られ、面談官が内容を知らないことが多い。コードを見せるほうが早いと考えられやすい
- **案件と関わりの薄い製品の資格**：特定の業務パッケージの資格は、TypeScriptの開発の力を示す材料にはなりにくい
- **有効期限の切れた資格**：更新が必要な資格は、期限が切れていると、かえって確認の手間を増やす

民間の検定を学ぶこと自体は、基礎を固める助けになります。評価の材料としては、検定の名前より、学んだことを使って書いたコードを示すほうが伝わります。

:::caution
資格の学習で覚えた書き方や設定を、そのまま現場に持ち込むと、既存のコードの決まりとぶつかることがあります。型の厳しさや書き方は、現場ごとに決まりがあります。まずは現場の決まりに合わせ、改善したい点はレビューや提案の場で根拠を示して話しましょう。
:::

## 実務経験との組み合わせ方

資格は、実務のどこを補うかを決めてから選ぶと効果が出ます。

| 今の経験 | 広げたい方向 | 組み合わせやすい資格 |
|---|---|---|
| 画面の実装が中心で、実務の年数が短い | 設計やサーバーにも関わる案件 | 基本情報技術者試験、応用情報技術者試験 |
| 画面の実装が中心 | Node.jsのサーバー・フルスタック | クラウドの開発者向けの認定 |
| Node.jsのAPIの実装 | 認証や決済を扱う案件 | 情報処理安全確保支援士 |
| 機能の開発が中心 | テストや品質の仕組みづくり | テストの資格 |

組み合わせのポイントは、資格と**同じ方向の実務の場面**を1つでも持っておくことです。クラウドの資格を取ったなら、小さくてもTypeScriptで書いた処理を自分でデプロイし、ログを見た経験を話せるようにします。セキュリティの資格を取ったなら、入力の検証やエラーの扱いを見直した場面をつくっておきます。

TypeScriptそのものの力は、資格の代わりに公開リポジトリや技術記事で示すこともできます。前の案件のコードを使わず、自分で作ったものに限って公開しましょう。書き方は[GitHubとポートフォリオの記事](/media/portfolio-github/)で解説しています。

## スキルシートと面談での伝え方

資格は、資格欄に名前と取得年月を書くだけでなく、経歴欄の取り組みと結びつけると効きます。

1. **資格欄**：正式な名称と取得年月。更新が必要な資格は有効期限も書く
2. **経歴欄**：資格で学んだことを使った場面があれば、何を防いだかとして書く
3. **面談**：資格について聞かれたら、取った理由と、実務で生かした場面を1つ話す

学習中の資格は、受験予定の時期とあわせて書いておくと、広げたい方向が伝わります。ただし、取得していない資格を取得済みのように読める書き方は避けてください。

:::view
当社では、案件をご案内する前に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをお出ししています。TypeScriptの案件で資格を条件に挙げているものは多くなく、実務の経験が中心に見られます。お持ちの資格が案件の条件にどう関わるか気になる場合は、ご質問いただければ確認します。経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。
:::

:::point
- TypeScriptの案件は資格がなくても参画できるものがほとんどで、TypeScriptそのものの公式の認定資格はない
- Node.jsの認定試験JSNADは2025年9月30日で終了している
- 評価されやすいのは、基本情報・応用情報、クラウドの開発者向けの認定、情報処理安全確保支援士、テストの資格
- 資格は、広げたい方向の実務の場面と組み合わせて伝えると効く
:::

## よくある質問

### 未経験からTypeScriptの案件を目指すなら、まず資格を取るべきですか？

フリーランスの案件は即戦力を求めるものが多く、資格だけで参画できることはほとんどありません。資格の学習で基礎を固めつつ、会社員として実務の経験を積むか、自分でTypeScriptのアプリを作って公開するほうが近道です。

### 基本情報技術者試験は、2027年度以降に取っても意味がありますか？

IPAの案内では、基本情報技術者試験は新しい制度でも続く予定です（2026年10月時点）。基礎の知識を示す材料としての役割は変わらないと考えられますが、試験の内容や形式はIPAの最新の案内で確かめてください。

### クラウドの資格は、画面だけの案件でも評価されますか？

画面だけの案件では、評価の中心にはなりにくいのが実情です。ただ、画面のデプロイの仕組みや、サーバー側との連携の話が通じることは伝わります。フルスタックやサーバー側に広げたいときに、より効きやすい資格です。
