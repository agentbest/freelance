DXコンサルタントの案件は、**「DX」という名前ではなく、何をもって成功とするか、検証の後に何が予定されているか、誰が決めて誰が社内で続けるか**で選びます。DXの案件は依頼の時点で中身が固まっていないことが多く、契約の前にここを確かめておくかどうかで、参画後の働きやすさが大きく変わります。

この記事では、DXの案件ならではの確かめどころを、契約の前に聞く順に整理します。業務委託契約の一般的な読み方は[業務委託契約書のチェックポイント](/media/contract-checkpoints/)にまとめているため、ここではDX特有の論点に絞ります。

## 1. 成功の定義と成果物

最初に確かめたいのは、**契約期間の終わりに何ができていれば成功なのか**です。DXの案件では、「DX推進の支援」「デジタル化の推進」のような言葉だけで募集が出ることがあり、そのまま参画すると、何を目指して動けばよいかが途中で揺れます。

面談や事前の確認で、次の点を聞いておきます。

- 期間の終わりに、どんな状態になっていれば成功か（計画が承認される、検証の結果が出る、利用が一定の部署に広がる、など）
- 成果物は何か（報告書、計画書、手順書、それとも助言だけか）
- 成功かどうかを誰が判断するか

成功の定義があいまいな案件は、参画してから範囲が広がりやすく、評価も担当者の印象に左右されやすくなります。定義が決まっていない場合は、最初の数週間で定義を一緒に決めることを業務に含めてもらう、という選び方もあります。

## 2. 今の局面と、その後の予定

DXの取り組みには、構想、検証、本番化、定着といった局面があります。案件が今どの局面にあり、**その後にどの局面が予定されているか**を確かめます。

| 今の局面 | 確かめたいこと |
|---|---|
| 構想 | 計画が承認された後、実行の局面にも関わる見込みがあるか |
| 検証 | 本番に進む条件と、進まない場合の契約の扱い |
| 本番化 | 社内やベンダーとの役割の分け方、稼働の山の時期 |
| 定着 | 社内に引き継ぐ時期と、引き継ぎ先の担当者 |

特に検証の案件は、結果が出た時点で契約も終わることがあります。契約期間の区切りと更新の判断の時期を確かめておくと、次の案件を探し始める時期の見通しが立ちます。契約期間の考え方は[業務委託の契約期間の決め方](/media/keiyaku-period/)で解説しています。

## 3. 決める人と、社内の推進役

DXの取り組みは、決める権限を持つ人に材料が届かないと進みません。次の2人がいるかを確かめます。

- **決める人**：投資や方針を決める役員や部門長に、報告の場で会えるか
- **社内の推進役**：自分が不在の日や、契約が終わった後に取り組みを続ける社内の担当者がいるか

決める人に会えず、資料を作って担当者に渡すところまでで仕事が終わる案件は、取り組みが進んでいるのかが見えにくくなります。社内の推進役がいない案件は、外部の人が抜けたときに止まりやすく、結果として「成果が出なかった」と受け止められるおそれがあります。

:::view
DXの案件をご紹介していると、参画後に「思っていた仕事と違った」となりやすいのは、成功の定義と報告先が決まらないまま始まった案件です。面談では、報告先と、期間の終わりに何ができていればよいかを、遠慮せずに聞いておくことをおすすめします。当社では、先に稼働日数・リモートの可否・ご希望の金額を伺い、合う案件だけをご案内しています。
:::

## 4. ベンダーや製品との関係

DXコンサルは、ツールやサービスの比較、ベンダーの選定に関わることがあります。このとき、次の点を確かめておきます。

- **発注元と特定のベンダーとの関係**：選ぶ製品がすでに決まっているのか、比較から関わるのか
- **自分の立ち位置**：発注側の立場で選定を支援するのか、ベンダー側の体制の一員として入るのか
- **自分と製品の関係**：自分が特定の製品の販売や導入で収入を得ている場合、それが選定の仕事とぶつからないか

製品がすでに決まっているのに「比較から」と説明されている、あるいはその逆、というずれは、参画後の動き方を大きく変えます。また、ご自身が特定の製品と関係を持っている場合は、選定に関わる前に発注側に伝えておくほうが、後から信頼を損なうおそれを避けられます。

## 5. データと生成AIの扱い

DXの仕事では、発注側の業務データや顧客のデータを見たり、生成AIを使って資料や分析を進めたりする場面があります。契約の前に、次の扱いを確かめます。

- 分析のために見てよいデータの範囲と、作業してよい場所（発注側の環境だけか、自分の端末でもよいか）
- 個人情報を含むデータを扱うかどうか
- 生成AIを自分の作業に使ってよいか、使ってよい道具と入力してよい情報の範囲
- 契約が終わったときのデータの返却と削除の方法

個人情報を扱うときの契約上の注意は[業務で個人情報を扱うときの契約と注意点](/media/kojin-joho-itaku/)、生成AIの利用の条項は[業務での生成AIの利用に関する契約条項](/media/ai-riyou-keiyaku/)で解説しています。

:::caution
生成AIの活用を支援する案件でも、自分の作業に生成AIを使ってよいとは限りません。発注側の利用ルールが整う前に参画する場合は特に、使ってよい道具と入力してよい情報を、作業を始める前に書面やメールで確かめておきましょう。
:::

## 6. 契約の形と、自分が作るものの扱い

### 準委任か請負か

DXコンサルの案件は、多くの場合、業務の遂行に対して報酬が支払われる準委任契約です。ただ、「構想の報告書の納品」のように成果物の完成が求められる書き方になっている場合は、請負に近い責任を負うことがあります。どちらの形かで、報酬が確定する時期や負う責任が変わるため、契約書の書き方を確かめます。違いは[準委任契約と請負契約の違い](/media/junin-vs-ukeoi/)をご覧ください。

推進部門に入り込んで働く案件では、発注側の社員と同じように細かい指示を受ける働き方になっていないかも確かめどころです。考え方は[偽装請負とは](/media/gisou-ukeoi/)で整理しています。

### 自分の型や資料の扱い

DXコンサルは、現状の整理の型、ヒアリングの項目、テーマの評価の観点など、自分で作ってきた道具を案件に持ち込むことがあります。案件の中で作った資料の権利がどちらに帰属するか、自分が以前から持っている型を他の案件でも使い続けられるかを、契約の前に確かめておくと安心です。成果物の権利の考え方は[成果物の著作権は誰のもの？](/media/copyright/)で解説しています。

## 複数の案件を比べるときの並べ方

候補の案件が複数あるときは、報酬と稼働日数だけで比べず、ここまでの確かめどころを同じ表に並べると違いが見えます。

| 比べる観点 | 案件A | 案件B |
|---|---|---|
| 成功の定義と成果物 | 決まっている／未定 | |
| 今の局面とその後の予定 | | |
| 決める人に会えるか | | |
| 社内の推進役の有無 | | |
| ベンダーとの関係 | | |
| データと生成AIの扱い | | |
| 契約の形 | 準委任／請負 | |

空欄が多く残る案件は、参画後に確かめることが多い案件です。空欄そのものが悪いわけではありませんが、空欄の数と、それを埋めるのにかかりそうな手間を見込んで選ぶと、参画後の負担を想像しやすくなります。

## 契約条件の明示を受け取って照らし合わせる

フリーランス法では、発注側がフリーランスに業務を委託したときに、給付の内容、報酬の額、支払期日、役務の提供を受ける日や場所などを、書面やメールなどで明示することが求められています。報酬の支払期日は、給付を受け取った日から60日以内のできるだけ短い期間で定めることとされています（2026年10月時点、公正取引委員会の案内による）。

DXの案件では、面談で聞いた成功の定義や担う範囲が、明示された「給付の内容」に反映されているかを照らし合わせます。ずれがあれば、署名の前に確かめましょう。エージェントを通す場合の契約の相手は[エージェント経由の契約の相手は誰？](/media/sansha-kankei/)が参考になります。個別の契約の判断に迷う場合は、専門家にご相談ください。

:::view
当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。DXの案件は担う範囲があいまいになりやすいため、面談で聞いた内容と個別契約の書き方に違いがないかを、署名の前にご覧ください。気になる点は、ご質問いただければ確認します。
:::

:::point
- DXの案件は名前ではなく、成功の定義、成果物、今の局面とその後の予定で選ぶ
- 決める人に会えるか、社内に推進役がいるかで、取り組みが続くかが変わる
- ベンダーとの関係、データと生成AIの扱い、自分の型や資料の権利は、契約の前に確かめる
- 面談で聞いた内容が、明示された給付の内容に反映されているかを照らし合わせる
:::

## よくある質問

### 成功の定義が決まっていない案件は、避けたほうがよいですか？

一概には言えません。DXの初期の段階では、何を目指すかを決めること自体が仕事になることもあります。その場合は、定義を決めることを業務の範囲に入れてもらい、決まった時点で範囲と条件を見直すと決めておけば、参画後のずれを抑えられます。

### 面談でこれだけのことを聞くと、失礼になりませんか？

DXの案件では、成功の定義や報告先を聞くことは、仕事の進め方を真剣に考えている表れとして受け止められることが多くあります。質問の数が多い場合は、事前に確かめられることをエージェントに聞いておき、面談では業務の中身に絞ると時間を有効に使えます。逆質問の選び方は[業務委託の面談で聞いておくべき逆質問](/media/reverse-questions/)をご覧ください。

### 参画した後で、案件の中身が聞いていた話と違うと分かったらどうすればよいですか？

まず、明示された業務の内容と、実際に求められている仕事を書き出して比べます。範囲を超える仕事が続いている場合は、早めに発注側やエージェントに伝え、範囲と条件の見直しを話し合いましょう。考え方は[作業範囲が広がったときの契約の扱い](/media/scope-change/)で解説しています。
