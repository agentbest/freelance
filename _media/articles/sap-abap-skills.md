SAP ABAPエンジニアのフリーランス案件では、**言語の基本を前提に、HANAを生かしたデータの取り方、標準の処理を壊さない拡張の作り方、S/4HANA移行でのカスタムコード対応、CDS・RAP・ABAP Cloudといった新しい開発の形、そして担当領域の業務の理解**が見られます。「ABAPが書ける」ことより、どの分野をどの深さで担えるかが問われます。

この記事では、案件で問われるスキルを分野ごとに整理し、経験の段階ごとに何が求められるかをまとめます。

## 分野ごとに見られるスキル

| 分野 | 主な内容 | 案件で見られる点 |
|---|---|---|
| 言語の基本 | 内部テーブル、データの読み書き、モジュール化、オブジェクト指向 | 他人が読める書き方、開発の決まりに合わせられるか |
| データの取り方と性能 | 大量データの読み方、データベース側での処理 | 遅い処理の原因を見つけて直した経験 |
| 拡張 | 標準の処理に独自の処理を足す仕組み | 標準を書き換えずに要件を満たせるか |
| 連携と帳票 | 他システムとのやり取り、帳票の出力 | エラー時の扱い、出力条件の作り |
| 移行のカスタムコード対応 | 既存のアドオンの調査、指摘への対応 | 対象の絞り込みと工数の見積もり |
| 新しい開発の形 | CDS、RAP、ABAP Cloud | 実務で作った経験があるか |
| 業務の理解 | 会計、販売、購買、生産などの流れ | 仕様の行間を読んで質問を返せるか |
| テストと品質 | 単体テストの自動化、コードのチェック | 品質を数字や仕組みで示せるか |

### データの取り方と性能

S/4HANAはSAP HANAの上で動きます。旧来は、データを少しずつ読み出してプログラムの中で集計する書き方が多く見られました。HANAを前提にした開発では、集計や結合をできるだけデータベースの側で行い、プログラムに渡すデータを減らす考え方が求められます。遅いバッチの原因を調べ、読み方を変えて処理時間を短くした経験は、どの案件でも話しやすい材料です。

### 拡張の作り方

標準のプログラムを直接書き換えると、SAPの更新のたびに手直しが必要になります。案件では、SAPが用意した拡張の仕組みを使い、標準を書き換えずに要件を満たせるかが見られます。

SAPは2025年8月の記事で、S/4HANA Cloudの拡張を「クリーンコア」の観点からA〜Dの4段階に分ける考え方を示しました。公開された安定したインターフェースだけを使うものが最も望ましく、標準の書き換えやSAPのテーブルへの直接の書き込みなどは推奨されない、と整理されています。この考え方を知っておくと、設計の段階で「どの作り方を選ぶか」を説明しやすくなります。

### 連携と帳票

他のシステムとのデータのやり取りは、多くの案件で開発の中心になります。見られるのは、連携の方式を知っていることより、相手のシステムが止まったときやデータに誤りがあったときに、どう再処理し、どう知らせる作りにしたかです。帳票では、出力の条件や様式の違いを、業務の担当者と詰めた経験が評価されます。

## S/4HANA移行のカスタムコード対応

移行の案件では、旧環境で作られたアドオンを、新しい環境で動くように直す仕事があります。SAP Learningの教材では、カスタムコードの分析の方法として、FioriのCustom Code MigrationアプリとADT上のABAP Test Cockpit（ATC）が紹介されています（2026年10月時点）。

同じ教材では、本番環境での利用状況を記録する仕組みでデータを集め、使われていないアドオンを見つけて、システム変換のときに削除できると説明されています。データを集める期間として、年度末の締めを含む6〜18か月が推奨されています。消したプログラムが後で必要になったときに備え、退避と復元の手順を用意し、復元したコードはATCで確かめるよう示されています。

案件で見られるのは、次のような力です。

1. **指摘を種類ごとに分ける**：自動で直せるもの、考え方を変えて直すもの、業務の確認が要るもの
2. **使われていないものを見極める**：利用状況のデータから廃止を提案し、業務部門の確認を取る
3. **工数を見積もる**：指摘の種類と本数から作業量を読む
4. **直した結果を確かめる**：業務のシナリオで動作を確認する

移行全体で求められる力は[S/4HANA移行のスキルの記事](/media/s4hana-skills/)で整理しています。ここでは、ABAPの担当として、プログラムの側から対象を減らし、量を読めるかが大切です。

:::view
ABAPの案件紹介の現場では、移行の案件の面談で「指摘が何件あり、そのうちどれだけを廃止や自動の修正で片づけたか」と問われる場面をよく見ます。評価されやすいのは、全体の件数と、種類ごとの対応の仕方を分けて話せる方です。直した本数だけを伝えるより、減らした本数と理由をあわせて伝えるほうが、移行の難しさを理解している人として伝わります。
:::

## CDS・RAP・ABAP Cloudの実務

SAPのコミュニティサイトのABAP Cloud FAQでは、ABAP Cloudは公開されたオブジェクトとAPI、拡張ポイントを使う開発の形とされています（2026年10月時点）。S/4HANAのパブリッククラウド版では必須、プライベートクラウド版とオンプレミス版では2022年の版から使え、推奨だが必須ではないと説明されています。RAPは、S/4HANAでFioriアプリやサービスを作るときの標準のプログラミングモデルとされています。

案件で見られるのは、次のような経験です。

- **CDSビュー**：データの形と関係を定義し、画面やサービスの土台にする
- **RAPの業務オブジェクト**：データの登録・更新・チェックの振る舞いを決める
- **公開されたAPIだけで作る**：使いたい標準の機能が公開されていないとき、どう代わりの手段を考えたか
- **ADTでの開発**：Eclipse上の開発環境での作業

クラシックな書き方と新しい形のどちらが求められるかは、案件の版と方針で変わります。両方を知っていて、どちらで作るかを説明できると、設計の段階で頼られやすくなります。SAP BTPの上で別に作る開発は、SAP BTPエンジニアの領域と重なるため、BTPの経験は別に整理しておくと伝わりやすくなります。

## 経験の段階ごとに求められること

| 段階 | 主な役割 | 求められること |
|---|---|---|
| 製造が中心 | 詳細設計書からの製造と単体テスト | 開発の決まりに沿った書き方、テストの記録、質問の出し方 |
| 設計を担う | 機能の仕様から詳細設計、改修の影響の調査 | 処理の作りを決める力、性能への配慮、拡張の選び方 |
| 方式とまとめ役 | 開発の決まりや共通部品づくり、レビュー、移行の対象の判断 | 作り方の方針を決め、チームにそろえさせる力 |

製造が中心の段階では、決まりに沿って速く正確に作れることが土台です。設計を担う段階では、業務コンサルとのやり取りと、作り方の選び方が問われます。方式とまとめ役の段階では、クリーンコアの考え方に沿った開発の決まりを作り、オフショアを含む開発者のレビューを担う力が見られます。

## 業務の理解とテスト

業務の知識は、設定を担うほど深くなくてかまいません。ただ、自分の担当する領域で、伝票がどう流れ、どのテーブルにどう残るかを説明できると、仕様の確認が早く進みます。

テストでは、ABAP Unitによる単体テストの自動化や、ATCでのチェックを開発の流れに組み込んだ経験が評価されることがあります。テストの記録の残し方は案件の決まりに合わせますが、品質を仕組みで守った経験は、レビューを任される段階で生きます。

:::caution
新しい開発の形は、学習の環境で触っただけの経験と、実務で作った経験とで、面談での受け止められ方が大きく変わります。経歴に書くときは、どちらの経験かを分けて書きましょう。学習中の技術を実務経験として書くと、参画後に任される内容と合わなくなるおそれがあります。
:::

## 資格の位置づけ

SAPの認定資格には、ABAP Cloudの開発者向けのものもあります。ただ、案件では実務の経験が先に見られます。認定が役立つ場面と準備の考え方は[SAP認定コンサルタントの記事](/media/cert-sap/)で解説しています。

:::view
当社では、先に稼働日数・リモートの希望・ご希望の金額を伺い、その条件に合う案件だけをご案内しています。ABAPの案件は、製造中心か、設計から任されるか、移行の調査か、新しい開発の形を使うかで、求められるスキルが大きく変わります。どの分野を中心にしたいかを先に決めておくことをおすすめします。
:::

:::point
- 分野は、言語の基本、データの取り方と性能、拡張、連携と帳票、移行のカスタムコード対応、新しい開発の形、業務の理解、テスト
- 移行では、指摘を分け、使われていないものを見極め、量を読む力が見られる
- CDS・RAP・ABAP Cloudは、学習と実務を分けて示す
:::

## よくある質問

### クラシックなABAPしか書けなくても案件はありますか？

あります。保守や移行のカスタムコード対応では、旧環境のプログラムを読み、直す力がそのまま求められます。ただ、新規の導入や作り直しの案件では、CDSやRAPの経験が見られることが増えています。経験の幅を広げる考え方は[ABAPエンジニアの将来性](/media/sap-abap-future/)で扱っています。

### 業務の知識はどのモジュールから身につけるとよいですか？

これまで担当した領域から深めるのが近道です。会計、販売、購買はアドオンの多い領域で、案件の数も多い傾向があります。担当した伝票がどのテーブルに残るかを説明できるところから始めるとよいでしょう。

### 他の言語の経験は生かせますか？

オブジェクト指向の考え方や、SQLでのデータの扱い、テストの自動化の経験は、ABAPでも生かせます。ただ、SAPの標準の仕組みや移送の流れは独特のため、他の言語の経験だけでは任される範囲が限られることがあります。
