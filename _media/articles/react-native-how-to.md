React Nativeエンジニアがフリーランスになるには、**Reactの考え方で画面と機能を作れることに加えて、iOSとAndroidの両方のストアにアプリを出し、ビルドや版上げで詰まった問題を自分で直した経験**が必要です。React Nativeの案件は少人数で両方のOSを担うことが多く、JavaScriptの外で起きる問題に一人で向き合えるかが見られます。

独立の準備は、経験の棚卸し、出身に応じた弱点の補強、開発環境とお金の準備、最初の案件選びの順に進めます。この記事では、React Nativeならではの事情に絞って説明します。

## React Nativeの案件で多い現場

React Nativeの公式サイトは、新しくアプリを作る場合はフレームワークを使うことを勧め、Expoを本番で使えるフレームワークとして紹介しています（2026年10月時点）。そのため最近立ち上がるアプリはExpoを使うものが多い一方で、数年前から運用されているアプリにはExpoを使わずに作られたものも多く残っています。

| 現場の型 | 主な仕事 | 特に見られる経験 |
|---|---|---|
| Expoでの新規立ち上げ | 少人数で設計から両ストアへの公開までを担う | 画面遷移と状態管理の方針、ビルドと配布の仕組みづくり |
| 運用中アプリの機能追加 | 公開済みのアプリに機能を足し、不具合を直す | 既存コードの読解、ライブラリの更新への対応 |
| 長く止まっていたアプリの版上げ | 古い版から段階的に上げ、動かないライブラリを置き換える | ネイティブ側の設定の読解、根気よく原因を絞る力 |
| ネイティブアプリへの部分導入 | 既存のSwift・Kotlinのアプリに一部の画面を足す | 両方の仕組みの理解、ビルドの設定 |
| 受託開発 | 発注元のアプリを仕様に沿って作る | 見積もり、納品の範囲、公開後の保守の取り決め |

どの型でも、画面を作れることは前提です。差がつくのは、公開までの流れと、壊れたときの直し方を知っているかどうかです。

## 出身によって補っておきたいこと

React Nativeエンジニアの経歴は、主に3つの入り口に分かれます。どこから来たかで、独立前に補うべき点が違います。

| 出身 | 強みになりやすい経験 | 独立前に補っておきたいこと |
|---|---|---|
| WebのReactから来た | コンポーネント設計、状態管理、TypeScript | 端末の制約（通信の切れ方、権限、バックグラウンド）、ストア審査、ネイティブの設定ファイルの読み方 |
| iOS・Androidのネイティブから来た | OSの仕組み、ストア対応、ネイティブ連携 | Reactの描画の考え方、JavaScriptの非同期処理、npmの依存関係の管理 |
| Flutterから来た | 両OSを一人で見る感覚、ストア対応 | Reactの考え方、JavaScriptのライブラリの選び方 |

Webから来た方は、Reactの知識が通じる分、モバイル特有の問題に気づきにくいことがあります。ネイティブから来た方は、npmの依存関係が深く入り組む点に戸惑いやすい傾向があります。足りない側を一つ選び、実務の中で一度でも手を動かしておくと、面談で説明しやすくなります。Webのフロントエンドとしての独立は[Reactエンジニアがフリーランスになるには](/media/react-how-to/)、ネイティブ側の準備は[iOSエンジニアがフリーランスになるには](/media/ios-how-to/)と[Androidエンジニアがフリーランスになるには](/media/android-how-to/)も参考になります。

## 独立前に積んでおきたい経験

### 両方のストアへの公開を最後までやる

React NativeでもiOSとAndroidのストアには別々に申請します。Expoの現場ではEAS Submitでストアへのアップロードを自動化できますが、Expoの公式ドキュメントにあるとおり、EAS Submitはバイナリを届けるところまでで、iOSの審査への提出はApp Store Connectで自分で行う必要があります。アップロードの先にある、メタデータの入力、審査用のアカウントの準備、指摘への返答まで経験しておくと、公開を一人で任せられる人になります。

### 開発ビルドとExpo Goの違いを体で知る

Expoの公式ドキュメントでは、ストアに出す自分のアプリを作るなら、Expo Goではなく開発ビルドを使うことを勧めています。開発ビルドなら任意のネイティブのライブラリを入れ、ネイティブの設定を変えられるためです。学習用にExpo Goだけで動かしてきた方は、独立前に開発ビルドを作り、ネイティブのライブラリを一つ足すところまで試しておきましょう。

### 版上げを一度通しでやる

React Nativeは版が上がるたびに、ライブラリやビルドの設定の対応が必要になります。業務で版上げを担当したことがなければ、自分の検証用のアプリで、一つ前の版から最新の版へ上げる作業を通しでやっておくと、案件で起きる問題の見当がつくようになります。求められるスキルの全体は[React Nativeの案件で求められるスキル](/media/react-native-skills/)にまとめています。

:::view
React Nativeの案件をご紹介していると、面談で評価されやすいのは、画面を作った経験に加えて「JavaScriptの外で起きた問題」をどう解決したかを話せる方です。ビルドのエラー、証明書や署名、ストアの審査の指摘など、自分で調べて直した経験を一つでも具体的に説明できると、少人数のチームでも任せやすい人として見てもらえます。面談の前に、担当した画面と、公開までに関わった範囲を分けて整理しておくことをおすすめします。
:::

## 独立までの進め方

### 1. アプリごとに経験を書き出す

関わったアプリごとに、期間、チームの人数、担当した機能、Expoの有無、React Nativeの版、ネイティブ側で手を入れた範囲、どちらのストアに何回公開したかを書き出します。書き方は[React Nativeのスキルシートの記事](/media/react-native-skillsheet/)と[スキルシートの基本](/media/skillsheet-basics/)をご覧ください。

### 2. 開発環境を用意する

iOS向けの開発と確認にはMacが要るため、貸与がない案件では自分で用意することになります。検証用の端末も、両方のOSで揃えておくと確認が早くなります。参画先によっては私物の機器を使えないこともあるため、貸与か持ち込みかは面談で確かめましょう。働き方の詳細は[React Nativeのリモート案件の記事](/media/react-native-remote/)で解説しています。

### 3. 希望する条件を決める

稼働日数、リモートか出社か、報酬の下限を決めておきます。報酬の決まり方は[React Nativeの報酬の記事](/media/react-native-rate/)で整理しています。

### 4. 案件を探して面談を受ける

フリーランスエージェント（案件紹介サービス）、知人の紹介、発注元との直接契約などの方法があります。使い方は[フリーランスエージェントの使い方](/media/agent-how-to-use/)で解説しています。

## 面談で聞かれやすいこと

1. **アプリの構成**：Expoの有無、画面遷移の方法、状態管理の方法
2. **版とアーキテクチャ**：React Nativeの版、New Architectureへの対応の状況
3. **ネイティブ側**：ライブラリで足りなかった機能と、その対応
4. **ストア対応**：両方のストアで受けた指摘と直し方
5. **チームでの進め方**：デザイナーやサーバー側、Web側との仕様のすり合わせ

:::caution
立ち上げの案件では、「アプリを公開するまで」を一式で請け負う形になっていることがあります。ストアの審査で何度も指摘を受けた場合や、途中でReact NativeやExpoの版上げが必要になった場合に、どこまでを範囲に含むかで負担が大きく変わります。契約の形と範囲は参画前に確かめましょう。違いは[準委任契約と請負契約の違い](/media/junin-vs-ukeoi/)で解説しています。
:::

## 独立前後の手続きと契約

退職して独立する場合は、健康保険と年金の切り替えに加え、開業届を出します。開業届の提出期限は、国税庁の案内では事業を始めた年分の確定申告期限までです（2026年10月時点）。手順の全体は[会社員からフリーランスになる手順](/media/quit-company-steps/)、開業届は[開業届の出し方](/media/kaigyo-todoke/)で解説しています。税金の判断に迷う場合は、税理士にご相談ください。

2024年11月に施行されたフリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容・報酬の額・支払期日などを書面やメールなどで明示することとされています。両方のストアへの申請や、公開後の版上げを範囲に含むかを確かめておきましょう。

:::view
当社では、案件をご案内する前に、稼働日数・リモートの希望・希望金額を伺い、合う案件だけをお出ししています。経歴は、ご了承いただいた案件にだけ、氏名・連絡先を伏せて提案し、業務の範囲・報酬・支払期日・契約期間は個別契約に書いてお渡ししています。開発機の貸与やストア申請の範囲など、React Nativeの案件で差が出やすい点は、面談の前に整理しておくことをおすすめします。
:::

:::point
- React Nativeで独立するには、Reactでの開発に加え、両ストアへの公開とJavaScriptの外の問題を直した経験が大切
- Web・ネイティブ・Flutterのどこから来たかで、補うべき点が違う
- Expo Goだけでなく開発ビルドを作り、版上げを一度通しでやっておく
- 公開まで一式で請け負う案件は、審査や版上げへの対応の範囲を参画前に確認する
:::

## よくある質問

### WebのReactの経験だけで、React Nativeのフリーランスになれますか？

Reactの考え方はそのまま生かせるため、Webから移って参画する方もいます。ただ、モバイルの案件ではストアへの公開やネイティブ側の設定で詰まったときに自分で進められるかを聞かれることが多いため、個人の検証用のアプリでもよいので、両ストアに出す流れとネイティブのライブラリを足す流れを一度経験しておくと安心です。

### Expoを使った経験しかありません。不利になりますか？

公式サイトが新しいアプリにはフレームワークを勧めていることもあり、Expoの現場は多くあります。ただ、Expoを使わずに作られた既存のアプリを保守する案件もあるため、ネイティブのファイルがどう生成され、どう組み立てられているかを理解しておくと、応募できる案件の幅が広がります。

### 最初の案件は新規開発と運用中のアプリのどちらがよいですか？

新規開発は任される範囲が広く、判断を一人で求められる場面が多くなります。運用中のアプリは、既存の設計に沿って進められるため、独立して最初の案件として入りやすい傾向があります。ただし長く版上げが止まっていたアプリは調査の量が読みにくいため、現状の版を確かめてから判断しましょう。選び方は[最初の案件の記事](/media/first-project/)も参考にしてください。
