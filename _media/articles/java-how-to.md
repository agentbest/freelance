Javaエンジニアがフリーランスになるには、**Spring・Spring Bootなどを使った業務システムやWebサービスの開発経験**に加えて、**設計書を自分で書いた経験と、担当した工程を具体的に説明できる材料**が必要です。Javaの案件はチームで進む中〜大規模の開発が多く、「どの工程を、どの規模のチームで担ったか」が最初に確認されます。

独立の準備は、経歴の棚卸し、足りない経験の補強、スキルシートの作成、手続きとお金の準備の順に進めると無理がありません。この記事では、Javaならではの見られ方と、出身の違いによる準備の差を中心に整理します。

## Javaの案件で最初に確認される3つのこと

Javaのフリーランス案件は、金融・公共・流通などの業務システムや、Webサービスのバックエンドが中心です。人を募集する時点で設計がある程度決まっていて、その中の役割を埋める形が多いため、次の3点が早い段階で確認されます。

| 確認される点 | 具体的に聞かれること |
|---|---|
| 担当した工程 | 基本設計・詳細設計から入れるか、実装・テストが中心か |
| チームと開発の規模 | 何人のチームで、どの範囲を担当したか。複数社が関わる体制の経験はあるか |
| 使ってきた技術の世代 | JavaとSpringのバージョン、アプリケーションサーバー、ビルドツール |

報酬がこれらの要素でどう変わるかは[Javaエンジニアの報酬の記事](/media/java-rate/)で扱っています。ここでは、独立前に何を準備すれば案件に入りやすくなるかに絞ります。

### 「設計書を書いたことがあるか」が分かれ目になりやすい

Javaの業務システム案件では、詳細設計書やテスト仕様書などのドキュメントを書く工程が多く含まれます。実装経験が長くても、設計書を自分で起こした経験がないと、参画できる案件が実装・テスト中心に限られがちです。会社員のうちに設計書の作成やレビューを担当させてもらえる機会があれば、独立前に経験しておくと選択肢が広がります。

### バージョンの経験は「移行」で語れると強い

OpenJDKのプロジェクトページでは、JDK 21（2023年9月にGA）とJDK 25（2025年9月にGA）は、多くのベンダーから長期サポート（LTS）版として提供されるとされています（2026年10月時点）。現場では、古いバージョンのまま動いているシステムも少なくありません。そのため、新しいバージョンでの開発経験だけでなく、**古いJavaやSpringから新しいものへ移行した経験**も評価されやすい傾向があります。ライブラリの入れ替え、非推奨APIの置き換え、テストでの動作確認など、移行で自分が担った作業を書き出しておきましょう。

## 出身によって準備することが違う

Javaエンジニアの経歴は、大きく「SIer・受託開発の出身」と「Web系・自社サービスの出身」に分かれます。どちらが有利ということはなく、強みと補うべき点が違います。

| 出身 | 強みになりやすい経験 | 独立前に補っておきたいこと |
|---|---|---|
| SIer・受託開発 | 設計書の作成、工程管理、業務知識、大人数のチームでの開発 | Spring Bootでの開発、Gitでのレビュー運用、クラウド環境での開発経験 |
| Web系・自社サービス | Spring Bootでの開発、API設計、クラウド、CI/CD | 設計ドキュメントの作成、業務システム特有の要件（帳票・バッチ・権限）への理解 |

SIer出身の方は、社内の標準フレームワークや古い構成での経験が中心になっていることがあります。その場合でも、業務の理解や工程の進め方は強みになります。足りない技術は、個人での学習に加え、社内の新しい案件に手を挙げるなど、実務に近い形で触れておくと説明しやすくなります。

Web系出身の方は、技術の新しさでは評価されやすい一方、業務システム案件では「設計書の粒度」「バッチ処理」「夜間運用」など、進め方の違いに戸惑うことがあります。応募する案件の分野を、経験に近いところから選ぶのが無難です。

:::view
Javaの案件をご紹介していると、技術の経験は十分でも「どの工程を担当したか」をうまく説明できずに面談で苦戦する方を見かけます。反対に、実装中心の経歴でも、設計書のレビューに加わった経験や、移行作業で自分が判断した点を具体的に話せる方は評価されやすい傾向があります。経歴を伺う際は、担当工程と体制を一緒に整理するようにしています。
:::

## 独立までの進め方

### 1. 担当した工程を案件ごとに書き出す

関わったプロジェクトごとに、期間、業界、チームの人数、担当した工程、使った技術とバージョン、成果を書き出します。Javaの経歴では、工程の書き分けが特に重要です。「開発」とひとまとめにせず、「詳細設計・実装・単体テスト」のように分けて書くと、案件との合い具合が伝わります。

### 2. 足りない経験を一つだけ補う

すべてを埋めようとすると時間がかかります。棚卸しで見えた弱点のうち、応募したい案件の条件に一番多く出てくるものを一つ選び、補強します。たとえば次のようなものです。

- Spring Bootでの開発（設定、DI、テストの書き方）
- SQLのチューニングや実行計画の読み方
- REST APIの設計とドキュメント化
- AWSなどのクラウド上での開発・デプロイ
- 単体テストの自動化（JUnitなど）

必要とされるスキルの全体像は[Javaの案件で求められるスキルの記事](/media/java-skills/)でまとめています。

### 3. スキルシートを用意する

フリーランスの案件では、職務経歴書の代わりにスキルシートで経歴を伝えます。Javaの場合は、プロジェクトごとに工程を表の形で示し、使ったバージョンやフレームワークを具体的に書くと読み手に伝わりやすくなります。書き方は[スキルシートの基本](/media/skillsheet-basics/)と[Javaのスキルシートの記事](/media/java-skillsheet/)を参考にしてください。

### 4. 案件の条件を決める

Javaの案件は、常駐かリモートか、稼働日数、契約期間がさまざまです。長期の業務システム案件では週5日の稼働を前提にするものも多いため、希望の稼働日数、働く場所、報酬の下限を先に決めておくと、合わない案件に時間を使わずに済みます。リモートの傾向は[Javaのリモート案件の記事](/media/java-remote/)で解説しています。

### 5. 案件を探して面談を受ける

案件の探し方には、フリーランスエージェント（案件紹介サービス）、知人の紹介、発注元との直接契約などがあります。最初の案件は、条件の確認や契約手続きの支援がある経路を選ぶと負担を減らせます。流れは[フリーランスエージェントの使い方](/media/agent-how-to-use/)で解説しています。

## 面談でよく問われること

Javaの案件の面談は、参画先の担当者とオンラインで行うことが多く、技術の深さよりも「参画してすぐに動けるか」を確かめる質問が中心になります。

1. **直近の案件での担当範囲**：どの機能を、どの工程から担当したか
2. **チームでの進め方**：レビューの受け方、課題の報告、ほかの会社のメンバーとのやり取り
3. **障害やトラブルへの対応**：性能問題や本番障害で、自分が何を調べ、どう対処したか
4. **技術の判断**：Springの機能をどう使い分けたか、なぜその設計にしたか
5. **稼働の条件**：開始時期、稼働日数、出社できる日

「何をしたか」だけでなく「なぜそうしたか」まで話せると、設計に関われる人として見てもらいやすくなります。面談の一般的な質問は[面談でよく聞かれる質問の記事](/media/interview-questions/)にまとめています。

:::caution
Javaの業務システム案件は、発注元から複数の会社を経て人を募集する体制になっていることがあります。間に入る会社が多いと、報酬の取り分や指示の流れが分かりにくくなります。参画前に、契約の相手と業務の指示を出す人を確認しておきましょう。商流の考え方は[商流の記事](/media/shoryu/)、上流工程に入るための考え方は[上流工程の記事](/media/upper-process/)で解説しています。
:::

## 独立前後の手続きとお金の準備

会社を辞めて独立する場合は、次の手続きが必要です（2026年10月時点の公的な案内による）。

| 手続き | 期限・内容 | 窓口 |
|---|---|---|
| 国民年金への切り替え | 退職日の翌日から14日以内 | 住所地の市区町村 |
| 健康保険の切り替え | 国民健康保険への加入、または任意継続を選ぶ | 市区町村・加入していた健康保険 |
| 開業届 | 事業を始めた年分の確定申告期限まで | 納税地の税務署 |
| 青色申告承認申請書 | 1月16日以後に開業した場合は開業日から2か月以内 | 納税地の税務署 |

退職から最初の報酬が入るまでには時間がかかることがあるため、数か月分の生活費を用意しておくと安心です。手順の全体は[会社員からフリーランスになる手順](/media/quit-company-steps/)、開業届の書き方は[開業届の出し方](/media/kaigyo-todoke/)で解説しています。税金や保険の判断に迷う場合は、税理士や窓口にご相談ください。

### 契約では業務の範囲と条件を確かめる

2024年11月に施行されたフリーランス法では、発注する事業者は、業務の内容、報酬の額、支払期日などの取引条件を、書面またはメールなどで直ちに明示することとされています。Javaの案件では「詳細設計から」「実装とテストのみ」など担当範囲が細かく分かれるため、明示された業務の内容が面談で聞いた内容と合っているかを確認しましょう。

:::view
当社では、経歴をご紹介する前に、どの案件に提案するかをご本人に確認し、ご了承いただいた案件にだけ、氏名・連絡先を伏せて経歴を提案しています。業務の範囲・報酬・支払期日・契約期間は個別契約に書いてお渡ししています。最初の案件では、稼働日数やリモートの希望、担当したい工程を先に伺い、条件に合う案件に絞ってご案内しています。
:::

:::point
- Javaの独立では、Spring系の開発経験に加え、担当工程と設計書の経験を説明できることが大切
- SIer出身はSpring Bootやクラウド、Web系出身は設計ドキュメントや業務システムの進め方を補う
- バージョン移行の経験は評価されやすいので、自分が担った作業を書き出しておく
- 退職後は年金・健康保険の切り替えと開業届の期限を確認する
:::

## よくある質問

### Javaの実務経験は何年あれば独立できますか？

決まった年数はありません。案件の条件には数年以上の経験を求めるものが多くありますが、見られるのは年数よりも、どの工程を担当し、どの規模のチームで動いてきたかです。設計から実装、テストまでを一通り担当した経験があり、それを説明できるかを目安にしてください。

### 社内独自のフレームワークしか使ったことがありません。

社内フレームワークの経験も、Javaで業務システムを作った経験として伝えられます。ただ、案件ではSpringなど広く使われるフレームワークの経験を条件にすることが多いため、独立前に個人の学習や社内の新しい案件でSpring Bootに触れておくと、参画できる案件が広がります。

### 最初の案件は常駐とリモートのどちらがよいですか？

どちらがよいかは、経験とご自身の生活によります。業務システムの案件では、立ち上がりの期間だけ出社を求めるものもあります。最初の案件は、慣れた分野で、業務の範囲と相談相手がはっきりしているかを重視して選ぶと、立ち上がりで困りにくくなります。選び方は[最初の案件の記事](/media/first-project/)も参考にしてください。
