ITコンサルタントのフリーランス案件は、**資格がなくても参画できるものが多く、評価の中心は「どの局面で、誰を相手に、何を決めてきたか」という実務の経験**です。資格が効くのは、案件票の条件に資格の名前がある場合と、経験の浅い局面に役割を広げたいときに知識の裏付けとして示す場合です。

資格は、担当したい局面と結びつけて持つと評価に変わり、数を並べるだけでは評価につながりにくくなります。この記事では、ITコンサルの局面ごとに関係の深い資格、効きにくい持ち方、実務との組み合わせ方を整理します。資格全般の考え方は[資格はフリーランスの案件獲得に役立つ？](/media/shikaku/)、各資格の試験の中身は個別の資格の記事で扱っています。

## 資格が問われる場面と、問われない場面

ITコンサルの案件で資格がどう扱われるかは、案件の性格でおおむね分かれます。

| 場面 | 資格の扱われ方 |
|---|---|
| 公共系や大手企業の上流の案件 | 案件票の歓迎条件に情報処理技術者試験の区分名などが挙がることがあり、書類の段階で目に留まりやすい |
| 監査や内部統制の評価に関わる案件 | 監査の進め方を体系的に知っている裏付けとして見られやすい |
| 製品の導入を前提にした案件 | その製品のベンダー認定が条件や歓迎条件になることがある |
| 構想・選定・導入支援の一般的な案件 | 資格より、局面の経験と成果物の説明が先に見られる |

多くの案件は最後の行にあたります。資格を持っていない場合でも、経験を具体的に説明できれば不利になりにくいと考えてよいでしょう。

## 局面ごとに関係の深い資格

ITコンサルの仕事は局面ごとに中身が違うため、関係の深い資格も局面ごとに変わります。

| 局面・テーマ | 関係の深い資格 | 詳しい記事 |
|---|---|---|
| IT戦略・構想づくり | ITストラテジスト試験 | [ITストラテジスト試験](/media/cert-ipa-st/) |
| 経営の視点が強い構想 | 中小企業診断士 | [中小企業診断士](/media/cert-shindanshi/) |
| 要件の整理・全体の方式 | システムアーキテクト試験 | [システムアーキテクト試験](/media/cert-ipa-sa/) |
| 発注側の導入支援・PMO | プロジェクトマネージャ試験、PMP | [プロジェクトマネージャ試験](/media/cert-ipa-pm/)、[PMP](/media/cert-pmp/) |
| ITガバナンス・監査 | システム監査技術者試験、CISA | [システム監査技術者試験](/media/cert-ipa-au/)、[CISA](/media/cert-cisa/) |
| 運用の見直し・サービス管理 | ITIL | [ITIL](/media/cert-itil/) |

この表は、資格と局面の重なりを示したもので、取るべき資格の一覧ではありません。担当したい局面が決まっていれば、その行の資格だけを検討すれば足ります。

## IPAの試験は制度の切り替わりに注意

IPA（情報処理推進機構）の試験区分の案内では、ITストラテジスト試験は2026年度はCBT方式で前期に実施、システム監査技術者試験はCBT方式で後期に実施とされています。どちらも、現行の試験制度は2026年度の実施をもって終わり、2027年度から新しい試験制度に移る予定と案内されています（2026年10月時点、IPAの各試験区分のページによる）。

これから受験を考える場合は、受けられる時期と、新しい制度でどの区分に当たるかを、IPAの公式ページでご確認ください。すでに合格している資格の書き方や、制度の移行の詳しい内容は、上の表の各記事で整理しています。

制度が変わっても、ITストラテジスト試験の対象者像に書かれた、経営戦略に基づいてITで事業を改革・高度化・最適化するための基本戦略を策定・提案・推進する仕事は、ITコンサルの案件で求められる仕事として続きます。資格の名前より、この仕事を経験で語れるかが問われる点は変わりません。

:::view
ITコンサルの案件をご紹介していると、資格を多く持っている方より、資格で学んだ枠組みを使って自分の経験を説明できる方のほうが、面談で評価されやすい傾向があります。たとえば、試験の範囲にある「全体システム化計画」の考え方で、過去に複数のシステムの更改の順番を決めた経験を話せると、資格と実務の両方が伝わります。資格は、経験の説明を補う道具として使うことをおすすめします。
:::

## 効きにくい資格の持ち方

資格があっても評価につながりにくいのは、次のような場合です。

- **数を並べるだけ**：局面と関係のない資格が多く並ぶと、何を任せたい人なのかがかえって見えにくくなる
- **入門の資格だけを前面に出す**：基礎的な資格は学び始めの証明にはなるが、上流の局面の案件では経験の裏付けとしては弱い
- **経験と結びつかない**：上流の資格を持っていても、その局面の経験が一つもなければ、任せられるかは判断しにくい
- **古い製品の認定だけが残っている**：製品の版が変わっている場合、今の知識の証明としては読まれにくい

資格欄は、応募する案件の局面に関係するものを上に書き、関係の薄いものは簡潔にまとめると読みやすくなります。

## 実務と組み合わせて伝える方法

資格を評価に変えるには、資格と経験を一つの話としてつなげます。

1. **資格の範囲と、自分が担った局面を重ねる**：資格の対象者像や業務の範囲のうち、実際に担った部分を書き出す
2. **担っていない部分は、正直に分ける**：「構想は担当、プログラムの実行管理は未経験」のように書く
3. **スキルシートの要約に一行で入れる**：架空の例では「製造業の基幹刷新で構想から選定までを担当。ITストラテジスト試験 合格」のように、経験と資格を同じ行に並べる
4. **面談では経験の話の中で触れる**：資格の名前から話し始めず、案件の話の中で「その整理の仕方は試験の学習で身につけた」と添える

面談で資格について聞かれたときは、試験の範囲の説明より、「その知識を、どの案件のどの場面で使ったか」を一つ挙げるほうが伝わります。架空の例では、「選定の評価基準を作るとき、試験の学習で身につけた投資の評価の観点を使い、費用だけでなく運用の負担も比べる項目を入れました」のような形です。反対に、資格の勉強の苦労や合格までの期間を長く話しても、案件で任せられる範囲の判断にはつながりにくくなります。

資格を持っていない場合に「資格はお持ちですか」と聞かれても、持っていないことを気にする必要はありません。その局面の経験を具体的に話し、知識の抜けを感じている分野があれば、どう補っているかを添えれば十分です。

スキルシート全体の組み立ては[ITコンサルタントのスキルシートの記事](/media/it-consultant-skillsheet/)、面談の答え方は[ITコンサルタントの面談の記事](/media/it-consultant-interview/)で解説しています。

:::caution
システム選定の局面の案件では、特定の製品のベンダー認定ばかりが並んでいると、その製品に寄った評価をする人ではないかと受け止められることがあります。製品の認定は導入の案件では強みになりますが、選定の案件に応募するときは、比べ方の経験や中立の立場で関わった経験を先に書き、製品の認定はその後ろに置くなど、見せる順番を工夫しましょう。
:::

## これから取るか迷ったときの考え方

資格の勉強は、案件と並行すると時間の確保が課題になります。迷ったときは、次の順で考えると判断しやすくなります。

- **狙う案件票に名前が出ているか**：公共系や大手企業の上流の案件を狙うなら、案件票の歓迎条件を確かめる
- **広げたい局面の知識を体系的に学びたいか**：経験の浅い局面に入るとき、知識の抜けを埋める目的なら意味がある
- **受験の時期と制度の変化**：IPAの試験は2027年度から新しい制度に移る予定のため、受けられる時期を確かめてから計画する

案件と並行した学習の時間の作り方は[学習時間の作り方の記事](/media/benkyo-jikan/)をご覧ください。資格より先に、担当したい局面での経験を一つ増やすことが近道になる場合も多くあります。上流の局面に入る道筋は[上流工程の案件に入るために必要な経験](/media/upper-process/)で整理しています。

:::view
当社では、案件をご案内する前に、稼働日数・リモートの希望・ご希望の金額を伺い、条件に合う案件だけをお出ししています。資格が歓迎条件に挙がっている案件でも、多くの場合は局面の経験とあわせて見られます。広げたい局面や、取ろうとしている資格がある場合は、早めにご相談ください。
:::

## よくある質問

### ITコンサルとして独立する前に、何か資格を取っておくべきですか？

独立の条件として資格が必要になることは多くありません。独立前は、局面ごとに自分で作った成果物を説明できるよう、経験の棚卸しを優先するほうが案件につながりやすくなります。独立の進め方は[ITコンサルタントがフリーランスになるには](/media/it-consultant-how-to/)をご覧ください。

### ITストラテジスト試験と中小企業診断士は、どちらがITコンサルに向いていますか？

ITを使った事業の改革や情報システムの計画に寄った案件なら、ITストラテジスト試験のほうが仕事の中身と重なります。経営や財務の分析に寄った案件では、中小企業診断士のほうが伝わることがあります。担当したい案件の性格で選ぶのが基本です。

### 英語の資格は評価されますか？

外資系企業や海外の拠点と関わる案件では、英語で会議や資料作成ができることが条件になることがあります。その場合も、試験の点数より、英語で何をしてきたかが見られやすいため、英語を使った業務の経験とあわせて示すと伝わります。考え方は[TOEICの記事](/media/cert-toeic/)でも整理しています。
