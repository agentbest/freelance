クラウドセキュリティエンジニアのフリーランス案件に、**資格は必須ではありません**。多くの案件は、権限設計・ログと検知・設定の監査のどれを、どの範囲で、指摘・是正・予防のどこまで担ってきたかで参画が決まります。

一方で、クラウドのセキュリティは**クラウドごとの認定がはっきり分かれている分野**でもあり、使うクラウドが決まっている案件や、インフラ構築からセキュリティに広げるときには資格が効きます。この記事では、評価されやすい資格と効きにくい資格を分け、実務とどう組み合わせると効くかを整理します。セキュリティ全般の資格の考え方は[セキュリティエンジニアの資格の記事](/media/security-engineer-shikaku/)で扱っています。

## 資格がなくてもクラウドセキュリティの案件に入れる理由

クラウドセキュリティの力量は、実際の設定と運用に表れます。使われていない権限を業務を止めずに減らせるか、監査ツールの大量の指摘を危険の大きい順に並べられるか、同じ指摘が繰り返し出ないようにテンプレートを直せるか。こうした力は、面談で過去の場面を掘り下げれば測れると、発注元の責任者は考えています。

そのため、案件票の必須条件は「AWSでの権限設計の経験」「監査ツールの運用経験」のように経験で書かれることが多く、資格は「歓迎」の扱いにとどまることが多くあります。まずは[クラウドセキュリティのスキルシートの記事](/media/cloud-security-skillsheet/)を参考に、分野と担った段階を伝わる形にすることが先です。

## 資格が効く4つの場面

| 場面 | 資格が効く理由 |
|---|---|
| 使うクラウドが決まっている案件 | そのクラウドのセキュリティの機能を体系的に知っていることを短く示せる |
| インフラ構築からセキュリティに広げるとき | 構築の経験に、守る側の知識を足したことの裏付けになる |
| 公共系・大手企業の案件 | 体制表や提案書に要員の資格を書く慣習があり、発注元が社内に説明しやすい |
| 複数のクラウドをまたぐ統制の案件 | 製品に依らない資格が、共通の考え方で話せることの裏付けになる |

どの場面でも、資格だけで決まることはありません。**実務の経験と並べたときに、その説明を補強する**ときに効きます。

:::view
クラウドセキュリティの案件をご紹介していると、インフラ構築の経験が長い方がセキュリティの案件に応募するときに、クラウドのセキュリティの認定が書類の段階で目に留まりやすい傾向があります。一方で、面談で評価が分かれるのは、権限を減らした場面や指摘を直した場面を具体的に話せるかどうかです。資格は経験を伝える助けとして使うことをおすすめします。
:::

## 評価されやすい資格

### 各クラウドのセキュリティの認定

**AWS**では、AWS Certified Security - Specialty（セキュリティ専門知識）がセキュリティを専門に問う認定です。2026年10月時点のAWSの公式ページでは、試験は170分・65問、受験料は300米ドル、有効期間は3年間で、ITセキュリティの設計の経験5年程度と、AWSのワークロードを守る実務の経験2年以上が推奨されています。詳しくは[AWS認定セキュリティ–専門知識の記事](/media/cert-aws-security/)で扱っています。

**Microsoft Azure**では、認定の入れ替わりに注意が必要です。Azure セキュリティ エンジニア アソシエイト（AZ-500）は、関連する試験と更新の評価とあわせて2026年8月31日に廃止され、以降は取得も更新もできないと案内されています。2026年10月時点のMicrosoft Learnには、Azure・ハイブリッド・AIの環境のセキュリティを扱う「クラウドおよび AI セキュリティ エンジニア アソシエイト」（試験SC-500）が掲載されています。設計の役割に近い認定として、サイバーセキュリティ アーキテクト エキスパート（試験SC-100）もあり、取得にはアソシエイトの認定のいずれかが前提とされています。Microsoftのロールベースの認定は更新しないと期限が切れ、オンラインの評価で無料で更新できる仕組みです。Azureの認定全体は[Azureの認定資格の記事](/media/cert-azure/)をご覧ください。

**Google Cloud**では、Professional Cloud Security Engineerがあります。2026年10月時点の公式ページでは、試験は2時間・50〜60問、登録料は200米ドル（税別）、受験の前提条件はなく、業界経験3年以上（Google Cloudでの設計と管理の経験1年以上を含む）が推奨されています。Professional認定は、更新の試験に合格すると有効期限に2年が加わると案内されています。

### CCSP（ISC2）

特定のクラウドに依らず、クラウドのセキュリティを横断して問う資格です。ISC2の案内では、認定にはITの分野で通算5年以上のフルタイムの実務経験が必要で、そのうち3年はサイバーセキュリティ、1年はCCSPの6つのドメインのいずれかに関わる経験であることが求められます。有効なCISSPを持っていれば経験の要件をすべて満たせ、経験が足りない場合は試験に合格して「Associate of ISC2」になり、6年以内に経験を積む道もあります（2026年10月時点）。複数のクラウドの方針を作る案件で効きやすい資格です。詳しくは[CCSPの記事](/media/cert-ccsp/)で扱っています。

### 情報処理安全確保支援士（IPA）

国内でセキュリティの専門性を示す国家資格です。クラウドに特化した資格ではありませんが、公共系や大手企業の案件では、体制表に書く資格として見られることがあります。2026年度はCBT方式で前期・後期に実施され、現行の試験制度は2026年度で終わり、2027年度から新しい制度に移る予定です（2026年10月時点のIPAの案内による）。登録の仕組みや新制度の動きは[情報処理安全確保支援士の記事](/media/cert-ipa-sc/)にまとめています。

## クラウドセキュリティの案件では効きにくい資格

次のような資格は、持っていて損はないものの、クラウドセキュリティの案件の評価にはつながりにくい傾向があります。

- **クラウドの基礎の認定**：セキュリティの専門家として参画する段階では前提とみなされ、差がつきにくい
- **案件と違うクラウドの認定だけ**：AWSの案件にGoogle Cloudの認定だけを示しても、置き換えの説明が別に要る
- **期限の切れた認定・廃止された認定**：クラウドの認定は期限や入れ替わりが多く、状態を書かないと確認の手間を増やす

設計全般を問う認定（ソリューションアーキテクトなど）は、構築の経験の裏付けにはなりますが、セキュリティを任せる根拠としては補助にとどまります。

:::caution
クラウドの認定は、名称の変更や廃止、試験の改定がよく起こります。スキルシートに書くときは、正式名称、試験番号、取得年月、有効期限を各社の資格の管理画面で確かめてから書いてください。廃止された認定は、取得した事実は書けますが、現在も有効であるように読める書き方は避けましょう。受験料や形式も変わることがあるため、受験の前に公式サイトで最新をご確認ください。
:::

## 実務経験との組み合わせ方

資格は、実務のどこを補うかを決めてから選ぶと効果が出ます。

| 今の経験 | 広げたい方向 | 組み合わせやすい資格 |
|---|---|---|
| AWSやAzureの構築が中心 | そのクラウドのセキュリティ専任の案件 | そのクラウドのセキュリティの認定 |
| 1つのクラウドのセキュリティが中心 | 複数のクラウドをまたぐ統制の案件 | CCSP、別のクラウドのセキュリティの認定 |
| オンプレミスのセキュリティが中心 | クラウドの権限や監査の案件 | 使うクラウドのセキュリティの認定 |
| 技術の作業が中心 | 方針づくりや公共系の案件 | CCSP、情報処理安全確保支援士 |

組み合わせのポイントは、資格と**同じ方向の実務の場面**を1つでも持っておくことです。AWSのセキュリティの認定を取ったなら、使われていない権限を減らした場面や、ログの集約先を設計した場面を話せるようにします。CCSPを取ったなら、2つ以上のクラウドで同じ方針をどう設定に落としたかを話せると、資格の中身が伝わります。必要な経験の全体像は[クラウドセキュリティのスキルの記事](/media/cloud-security-skills/)にまとめています。

## スキルシートと面談での伝え方

1. **資格欄**：正式名称、試験番号、取得年月、有効期限。経験の要件がある資格は、認定済みか合格のみかを書き分ける
2. **経歴欄**：資格で学んだ考え方を使った場面があれば、作業や判断の中身として書く
3. **面談**：資格について聞かれたら、取った理由と、実務で生かした場面を1つ話す

学習中の資格は、受験予定の時期とあわせて書くと学ぶ姿勢が伝わります。ただし、取得していない資格を取得済みのように読める書き方は避けてください。

:::view
当社では、案件をご案内する前に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをお出ししています。資格を条件に挙げている案件もありますが、多くは実務の経験が中心に見られます。お持ちの認定や有効期限が案件の条件にどう関わるか気になる場合は、ご質問いただければ確認します。
:::

:::point
- クラウドセキュリティの案件は、資格がなくても実務経験で参画できるものが多い
- 資格が効くのは、使うクラウドが決まっている案件、構築から広げるとき、公共系・大手企業、複数のクラウドをまたぐ統制
- AzureのAZ-500は2026年8月31日に廃止。クラウドの認定は名称・期限・入れ替わりを公式で確かめる
- 資格は、同じ方向の実務の場面と組み合わせて伝えると効く
:::

## よくある質問

### 最初に取るなら、どのクラウドのセキュリティの認定がよいですか？

今の案件や狙う案件で使われているクラウドから選ぶのが基本です。実務で触れているクラウドの認定のほうが、学んだことを現場で確かめやすく、面談でも経験と結びつけて話せます。

### AZ-500を持っています。スキルシートにはどう書けばよいですか？

取得した事実と取得年月は書けます。廃止により更新できなくなっているため、有効期限の状態もあわせて書き、現在も有効に見えないようにしましょう。後継の認定を取るかどうかは、Microsoft Learnの最新の案内をご確認ください。

### CCSPと各クラウドの認定は、どちらを優先すべきですか？

1つのクラウドの案件を中心にするなら、そのクラウドの認定のほうが直接の裏付けになります。複数のクラウドの方針づくりや、組織の決まりを作る役割に広げたいなら、CCSPが効きやすくなります。経験の要件があるため、ISC2の案内で条件を確かめてから準備してください。
