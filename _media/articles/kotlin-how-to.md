Kotlinエンジニアがフリーランスになるには、**Kotlinでサーバーサイドのサービスを作り、本番で動かした経験**と、**JVM・Spring BootやKtor・Gradleといった周辺の土台を自分で扱えること**が目安になります。言語の文法を覚えただけでは、業務委託の案件で任せてもらえる範囲は限られます。

この記事では、サーバーサイドのKotlinを軸に、独立までに積んでおきたい経験と、出発点ごとの準備、独立までの進め方を整理します。Androidアプリで独立する場合は[Androidエンジニアがフリーランスになるには](/media/android-how-to/)をご覧ください。

## 独立前に積んでおきたい経験の目安

業務委託の案件は、参画してすぐに作業を任されることが多く、教わりながら覚える前提にはなりにくい働き方です。サーバーサイドKotlinの案件では、少なくとも次の経験を自分の言葉で説明できる状態を目指します。

| 経験 | 目安 |
|---|---|
| Kotlinでの実装 | 業務のAPIやバッチを、レビューを通る品質で書いてきた |
| 本番での運用 | 作った機能がリリースされ、不具合や問い合わせに対応した |
| フレームワーク | Spring BootかKtorで、設定やテストの書き方を含めて扱える |
| ビルド | Gradleの設定を読み、依存関係の追加や更新ができる |
| データベース | SQLを書き、テーブルの設計やインデックスの意味を説明できる |
| Javaとの境界 | Javaのライブラリやコードを読み、Kotlinから安全に呼べる |

年数より、これらを本番の仕事でどこまで担ったかが見られます。言語の知識をどの深さまで問われるかは[Kotlinの案件で求められるスキル](/media/kotlin-skills/)で分野ごとに整理しています。

## 出発点ごとの準備

### Javaのサーバーサイド経験がある人

最も近い道です。Kotlinの公式ドキュメントは、JavaからKotlinへ大きなコードベースを少しずつ移せること、テストや新しいコードからKotlinで書き始められることを案内しています（2026年10月時点）。社内のJavaのプロジェクトで、テストや新しいモジュールをKotlinで書く機会を作れれば、それがそのまま実績になります。

注意したいのは、Javaの書き方をKotlinの文法に置き換えただけで終わらせないことです。null安全、data class、sealedクラス、コルーチンを使うと設計がどう変わるかを説明できるようにしておくと、Kotlinの案件としての評価につながります。Javaのまま独立する道は[Javaエンジニアがフリーランスになるには](/media/java-how-to/)で扱っています。

### AndroidでKotlinを書いてきた人

言語とコルーチンの経験は、サーバーサイドでもそのまま土台になります。足りなくなりやすいのは、データベースの設計、トランザクション、APIの設計、本番の監視です。社内のバックエンドの改修に関わる、BFF（画面向けのAPI）をKotlinで作るなど、サーバー側の実務を一つでも持ってから独立すると、選べる案件が広がります。

### ほかの言語のバックエンド経験がある人

GoやPython、PHPなどでサービスを作ってきた人は、APIや運用の経験は生かせます。一方で、JVMの仕組みやSpringのような大きなフレームワークの作法に慣れるまで時間がかかることがあります。まずはSpring BootかKtorのどちらかで、テストとビルドの設定まで含めて一つのサービスを通して作ってみるのがおすすめです。

:::view
Kotlinの案件をご紹介していると、面談でつまずきやすいのは、Kotlinの経験が社内の一部の機能や個人の学習に限られ、本番での運用の話ができない場面です。短い期間でも、リリース後の不具合にどう対応したかを話せると、印象が変わる傾向があります。独立を考え始めたら、Kotlinで書いた機能が本番でどう動いたかを書き出しておくことをおすすめします。
:::

## 社内で実務を増やす方法

独立前の会社でKotlinの実務を増やせると、準備の負担が軽くなります。

- **テストから書く**：既存のJavaのプロジェクトで、新しいテストだけKotlinで書く提案をする
- **新しいモジュールを任される**：小さな管理用のAPIや社内ツールをKotlinで作る
- **規約づくりに関わる**：Kotlinを採り入れるときのコーディング規約やライブラリの選定に参加する

いきなり独立せず、副業として業務委託の案件を受けて経験を足す方法もあります。会社の規程や働き方の注意点は[会社員の副業で業務委託を受けるとき](/media/fukugyo-gyomu-itaku/)をご覧ください。

## Spring Bootの前提を押さえておく

サーバーサイドKotlinの案件では、Spring Bootを使う現場によく出会います。Spring Bootのリファレンスでは、2026年10月時点で、Kotlinを使うにはKotlin 2.2系以上が必要とされ、Kotlinのバージョンは依存関係の管理の中で扱われると案内されています。また、`@ConfigurationProperties`をKotlinのdata classで受けられること、JSONの変換にはJacksonのKotlinモジュールが要ることなども説明されています。

独立前に、手元のプロジェクトで使っているKotlinとSpring Bootの版を確かめ、新しい版での動きを一度試しておくと、面談で版の話になったときに具体的に答えられます。

:::caution
個人で学んだKotlinの成果物は、実務経験の代わりにはなりにくいのが実情です。公開しているコードは補足として役立ちますが、「本番で誰がどう使い、どんな問題が起きたか」を語れる実務の経験を、少なくとも一つは持ってから独立するほうが無理がありません。
:::

## 独立のタイミングを見極める

「Kotlinの経験が何年あれば独立できる」という決まった線はありません。目安になるのは、次の3つがそろったかどうかです。

- 上に挙げた経験を、実際の仕事の例とともに説明できる
- 得意な案件の型を一つ言える（新規開発、移行、非同期処理など）
- 案件が決まるまでの生活費と、税や保険の支払いの見通しが立っている

経験の面では十分でも、生活の備えが不足していると、条件を妥協して案件を選ぶことになりがちです。時期の考え方は[独立のタイミングの記事](/media/independence-timing/)、お金の備えは[独立前の準備の記事](/media/before-independence-prepare/)で扱っています。

## 独立までの進め方

### 1. 実績を棚卸しする

関わったサービスごとに、期間、チームの人数、担当した工程、Kotlinとほかの言語の比率、使ったフレームワークと版、運用で起きたことを書き出します。まとめ方は[Kotlinのスキルシートの書き方](/media/kotlin-skillsheet/)で扱っています。

### 2. 軸を一つ決める

「Spring Bootでの新規開発」「Javaからの移行」「コルーチンを使った非同期のサービス」など、得意な型を一つ決めておくと、案件を絞り込みやすくなります。報酬との関係は[Kotlinエンジニアの報酬の記事](/media/kotlin-rate/)をご覧ください。

### 3. 条件を決める

稼働日数、リモートの希望、希望する金額、契約期間を先に決めます。サーバーサイドKotlinのリモート事情は[Kotlinエンジニアのリモート案件の記事](/media/kotlin-remote/)で扱っています。

### 4. 手続きと契約の準備をする

退職後の年金・保険の切り替え、開業届、青色申告などの手続きは、[会社員からフリーランスになる手順](/media/quit-company-steps/)、[開業届の出し方](/media/kaigyo-todoke/)、[青色申告の記事](/media/aoiro-shinkoku/)にまとめています。個別の判断は税理士や窓口にご相談ください。契約で明示されるべき条件は[フリーランス法の取引条件の明示の記事](/media/freelance-act-terms/)で確認できます。

:::view
当社では、経歴はご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。Kotlinの案件は、新規開発か移行か、Spring BootかKtorかで、求められる周辺の経験が違います。独立の時期が決まっていなくても、得意な型と希望の条件を早めに決めておくことをおすすめします。気になる案件の前提は、ご質問いただければ確認します。
:::

:::point
- 目安は、Kotlinでサーバーサイドのサービスを作り本番で動かした経験と、JVM・フレームワーク・Gradleを扱えること
- Java経験者はKotlinらしい設計を、Android経験者はデータベースと運用の経験を足す
- 実績の棚卸し、軸の決定、条件の決定、手続きの順で進める
:::

## よくある質問

### Kotlinの実務が1年ほどでも独立できますか？

Kotlinの期間が短くても、Javaなどでのサーバーサイドの経験が長ければ、あわせて伝えることで参画できる案件はあります。大切なのは、Kotlinの期間とそれ以前の経験を分けて示し、本番での運用まで担った経験を具体的に話せることです。

### Spring BootとKtorのどちらを覚えればよいですか？

どちらを使うかは現場によって違い、案件ごとに分かれます。まずは今の仕事で使っている方を深め、もう一方は小さなサービスを作って違いを説明できる程度にしておくと、選べる案件が広がります。

### Kotlin Multiplatformの経験がないと独立は難しいですか？

サーバーサイドの案件では、Kotlin Multiplatformの経験を必須にするものは多くありません。まずはサーバー側の実務を固め、余力があれば、クライアントとデータの型を共有する構成を試してみる程度で十分です。
