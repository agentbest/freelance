フリーランスの機械学習エンジニアの面談でよく聞かれるのは、**何の課題をどの指標で評価したか、データの問題にどう向き合ったか、精度が出なかったときに何を判断したか、本番でどう動かし監視したか**の4つです。面談官は手法の名前の多さより、「この人にデータとモデルを預けたら、思いどおりにいかないときにどう動くか」を確かめようとしています。

答えるときは、模範解答を覚えるより、自分の経験から性質の違うプロジェクトを2〜3件選び、どの質問にもそこから答えられるように準備しておくのが近道です。面談全般の答え方は[業務委託の面談でよく聞かれる質問と答え方](/media/interview-questions/)で解説しているので、この記事では機械学習の面談に固有の質問に絞ります。

## 機械学習の面談で面談官が見ていること

機械学習の案件の面談に出てくるのは、発注元のデータサイエンティストや機械学習のチームの責任者、開発チームのリーダーであることが多くあります。相手も技術に詳しいため、話の中の**判断の順番と根拠**がよく聞かれます。

面談官が知りたいのは、おおむね次の3点です。

1. **担える工程**：データの準備・学習・評価・推論の提供・監視のどこを、どの深さで担ってきたか
2. **不確かさへの向き合い方**：結果が読めない仕事で、何を基準に進め、どこで見切ったか
3. **チームとの合い方**：開発者や事業部門と、どう役割を分け、どう伝えてきたか

以下の質問は、この3点のどれかを確かめるためのものです。質問の意図が分かれば、答えの中心に何を置くかも決まります。

## よく聞かれる質問と答え方の考え方

ここで示す答えの例は、組み立て方を伝えるための**架空の例**です。そのまま使うのではなく、ご自身の経験に置き換えて準備してください。

### 1. 「直近のプロジェクトで、何を解くモデルを作りましたか」

確かめたいのは、課題の理解と担当の範囲です。業務の課題、データの種類、モデルの使われ方、チームの人数、自分が担った工程を短く伝えます。手法の名前から話し始めると、面談官は課題との結びつきを想像できません。**課題 → 使われ方 → 自分の担当 → 手法**の順に話すと伝わりやすくなります。

架空の例：「問い合わせを担当の部署に振り分けるための分類モデルです。4名のチームで、私はデータの整備と学習、推論のAPIまでを担当しました。手法は〜です」

### 2. 「評価指標は何で、なぜそれを選びましたか」

最も掘り下げられやすい質問の一つです。指標の名前だけでなく、**業務で困る誤りはどちらか、何と比べて判断したか、誰と決めたか**を話します。たとえば、見逃しが困る業務なのか、誤った警告が困る業務なのかで、選ぶ指標も閾値も変わります。比較の相手（今のルール、単純なモデル、人の判断）を挙げられると、数字の意味が伝わります。

### 3. 「データにどんな問題があり、どう対処しましたか」

欠損、偏り、ラベルの揺れ、学習時と本番時のデータの違いなど、実データには何かしらの問題があります。面談官は、問題に気づいたきっかけと、モデルの工夫で補ったのか、データの側を直してもらったのかを聞いています。データの持ち主に掛け合った経験は、発注元との関係づくりの力として評価されます。

### 4. 「精度が出なかったとき、何を試し、どう判断しましたか」

機械学習の面談に特有の質問です。答えは次の順番で組み立てると伝わりやすくなります。

- どの時点で、どの数字を見て「足りない」と判断したか
- 原因の見立て（データの量や質、特徴量、課題の設定そのもの）
- 試したことと、試さなかったことの理由
- 誰に、どう伝えて、続けるかやめるかを決めたか

「いろいろな手法を試しました」で終わると、判断の中身が見えません。**見切った判断**を説明できると、検証の進め方を任せられる人として伝わります。

### 5. 「本番でどう動かし、どう監視していましたか」

推論の方式（リアルタイムかバッチか）、配置の方法、監視していた項目、再学習のきっかけと流れを聞かれます。担当していない部分は「そこは基盤のチームが担っていて、私は監視の項目を決めるところまで関わりました」のように線を引いて話します。運用の経験が浅い場合も、本番に出す前に何を確かめたかは話せるはずです。

### 6. 「実験の管理や再現性をどう確保していましたか」

データの版、コードの版、学習の条件、乱数の扱い、結果の記録をどう残していたかを確かめる質問です。チームで使っていた仕組みと、自分が決めた運用のルールを分けて話すと、どこまでを自分で整えられるかが伝わります。

### 7. 「開発者や事業部門とはどう連携しましたか」

推論の入出力の仕様をどう決めたか、事業部門に結果をどう説明したかを聞かれます。精度の数字を事業の言葉に直した場面を一つ話せると、相手との合い方が伝わります。

### 8. 「このプロジェクトでは、最初の1か月で何をしますか」

面談の段階で分かる情報は限られています。断定的な計画を語るより、**データ、評価の基準、既存の仕組み、関係者の何を確かめてから判断するか**を順に示すほうが信頼されます。

:::view
機械学習の案件をご紹介していると、面談で評価されやすいのは、精度が出た話より「出なかったときに何を見て、どう判断したか」を順を追って話せる方です。反対に、手法やライブラリの名前が続き、課題や評価の話が出てこないと、案件に合うかを判断しにくく、見送られやすい傾向があります。結果がよくなかった検証でも、見切りの根拠を話せれば、経験として受け止められることが多くあります。
:::

## 準備は「性質の違うプロジェクト」を2〜3件に絞る

上の質問は数が多く見えますが、答えの材料は共通しています。準備は次の手順で進めると効率的です。

1. **プロジェクトを選ぶ**：検証で終わったもの、本番に出したもの、運用を続けたものなど、性質の違うものを2〜3件選ぶ
2. **プロジェクトごとにメモをつくる**：課題、データ、評価指標と比較の相手、試したこと、判断、本番での扱い、自分の担当を書き出す
3. **規模をそろえる**：データの量の目安、チームの人数、期間を、どの質問でも同じ言い方で答えられるようにする
4. **2分版と5分版をつくる**：最初は短く話し、掘り下げられたら詳しく話せるようにする
5. **スキルシートと照らし合わせる**：シートに書いた担当の工程と、話す内容が一致しているかを確かめる

技術の確認として、コードの課題や設計の口頭質問が出ることもあります。進め方は[技術テストの記事](/media/tech-test/)で解説しています。スキルシートの書き方は[機械学習エンジニアのスキルシートの記事](/media/ml-engineer-skillsheet/)、冒頭の自己紹介は[面談の自己紹介の記事](/media/self-introduction/)をご覧ください。

:::caution
面談では、前の案件の発注元の社名、扱ったデータの中身、モデルの精度の具体的な値などを話してしまいがちです。機械学習の仕事は、顧客のデータや事業の数字に深く触れる分、話の具体性と守秘のバランスが問われます。社名やデータの中身は伏せ、規模や改善の方向で伝えましょう。どこまで話してよいかの考え方は[スキルシートに書いてよいこと・いけないこと](/media/confidentiality-in-skillsheet/)が参考になります。
:::

## 面談の相手によって重心が変わる

| 面談の相手 | 重く見られやすい点 |
|---|---|
| 機械学習・データのチームの責任者 | 評価の設計、実験の進め方、見切りの判断 |
| 開発チームのリーダー | コードの品質、テスト、推論の組み込み、レビューへの対応 |
| 事業部門・プロダクトの担当者 | 課題の理解、結果の説明の仕方、期待値の合わせ方 |
| 基盤・SREの担当者 | 監視、障害の切り分け、計算資源と費用の扱い |

複数の相手が同席する面談では、最初に誰が何を知りたいかを意識し、技術の深さと事業の言葉を使い分けると、限られた時間を有効に使えます。データ分析の色が強い案件の面談は[データサイエンティストの面談の記事](/media/data-scientist-interview/)、基盤と運用の色が強い案件は[MLOpsエンジニアの面談の記事](/media/mlops-interview/)もあわせてご覧ください。

## 機械学習エンジニアならではの逆質問

逆質問は、印象づくりより**参画後のずれを防ぐ確認**に使います。機械学習の案件では、次の点を聞いておくと判断がしやすくなります。

- 使えるデータの量と状態、アクセスできるようになる時期
- 評価の基準と、検証を続けるかやめるかを決める人
- 学習に使える計算資源の環境と、費用の上限
- 本番への配置や監視を担うチームの有無と、役割の分担
- 外部のAIサービスやライブラリの利用についての社内のルール

一般的な逆質問の考え方は[業務委託の面談で聞いておくべき逆質問](/media/reverse-questions/)にまとめています。聞いた内容は、契約前の確認にもそのまま使えます。案件を選ぶときの確認点は[機械学習エンジニアの案件の選び方](/media/ml-engineer-anken-erabi/)で整理しています。

:::view
当社では、経歴をご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。機械学習の案件では、案件票だけでは分からないデータの状態や計算資源の環境について、面談の前に確認しておきたい点があれば、ご質問いただければ確認します。
:::

:::point
- 機械学習の面談では、課題と評価指標、データの問題、精度が出なかったときの判断、本番での運用がよく聞かれる
- 答えは「課題→使われ方→自分の担当→手法」の順で、手法の名前から話し始めない
- 準備は性質の違うプロジェクトを2〜3件に絞り、スキルシートと内容をそろえる
- 逆質問では、データの状態、評価の基準と決める人、計算資源、運用の分担を確かめる
:::

## よくある質問

### 論文やコンペの実績は面談で話したほうがよいですか？

聞かれたら話して問題ありません。ただ、多くの案件で重く見られるのは、実データでモデルを作り、業務やシステムにつないだ経験です。論文やコンペの話をする場合も、そこで身につけた進め方が実務のどこで生きたかを添えると、案件との結びつきが伝わります。

### 検証で終わったプロジェクトばかりですが、どう話せばよいですか？

検証の結果をどう判断し、どう報告したかを中心に話します。本番に進まなかった理由を、データや費用、業務の都合など根拠とともに説明できれば、検証を任せられる人として受け止められます。本番に近い作業（APIの試作、推論の速さの測定など）に関わった部分があれば、あわせて伝えましょう。

### 面談で精度の具体的な数字を聞かれたら答えるべきですか？

前の案件の精度の値は、守秘の対象になっていることがあります。具体的な値は伏せ、「既存のルールより誤りを減らし、運用に乗せる判断につながった」のように、比べた相手と結果の方向で伝えれば十分です。面談で見送られやすい理由は[面談で見送られる理由の記事](/media/interview-fail-reasons/)で解説しています。
