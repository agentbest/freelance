ブリッジSEのスキルシートは、**使える言語や関わったプロジェクトを並べるより、「どの拠点体制で、どこまでの役割を担い、何を防いだか」を先に読ませる**のが基本です。1件ごとに「拠点体制・自分の立ち位置・使った言語と場面・やりとりの仕組み・品質への関わり・結果」をそろえて書くと、読み手は任せられる範囲を判断しやすくなります。

語学のスコアを目立たせるだけでは、通訳・翻訳の担当と区別されにくくなります。この記事では、ブリッジSEのシートに固有の書き方を、架空の記入例を使って紹介します。全体の構成は[フリーランスのスキルシートの書き方](/media/skillsheet-basics/)で解説しているので、あわせてご覧ください。

## ブリッジSEのシートはどう読まれるか

ブリッジSEのシートを読むのは、オフショア開発を進める側のPMや開発の責任者であることが多く、拠点とのやりとりの難しさを知っています。そのため、次のような点を読み取ろうとします。

- 伝達役だったのか、技術や品質の判断まで担ったのか
- 拠点の規模と、日本側・拠点側の誰と向き合っていたか
- 会議の進行まで任せられる語学力か、資料中心の語学力か
- 仕様のずれや品質の問題に、自分で手を打った経験があるか

求められるスキルの全体像は[ブリッジSEに求められるスキルの記事](/media/bridge-se-skills/)で整理しています。ここでは、それをシートの上でどう表すかに絞ります。

## 要約欄は「役割の型」と「言語の場面」を3行で

要約欄は、もっとも読まれる部分です。ブリッジSEの場合は、経歴を年代順にまとめるより、**どの型のブリッジSEか**と、**言語をどの場面で使えるか**を先に書きます。

架空の例：
- オフショア開発の日本側窓口として、業務システムの詳細設計から受入テストまでを担当
- 拠点の開発者十数名との定例会議を、日本語と英語で進行。質問票とチケットの運用を設計
- 受入テストで見つかる不具合の傾向を分析し、仕様書の書き方とレビューの観点を見直した経験あり

これは書き方を示すための架空の例です。実際には、応募する案件の型に近い行を一番上に置き、案件ごとに並べ替えます。

## プロジェクト欄に入れる項目

ブリッジSEのプロジェクト欄は、基本の型に固有の項目を足して書きます。

| 項目 | 書き方のポイント |
|---|---|
| 期間 | 年月で書く。自分が関わった期間と全体の期間が違う場合は分ける |
| 案件の概要 | 業種と目的で書く（例：製造業向け 受発注システムの再構築）。社名・拠点の会社名は書かない |
| 拠点体制 | 拠点の人数、拠点の数、拠点側のリーダーの有無。国名は必要な範囲で |
| 自分の立ち位置 | 日本側の発注元の中か、開発会社の側か。報告先と、向き合っていた相手 |
| 使った言語と場面 | 言語ごとに、資料・チャット・会議・進行のどこまでを担ったか |
| やりとりの仕組み | 質問票、チケット、定例会議の頻度、時差への対応など、自分が作ったり変えたりしたもの |
| 品質への関わり | レビュー、受入テスト、不具合の分析のうち、担った範囲 |
| 主な判断 | 自分が決めた、または決定を主導したことを1〜3行で |
| 結果 | 伏せられる範囲での結果（手戻りの減少、稼働の時期など） |

### 架空の記入例

> **期間**：（架空の例）約1年。うち自分の参画は詳細設計の途中から稼働後2か月まで
> **案件の概要**：（架空の例）流通業向け 在庫管理システムの機能追加
> **拠点体制**：海外の開発拠点1か所、開発者約12名。拠点側に日本語の分かるリーダー1名
> **自分の立ち位置**：日本側の開発会社のブリッジSE。報告先は日本側のPM
> **使った言語と場面**：英語で週2回の定例会議を進行。仕様の質問はチャットとチケットで英語、日本側への報告は日本語
> **やりとりの仕組み**：質問票を一覧にまとめ、回答期限と担当者を明記する形に変更
> **品質への関わり**：拠点のプログラムのレビュー、受入テストの手順作成と実施
> **主な判断**：受入テストで同じ種類の不具合が続いたため、画面の入力チェックの仕様を表にまとめ直し、拠点と読み合わせを行った
> **結果**：以降の機能追加では、同じ種類の不具合が受入テストで見つからなくなった

これは項目の埋め方を示すための架空の例です。人数や回数などは、実際の経験の数字に置き換えて書いてください。

:::view
ブリッジSEの案件をご紹介していると、面談に進みやすいシートは「やりとりの仕組み」と「主な判断」の欄が具体的なものです。質問票の形を変えた、レビューの観点を決めた、といった工夫が書かれていると、読み手は参画後の動きを想像しやすくなります。当社では、経歴はご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。
:::

## 語学欄の書き方

語学欄は、「ビジネスレベル」といった言葉だけで済ませず、次の3つを書きます。

1. **言語と、業務で使った場面**：読む・書く・会議で話す・会議を進める、のどこまでか
2. **試験のスコアや級**：試験の名前を正確に書き、取得した時期を添える
3. **技術の領域**：どの分野の技術用語に慣れているか

英語の試験は、テストの種類によって測る技能が違うため、どのテストのスコアかを正確に書きます（詳しくは[TOEICの記事](/media/cert-toeic/)）。日本語を母語としない方は、日本語能力試験（JLPT）の級を書くことがあります。JLPTは、日本語を母語としない人の日本語能力を測定し認定する試験です（2026年10月時点で公式サイトで確認）。あわせて、日本語の設計書を書いた、日本側の会議で報告した、といった業務の場面を書くと、読み手が判断しやすくなります。

英語でシートを求められる場合の書き方は[英文レジュメの記事](/media/eibun-resume/)をご覧ください。

## 書いてはいけないこと・伏せること

ブリッジSEのシートには、一般的なシートより固有の名前が入り込みやすくなります。

- 拠点の会社名、拠点のある都市や建物の名前
- 拠点と結んだ契約の金額、人月の単価、要員の費用
- 取引先の製品名や、プロジェクトの社内での呼び名
- 個人データや設計情報など、拠点に渡した資料の中身

規模を伝えたいときは、金額ではなく、拠点の人数や拠点の数で示します。どこまで書いてよいかの考え方は[スキルシートに書いてよいこと・いけないこと](/media/confidentiality-in-skillsheet/)で解説しています。

:::caution
通訳・翻訳が中心だった経歴を、品質や進捗の管理まで担ったように書くのは避けてください。ブリッジSEの面談では、レビューや受入の手順を具体的に聞かれることが多く、書いた内容と話す内容がずれると信頼を損ねます。担った範囲をそのまま書き、伸ばしたい部分は面談で意欲として伝えるほうが、合う案件につながります。
:::

## 肩書きと実際の役割がずれるとき

ブリッジSEは、会社によって呼び方が違います。「オフショア担当」「海外窓口」「通訳兼SE」「オフショアPM」など、肩書きと役割が合わないことがよくあります。

- 肩書きが「SE」でも、拠点との窓口を担っていた場合は、その範囲を役割として書く
- 肩書きが「ブリッジSE」でも、実際は翻訳と通訳が中心だった場合は、その範囲で書く
- 拠点の体制や計画まで任されていた場合は、PMに近い経験として、判断した範囲を書く

PMとしての書き方は[PMのスキルシートの記事](/media/pm-skillsheet/)、PMOとしての書き方は[PMOのスキルシートの記事](/media/pmo-skillsheet/)が参考になります。

## 提出前に見直したいこと

1. 要約欄の1行目に、応募する案件の型に近い経験が来ているか
2. すべてのプロジェクトに「拠点体制」と「自分の立ち位置」が入っているか
3. 語学は、言語ごとに使った場面が書けているか
4. 「主な判断」が、状況・取った手・結果の形で書けているか
5. 拠点の会社名、金額、資料の中身が入っていないか

:::view
ブリッジSEの面談では、シートの「やりとりの仕組み」や「主な判断」の行について、なぜその形にしたのか、拠点の反応はどうだったかを掘り下げて聞かれる傾向があります。シートに書いたそれぞれの工夫について、背景を2〜3分で話せるように準備しておくことをおすすめします。面談でよく聞かれる質問は[面談の質問と答え方の記事](/media/interview-questions/)にまとめています。
:::

:::point
- ブリッジSEのシートは「拠点体制・立ち位置・言語と場面・やりとりの仕組み・品質への関わり・判断・結果」をそろえて書く
- 語学は、スコアより業務で使った場面を書き、試験名と時期を正確に添える
- 拠点の会社名や金額は書かず、規模は人数と拠点の数で示す
:::

## よくある質問

### 語学のスコアがありません。シートに何を書けばよいですか？

スコアがなくても、業務で使った場面を具体的に書けば伝わります。週に何回の会議に参加したか、どの資料を訳したか、チャットで何をやりとりしたかなど、実際の数字と場面で示しましょう。

### 拠点のある国名は書いてもよいですか？

国名は、言語や時差の経験を示す情報になります。ただし、国名と業種、時期の組み合わせで特定されるおそれがある場合は、地域名にとどめるなど調整しましょう。

### 複数の拠点を同時に担当していた場合はどう書けばよいですか？

拠点ごとに体制と使った言語を分けて書き、それぞれへの関わり方の濃さ（主担当か、補助か）を添えます。複数の拠点を並行して回した経験は、それ自体が強みとして読まれます。
