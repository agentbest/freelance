SAP Basisエンジニアのフリーランス案件では、**OSとデータベース、特にSAP HANAの運用の知識、移送や更新の手順を組み立てる力、性能の問題を切り分ける力、移行のツールを扱った経験**が見られます。作業の種類を並べられることより、その作業で何を判断し、どう失敗を防いだかを説明できるかが、任される範囲を決めます。

この記事では、Basisの案件で問われやすい技術を分野ごとに整理し、面談で伝わる経験の示し方を解説します。作業の種類による棚卸しや独立の手順は[SAP Basisエンジニアがフリーランスになるには](/media/sap-basis-how-to/)で扱っているので、ここでは技術の中身に絞ります。

## Basisのスキルは「層」で整理する

SAPのシステムは、ハードウェアやクラウドの基盤の上にOS、データベース、SAPのアプリケーションサーバーが重なって動いています。Basisエンジニアに求められる知識も、この層ごとに分けると整理しやすくなります。

| 層 | 主な知識 | 面談で確かめられやすい点 |
|---|---|---|
| 基盤（オンプレミス・クラウド） | サーバー、ストレージ、ネットワーク、仮想化、クラウドのサービス | サイジングの考え方、冗長化の構成 |
| OS | Linuxを中心としたOSの管理、ファイルシステム、カーネルのパラメータ | SAPの前提条件の確認、OSの更新の段取り |
| データベース | SAP HANAのほか、旧環境のOracle・Db2・SQL Serverなど | バックアップと復旧、容量と性能の監視 |
| SAPのアプリケーション層 | インスタンスの構成、ワークプロセス、メモリの設定、ジョブ | 性能の問題の切り分け、設定の変更の判断 |
| 周辺 | 帳票の出力、外部との接続、Webの入口、シングルサインオン | 接続の不具合の調べ方 |

すべての層に同じ深さで強い必要はありません。インフラ出身の人は下の層に、SAPの運用から入った人は上の層に強いことが多いため、自分の強い層と、補いたい層を把握しておくと、案件を選ぶときの軸になります。

## データベースの運用、とくにSAP HANA

S/4HANAはSAP HANAの上で動くため、HANAの運用の経験は、Basisの案件で特に重く見られます。

- **メモリの使い方の理解**：HANAはデータをメモリ上で扱うため、メモリの使用量の監視と、増えたときの原因の調べ方が欠かせない
- **バックアップと復旧**：データとログのバックアップの仕組み、復旧の手順、復旧にかかる時間の見積もり
- **冗長化と災害対策**：別のサーバーにデータを複製して切り替えに備える構成の設計と、切り替えの訓練
- **容量の管理**：データの増え方の見通しと、古いデータの整理の提案

旧環境のデータベースの経験も、移行の案件では生きます。移行元のデータベースの特性を知っていると、データの抽出や移行の時間の見積もりで頼りにされます。

:::view
Basisの案件紹介の現場では、面談で「その障害のとき、どの順番で何を確認したか」と問われる場面をよく見ます。評価されやすいのは、OS・データベース・SAPのどの層の問題かを切り分け、ログや監視の数字から原因を絞った手順を、順を追って話せる方です。「障害対応の経験あり」とだけ伝えると、どこまで一人で任せられるかが伝わりにくくなります。
:::

## 変更と更新の手順を組み立てる力

### 移送の経路と本番反映の管理

SAPのシステムでは、開発環境で作った設定やプログラムを、検証環境、本番環境へと順に移送して反映します。Basisエンジニアは、この移送の経路を設計し、反映のルールを運用します。

案件で評価されるのは、移送の操作そのものより、移送の順番が前後したときや、反映に失敗したときの扱いを決めた経験です。複数のプロジェクトが同じシステムに並行して変更を入れる環境では、どの変更をいつ本番に入れるかの調整に関わることもあります。

### カーネル・サポートパッケージの適用とバージョンアップ

SAPのカーネルの入れ替えや、サポートパッケージの適用、バージョンアップは、Basisの定番の作業です。ここで見られるのは、次のような段取りの力です。

1. **前提の確認**：対象の版がOS・データベースの前提条件を満たすか、関連するSAPノートを読んで確かめる
2. **影響の見積もり**：業務の設定や追加開発への影響を、業務側・開発側と確認する
3. **手順書と時間の見積もり**：検証環境での実施結果から、本番の停止時間を見積もる
4. **切り戻しの計画**：失敗したときにどこまで戻すか、判断の基準と手順を決めておく

SAPのノートやサポートへの問い合わせは英語で行うことが多いため、英語の技術文書を読み、問い合わせの文面を書ける力も役に立ちます。

## 性能の問題を切り分ける力

「画面が遅い」「夜間のジョブが朝までに終わらない」といった性能の問題は、Basisエンジニアに持ち込まれやすい相談です。原因は、OSやデータベースの資源の不足、SAPの設定、特定のプログラムの作り、データ量の増加などさまざまです。

評価されるのは、監視のツールやSAPの分析の画面から、どの資源が詰まっているかを数字で示し、原因の候補を絞れることです。プログラムの作りに原因がある場合は、開発者に渡せる形で根拠をまとめる力も求められます。性能の改善は、ジョブの実行時間をずらす、データを整理する、設定を変えるなど、関係者と合意しながら進めることが多いため、説明の力も問われます。

## 移行のツールと進め方

S/4HANAへの移行や、データベースの切り替え、クラウドへの移設では、SAPが提供する移行のツールを使います。代表的なものが、SUM（Software Update Manager）の機能であるDMO（Database Migration Option）です。

SAPの公式サポートページによると、DMOは、ABAPベースのシステムでソフトウェアの更新とデータベースの移行を組み合わせて行う機能です。S/4HANAへの変換に向けた方式や、システムを別の環境へ移す方式、大きなテーブルをシステムの稼働中に移して停止時間を短くする方式などが用意されています。

移行の案件では、こうした方式の中からどれを選んだか、リハーサルで所要時間をどう縮めたかが問われます。方式の選び方は、データ量、許される停止時間、移行先の環境によって変わるため、選んだ理由を説明できるようにしておきましょう。移行のプロジェクト全体で求められるスキルは[S/4HANA移行のフリーランス案件で求められるスキル](/media/s4hana-skills/)で解説しています。

:::caution
移行や更新の作業では、手順書どおりに進めても、本番のデータ量や環境の違いで想定外のことが起こります。リハーサルの回数や検証環境のデータが本番に近いかどうかで、当日の危うさが大きく変わります。参画する案件で、リハーサルの計画と、当日に判断する人が決まっているかを早めに確かめておくと安心です。
:::

## クラウドと自動化の経験

SAPのシステムをクラウドの基盤の上で動かす案件が続いています。クラウドの上では、仮想マシンの大きさの選び方、ストレージの性能、ネットワークの設計、バックアップの仕組みなどを、クラウドのサービスに合わせて組み立てます。Basisの知識に加えてクラウドの構築の経験があると、参画できる案件の幅が広がります。クラウドの側のスキルは[AWSエンジニアのスキル](/media/aws-skills/)や[Azureエンジニアのスキル](/media/azure-skills/)もあわせてご覧ください。

また、システムの起動・停止、定期的な確認、システムのコピーの後処理などを、スクリプトや自動化のツールで定型化した経験も評価されます。手作業の手順を減らした経験は、作業の誤りを防いだ実績として伝えられます。

## 権限とセキュリティの扱い

ユーザーの管理や権限の付与、セキュリティの設定は、Basisの担当に含まれることがあります。案件によっては専任の権限の担当がいる場合もあるため、自分がどこまで担ったかを書き分けておくことが大切です。

監査への対応で、権限の付与の記録や、特権を持つユーザーの利用の記録を提出した経験は、内部統制の厳しい業界の案件で評価されることがあります。

## スキルシートと面談で伝えたいこと

Basisの経験は、作業の名前より、その作業での判断を書くと伝わります。プロジェクトごとに次の点をそろえておきましょう。

- システムの種類と規模（ECCかS/4HANAか、システムの台数、データ量の目安）
- 基盤、OS、データベースの組み合わせ
- 担当した作業と、計画・判断まで担ったかどうか
- 停止時間の見積もりと実績、リハーサルで変えた手順
- 障害や性能の問題で、自分が原因を突き止めた例

書き方の詳細は[SAP Basisエンジニアのスキルシートの書き方](/media/sap-basis-skillsheet/)をご覧ください。

:::view
当社では、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをご案内しています。ご経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せて提案しています。Basisの案件は、データベースや基盤の組み合わせで求める経験が変わることが多いため、上の項目でプロジェクトごとに整理しておくことをおすすめします。
:::

:::point
- Basisのスキルは、基盤・OS・データベース・SAPのアプリケーション層・周辺の層で整理すると強みが見えやすい
- SAP HANAの運用、移送と更新の段取り、性能の切り分けが、案件でよく問われる
- 移行では、DMOなどの方式を選んだ理由と、リハーサルで手順をどう変えたかを説明できるようにする
:::

## よくある質問

### SAP HANAの経験がないと案件に参画できませんか？

旧環境のデータベースの経験で参画できる案件もあります。保守・運用の案件や、移行元の環境を扱う工程では、旧環境の知識が求められます。一方で、S/4HANAの環境の案件が増えているため、HANAのバックアップや監視の仕組みを学び、検証環境で触れておくと、選べる案件が広がります。

### 英語はどのくらい必要ですか？

SAPのノートや技術文書は英語のものが多く、読む力は多くの案件で役立ちます。海外の拠点やSAPのサポートと直接やり取りする案件では、書く力や話す力が求められることもあります。必要な水準は案件によって違うため、応募の前に確かめておきましょう。

### インフラエンジニアの経験はどこまで生かせますか？

基盤、OS、ネットワーク、データベースの経験は、Basisの下の層の知識としてそのまま生かせます。そのうえで、移送の管理やSAPの更新の手順など、SAP特有の作業を学ぶと、Basisとして任される範囲が広がります。クラウドの構築の経験は、SAPをクラウドに移す案件で特に評価されやすい部分です。
