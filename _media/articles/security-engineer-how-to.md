セキュリティエンジニアがフリーランスになるには、**脆弱性診断、セキュリティを組み込んだ設計、監視、インシデント対応のどれかを自分で担った経験と、機密を任せられる人だと示せる裏付け**が必要です。セキュリティの案件では、発注元の弱点や事故の情報に触れるため、技術と同じくらい信頼が見られます。

独立の準備は、自分の経験がどの型の案件に近いかを決め、経験と資格で信頼の裏付けを整え、作業範囲の取り決め方を理解してから案件を探す、という順に進めます。

## セキュリティエンジニアの案件で多い型

セキュリティの業務委託案件は、守る対象と工程によっていくつかの型に分かれます。

| 案件の型 | 主な仕事 | 特に見られる経験 |
|---|---|---|
| 脆弱性診断 | Webアプリやネットワークの弱点を調べ、報告する | 診断の手法、ツールと手作業の使い分け、報告書 |
| セキュリティ設計・クラウドセキュリティ | 権限、ログ、暗号化などを設計の段階で組み込む | クラウドの設定、認証・認可、ネットワーク |
| 監視・運用 | ログやアラートを分析し、異常を見つける | 監視の道具、ログの読み方、判断の基準づくり |
| インシデント対応 | 事故の調査、封じ込め、復旧、再発防止 | 調査の手順、証拠の保全、関係者への報告 |
| 規程・体制づくり | セキュリティの方針や手順を整え、教育する | 規程の作成、リスク評価、監査への対応 |

規程づくりや監査への対応が中心の案件は、コンサルタントの役割に近くなります。その方向を考えている場合は[セキュリティコンサルタントがフリーランスになるには](/media/security-consultant-how-to/)もあわせてご覧ください。この記事では、手を動かす技術の仕事を中心に説明します。

## 独立前に積んでおきたい経験

### 一つの型を「一人で回せる」状態にする

セキュリティは範囲が広く、すべてを浅く知っているより、一つの型を最初から最後まで担えるほうが案件につながりやすい分野です。たとえば診断なら、対象の確認、診断の計画、実施、報告書の作成、発注元への説明までを一人で進めた経験があるかが問われます。

### 開発やインフラの経験を持つ

セキュリティの専門家として参画しても、相手は開発チームやインフラの担当者です。アプリケーションの作りやクラウドの構成が分かると、指摘が具体的になり、直し方まで提案できます。開発やインフラの経験がある人がセキュリティに広げるのは、独立後に強みとして生かしやすい道筋です。

### 報告と説明の力

診断やインシデント対応の結果は、技術者だけでなく経営層や事業部門にも伝える必要があります。影響の大きさと対応の優先順位を、専門用語を使わずに説明した経験は、どの型の案件でも評価されます。

:::view
セキュリティの案件をご紹介していると、面談で評価されやすいのは、見つけた脆弱性の数より「何を優先して直すべきかをどう伝えたか」を話せる方です。指摘したあと、開発チームと一緒に直し方を決めた経験があると、任せられる範囲が広がりやすくなります。守秘義務で具体的な事例を話せない場合も、進め方や判断の基準を一般化して説明できるように準備しておくことをおすすめします。
:::

## 資格は信頼の裏付けとして役立つ

セキュリティの案件では、発注元の機密に触れるため、知識と倫理の裏付けとして資格が見られることがあります。

### 情報処理安全確保支援士

IPAの情報処理安全確保支援士試験は、セキュリティの専門知識を使って、安全な情報システムの企画・設計・開発・運用を支援し、対策の調査・分析・評価と助言を行う人を対象にした国家試験です。2026年度はCBT方式で実施され、2027年度から新しい試験制度に移る予定とされています。

試験に合格したあと、登録の手続きをすることで、国家資格「情報処理安全確保支援士（登録セキスペ）」を名乗れるようになります。登録には有効期間があり、登録日または更新日から3年ごとに更新が必要です。更新には、毎年の講習（3年間でオンライン講習3回と実践講習1回）をすべて修了していることが求められます（いずれも2026年10月時点のIPAの案内による）。

試験に合格しただけの状態と、登録して講習を受け続けている状態は区別されます。スキルシートに書くときは、どちらの状態かを正しく書きましょう。

### 民間の資格

診断、クラウドセキュリティ、インシデント対応などの分野ごとに、民間の資格もあります。名称や更新の条件は変わることがあるため、取得や更新の前に各資格の公式サイトで最新の内容をご確認ください。

## 作業範囲の取り決めが特に大切な理由

診断や調査の仕事は、やり方を誤ると、他人のシステムへの不正な侵入と区別がつかなくなります。不正アクセス禁止法では、アクセス制御のあるコンピュータに、管理者の承諾を得ずに、他人の識別符号（IDやパスワードなど）を使ったり、アクセス制御の弱点を突いて制限をすり抜けたりしてアクセスする行為を不正アクセス行為とし、これを禁止しています。

そのため、診断の案件では、作業の前に次の点を書面やメールで確かめておくことが大切です。

1. **対象**：診断してよいシステム、URL、IPアドレスの範囲
2. **期間と時間帯**：作業してよい日時
3. **手法**：行ってよい診断の種類と、行わない操作
4. **承諾**：対象システムの管理者が承諾していること（委託元と管理者が違う場合は特に注意）
5. **異常時の連絡**：システムに影響が出たときの連絡先と止め方

:::caution
「ついでにこのサーバーも見ておいて」といった口頭の依頼で、取り決めた範囲の外を診断することは避けましょう。管理者の承諾が確認できない対象への作業は、法律上の問題になるおそれがあります。範囲を広げる場合は、改めて書面やメールで取り決めてから作業してください。判断に迷う場合は専門家にご相談ください。
:::

診断の結果、システムが止まるなどの影響が出る可能性もあります。契約書の損害賠償の条項を確かめるとともに、[フリーランスの賠償責任保険](/media/baisho-sekinin/)で備え方を見ておくと安心です。契約書全体の見方は[業務委託契約書のチェックポイント](/media/contract-checkpoints/)、秘密保持は[NDAの記事](/media/nda/)で解説しています。

## 面談で聞かれやすいこと

| 質問の例 | 見られていること |
|---|---|
| どんな対象を、どの手法で診断・監視してきましたか | 担える型と、経験の深さ |
| 重大な指摘を見つけたとき、どう報告しましたか | 優先順位をつけて伝えられるか |
| インシデントに対応した経験を教えてください | 手順に沿って冷静に進められるか |
| 開発チームやインフラ担当とどう協力しましたか | 指摘だけでなく、直す段階まで関われるか |
| 機密情報をどう管理していましたか | 情報の扱いを任せられるか |

経験の書き方は[セキュリティエンジニアのスキルシートの記事](/media/security-engineer-skillsheet/)、求められるスキルは[セキュリティエンジニアのスキルの記事](/media/security-engineer-skills/)にまとめています。

## 独立までの進め方

1. **経験を型ごとに整理する**：診断・設計・監視・インシデント対応のどれを、どの範囲まで担ったか
2. **信頼の裏付けを整える**：資格の登録状況、守秘義務を守った形での経験の説明
3. **条件を決める**：稼働日数、リモートの希望、夜間対応を受けるか、報酬の下限。リモートの傾向は[セキュリティエンジニアのリモート案件の記事](/media/security-engineer-remote/)、報酬は[セキュリティエンジニアの報酬の記事](/media/security-engineer-rate/)を参照
4. **手続きとお金を準備する**：[会社員からフリーランスになる手順](/media/quit-company-steps/)と[開業届の出し方](/media/kaigyo-todoke/)を参照
5. **案件を探す**：[フリーランスエージェントの使い方](/media/agent-how-to-use/)を参照

2024年11月に施行されたフリーランス法では、発注側は業務を委託したとき、業務の内容・報酬の額・支払期日などを書面やメールなどで直ちに明示することが求められています。監視やインシデント対応の案件では、夜間・休日の呼び出しの扱いも、業務の内容として確かめておきましょう。

:::view
当社では、経歴をご紹介する前にどの案件に提案するかを伺い、ご了承いただいた案件にだけ、氏名・連絡先を伏せて提案しています。取引先の会社の実態と支払条件を確かめた案件を扱い、業務の範囲・報酬・支払期日・契約期間は個別契約に書いてお渡ししています。診断の対象や作業の範囲など、参画前に確かめたい点があれば、ご質問いただければ確認します。
:::

:::point
- セキュリティで独立するには、一つの型を一人で回せる経験と、機密を任せられる信頼の裏付けが必要
- 情報処理安全確保支援士は、合格後に登録し、毎年の講習を受けて3年ごとに更新する資格
- 診断の案件では、対象・期間・手法・承諾・異常時の連絡を書面やメールで取り決めてから作業する
:::

## よくある質問

### セキュリティ専任の経験がなくても独立できますか？

開発やインフラの中でセキュリティの対策を担ってきた経験があれば、それを生かせる案件はあります。ただし、診断やインシデント対応を専門に求める案件では、その分野の実務経験が問われます。まずは自分の経験に近い型の案件から始め、範囲を広げていくと無理がありません。

### 情報処理安全確保支援士は登録しないと意味がありませんか？

試験に合格したことは、知識の裏付けとして伝えられます。一方、「情報処理安全確保支援士」を名乗るには登録が必要で、登録後は講習を受け続けることが求められます。名乗り方に気をつけて、スキルシートには合格か登録かを正しく書きましょう。

### 自宅から診断作業をしてもよいですか？

案件によって違います。リモートでの作業を認める案件もあれば、発注元が指定する場所や端末でしか作業できない案件もあります。作業する場所と使う端末・ネットワークは、診断の範囲とあわせて、参画前に取り決めておきましょう。
