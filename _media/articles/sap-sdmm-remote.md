SAP SD/MMコンサルのフリーランスは、**受注・出荷・請求、購買・入庫・請求書照合の設定や仕様書の作成、テストを中心に、リモートで働ける案件があります**。システムの中で完結する作業は、接続環境さえ整えばどこからでも進められます。

ただし、SD/MMは「モノが動く現場」とつながるモジュールです。倉庫や工場での業務調査、納品書やラベルの印刷確認、取引先とのデータ連携のテスト、出荷を止められない本番切替などでは、現地での作業が求められやすくなります。この記事では、SD/MMならではの現地作業の中身と、リモートで信頼を得る進め方、参画前に確かめる点を整理します。

## SD/MMの仕事で現地が求められやすい理由

FI/COが「数字」を扱うのに対して、SD/MMは「受注から出荷」「発注から入庫」という、倉庫・工場・営業所の人の動きと結びついた業務を扱います。システムの画面だけを見ていても、次のようなことは分かりにくいものです。

- 出荷の前に、倉庫で誰がどの順番で何を確認しているか
- 入庫のとき、現品と納品書が合わなかったら現場でどう処理しているか
- 営業担当が、特別な値引きや分納の約束をどう伝えているか

こうした実際の動きを踏まえずに設計すると、稼働してから「現場で使えない」と言われることになります。発注側が現状調査の段階で拠点への訪問を求めるのは、このためです。

## リモートで進めやすい作業と現地が選ばれやすい作業

| 作業 | 進め方の傾向 | ポイント |
|---|---|---|
| 販売・購買の組織構造、伝票タイプ、価格条件の設定 | リモートで進めやすい | 設定の内容を一覧にして共有できる |
| アドオンや出力の仕様書の作成 | リモートで進めやすい | 帳票のレイアウトも画像で受け渡しできる |
| 単体テスト・結合テスト | リモートで進めやすい | テストデータで受注から請求まで通せる |
| 倉庫・工場・営業所の業務調査 | 現地が選ばれやすい | 作業の順番や例外処理は見ないと分からないことが多い |
| 帳票・ラベルの印刷確認 | 現地が選ばれやすい | 拠点のプリンタや用紙、バーコードの読み取りで確かめる |
| ハンディ端末や倉庫管理システムとの連携テスト | 現地が選ばれやすい | 実際の機器と棚で動かす必要がある |
| 取引先とのEDI連携テスト | 案件による | 取引先との日程調整や、問題が出たときの即時対応が要る |
| 本番切替（在庫・未完了伝票の移行） | 現地が選ばれやすい | 出荷・入庫を止める時間が限られている |

### 帳票と機器は「その場」で確かめる

納品書、出荷指示書、送り状、現品票などの帳票は、取引先との約束や、物流会社の決まりに合わせた形式が求められます。画面で見て正しくても、拠点のプリンタで印刷すると位置がずれる、バーコードが読み取れない、といった問題は現地でしか分からないことがあります。ハンディ端末を使った入出庫も同様です。

### 本番切替は出荷を止めない段取りが中心

SD/MMの本番切替では、在庫の数量と評価額、受注残や発注残などの未完了の伝票を旧システムから移します。その間、出荷や入庫をどこまで止めてよいかは、物流の現場と細かく決める必要があります。切替の当日は、倉庫の担当者と連絡を取りながら最初の出荷・入庫を確かめるため、現地に詰める体制が組まれやすくなります。

### 取引先との連携テストは相手の都合で決まる

受注や発注のデータを取引先とEDIでやり取りしている企業では、新しいシステムでの送受信を、取引先と一緒に確かめるテストが必要になります。日程は取引先の都合に左右され、問題が出たときには、相手の担当者と画面やデータを突き合わせながら原因を探します。リモートで対応できる場合も多いものの、テストの日は終日連絡が取れる状態でいることが求められやすく、取引先の数が多いと期間も長くなります。

:::view
SD/MMの案件をご紹介していると、普段の作業はリモートでも、現状調査や切替の時期に「拠点への出張」を条件にする案件がよく見られます。本社だけでなく、工場や物流センターなど地方の拠点が対象になることもあります。当社では、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをご案内しています。出張ができるかどうか、どのくらいの頻度まで可能かも、あわせて考えておくことをおすすめします。
:::

## リモートで信頼を得る進め方

SD/MMでリモートの評価を保つには、現場の人が「自分の業務がどう変わるか」を離れた場所からでも理解できるように伝えることが大切です。

- **業務の流れの図と設定をつなぐ**：受注から請求まで、発注から支払まで、業務の流れの図に「ここで使う伝票タイプ」「ここで決まる価格条件」を書き込んで共有する
- **例外処理を一覧にする**：返品、分納、直送、無償出荷、検収の差異など、例外の扱いを表にして、現場の担当者に確認してもらう
- **画面の動画を活用する**：拠点の担当者に新しい操作を伝えるとき、画面を録画した短い動画を添えると、出社しなくても理解が進む
- **会計への影響を添える**：出荷や入庫で動く在庫の評価や売上の計上は、FI側の担当者に関わる。どの処理で何の仕訳が起きるかを書き添えると、モジュールをまたいだ確認が早く進む

SDとMMで深く問われる機能は[SAP SD/MMコンサルに求められるスキル](/media/sap-sdmm-skills/)で解説しています。

:::caution
リモートの案件でも、拠点への出張が契約の範囲に含まれていることがあります。出張の交通費や宿泊費を報酬に含めるのか、別に精算するのかは案件によって違います。移動の時間を稼働として数えるかどうかもあわせて、参画の前に確認しておきましょう。考え方は[交通費・経費の記事](/media/transportation-fee/)にまとめています。
:::

## 契約と接続環境で確かめること

リモート中心のSD/MM案件では、参画の前に次の点を確かめておくと安心です。

1. **出張・出社の対象と頻度**：本社だけか、工場・物流センター・営業所も含むか。現状調査・テスト・切替のどの段階か
2. **出張の費用**：交通費・宿泊費の精算の方法と、移動時間の扱い
3. **接続の方法**：VPNか仮想デスクトップか。帳票の出力を自宅から確かめられる環境があるか
4. **連携先との窓口**：EDIや倉庫管理システムの担当者と直接やり取りしてよいか
5. **切替の日程**：出荷を止める時間帯と、休日や夜間の作業があるか
6. **契約の範囲**：拠点の利用者向けの説明会や、稼働後の問い合わせ対応まで含むか

在宅で作業する場合は、発注側のセキュリティの決まりに合わせる必要があります。総務省は、テレワークを導入する組織向けに「テレワークセキュリティガイドライン」（第5版、2021年5月）を公表し、端末やリモートアクセス、公衆無線LANの扱いなどの手引きも示しています。発注側の決まりがこうした考え方にもとづくこともあるため、求められる対策を参画前に確かめておきましょう。

2024年11月1日に施行されたフリーランス法では、業務を委託したときに、業務の内容や報酬の額、支払期日とあわせて、役務の提供を受ける場所などを書面やメールで明示することが求められています（2026年10月時点で公正取引委員会のページで確認）。出張先や出社の条件も、書面でどう扱われているか確かめておくと、参画後のずれを防げます。

:::view
SD/MMの面談では、「リモートで現場の業務をどうつかんだか」を聞かれることがあります。拠点の担当者とのやり取りの工夫や、例外処理を洗い出した方法を具体的に話せる方は、評価されやすい傾向があります。当社がご紹介する案件は、取引先の会社の実態と支払条件を確かめたもので、業務の範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。出張の扱いなどで気になる点は、ご質問いただければ確認します。
:::

## リモート案件の探し方

SD/MMでリモート中心の案件を探すときは、次の点を意識すると選びやすくなります。

- **役割と工程を伝える**：設定・テスト・アドオンの仕様を担う役割は、リモートにしやすい
- **保守の案件も視野に入れる**：稼働後の保守や、価格条件・取引先の追加などの小さな改修は、リモートで回しやすいことがある
- **業種の経験を前に出す**：製造・卸・小売など、業界の商習慣を知っていると、現地の調査が少なくても設計の精度を出しやすい
- **出張できる範囲を決めておく**：「首都圏の拠点なら月数回」「遠方は切替の前後だけ」のように条件を決めておくと、出張を含む案件も選択肢に入れやすい

移行のプロジェクトの働き方は[S/4HANA移行はリモートで働ける？](/media/s4hana-remote/)、独立の進め方は[SAP SD/MMコンサルがフリーランスになるには](/media/sap-sdmm-how-to/)で解説しています。

:::point
- 設定・仕様書・テストはリモートで進めやすい
- 倉庫や工場の業務調査、帳票・機器の確認、本番切替は現地が求められやすい
- 地方の拠点への出張を含む案件もある。出張の費用と頻度を確かめる
- 業務の流れの図と例外処理の一覧で、離れていても現場に伝わる形を作る
:::

## よくある質問

### SD/MMでフルリモートの案件はありますか？

あります。保守・運用の案件や、設定とテストを中心に担う役割では、フルリモートになることがあります。導入や移行のプロジェクトでは、現状調査や本番切替の時期に出社・出張を求められることが多いため、案件ごとの確認が必要です。

### 地方の工場や倉庫への出張はよくありますか？

対象の企業が地方に拠点を持つ場合、現状調査やユーザーテスト、切替の時期に出張が入ることがあります。頻度と費用の扱いは案件によって違うため、面談の段階で確かめておきましょう。

### SDとMMのどちらがリモートにしやすいですか？

一概には言えません。どちらも設定やテストはリモートで進めやすく、現地作業の多さは、対象の業務（物流センターの有無、取引先との連携の多さなど）やプロジェクトの段階で変わります。報酬の考え方は[SAP SD/MMコンサルの報酬の記事](/media/sap-sdmm-rate/)をご覧ください。
