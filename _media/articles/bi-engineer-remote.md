BIエンジニアは、**データモデルや画面の開発・改修を中心に、リモートで働けるフリーランス案件があります**。Power BIやTableauのクラウドのサービスに公開する構成なら、作業の多くは離れた場所から進められるためです。

ただし、要件を固める初期の打ち合わせ、社内ネットワークの中にあるデータへの接続、個人情報を含む画面の確認などは、出社や決められた端末での作業を求められることがあります。この記事では、リモートで進めやすい仕事としにくい仕事、参画前に確かめたい環境の準備、案件の探し方を整理します。

## リモートで進めやすい仕事・しにくい仕事

| 仕事 | リモートとの相性 | 理由 |
|---|---|---|
| 既存モデルの上での画面の追加・改修 | 進めやすい | 対象が決まっていて、画面の確認もオンラインでできる |
| データモデルや計算式の改善 | 進めやすい | 設計と検証が手元で完結しやすい |
| 性能の改善 | 進めやすい | 計測と修正を繰り返す作業が中心 |
| 新規導入の要件の整理 | しにくいことがある | 複数の部門と指標の定義をそろえる会議が続く |
| 社内に定着させる支援 | しにくいことがある | 利用者への説明会や、席を回っての支援を求められる |
| 社内ネットワークのデータへの接続 | 条件しだい | ゲートウェイの設定や社内の端末からの作業が必要になる |
| 個人情報を含む画面の確認 | 条件しだい | 決められた端末やネットワークでの確認を求められる |

同じ案件でも、立ち上げの時期は出社が多く、運用に入るとリモートが中心になる、という形もよくあります。期間によって働き方が変わるかどうかも確かめておくとよいでしょう。

リモートで進めやすいかどうかは、ツールの種類より、**データと利用者にどれだけ離れた場所から触れられるか**で決まります。クラウドのDWHと、オンラインの会議で要望を聞ける利用者がそろっていれば、新規導入でも多くの作業を離れた場所から進められます。

## 参画前に確かめたい「環境の準備」

BIの案件のリモート作業で詰まりやすいのは、技術より環境の準備です。次の点を参画前に確かめておくと、最初の数日を待ちで過ごすことを避けやすくなります。

### アカウントとライセンス

取引先の組織のアカウントを発行してもらうのか、外部のゲストとして招待されるのかで、使える機能や権限の申請の流れが変わります。

Power BIでは、ライセンスの種類によってできることが違います。Microsoft Learnでは、無料のライセンスでは自分用のコンテンツは作れても、他のユーザーとの共有や共同作業、他のワークスペースへの発行はできず、Proライセンスの利用者は他のPro利用者とコンテンツを共有して共同作業ができると説明されています（2026年10月時点）。作成と公開を担当する場合は、どのライセンスが割り当てられるのかを確かめておきましょう。ワークスペースでどの役割を与えられるかによっても、公開や権限の設定ができるかどうかが変わります。

### 作業する端末

貸与端末か、私物の端末を使えるか、仮想デスクトップ経由かで、作業の快適さが大きく変わります。Power BI DesktopはWindowsのアプリのため、普段Windows以外の端末を使っている場合は、作業環境の用意についても確認が必要です。

### データへの接続の経路

クラウドのDWHに直接つなげるのか、社内ネットワークのデータにゲートウェイ経由でつなぐのかで、自宅からできる作業の範囲が変わります。Power BI Report Serverを使ってレポートを社内に置いている現場では、社内の環境からの作業が前提になることもあります。

## 本番データを見ずに作る段取り

個人情報や売上の詳細を含むデータは、リモートで扱える範囲が限られることがあります。その場合でも、次の段取りで作業を進められることがあります。

- **開発用のデータを用意してもらう**：氏名などを置き換えたデータや、件数を絞ったデータで、モデルと画面を作る
- **数字の確認は集計値で行う**：明細を見るのではなく、合計や件数を旧帳票と突き合わせて確かめる
- **権限の確認は実際の利用者の立場で行う**：見える範囲の設定は、設定した本人の目線では確かめきれないことがある

最後の点について、Microsoft Learnでは、Power BIサービスの「ロールとしてテスト」機能は動的な行レベルのセキュリティの式を自分のIDで評価するため、外部のゲストユーザーに何が表示されるかは確かめられず、実際のゲストユーザーとしてサインインして確認するよう案内されています。外部の利用者に見せる画面では、確認の手順を取引先と決めておくことが大切です。

:::view
BIエンジニアの案件をご紹介していると、リモート中心の案件で評価されやすいのは、画面の確認を待たずに、試作を早めに見せて意見をもらう進め方ができる方です。利用者と顔を合わせる機会が少ないぶん、短い間隔で画面を共有し、指標の解釈のずれを早めに見つけられるかどうかが、作り直しの量を左右しやすい傾向があります。
:::

## リモート案件の探し方と確認点

案件を探すときは、「リモート可」の表示だけで判断せず、次の点を確かめましょう。案件票の読み方は[案件情報の読み方の記事](/media/project-info-read/)でも解説しています。

1. **出社の頻度と時期**：立ち上げ期だけ出社が多いのか、定例の会議に出る必要があるのか
2. **利用者とのやり取りの方法**：要望を直接聞けるのか、取引先の担当者を経由するのか
3. **アカウント・ライセンス・端末**：発行の時期、割り当てられるライセンス、使う端末
4. **データの扱い**：個人情報を含むか、開発用のデータがあるか、データを手元に保存してよいか
5. **更新の監視**：早朝の更新の失敗に誰が対応するのか、連絡の時間帯

フルリモートの働き方全般は[フルリモートの記事](/media/full-remote/)にまとめています。データの扱いの取り決めは[NDAの記事](/media/nda/)で確かめておくと安心です。

:::caution
画面の確認のためでも、取引先のデータを含むファイルや画面のスクリーンショットを、私物の端末や個人のクラウドの保存先に置くと、秘密保持の約束に反するおそれがあります。保存してよい場所と共有の方法は、参画の前に取引先のルールを確かめてください。
:::

## 時間帯と連絡の決めごと

BIの運用を含む案件では、利用者が画面を見る時間帯と、自分の作業時間がずれることがあります。たとえば、毎朝の始業前に更新が終わっている必要がある画面では、更新の失敗に気づくのが早朝になります。リモートで働く場合は、次の点を決めておくと、後から負担が増えにくくなります。

- 更新の失敗の通知を誰が受け取り、何時までに対応するのか
- 稼働日以外に失敗した場合の扱い
- 利用者からの問い合わせを、どの窓口で、どの時間帯に受けるのか
- 急ぎの修正を頼まれたときに、誰の判断で本番に反映するのか

チャットで直接利用者から依頼が届く形にすると、優先順位があいまいになりがちです。依頼は取引先の担当者を通して受ける、といった決めごとを最初に確認しておくと、作業の範囲を守りやすくなります。

## リモートで信頼を得るための工夫

離れた場所から働く場合は、作業の見えにくさを補う工夫が要ります。

- **変更の記録を残す**：どの計算式やページを、なぜ変えたかを短く残す
- **指標の定義を文書にする**：画面の数字が何を意味するかを、利用者が確かめられる形にする
- **確認してほしい点を絞る**：画面を共有するときは、見てほしい数字と判断してほしい点を先に伝える

- **会議の前に資料を配る**：画面の変更点や判断してほしい点を、会議の前日までに共有しておくと、短い会議でも結論が出やすい
- **問い合わせの答えを残す**：「この数字はなぜ違うのか」という問い合わせへの回答を記録しておくと、同じ質問に何度も答える手間が減り、利用者の信頼にもつながる

リモートでの進め方は、隣の職種でも事情が違います。データ基盤側の事情は[データエンジニアのリモート案件の記事](/media/data-engineer-remote/)、分析側の事情は[データアナリストのリモート案件の記事](/media/data-analyst-remote/)で整理しています。

:::view
当社では、案件をご案内するときに、先に稼働日数・リモートの希望・希望金額を伺い、合う案件だけをお出ししています。BIの案件は、立ち上げの時期と運用の時期で出社の頻度が変わることがあるため、期間ごとの働き方が分かりにくいときは、ご質問いただければ確認します。
:::

:::point
- BIエンジニアは、画面の追加・改修、モデルの改善、性能の改善を中心にリモートで進めやすい
- 要件の整理、定着支援、社内ネットワークのデータ接続、個人情報を含む画面の確認は条件しだい
- アカウント、ライセンス、端末、データへの接続の経路を参画前に確かめる
- 外部の利用者に見せる画面は、実際の利用者の立場での確認の手順を決めておく
:::

## よくある質問

### フルリモートのBIの案件はありますか？

あります。既存の環境で画面の追加やモデルの改善を担う案件は、フルリモートで進められることがあります。ただ、立ち上げの時期や、利用者向けの説明会がある時期だけ出社を求められることもあるため、期間ごとの働き方を確かめておきましょう。

### 自分のPower BIのライセンスを使って作業してもよいですか？

取引先の組織のデータやコンテンツを扱う場合は、取引先が用意するアカウントとライセンスで作業するのが一般的です。自分のアカウントにデータを取り込むと、データの持ち出しにあたるおそれがあります。迷う場合は、参画の前に取引先に確かめてください。

### 仮想デスクトップでの作業は不便ではありませんか？

画面の操作が多いBIの作業では、表示の遅れが気になることがあります。参画前に、仮想デスクトップの環境でBIツールを動かせるか、画面の大きさや操作の反応に問題がないかを確かめておくとよいでしょう。
