PM（プロジェクトマネージャー）としてフリーランスになるには、**プロジェクトの計画を自分で立て、遅延や品質の問題が起きたときに判断し、立て直した経験**が必要です。案件側が知りたいのは「PMをしていたか」より、「何を決め、その結果どうなったか」です。

独立の準備は、判断した場面の棚卸し、案件の型の見極め、スキルシートと面談の準備、お金と手続きの順に進めると無理がありません。

## PMの案件で問われるのは「判断した経験」

PMの案件では、進捗や課題を見える状態にするだけでなく、その情報をもとに優先順位や体制、スケジュールを変える判断が求められます。ここがPMOとの大きな違いです。PMOは判断の材料をそろえる役割、PMは材料をもとに決める役割と考えると整理しやすくなります（PMOとしての独立は[PMOがフリーランスになるには](/media/pmo-how-to/)で解説しています）。

振り返るときは、次のような「判断の場面」を書き出してみてください。

| 判断の場面 | 書き出す内容の例 |
|---|---|
| 計画づくり | スコープの切り方、フェーズの分け方、見積もりの根拠 |
| 遅延への対応 | 遅れに気づいた時点、取った手（要員追加・スコープ調整・リリース分割）と結果 |
| 品質の問題 | テストで不具合が多発したときの原因の見立てと手当て |
| 体制の変更 | メンバーやベンダーの入れ替え、役割分担の見直し |
| 予算・契約 | 追加費用の交渉、変更管理の進め方 |
| 経営層への報告 | 悪い知らせをいつ、どう伝え、何を決めてもらったか |

肩書きが「リーダー」「サブPM」でも、こうした判断を任されていたなら、その範囲を正確に書けばPMの経験として伝えられます。逆に、PMの肩書きでも判断は上司が行い、自分は報告をまとめていた場合は、PMOに近い経験として整理したほうが面談で食い違いが起きません。

### 規模と体制は数字で言えるようにする

PMの案件では、プロジェクトの規模がそのまま任せられる範囲の目安になります。期間、メンバーの人数、関わった会社の数、自分の直下にいたリーダーの人数などを、数字で言えるようにしておきます。予算の額は守秘の対象になりやすいため、「億円規模」などの幅で伝えるか、伏せたうえで体制の大きさで示します。

## フリーランスPMの案件の主な型

フリーランスのPM案件は、どちらの側に立つかで求められる動きが変わります。

| 案件の型 | 主な役割 | 見られやすい経験 |
|---|---|---|
| 発注側（ユーザー企業）のPM・PM支援 | 社内の要件をまとめ、ベンダーを管理する | 要件の取りまとめ、ベンダー選定や受け入れ判断 |
| 受託側（開発会社・SIer）のPM | 開発チームを率い、納期と品質に責任を持つ | 見積もり、開発チームの運営、顧客との調整 |
| 立て直し（炎上案件）のPM | 遅れたプロジェクトの現状を把握し、計画を引き直す | 短期間での状況把握、優先順位の再設定 |
| 自社サービス開発のPM | 社内チームの開発の進め方を整える | アジャイル開発の運営、リリース計画 |

発注側のPM案件では、社内の決裁ルートや業務部門の事情を短期間でつかむ力が問われます。受託側では、見積もりと実績のずれをどう管理したかが見られます。自分の経験がどちらの側に寄っているかを把握すると、応募する案件を絞りやすくなります。

### 外部のPMは「決める権限」の範囲を確かめる

フリーランスのPMは発注者の社員ではないため、予算の承認や人事に関わる判断は発注者側に残るのが一般的です。参画前に、どこまでを自分の判断で進めてよいか、誰に決裁を仰ぐかを確認しておくと、着任後に動きが止まりにくくなります。

:::view
案件紹介の現場では、PMの面談で「一番苦しかったプロジェクトで何をしたか」を問われることがよくあります。評価されやすいのは、遅れの原因をどう見立て、どの選択肢から何を選び、その結果どうなったかを順を追って話せる方です。うまくいかなかった判断も、何を学び、次にどう変えたかまで話せれば、経験として受け止められる傾向があります。
:::

## 独立前に積んでおきたい実績

会社員のうちに次の経験を意識して積んでおくと、独立後に任せてもらえる範囲が広がります。

1. **計画を一から作った経験**：既に動いているプロジェクトの引き継ぎだけでなく、立ち上げからWBSや体制を組んだ経験
2. **計画を変えた経験**：計画どおりに進まなかったときに、関係者の合意を取って計画を引き直した経験
3. **社外の関係者を動かした経験**：ベンダーや顧客など、指揮命令の及ばない相手と調整した経験
4. **報告の型を持つこと**：状況を短く伝える報告資料や会議の運び方を、自分のやり方として説明できること

資格は必須ではありませんが、知識を体系的に持っている裏付けになります。IPAのプロジェクトマネージャ試験は、組織の戦略の実現に寄与するシステム開発プロジェクトで、プロジェクトマネジメント業務を担う人を対象にした国家試験です。2026年度はCBT方式で後期に実施され、現行の試験制度は2026年度で終わり、2027年度から新しい制度に移る予定とされています（2026年10月時点、IPAの案内による）。

## 独立までの進め方

### 1. 判断の場面を棚卸しする

関わったプロジェクトごとに、期間、規模、体制、自分の役割に加えて、上の表のような「判断の場面」を1つ以上書き出します。手元のメモの段階では細かく書き、スキルシートに移すときに社名や固有の情報を伏せます。

### 2. スキルシートを用意する

PMのスキルシートでは、プロジェクトの概要より「自分が何に責任を持ち、何を決めたか」を先に読ませる書き方が伝わりやすくなります。基本の構成は[スキルシートの書き方](/media/skillsheet-basics/)、PM向けの書き方は[PMのスキルシートの記事](/media/pm-skillsheet/)で解説しています。

### 3. 条件を決めて案件を探す

PMは定例会や関係者との調整が多いため、週5日の稼働を前提とする案件が多い傾向があります。稼働日数、出社の頻度、希望する報酬の下限、得意な業界と開発手法を先に決めておくと、合わない案件に時間を使わずに済みます。報酬の決まり方は[PMの報酬の記事](/media/pm-rate/)、探し方は[フリーランスエージェントの使い方](/media/agent-how-to-use/)をご覧ください。

### 4. お金と手続きを準備する

退職後は健康保険・年金・住民税の切り替えが必要です。所得税の手続きとしては、事業を始めた年分の確定申告期限までに、納税地の税務署へ開業届を出すことになっています。青色申告をする場合、1月16日以降に開業した人は、事業開始日から2か月以内に承認申請書を出します（いずれも2026年10月時点、国税庁の案内による）。くわしくは[開業届の出し方](/media/kaigyo-todoke/)と[会社員からフリーランスになる手順](/media/quit-company-steps/)をご覧ください。

:::caution
PMの立場で前職の取引先から直接声がかかることがあります。退職時の誓約書や就業規則に、取引先との直接取引や競業を制限する定めがないか確認してください。判断に迷う場合は、弁護士などの専門家にご相談ください。
:::

## 契約で確かめておきたいPM特有の点

フリーランスのPMは、多くの場合、準委任契約で参画します。準委任ではプロジェクトの成功そのものではなく、PMとしての業務を専門家として通常求められる注意を払って行うことが約束の中身になります。契約の違いは[準委任契約と請負契約の違い](/media/junin-vs-ukeoi/)で解説しています。

PMならではの確認点は次のとおりです。

- **業務の範囲と権限**：計画の変更やベンダーへの指示をどこまで任されるか
- **責任の範囲**：プロジェクトの遅延そのものの責任を負う書き方になっていないか
- **稼働の幅**：障害対応やリリース作業で時間が延びたときの精算方法
- **契約期間**：プロジェクトのフェーズの区切りと、契約の更新時期が合っているか

フリーランス法では、発注側は業務を委託したとき、業務の内容、報酬の額、支払期日などを書面またはメールなどで直ちに明示する必要があります。また、6か月以上継続して委託している契約を解除したり更新しなかったりする場合は、原則として30日前までの予告が必要です（公正取引委員会の案内による）。

:::view
当社では、案件をご案内する前に稼働日数・リモートの可否・希望金額を伺い、条件に合う案件だけをお出ししています。経歴は、ご了承いただいた案件にだけ、氏名・連絡先を伏せてご提案します。契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししていますので、PMとしての権限の範囲など気になる点はご質問いただければ確認します。
:::

:::point
- PMの独立には、計画を立て、問題が起きたときに判断して立て直した経験が必要
- 発注側・受託側・立て直しなど、案件の型によって見られる経験が違う
- 契約では、業務の範囲と権限、責任の範囲、稼働の幅を確かめる
:::

## よくある質問

### PMOの経験しかなくてもフリーランスのPMになれますか？

PMOとして判断の材料をそろえていた経験は、PMの仕事の土台になります。ただし、PM案件では自分で決めた経験が問われるため、最初はPMOやPM補佐の案件で参画し、判断を任される範囲を広げていく進め方が現実的です。PMOの経験の中に、自分の提案で計画が変わった場面があれば、具体的に整理しておきましょう。

### 開発の経験が浅くてもPM案件に参画できますか？

参画できる案件はあります。発注側のPM支援や業務改革のプロジェクトでは、技術の深さより業務の理解と調整の力が重視されることがあります。一方、受託側の開発PMでは、見積もりや技術的なリスクの判断が求められるため、開発の経験が見られやすくなります。

### 炎上案件のPMは引き受けないほうがよいですか？

一概には言えません。立て直しの経験は評価されやすい一方、稼働が想定より増えやすく、負担が大きくなりがちです。引き受ける場合は、現状の把握にかける期間、自分の権限、稼働の上限と精算方法を、参画前に確認しておくことをおすすめします。
