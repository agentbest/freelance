Oracle ERPコンサルの案件で問われるのは、**担当領域の業務の流れを理解したうえで、Oracle Fusion Cloud ERPやE-Business Suite（EBS）の設定に置き換え、データ移行・帳票・連携まで見通し、更新やパッチの影響を判断できること**です。どの分野をどの深さで求めるかは、製品と案件の型で変わります。

この記事では、スキルを分野ごとに分け、経験の段階ごとに案件で期待される水準を整理します。独立までの道筋は[Oracle ERPコンサルがフリーランスになるには](/media/oracle-erp-how-to/)で扱っています。

## 分野1：担当領域の業務の流れ

Oracle ERPの機能コンサルは、領域ごとに担当が分かれます。財務（総勘定元帳、買掛金、売掛金、固定資産、資金管理）、調達、プロジェクト管理、サプライチェーンなどです。どの領域でも、次のような「流れ」を説明できることが土台になります。

- **財務**：取引から仕訳が作られ、元帳に集まり、締めと報告に至るまで
- **調達から支払**：購買依頼、発注、検収、請求書の照合、支払まで
- **受注から入金**：受注、出荷、請求、入金の消込まで

会計や財務の専門的な論点（決算の早期化、管理会計の設計など）を深く問われる案件は、財務・経理コンサルタントの領域と重なります。Oracle ERPの案件では、その論点を**製品のどの機能で受け、データがどこからどこへ流れるか**に置き換えて説明できるかが見られます。

## 分野2：製品の設定

### Fusion Cloud ERP

Fusionでは、法人、元帳、事業単位などの組織の構造をどう作るかが、後から変えにくい土台になります。導入案件では、この構造の設計と、勘定科目の体系、承認の流れ、権限（ロール）の設計に関わった経験が問われます。設定は画面から行う部分が多く、標準機能で業務を回す前提で議論が進みます。そのため、利用部門の要望を聞いたときに、標準機能のどこで受けられそうか、運用の工夫で足りるかをその場で見立てられる力が、設定の手の速さ以上に評価されます。

### EBS

EBSでは、長年の運用で積み重なった設定と、独自に作られたアドオン（追加開発の帳票、インターフェース、画面）を読み解く力が求められます。保守の案件では、問い合わせの原因が設定なのか、アドオンなのか、データなのかを切り分けられることが重要です。EBS 12.2は2026年10月時点でも新しい版が提供されており、Oracleの案内ページには12.2.13〜12.2.15の新機能資料が並んでいます。リリースによって使える機能が違うため、担当した環境のリリースを把握していることも前提になります。

## 分野3：データ移行・帳票・連携

機能コンサルでも、次の3つには関わる場面が多くあります。

| 分野 | Fusionで問われやすいこと | EBSで問われやすいこと |
|---|---|---|
| データ移行 | 決められたテンプレートでの取り込み、取り込みエラーの読み方、移行後の照合 | 移行元としてのデータの抽出と整理、残高の照合 |
| 帳票・レポート | 標準のレポート機能で何が出せるか、足りない帳票をどう補うか | 既存の帳票の仕様の理解、改修の仕様 |
| 連携 | 外部システムとの連携の方式と頻度、エラー時の運用 | 既存のインターフェースの仕様とバッチの流れ |

EBSの案件では、SQLで本番データを確かめられる、PL/SQLで書かれたアドオンの処理を追えるといった力があると、開発者を待たずに原因を絞り込めます。技術の深さは案件によって違うため、どこまで自分でできるかを面談ではっきり伝えることが大切です。

## 分野4：更新・パッチへの対応

Fusionは四半期ごとに更新され、2026年10月時点では財務領域の「26D」の新機能資料が公開されています。Oracleのドキュメントでは、テスト環境は本番環境に同じメンテナンスを当てる前の検証にも使うと説明されています。運用案件では、次の流れを回せることが求められます。

1. 新機能資料を読み、自社の業務に影響する変更を洗い出す
2. 新しい機能を使うかどうかを利用部門と決める
3. テスト環境で主要な業務を流し、結果を記録する
4. 本番の更新後に問い合わせに備える

EBSでは、パッチの適用やバージョンアップの際に、アドオンへの影響を確かめる作業が同じ役割を持ちます。

:::view
Oracle ERPの案件紹介の現場では、面談で「標準機能で足りなかった要件を、どう扱ったか」を聞かれる場面をよく見ます。評価されやすいのは、アドオンを作った話だけでなく、業務側の運用を変えて標準機能に合わせた例や、作らずに済ませた判断の理由まで話せる方です。Fusionの案件では、更新を前提にした運用を意識しているかどうかも見られます。
:::

## 分野5：権限・統制とやり取りの力

### 権限と承認の設計

ERPでは、誰がどの取引を入力し、誰が承認できるかが統制の土台になります。Oracle ERPの案件では、職務に応じて権限を分け、承認の流れを設定し、利用部門や監査の担当者に説明する場面があります。権限の設定は後から直すと影響が広いため、要件定義の早い段階で論点として挙げられる人は重宝されます。

### 関係者とのやり取り

Oracle ERPの機能コンサルは、利用部門、開発チーム、基盤の担当、場合によってはOracleのサポートとの間に立ちます。それぞれに求められる伝え方は違います。

- **利用部門へ**：画面や設定の名前ではなく、業務の手順がどう変わるかで伝える
- **開発チームへ**：アドオンや連携の仕様を、入力・処理・出力と例外の扱いまで書いて渡す
- **Oracleのサポートへ**：再現の手順、環境、発生した日時、影響の範囲を整理して問い合わせる（英語でのやり取りになることもある）

技術の深さが同じでも、このやり取りが円滑な人ほど、領域のリードを任されやすくなります。

## 経験の段階ごとに期待される水準

| 段階 | 主な役割 | 期待されること |
|---|---|---|
| 設定・テスト担当 | 決まった要件に沿った設定、テストの実施 | 担当領域の設定を一人で進め、テスト結果を記録して説明できる |
| 領域の担当者 | 一つの領域の要件定義から稼働まで | 利用部門と話して要件を決め、データ移行と本番稼働まで見通せる |
| 領域のリード | 複数の担当者のまとめ役 | 領域をまたぐつなぎ目の設計、課題の優先順位づけ、他チームとの調整 |
| 移行・全体のリード | EBSからFusionへの移行方針、全体の設計 | 現状の設定とアドオンの棚卸し、置き換えの方針、移行の段取りの判断 |

段階が上がるほど、設定の手数より、判断の理由を説明する力が重くなります。上流への進み方は[上流工程の案件に入るために必要な経験](/media/upper-process/)で解説しています。

### あると評価されやすい経験

- **領域をまたいだ統合テスト**：調達から支払、受注から入金までを通しで確かめた経験
- **本番稼働直後の対応**：最初の締めや支払処理で起きた問い合わせを裁いた経験
- **英語での作業**：英語の資料やOracleのサポートとのやり取り、海外拠点との会議
- **周辺製品の知識**：経営管理（予算・連結）や人事など、ERPとつながる製品の基本

:::caution
「Oracle」の経験として、データベースの構築・運用とERPの機能コンサルの経験を同じ欄にまとめると、読み手が判断を誤ります。ORACLE MASTERはデータベースの資格で、ERPの機能の資格ではありません。データベースの資格の扱いは[ORACLE MASTERの記事](/media/cert-oracle-master/)で解説しています。
:::

## スキルシートと面談で伝えたいこと

スキルは、「製品とリリース」「領域」「工程」「自分が決めたこと」をセットで伝えると、案件側が判断しやすくなります。SQLやデータ移行の技術は、何をどこまで自分でできるかを具体的に書きます。書き方の例は[Oracle ERPコンサルのスキルシートの記事](/media/oracle-erp-skillsheet/)で、報酬への表れ方は[報酬の記事](/media/oracle-erp-rate/)で扱っています。

:::view
当社では、ご経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。Oracle ERPの案件は、同じ「財務」でも求める領域や製品が案件ごとに違います。製品・領域・工程を分けて整理しておくことをおすすめします。案件で求められている領域や技術の深さは、ご質問いただければ確認します。
:::

:::point
- 土台は担当領域の業務の流れ。それを製品の機能とデータの流れに置き換えて説明できるかが見られる
- Fusionは組織構造・権限・標準機能での運用、EBSは既存の設定とアドオンを読み解く力が問われる
- データ移行・帳票・連携と、四半期アップデートやパッチへの対応は、機能コンサルにも求められる
:::

## よくある質問

### 機能コンサルでもSQLは必要ですか？

案件によります。EBSの保守では、SQLで本番データを確かめられると原因の切り分けが早くなり、評価されやすくなります。Fusionの案件では画面やレポート機能で確かめる場面が多くなります。どこまで自分でできるかを正直に伝えるのが大切です。

### Fusionの経験がなくてもFusionの案件に入れますか？

EBSで同じ領域を担った経験があれば、業務の理解は生きます。ただし組織の構造や設定の進め方は製品ごとに違うため、Fusionの考え方を学んでおくと面談で説明しやすくなります。学んだ内容は、触れた範囲と合わせてスキルシートに書き分けましょう。

### 調達や販売の経験だけでも案件はありますか？

あります。Oracle ERPの案件は領域ごとに担当が分かれることが多く、調達や受注から入金の領域に絞った募集もあります。財務とのつなぎ目（請求書の照合や入金の消込）を説明できると、任される範囲が広がります。
