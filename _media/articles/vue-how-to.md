Vue.jsエンジニアがフリーランスになるには、**Vue 3とTypeScriptで画面を作れることに加えて、運用中の画面を保守・移行した経験と、API側の開発者と仕様を詰めた経験**が必要です。Vue.jsの案件は、新しく作るより既存のサービスを改善する仕事が多く、古い書き方のコードを読み、少しずつ直していける人が求められます。

独立の準備は、経験の棚卸し、足りない経験の補強、見せられる成果物の用意、手続きとお金の準備の順に進めます。この記事では、Vue.jsの現場ならではの事情に絞って説明します。

## Vue.jsの案件で多い現場

Vue.jsは、PHP（Laravel）やRuby on Railsのバックエンドと組み合わせて使われることが多く、管理画面や業務向けのWebアプリでもよく採用されています。案件は次のような型に分かれます。

| 現場の型 | 主な仕事 | 特に見られる経験 |
|---|---|---|
| 運用中サービスの機能追加 | 既存の画面に機能を足し、使い勝手を直す | 既存コードの読解、コンポーネントの切り出し |
| Vue 2からVue 3への移行 | 古い書き方の画面を新しい版へ移す | 両方の書き方の理解、段階的な置き換えの計画 |
| Nuxtでのサイト・サービス開発 | 表示の速さや検索に配慮した画面を作る | サーバー側での描画、ルーティング、デプロイ |
| 管理画面・業務アプリ | 入力フォームや一覧画面を数多く作る | フォームの検証、表の操作、権限による出し分け |
| バックエンドとの兼任 | LaravelやRailsと画面の両方を担う | API設計、データベースの基本 |

バックエンドと兼ねる案件は数が多く、画面だけでなくAPIも触れる人は選べる案件が広がります。RailsやPHPの側の準備は[Rubyエンジニアがフリーランスになるには](/media/ruby-how-to/)と[PHPエンジニアがフリーランスになるには](/media/php-how-to/)も参考になります。

## 独立前に積んでおきたい経験

### Vue 2からVue 3への移行

Vue 2は2023年12月31日にEOL（サポート終了）を迎え、その後はセキュリティやブラウザ対応の修正も含めて更新されていません。Vue 2で作られたNuxt 2も、2024年6月30日にEOLを迎えています（いずれも2026年10月時点の公式の案内による）。

それでも、Vue 2のまま動いているサービスは残っており、移行は業務委託に任されやすい仕事です。次のような点に自分が関わったかを整理しておきましょう。

- Options APIで書かれた画面を、Composition APIへ書き換えた経験
- 状態管理をVuexからPiniaへ移すなど、周辺ライブラリの置き換え
- 一度にすべてを移さず、画面ごとに移してリリースした進め方

### TypeScriptでの開発

新しいVue.jsの開発では、TypeScriptを使うのが一般的になっています。APIから受け取るデータの型を定義し、コンポーネントの入出力に型を付けた経験があると、チームでの開発に入りやすくなります。TypeScriptの準備は[TypeScriptエンジニアがフリーランスになるには](/media/typescript-how-to/)でも扱っています。

### APIの仕様を詰める経験

画面の開発は、バックエンドから受け取るデータの形に左右されます。「この画面に必要な項目」「エラーのときに返す内容」を、バックエンドの開発者と相談して決めた経験は、面談でも話題にしやすい実績です。

### テストと品質の仕組み

Vitestなどでコンポーネントのテストを書いた経験や、ESLintでの書き方の統一、CIでの自動チェックの運用があると、チームで品質を保てる人として見てもらえます。

:::view
Vue.jsの案件をご紹介していると、画面をきれいに作れることに加えて、「古い書き方のコードをどう扱ったか」を具体的に話せる方が評価されやすい傾向があります。Vue 2のコードを読めること、移行のときに何を残し何を書き換えたかを説明できることは、運用中のサービスに入る案件で大きな材料になります。面談の前に、担当した画面と、移行や改修の判断を整理しておくことをおすすめします。
:::

## Reactの経験とどう組み合わせるか

フロントエンドの案件では、Vue.jsとReactの両方を条件に挙げる募集や、どちらかの経験があればよいとする募集もあります。

| 状況 | 考え方 |
|---|---|
| Vue.jsの経験が中心 | Vue.jsの案件に絞り、移行や設計の経験で差をつける |
| Reactの経験もある | 両方に応募できる。経歴ではそれぞれの担当範囲を分けて書く |
| Vue.jsの経験が浅い | JavaScriptとTypeScriptの基礎、コンポーネント設計の考え方を示す |

フレームワークが違っても、コンポーネントの分け方や状態の持ち方の考え方は共通する部分があります。Reactの準備は[Reactエンジニアがフリーランスになるには](/media/react-how-to/)で解説しています。

## 独立までの進め方

### 1. 画面とサービスごとに経験を書き出す

関わったサービスごとに、期間、チームの人数、担当した画面や機能、Vue.jsとNuxtの版、状態管理やUIライブラリ、組み合わせたバックエンドを書き出します。版の書き分けは特に大切で、「Vue 2での保守」と「Vue 3での新規開発」では、合う案件が違います。

### 2. 公開できる成果物を用意する

会社の案件は守秘義務で画面を見せられないことがあります。GitHubに置いたVue 3とTypeScriptの小さなアプリなど、コードの書き方が分かる成果物があると、経験の補いになります。見た目より、コンポーネントの分け方とテストが伝わる形を意識します。

### 3. スキルシートと条件を整える

書き方は[Vue.jsのスキルシートの記事](/media/vue-skillsheet/)と[スキルシートの基本](/media/skillsheet-basics/)をご覧ください。稼働日数、リモートの希望、報酬の下限も決めておきます。報酬の決まり方は[Vue.jsの報酬の記事](/media/vue-rate/)、求められるスキルは[Vue.jsの案件で求められるスキルの記事](/media/vue-skills/)で扱っています。

### 4. 案件を探して面談を受ける

フリーランスエージェント（案件紹介サービス）、知人の紹介、発注元との直接契約などの方法があります。使い方は[フリーランスエージェントの使い方](/media/agent-how-to-use/)で解説しています。

## 面談でよく問われること

1. **使ってきた版と書き方**：Vue 2とVue 3、Options APIとComposition APIのどちらで書いたか
2. **コンポーネント設計**：どの単位で分け、状態をどこに持たせたか
3. **表示の速さへの対応**：重い画面をどう調べ、どう直したか
4. **バックエンドとの連携**：APIの仕様をどう決め、食い違いをどう解消したか
5. **デザイナーとのやり取り**：デザインのデータからどこまで自分で判断したか

:::caution
移行の案件では、「Vue 3に上げる」という目標だけが決まっていて、どこまでを終わりとするかがあいまいなことがあります。周辺ライブラリの置き換えやテストの追加まで含むかで作業量は大きく変わります。参画前に、範囲と完了の考え方を確かめておきましょう。
:::

## 独立前後の手続きと契約

会社を辞めて独立する場合は、次の手続きが必要です（2026年10月時点の公的な案内による）。

| 手続き | 期限・内容 | 窓口 |
|---|---|---|
| 国民年金への切り替え | 退職日の翌日から14日以内 | 住所地の市区町村 |
| 健康保険の切り替え | 国民健康保険への加入か、任意継続を選ぶ | 市区町村・加入していた健康保険 |
| 開業届 | 事業を始めた年分の確定申告期限まで | 納税地の税務署 |
| 青色申告承認申請書 | 1月16日以後に開業した場合は開業日から2か月以内 | 納税地の税務署 |

手順の全体は[会社員からフリーランスになる手順](/media/quit-company-steps/)、開業届は[開業届の出し方](/media/kaigyo-todoke/)で解説しています。税金や保険の判断に迷う場合は、税理士や窓口にご相談ください。

2024年11月に施行されたフリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容・報酬の額・支払期日などを書面やメールなどで明示することとされています。画面だけか、APIまで担当するかなど、業務の内容が面談で聞いた内容と合っているかを確かめましょう。

:::view
当社では、案件をご案内する前に、稼働日数・リモートの希望・希望金額を伺い、合う案件だけをお出ししています。経歴は、ご了承いただいた案件にだけ、氏名・連絡先を伏せて提案しています。業務の範囲・報酬・支払期日・契約期間は個別契約に書いてお渡ししています。
:::

:::point
- Vue.jsの独立では、Vue 3とTypeScriptでの開発に加え、既存の画面を保守・移行した経験が大切

- 移行の案件は、範囲と完了の考え方を参画前に確かめる

## よくある質問

### Vue 2の経験しかなくても独立できますか？

Vue 2で画面を作ってきた経験は、保守や移行の案件で生かせます。ただ、新しい開発はVue 3で進むことが多いため、独立前にComposition APIとTypeScriptで小さなアプリを作っておくと、参画できる案件が広がります。

### バックエンドの経験も必要ですか？

画面だけの案件もありますが、LaravelやRailsと組み合わせる現場では、APIやデータベースの基本が分かる人のほうが選べる案件が多くなります。すべてを担える必要はなく、APIの仕様を一緒に考えられる程度の理解があると役立ちます。

### デザインのスキルはどこまで必要ですか？

多くの案件では、デザイナーが作ったデータをもとに画面を作ります。デザインを一から作る力より、デザインの意図をくみ取り、足りない状態（読み込み中・エラーなど）を相談して決められることが求められます。
