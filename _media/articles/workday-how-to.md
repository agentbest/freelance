Workdayコンサルとしてフリーランスになるには、**Workdayのテナント（利用企業ごとの環境）で自分で構成を行い、導入や運用のプロジェクトで工程を担った経験**が必要です。案件では「Workdayを使ったことがある」ではなく、どの機能を、どの工程で、どこまで自分で決めて設定したかが細かく確認されます。

独立の準備は、担当した機能と工程を表にして棚卸しし、経歴の入口に合った最初の案件の型を選ぶことから始めます。この記事では、必要な経験の目安と、独立までの進め方を整理します。

## Workdayの経験者はどこから来ることが多いか

Workdayの経験を積む場所は限られています。主な入口は次の3つで、それぞれ独立前に補いたい点が違います。

| 経歴の入口 | 強み | 独立前に補いたい点 |
|---|---|---|
| 導入を担う会社のコンサルタント | 複数社の導入経験、構成の手数 | 稼働後の運用で起きる問題への対応の経験 |
| 利用企業のWorkday担当（管理者） | 本番環境の運用、組織変更・制度変更への対応 | 新規導入の工程、他社の業務に合わせる経験 |
| 他の人事・会計システムの導入経験者 | 導入プロジェクトの進め方、業務知識 | Workdayの構成を自分で行った経験そのもの |

三つ目の入口の方は、Workdayの経験がまだ短い段階で独立すると、参画できる案件が限られます。社内でWorkdayの案件に一度入り、構成を自分の手で行った経験を作ってから独立するほうが、最初の案件を選びやすくなります。

## 経験は「機能 × 工程」の表で棚卸しする

Workdayの経験は、領域が広いため言葉で並べるだけでは伝わりにくくなります。担当した機能と工程を表にして、経験の厚い部分と薄い部分を見える状態にしておきましょう。

| 機能 | 要件の整理 | 構成 | データ移行 | テスト | 稼働・運用 |
|---|---|---|---|---|---|
| 組織・ポジション・従業員の基本情報 | | | | | |
| ビジネスプロセス（承認の流れ） | | | | | |
| セキュリティ（権限の設計） | | | | | |
| 報酬・評価・タレント | | | | | |
| 勤怠・休暇 | | | | | |
| 会計の基本構成・経費・購買 | | | | | |
| カスタムレポート・計算項目 | | | | | |
| 連携（EIB・コネクタ・Studio など） | | | | | |

担当した欄には「◯」、一部を担当した欄には「△」を書き込んでみてください。すべてを埋める必要はありません。案件側は、どの機能を自分で構成し、どの機能は会話ができる程度かという区別を知りたいと考えています。

### 独立の目安になる経験

明確な基準はありませんが、次の経験がそろうと、独立後に参画できる案件の幅が広がります。

1. **一つ以上の機能を、要件の整理から稼働まで通して担った経験**：途中の工程だけでなく、始めから終わりまでを一度経験していること
2. **ビジネスプロセスとセキュリティを自分で構成した経験**：どの機能を担当しても関わることになる土台の部分
3. **稼働後の問い合わせや構成変更に対応した経験**：本番環境で起きる問題を切り分けた経験
4. **利用企業の担当者と要件を詰めた経験**：人事部門や経理部門の言葉で話し、合意を取った経験

## 認定の位置づけ

Workdayには「Workday Pro」と呼ばれる認定があり、Workday Communityの公開ページでは、HCM、Financials、Integrations、Reporting and Analyticsなど製品領域ごとに認定が並び、推奨の講座と必須の試験で構成されると説明されています。パートナー向けの認定（Services Certifications）については、別のページを案内しています（いずれも2026年10月時点）。

また、Workdayの公式サイトでは、Workday Pro Platform Administratorの認定を、利用企業だけでなく「Everyone」向けとして、Learn with Workdayの講座とあわせて案内しています（2026年10月時点）。

認定は経験を補う材料になりますが、フリーランスの案件では、実際にどの機能をどこまで構成したかが重視されます。受験の条件や対象は所属や時期によって変わることがあるため、Workdayの公式ページで最新の内容を確かめてください。

:::view
Workdayの案件紹介の現場では、面談で「そのビジネスプロセスの承認の流れは、誰とどう決めたのか」と問われる場面をよく見ます。評価されやすいのは、設定の画面を説明するより、人事部門のどんな要望を、どの構成でどう実現し、テストで何を確かめたかを順に話せる方です。利用企業で運用を担ってきた方も、組織変更のたびに何を見直したかを具体的に話せると、導入の案件を検討するきっかけになることがあります。
:::

## 最初の案件の型を選ぶ

独立して最初の案件は、これまでの経験と重なりが大きい型を選ぶと、参画後に力を出しやすくなります。

| 案件の型 | 主な作業 | 向いている経歴 |
|---|---|---|
| 導入プロジェクトの構成担当 | 決まった設計に沿った構成、単体テスト | 導入を担う会社での構成経験 |
| 利用企業側のプロジェクト支援 | 要件の取りまとめ、導入側の設計の確認、受け入れテスト | 利用企業の管理者、他システムの導入経験 |
| 運用・保守 | 問い合わせ対応、組織変更・制度変更に伴う構成変更 | 利用企業の管理者経験 |
| 連携・レポートの専任 | 連携の構築・改修、カスタムレポートの作成 | 開発やデータの経験 |

報酬の決まり方は[Workdayコンサルの報酬の記事](/media/workday-rate/)で解説しています。

### 面談で確かめられやすいこと

最初の案件の面談では、次のような点を具体的に聞かれることが多くあります。独立前に、自分の言葉で答えられるようにしておきましょう。

- 構成した機能と、その機能で自分が決めたこと
- 標準の機能で足りなかった要件を、どう扱ったか（運用で補った、構成を工夫した、利用企業と要件を見直した、など）
- テストで見つけた問題と、その原因の切り分け方
- 稼働後に起きた問い合わせと、構成をどう直したか

答え方の準備は、面談全般の記事[よく聞かれる質問](/media/interview-questions/)も参考になります。

### 守秘義務と個人情報の扱いに慣れておく

Workdayは従業員の個人情報や給与、会計の情報を扱うため、参画時に守秘義務契約や情報の取扱いの誓約を求められるのが一般的です。会社員時代の資料を持ち出さないこと、案件で知った情報を次の案件の説明に使うときは特定されない形にすることを、独立前から習慣にしておきましょう。秘密保持の考え方は[NDAの記事](/media/nda/)で解説しています。

## 独立前に会社員のうちにしておくこと

- **経歴の棚卸し**：上の表を埋め、プロジェクトごとに担当した機能と工程を書き出す
- **スキルシートの作成**：書き方は[Workdayのスキルシートの記事](/media/workday-skillsheet/)を参照
- **学習の習慣**：担当領域のリリースの内容を読み、自分の経験した構成にどう影響するかを考える習慣をつける。独立後は、社内の勉強会のような機会がなくなるため、自分で情報を追う必要があります
- **資金の準備**：最初の報酬が入るまでの数か月分の生活費と、事業の立ち上げにかかる費用
- **退職の段取り**：引き継ぎの期間と有給休暇の消化を見込んで、参画の開始日を決める。手順は[会社を辞めてフリーランスになるまでの手順](/media/quit-company-steps/)にまとめています

税金の扱いは個別の事情で変わるため、判断に迷うときは税理士にご相談ください。

:::caution
Workdayの経験が短いうちに独立すると、「Workday可」とされた周辺の案件（データ移行の作業だけ、操作手順書の作成だけなど）に偏り、構成の経験が増えないことがあります。最初の案件では、自分で構成やテストを担える範囲が含まれているかを確かめておくと、次の案件につながる経験を積みやすくなります。
:::

:::view
当社では、ご経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。Workdayの案件は、領域や立場によって求められる経験が大きく違うため、機能と工程の表を作っておくと、合う案件を選びやすくなります。どの案件の型に経験が合うか迷う場合は、ご質問いただければ確認します。
:::

:::point
- 必要なのは、テナントで自分で構成し、導入や運用の工程を担った経験
- 経歴の入口（導入側・利用企業側・他システム）ごとに、独立前に補う点が違う
- 認定は経験を補う材料。案件では実際に構成した範囲が重視される
:::

## よくある質問

### Workdayの経験は何年あれば独立できますか？

年数の決まりはありません。目安になるのは、一つ以上の機能を要件の整理から稼働まで通して担い、ビジネスプロセスとセキュリティを自分で構成した経験があるかどうかです。年数が短くても、通しで担った経験を具体的に話せれば参画できる案件はあります。

### 認定を持っていないと案件に参画できませんか？

認定の有無を条件に挙げる案件もありますが、条件にしていない案件もあります。案件の条件の欄で確かめ、認定がない場合は、構成した機能と工程を具体的に示すことが大切です。受験の対象や条件は、Workdayの公式ページで最新の内容をご確認ください。

### 利用企業の管理者の経験だけでも独立できますか？

運用・保守や、利用企業側のプロジェクト支援の案件で経験が生きます。新規導入の構成担当を目指す場合は、他社の業務に合わせて一から構成した経験が問われるため、まずは経験に近い型の案件から始めると進めやすくなります。
