他の職種からNext.jsエンジニアを目指すなら、**ReactとTypeScriptで画面を書ける状態を土台に、サーバーで動く部分とブラウザで動く部分の境目、データの取得と更新、キャッシュと描画方式の順に身につける**のが近道です。出発点によって、すでに持っている部分と足りない部分が大きく違うため、自分の経験に合わせて埋める順番を決めます。

この記事では、出発点ごとに生かせる経験と足りない部分を整理し、埋める順番、面談で確かめられやすいこと、年代によるルートの違いを解説します。独立の手順そのものは[Next.jsエンジニアがフリーランスになるには](/media/nextjs-how-to/)で扱っています。

## Next.jsエンジニアに求められることを先に押さえる

Next.jsの案件で問われるのは、Reactで画面を書く力に加えて、**サーバーをまたぐ判断**ができるかです。具体的には次の5つです。

| 分野 | 中身 |
|---|---|
| 構成 | Server ComponentsとClient Componentsの境目をどこに引くか |
| データ | データをどこで取り、更新後の表示をどう新しくするか |
| 描画とキャッシュ | ページごとに、事前に作るか、リクエストのたびに描くか、何をキャッシュするか |
| 安全性 | Server Actionsなどサーバー側の入口で、権限と入力を確かめられるか |
| 配信 | どこにどう配信し、版上げや更新をどう回すか |

Next.js 16.4の公式ブログでは、Cache Componentsがすべてのアプリに勧められ、新しく作るアプリでは最初から有効になっています（2026年10月時点）。これから学ぶ人は、新しい考え方を前提にしつつ、既存のアプリで多い以前の書き方も読めるようにしておくと、入れる案件が広がります。スキルの全体像は[Next.jsの案件で求められるスキル](/media/nextjs-skills/)で詳しく整理しています。

## 出発点ごとの生かせる経験と足りない部分

| 出発点 | 生かせる経験 | 足りなくなりやすい部分 |
|---|---|---|
| Reactエンジニア | 部品の設計、状態の管理、画面のテスト | サーバー側での取得と更新、キャッシュ、配信 |
| バックエンドエンジニア | データベース、認証、APIの設計、権限の確認 | Reactの部品の考え方、画面の操作感、CSS |
| マークアップ・Webデザイン | HTMLとCSS、見た目の再現、アクセシビリティ | JavaScriptとTypeScript、データの流れ |
| インフラ・クラウド | 配信、CDN、コンテナ、監視 | 画面の実装全般 |

### Reactエンジニアから目指す

もっとも近い出発点です。部品の分け方や状態の扱いはそのまま使えます。足りなくなりやすいのは、**データの取得をサーバー側に寄せる発想**です。React単体の開発では、画面を表示してからブラウザでデータを取るのが普通でしたが、App Routerでは画面を描く前にサーバーで取るのが基本になります。何でも`'use client'`にしてしまう癖を直し、ブラウザで動かす必要がある部品だけを分ける練習から始めてください。Reactの側から見た広げ方は[Reactエンジニアのキャリアチェンジの記事](/media/react-career-change/)でも触れています。

### バックエンドエンジニアから目指す

Node.jsやPHP、Ruby、Javaでサーバー側を作ってきた人は、App Routerの「サーバーで描く」考え方になじみやすい立場です。データベースへの問い合わせ、認証、権限の確認の経験は、Next.jsの安全性の面で強みになります。Next.jsの公式ブログは、Server Actionsは外から呼び出せる入口になるため、関数の中で権限と引数を確かめるよう説明しています。この感覚は、APIを作ってきた人ほど早く身につきます。

足りなくなりやすいのは、Reactの部品の考え方と画面の操作感です。読み込み中の表示、入力の途中の状態、エラーの見せ方など、利用者が触る部分の作り込みを意識して学ぶ必要があります。

### マークアップ・Webデザインから目指す

HTMLとCSSで見た目を正確に作れる力は、Next.jsの案件でも評価されます。足りないのは、JavaScriptとTypeScriptでデータを扱う力です。いきなりNext.jsの全体を学ぶより、TypeScriptとReactを先に固め、部品に値を渡して画面を組み立てられるようになってからNext.jsに進むほうが、つまずきにくくなります。TypeScriptの身につけ方は[TypeScriptエンジニアのキャリアチェンジの記事](/media/typescript-career-change/)が参考になります。

### インフラ・クラウドから目指す

配信先やCDN、コンテナの知識は、Next.jsの配信や性能の改善で生きます。画面の実装の経験が少ないため、まずは画面を一通り作れるようになることが先です。そのうえで、配信と画面の両方が分かる人として、立ち上げや配信先の見直しの案件を狙うルートがあります。

:::view
案件紹介の現場では、他の職種からNext.jsに移った方が評価されやすいのは、前の職種の経験を「Next.jsのどの判断に効くか」で説明できる場合です。たとえばバックエンド出身なら「Server Actionsで権限を確かめる書き方」、インフラ出身なら「配信先とキャッシュの組み合わせ」のように結び付けて話せると、任せる範囲を判断してもらいやすくなります。
:::

## 足りない部分を埋めるときの順番

出発点を問わず、次の順で埋めると、途中で迷いにくくなります。

1. **TypeScriptとReactで画面を書ける**：部品に値を渡し、状態を扱い、フォームを作れる
2. **App Routerで境目を引ける**：ページとレイアウトの仕組み、Server ComponentsとClient Componentsの分け方
3. **データの取得と更新ができる**：サーバー側で取得し、Server Actionsで更新し、更新後の表示を新しくする
4. **描画方式とキャッシュを判断できる**：事前に作るページとリクエストのたびに描くページを分け、キャッシュする範囲を決める
5. **安全性を点検できる**：権限の確認、ブラウザに渡すデータの絞り込み、環境変数の扱い
6. **配信と版上げを回せる**：どこにどう配信するか、公式のサポート方針を見ながら版をどう上げるか

公式のサポート方針では、2026年10月時点で16.xがActive LTS、15.xがMaintenance LTSで、14.x以前はサポート外とされています。学ぶなら今の版で始め、仕事で出会う古い版は「違いを読める」ところまで押さえておくと十分です。

学んだことは、公開できる小さなアプリにまとめておくと、面談で手を動かせることを示す材料になります。成果物の見せ方は[GitHubとポートフォリオの記事](/media/portfolio-github/)をご覧ください。

:::caution
チュートリアルをなぞっただけのアプリは、面談で「どこを自分で判断したか」を聞かれると答えにくくなります。小さくてもよいので、境目を引いた理由やキャッシュを決めた理由を自分の言葉で説明できるアプリを一つ作っておくことをおすすめします。
:::

## 面談で確かめられやすいこと

他の職種から移ってきた人は、面談で次の点を確かめられやすくなります。

- **Next.jsの実務の長さと中身**：どの版で、どの範囲を担ったか。個人の開発と業務を分けて話せるか
- **境目の引き方**：ある画面を例に、どこからをClient Componentにしたか、その理由
- **データの更新**：更新したあとに表示をどう新しくしたか
- **前の職種の経験の生かし方**：Next.jsのどの判断に効くか
- **分からないときの調べ方**：公式のドキュメントやリリースの告知をどう追っているか

職種を変えたことそのものより、**今どこまでできて、どこを伸ばしている途中か**を正直に話せるかが見られます。スキルシートでの書き方は[Next.jsエンジニアのスキルシートの記事](/media/nextjs-skillsheet/)で解説しています。

## 年代によって選びやすいルート

20代〜30代前半は、正社員としてNext.jsを使う開発チームに入り、実務で境目の引き方やデータの更新を経験してから独立するルートが取りやすい年代です。フリーランスの案件は、入ってすぐに判断できることを前提にしたものが多いため、実務の経験を先に積むほうが案件を選びやすくなります。職種を問わない考え方は[未経験からフリーランスを目指すとき](/media/mikeiken/)をご覧ください。

30代後半〜40代は、前の職種の経験を軸にした移り方が現実的です。バックエンドの経験があるなら画面とサーバー側をまとめて担う案件、業務システムの経験があるなら管理画面の刷新の案件のように、Next.jsの未経験の部分を前の経験で補える案件を選びます。

50代以降は、Next.jsの実装者として一から始めるより、移行の計画や品質と安全性の点検など、経験が効く役割から関わる形が考えられます。年代ごとの役割は[Next.jsエンジニアは40代・50代でも働けるかの記事](/media/nextjs-nenrei/)で整理しています。

:::view
当社では、案件をご案内するときに稼働日数・リモートの可否・希望金額を先に伺い、条件に合う案件だけをお出ししています。職種を変えたばかりの時期は、条件と経験の両方が合う案件を選ぶことが特に大切になります。経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。
:::

:::point
- 土台はTypeScriptとReact。その上に、境目、データ、キャッシュと描画、安全性、配信の順で積む
- Reactエンジニアはサーバー側の取得と更新、バックエンドは画面の作り込み、マークアップはTypeScript、インフラは画面の実装が足りなくなりやすい
- 面談では、前の職種の経験がNext.jsのどの判断に効くかを話せるかが見られる
:::

## よくある質問

### プログラミングの経験がなくても、Next.jsエンジニアを目指せますか？

目指すことはできますが、いきなりNext.jsから始めるより、HTMLとCSS、JavaScriptとTypeScript、Reactの順に土台を固めるほうが近道です。フリーランスの案件は実務の経験を前提にしたものが多いため、まずは正社員などで開発の実務を経験してから独立を考えるのが現実的です。

### ReactとNext.jsは、どちらを先に学ぶべきですか？

Reactを先に学ぶことをおすすめします。Next.jsはReactの上に作られたフレームワークで、部品の設計や状態の扱いはReactの知識がそのまま前提になります。Reactで画面が作れるようになったら、Next.jsのApp Routerでサーバー側の取得と更新を学ぶ、という順が自然です。

### Pages Routerの古い教材で学んでも意味はありますか？

既存のアプリにはPages Routerで作られたものも残っているため、読めること自体は役に立ちます。ただ、これから新しく学ぶなら、App Routerと新しいキャッシュの考え方を中心にしてください。古い書き方は、移行の案件で出会ったときに違いを読める程度で足ります。
