WordPressエンジニアの週2〜3日・副業案件｜探し方と受けるときの注意点

公開 2026-11-04　監修：株式会社エージェントベスト

WordPressエンジニアの案件は、週2〜3日や副業でも受けやすい部類に入ります。保守の更新作業、小さな改修、独自ブロックやプラグインの開発は、作業の単位を切り出しやすく、毎日その場にいなくても進められるためです。一方で、急ぎの不具合への対応や、公開日の前後の立て込みがあるため、稼働日以外の連絡をどう扱うかを先に決めておかないと、短い稼働のつもりが崩れやすくなります。

この記事では、週2〜3日・副業で見つかりやすい案件の型、探し方、短い稼働で信頼を得る進め方、受けるときの注意点を整理します。週3日の働き方全般は週3日のフリーランス案件の記事で解説しています。

週2〜3日のWordPress案件が比較的見つかりやすい理由

WordPressの仕事には、短い稼働と相性のよい特徴があります。

  • 作業の単位が小さい：ブロック1つ、テンプレート1枚、プラグインの更新1回のように、区切って進められる
  • 検証環境で進められる：手元や検証環境で作って確かめ、まとめて本番に反映できる
  • チャットで回る現場が多い：毎日の会議より、依頼と報告の文章でやり取りする現場が多い
  • 常駐の担当者を置きにくいサイトが多い：中小の事業会社やメディアでは、毎日エンジニアを置くほどの作業量がないことがある

ただし、新しいサイトを一から作る大きな構築や、複数のエンジニアが同時に動く開発のチームでは、週5日の稼働が前提になりやすくなります。週2〜3日の案件は、範囲を絞った仕事として募集されることが多いと考えておくと、探し方を間違えません。

エージェントベストの見解

WordPressの案件をご紹介していると、週2〜3日の希望で決まりやすいのは、「この稼働日数なら、更新と小さな改修までを担える」のように、担える範囲を自分から示せる方です。反対に、急ぎの不具合にもすぐ対応してほしいという案件を週2日で受けようとすると、発注元が不在の日の対応に不安を持ち、見送られやすい傾向があります。稼働日数と担える範囲、稼働日以外の連絡の扱いをセットで伝えることをおすすめします。

週2〜3日の案件の探し方

1. 受ける仕事の型を先に決める

保守を受けるのか、改修や開発を受けるのかを先に決めておきます。保守なら更新の頻度と問い合わせの量、開発なら作るものの大きさが、週2〜3日に収まるかの目安になります。

2. 稼働する曜日と時間帯、連絡の扱いを決める

稼働する曜日を固定できるか、稼働日以外にどこまで連絡に応じられるかを決めておきます。会社員の副業で平日の日中に動けない場合は、夜や週末に作業し、連絡は翌稼働日にまとめて返す形を受け入れてくれる案件を選ぶ必要があります。夜や週末だけの探し方は週末・夜だけの業務委託案件の記事が参考になります。

3. リモートで受けられるかを確かめる

週2〜3日の案件は、リモートとの組み合わせで成り立つことが多くあります。検証環境があるか、本番への反映をどの方法で行うかで、リモートで進めやすいかが変わります。見分け方はWordPressエンジニアのリモート案件の記事で解説しています。

4. 経験の近い案件から選ぶ

稼働日数が少ないほど、立ち上がりの早さが求められます。サイトの種類（コーポレートサイト、メディア、会員のあるサイトなど）やテーマの作り方が自分の経験に近い案件を選ぶと、短い稼働でも成果を出しやすくなります。

短い稼働で信頼を得る進め方

週2〜3日のWordPressエンジニアは、不在の日があることを前提に仕事を組み立てる必要があります。

  • 依頼の窓口を一本にする：誰から依頼を受け、誰が優先順位を決めるかを最初にそろえる
  • 稼働日の最初と最後に短く報告する：今日やること、終わったこと、次回に持ち越すことを文章で残す
  • 本番への反映は稼働日の早い時間に：反映した後に様子を見られる時間を残し、不在の日に問題を持ち越さない
  • 戻し方を毎回用意する：バックアップと戻す手順を確かめてから反映する
  • 急ぎのときの代わりを決める：不在の日にサイトが止まったら、誰がどこまで対応するかを発注元と先に合意しておく

こうした進め方を面談で具体的に話せると、短い稼働でも任せられるかを発注元が判断しやすくなります。

受けるときの注意点

急ぎの対応をどこまで受けるかを決める

WordPressの保守で最も起きやすいのは、稼働は週2日の約束なのに、不具合の連絡が毎日のように来るという状態です。更新のあとの表示崩れやフォームの不具合は、発注元にとってはすぐ直してほしいものです。稼働日以外の連絡にどこまで応じるか、応じた時間をどう扱うかを、契約の前に決めておきましょう。

保守の範囲と稼働時間をそろえる

保守の契約の中で、新しいページや機能の追加を頼まれることがあります。範囲に入る作業と入らない作業を分け、入らない作業は別の見積もりにするかどうかを決めておきます。考え方は作業範囲が広がったときの契約の扱い、稼働時間の精算は精算幅の記事をご覧ください。

公開日の前後の立て込みを確かめる

改修や移行の案件では、公開や切り替えの日の前後に作業が集中します。その時期だけ稼働を増やしてほしいと頼まれることもあるため、応じられる範囲と、そのときの条件を先に決めておくと慌てずに済みます。

注意

複数のサイトの保守を掛け持ちすると、本体やプラグインの重要な更新が出た日に、すべてのサイトで作業が重なることがあります。管理画面やサーバーのアカウントも案件ごとに分けて管理する必要があります。掛け持ちの注意点は複数の案件を掛け持ちするときの注意点で解説しています。

会社員の副業でWordPressの案件を受けるとき

会社員が副業で受ける場合は、上の注意点に加えて、次の点を確かめます。

  • 勤務先の就業規則：副業が禁止か、許可制か、届出制か。業務委託が対象に含まれるか
  • 本業との競合：本業が制作会社の場合、本業の顧客や同じ業界の発注元の案件は、競業や秘密の扱いで問題になりやすい
  • 時間帯：急ぎの不具合の連絡が平日の日中に来たとき、本業の時間と重ならないか
  • 税金の手続き：副業の所得の扱いや確定申告が必要になる場面がある

本業で作ったテーマやプラグインのコードを、副業の案件で使い回すことは避けてください。コードの権利が勤務先にある場合が多く、問題になりやすいためです。就業規則の読み方や手続きは会社員の副業で業務委託案件を受けるときの注意点、副業禁止の会社で業務委託を受けるリスク、確定申告の考え方は副業の所得と確定申告の記事で解説しています。判断に迷う場合は、勤務先の担当部署や税理士などの専門家にご相談ください。

よくある質問

週2日の保守の案件でも、急ぎの不具合には対応しなければいけませんか？

契約で決めた内容によります。稼働日以外は翌稼働日の対応とするのか、急ぎのときだけ応じるのか、応じた時間をどう精算するのかを、契約の前に発注元とそろえておくことが大切です。決めないまま始めると、稼働日以外の対応が少しずつ増えやすくなります。

副業で受けるなら、保守と開発のどちらが向いていますか？

平日の日中に動けない場合は、締め切りまでに自分の時間で進められる開発や改修のほうが向いています。保守は急ぎの連絡が日中に来ることがあるため、連絡の扱いを発注元と合意できる案件を選びましょう。

週3日で始めて、あとから稼働を増やすことはできますか？

発注元の作業量や予算によっては、稼働を増やせることがあります。ただし、案件ごとに事情が違うため、増やせる前提で受けるのは避けたほうが無難です。将来の希望がある場合は、参画前に伝えておくと話がしやすくなります。
