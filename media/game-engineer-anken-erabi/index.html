組込み・ゲーム・XR

ゲームエンジニアのフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

ゲームエンジニアの案件を選ぶときは、報酬や稼働日数に加えて、担当する領域の実態、タイトルの今の局面、エンジンと機材の条件、情報管理の決まり、契約の形と成果物の扱い、節目の稼働、タイトルが止まったときの扱いを契約前に確かめることが大切です。ゲームの案件は、同じ「クライアントエンジニア」の募集でも、この違いで毎日の仕事と負う責任がまったく変わります。

この記事では、ゲームエンジニアの案件選びで差が出る理由と、契約前に確かめたい7つの点、確かめた内容を書面と照らし合わせる方法を整理します。契約全般の確認点は業務委託契約で確かめたいことで解説しています。

ゲームの案件選びで差が出る理由

ゲームの案件で参画後のずれが起きやすいのは、主に次の3つの事情からです。

  • 案件票の領域名が広い：「クライアント」「サーバー」と書かれていても、ゲームプレイの実装なのか、UIなのか、描画なのか、エンジンの改造なのかで、求められる経験が違う
  • 局面で仕事が変わる：試作の段階、本格的な開発、リリース直前、運営中で、作業の量の波も責任の重さも変わる
  • ゲームならではの条件が多い：開発機材、未発表の情報、エンジンの版、当番など、一般のWebの案件では出てこない条件が働き方を左右する

案件票だけでは分からない点が多いため、面談と契約前の確認で埋めていくことになります。

契約前に確かめたい7つの点

1. 担当する領域と、任される範囲の実態

まず、自分が何を担当するのかを具体的に確かめます。機能のまとまりを設計から任されるのか、決まった仕様を実装するのか、ほかのエンジニアのコードを確かめる役割もあるのか。リードに近い役割を期待されている場合は、判断をどこまで任されるかも聞いておきましょう。

2. タイトルの今の局面と、次の節目

試作か、本格的な開発か、リリース直前か、運営中か。次の試遊会、提出、更新はいつか。リリース直前の案件は作業が集中しやすく、運営中の案件は更新の間隔に合わせて仕事が回ります。遅れが表に出ている現場に立て直しのために入る場合は、その前提も確かめておきます。

3. エンジン・版・開発環境

使うエンジンとその版、版を上げる予定の有無、エンジンの内部に手が入っているか、ビルドの仕組みはどうなっているかを確かめます。社内のエンジンの場合は、資料の量や質問できる相手がいるかも大切です。手元のPCで作業するのか、取引先から機材が貸し出されるのかも、作業の進めやすさに直結します。

エージェントベストの見解

ゲームの案件をご紹介していると、参画後のずれとして多いのは、報酬より「思っていた担当と違った」「エンジンの版が古く、想定と違う作業が多かった」という点です。案件票の領域名は広く書かれることが多いため、面談の段階で担当の機能とエンジンの版まで聞いておくことをおすすめします。聞きにくい点は、ご質問いただければ確認します。

4. 作業の場所と、情報管理の決まり

家庭用ゲーム機の開発機材を使う作業や、未発表のタイトルの資料を扱う作業は、出社が条件になったり、作業できる場所や機器が限られたりします。どの作業で出社が必要か、手元の機器に資料を置いてよいか、秘密保持の約束の範囲はどこまでかを確かめましょう。秘密保持の考え方は秘密保持契約の記事、働く場所はゲームエンジニアのリモート案件の記事で解説しています。

5. 契約の形と、成果物・著作権の扱い

業務委託の契約には、作業すること自体に報酬が払われる準委任と、決まった成果物を完成させることに報酬が払われる請負があります。ゲームの案件は準委任が多いものの、ツールや機能を「納品」する形の契約では、完成の責任や不具合の直しの扱いが変わります。違いは準委任と請負の違いをご覧ください。

あわせて、作ったコードやツールの著作権がどちらに帰属するか、自分が前から持っているコードやライブラリを使ってよいかも確かめておきます。考え方は著作権の記事で整理しています。

6. 稼働の振れ幅、当番、精算

リリースや更新の前後に稼働が増えるか、増える場合の上限と精算の仕方はどうか、障害の当番や夜間・休日の対応があるかを確かめます。月の稼働時間に幅を決めて精算する契約では、その幅を超えたときの扱いも大切です。精算の仕組みは精算幅の記事をご覧ください。

7. 契約期間と、タイトルが止まったときの扱い

ゲームの開発では、計画の見直しでタイトルの開発が止まったり、規模が縮んだりすることがあります。契約期間はどこまでか、更新の区切りはいつか、開発が止まった場合に契約がどうなるかを確かめておくと、急に稼働がなくなったときの備えができます。

注意

ゲームの案件では、開発会社が受託した仕事のさらに一部を受ける形が少なくありません。その場合、仕様を決める人、作業を確かめる人、報酬を払う会社がそれぞれ違うことがあります。指示を誰から受けるのか、契約の相手は誰か、報酬の支払期日はいつかを分けて確かめましょう。誰が自分に直接指示を出すかは、契約の形が実態と合っているかにも関わります。

案件の型ごとに重く見たい点

7つの点のうち、どこを重く見るかは案件の型によって変わります。目安を整理すると、次のようになります。

案件の型特に確かめたい点理由
新規タイトルの開発局面と節目、契約期間と中止時の扱い計画の見直しで規模や期間が変わりやすい
運営中タイトルの更新当番、更新日の稼働、精算更新の前後と障害時に稼働が増えやすい
サーバー・バックエンド当番、障害時の責任の範囲価値のあるデータを扱い、夜間の対応が起きうる
移植・最適化機材と作業の場所、目標の数字開発機材の決まりと、何をもって終わりとするかが働き方を決める
ツール・基盤契約の形、著作権、使う人と窓口納品の形になりやすく、作ったものの権利が問題になりやすい

移植や最適化の案件では、「どの数字をどこまで下げれば終わりか」が決まっていないと、作業の区切りがつきにくくなります。ツールの案件では、使う人が多いほど要望が増えるため、要望を受ける窓口と優先順位を決める人を確かめておくと、範囲が広がりすぎるのを防げます。

確かめた内容を書面と照らし合わせる

面談や事前のやり取りで確かめた内容は、契約の書面と照らし合わせます。フリーランス法では、業務を委託する事業者は、発注のときに給付の内容、報酬の額、支払期日などの取引条件を、書面やメールなどで直ちに明示することとされています（2026年10月時点、公正取引委員会のフリーランス法特設サイトによる）。明示される事項の詳しい中身はフリーランス法で明示される取引条件で解説しています。

照らし合わせるときは、次の対応を確かめるとずれに気づきやすくなります。

面談で確かめたこと書面のどこに出てくるか
担当の領域と任される範囲業務の内容（給付の内容）
準委任か請負か、成果物の有無契約の形、業務の内容、検査の有無
稼働の幅と精算の仕方報酬の額と計算の方法
作業の場所と機材役務を提供する場所、別の取り決め
秘密保持と著作権秘密保持の条項、権利の帰属の条項
契約期間と更新契約期間、更新や解除の条項

面談で聞いた話と書面が違う場合は、署名の前に確かめましょう。口頭の約束は、後から確かめる手段が残りにくいためです。契約書の直し方は契約書を直してほしいときの記事が参考になります。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。ゲームの案件では、機材や作業の場所、当番の扱いなど、案件票に書かれにくい条件も多くあります。契約前に気になる点があれば、ご質問いただければ確認します。

ポイント

  • ゲームの案件は、担当の領域、局面、エンジンと機材、情報管理で毎日の仕事が変わる
  • 契約前に、担当の範囲、局面と節目、エンジンの版、作業の場所、契約の形と著作権、稼働と当番、期間と中止時の扱いを確かめる
  • 再委託の形では、指示を出す人・契約の相手・支払期日を分けて確かめる
  • 面談で確かめた内容を書面と照らし合わせ、違いは署名の前に解消する

よくある質問

リリース直前の案件は避けたほうがよいですか？

一概に避ける必要はありません。リリースの対応は経験として評価されやすく、短い期間で成果を出せる場面でもあります。ただ、作業が集中しやすいため、稼働の上限と精算の仕方、節目を過ぎた後の契約の見通しを、先に確かめておきましょう。

エンジンの版が古い現場は、選ばないほうがよいですか？

古い版を使うこと自体は珍しくありません。運営中のタイトルでは、安定を優先して版を上げないこともあります。気にしたいのは、版を上げる作業を自分が担うのか、古い版のままで自分の経験が生かせるのかです。面談で版の方針を聞いておきましょう。

報酬の高い案件と、担当がはっきりした案件で迷ったらどうしますか？

担当がはっきりした案件のほうが、参画後に成果を出しやすく、次の案件の材料も残しやすくなります。報酬の高さが、稼働の振れ幅や当番、責任の重さとどう結びついているかを確かめてから比べるとよいでしょう。報酬の決まり方はゲームエンジニアの報酬の記事で解説しています。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 業務委託契約の基礎

成果物の著作権は誰のもの？業務委託の知的財産の扱い

業務委託で作ったプログラムや資料の著作権は、契約で決めなければ原則として作ったフリーランスに残ります。発注者に移す場合は、譲渡の範囲・時期・対価と、以前から持っているコードの扱いを契約で確かめます。

 業務委託契約の基礎

秘密保持契約（NDA）で確認すること｜対象・期間・実績として話せる範囲

NDAで確かめたいのは、秘密情報の範囲と例外、使ってよい目的、守る期間、終了時の返還・廃棄、違反時の責任の5点です。フリーランスは、実績としてどこまで話せるかも署名前に決めておくと安心です。

 スキルシート・面談

業務委託の面談で聞いておくべき逆質問｜参画後のずれを防ぐ確認項目

業務委託の面談の逆質問は、印象づくりより「参画後のずれを防ぐ確認」に使うのが基本です。業務の範囲、体制と指示の流れ、稼働の実態、期間の見込みの4つを確かめておくと、契約後の「話が違う」を減らせます。
