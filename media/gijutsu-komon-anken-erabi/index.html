技術顧問・CTO代行のフリーランス案件の選び方｜契約前に確かめたい7つの点

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい7つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

技術顧問・CTO代行の案件を選ぶときは、報酬や稼働日数に加えて、困りごとの中身、関わり方と稼働の上限、判断の範囲、応答の範囲、指示の流れ、肩書きと立場、契約期間と秘密の扱いの7点を契約前に確かめておくことが大切です。技術顧問の案件は、同じ名前の募集でもこの7点の違いで負担と責任が大きく変わります。

特に見落としやすいのは、期待されている判断の重さと、契約の書き方が釣り合っているかです。助言のつもりで受けたのに、実際は技術の責任者としての判断を求められる、という食い違いがよく起きます。契約書全般の確認点は業務委託契約書のチェックポイントで解説しているので、ここでは技術顧問の案件に固有の点に絞ります。

技術顧問の案件選びで差が出る理由

エンジニアの案件なら、使う技術や担当する工程で仕事の中身がある程度読めます。技術顧問の案件は、案件票が「技術顧問募集」「CTO候補・CTO代行」のように抽象的になりやすく、成果物も形に残りにくい仕事です。参画してから想定との違いに気づくことが少なくありません。

よくある食い違いは次のようなものです。

  • 助言型で受けたのに、採用の面接やレビューの依頼で週の多くが埋まる
  • 「CTO代行」の募集だったが、実際は人手の足りない部分の実装が大半だった
  • 方針を提案しても、社内で決める人がおらず話が進まない
  • 月数回の契約なのに、チャットで日中すぐの返答を期待される

こうした食い違いは、面談と条件の確認の段階で聞き方を工夫すれば、多くを防げます。

契約前に確かめたい7つの点

1. 困りごとの中身と、解決した状態

最初に確かめたいのは、会社が何に困っていて、どうなれば顧問を頼んだ意味があったと言えるかです。「開発が遅い」「採用が進まない」「技術の判断ができる人がいない」など、困りごとによって必要な関わり方が変わります。

面談では、「半年後にどうなっていれば、顧問を入れてよかったと思えますか」と聞くと、期待の中身が見えやすくなります。答えがあいまいな場合は、最初の3か月で扱う範囲を自分から提案し、合意してから契約に進むと、互いの期待をそろえやすくなります。

2. 関わり方の型と、稼働の上限

月数回の助言型か、週数日の実務型か、技術の責任者の代行かを確かめます。そのうえで、次の点を言葉にしておきます。

  • 定例の回数と1回の時間
  • 月の稼働の上限と、超えたときの扱い
  • 面接やレビューなど、定例以外の仕事が含まれるか

上限を超えた稼働の扱いが決まっていないと、相談が増えても報酬は変わらず、実質の単価が下がっていきます。報酬の決まり方は技術顧問・CTO代行の報酬の記事で解説しています。

3. 判断の範囲と、報告の相手

自分が決めてよいことと、経営陣に決めてもらうことの線を確かめます。

  • 技術の選定や設計の方針は、自分で決めてよいか、提案までか
  • 採用の可否を決める場に入るか、意見を出すだけか
  • 外部の開発会社やサービスとの契約に関わるか
  • 報告の相手は社長か、役員か、開発の責任者か

報告の相手が意思決定できる人であることは大切です。決める人があいまいな会社では、どれだけ論点を整理しても結論が出ず、顧問の働きが見えにくくなります。

エージェントベストの見解

技術顧問の案件をご紹介していると、参画後に「聞いていた話と違った」となりやすいのは、判断の範囲と、チャットでの応答の期待の2点です。面談では聞きにくいと感じる方もいますが、顧問として何を任されるかを判断するために必要な確認として聞けば、多くの発注側は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

4. 問い合わせへの応答の範囲

助言型の案件では、定例の外でチャットやメールの質問が届きます。応答の範囲を決めておかないと、月の稼働は少ないのに常に連絡を待つ状態になります。

  • チャットに答える時間帯と、返答までの目安
  • 障害や緊急の判断が必要なときに連絡を受けるか
  • 夜間・休日の連絡の扱い

5. 指示の流れ：誰が誰に指示を出すのか

技術顧問の案件では、「社内のエンジニアに方針を示してほしい」と頼まれる一方で、自分の働き方を発注側から細かく指示されることもあります。準委任の契約なのに、発注側の社員から作業の手順や勤務時間を細かく管理される働き方は、偽装請負の問題につながるおそれがあります。

確かめたいのは、自分が社内のエンジニアにどこまで指示や助言をしてよいか、自分への依頼は誰から届くのか、の2点です。契約の形の違いは準委任契約と請負契約の違い、指示の問題は偽装請負の記事で解説しています。

6. 肩書きと立場：業務委託か、役員か

CTO代行の案件では、社外への見せ方として「CTO」の肩書きを使ってほしい、取締役に就任してほしい、と求められることがあります。業務委託で関わる場合と役員に就任する場合とでは、責任の根拠が違います。

  • 名刺や会社のサイトに、どの肩書きで名前を出すか
  • 投資家や取引先に、技術の責任者として紹介されるか
  • 役員への就任を前提にした話が出ていないか

肩書きが実態より重いと、社外からは技術の責任者として見られ、契約で決めた範囲を超える期待が集まります。役員への就任を打診されたときは、引き受ける前に弁護士・税理士などの専門家にご相談ください。立場の違いは技術顧問・CTO代行がフリーランスになるには、役員の報酬の考え方は役員報酬の記事をご覧ください。

7. 契約期間と、秘密・競業の扱い

技術顧問の契約は、3か月や6か月で区切って更新を重ねる形がよく見られます。期間の区切りが、採用の時期や刷新の節目と合っているかを確かめます。

フリーランス法では、6か月以上継続して業務を委託している場合に、契約を解除したり更新しなかったりするときは、原則として少なくとも30日前までに予告することが求められています（2026年10月時点、公正取引委員会の案内による）。

あわせて、秘密保持の範囲と期間、契約が終わった後に同じ業界の会社の顧問を受けてよいかを確かめます。技術顧問は事業計画やシステムの弱点に触れる立場なので、ほかの顧問先との関係で問題になりやすい点です。考え方は秘密保持契約（NDA）の記事と競業避止義務の記事で解説しています。

注意

技術顧問の案件では、関わるうちに相談の範囲が広がりやすい傾向があります。別の事業の技術相談、投資家向けの資料づくり、障害の一次対応など、契約の業務範囲に入っていない仕事を頼まれたときは、引き受ける前に範囲と条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容、報酬の額、支払期日などを書面またはメールなどで明示することとされています。報酬の支払期日は、給付を受け取った日から60日以内のできる限り短い期間で定めることとされています（2026年10月時点、公正取引委員会の案内による）。明示される事項の内容はフリーランス法で明示される取引条件をご覧ください。

技術顧問の案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、扱う領域（技術選定、設計のレビュー、採用、開発体制など）が書かれているか
  2. 定例の回数、月の稼働の上限、超えたときの扱い
  3. 問い合わせへの応答の範囲と時間帯
  4. 成果の完成や事業の結果を約束する書き方になっていないか
  5. 契約期間、更新の時期、秘密保持と競業の定め

面談で聞いておくとよい質問は技術顧問・CTO代行の面談でよく聞かれる質問の逆質問の項目でも紹介しています。一般的な逆質問の考え方は面談で聞いておくべき逆質問をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。技術顧問の案件で気になりやすい判断の範囲や、チャットへの応答の期待など、書面だけでは読み取りにくい点は、ご質問いただければ確認します。

ポイント

  • 技術顧問・CTO代行の案件は、同じ名前でも任される判断と稼働の実態が大きく違う
  • 困りごとの中身、関わり方と稼働の上限、判断の範囲と報告の相手を面談で確かめる
  • 応答の範囲、指示の流れ、肩書きと立場は、参画後の食い違いが起きやすい点
  • 契約期間、秘密保持と競業、稼働の上限を書面と照らし合わせる

よくある質問

「CTO候補」として業務委託で募集されている案件は、どう考えればよいですか？

最初は業務委託で関わり、相性を見てから正社員や役員として迎えたいという意図の募集です。将来の立場を前提に、今の契約の範囲を超える期待をされることがあるため、業務委託の間に担う範囲と、立場が変わるときの条件を分けて確かめておきましょう。

資金に余裕のない創業期の会社の案件は避けたほうがよいですか？

避ける必要はありませんが、報酬の支払条件と契約期間は丁寧に確かめてください。成果に応じた報酬や株式での支払いを提案されることもあり、その場合は条件と税金の扱いを専門家に確かめてから判断することをおすすめします。

前任の技術顧問やCTOが辞めた理由は聞いてもよいですか？

顧問として最初に取り組むべきことを把握するための確認として聞けば、失礼にはあたりません。答えられない場合もあるので、そのときは無理に聞き出さず、困りごとの中身や判断の範囲など、ほかの確認点で判断しましょう。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

偽装請負とは｜指揮命令の線引きとフリーランスが注意すること

偽装請負は、請負や準委任の契約なのに、実態として発注者が働き手に直接指揮命令している状態です。判断は契約の名前ではなく実態で行われます。フリーランスは「労働者性」の基準と、参画前に確かめたい点を押さえておきましょう。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 業務委託契約の基礎

秘密保持契約（NDA）で確認すること｜対象・期間・実績として話せる範囲

NDAで確かめたいのは、秘密情報の範囲と例外、使ってよい目的、守る期間、終了時の返還・廃棄、違反時の責任の5点です。フリーランスは、実績としてどこまで話せるかも署名前に決めておくと安心です。
