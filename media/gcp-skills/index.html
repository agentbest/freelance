GCPエンジニアのフリーランス案件で求められるスキルと経験

GCP（Google Cloud）のフリーランス案件では、リソース階層に沿って権限を設計する力、BigQueryの費用を読み解いて抑える力、GKEやCloud Runでアプリの実行環境を運用する力が中心に見られます。Google Cloudはデータ分析の用途で選ばれることが多く、インフラの設定だけでなく、データを使う人の動きまで想像して設計できるかが、ほかのクラウドより強く問われます。

独立までの進め方や在職中に積みたい実績はGCPエンジニアがフリーランスになるにはで扱っています。この記事では、案件で確認されるスキルの中身と、その示し方に絞って整理します。

Google Cloudの案件で見られるスキルの全体像

Google Cloudの案件で確認されるスキルは、おおむね次の5つに分かれます。

分野中身案件での見られ方
リソース階層とIAM組織・フォルダ・プロジェクトの構成、ロールの付け方権限の継承を踏まえて設計できるか
データ基盤BigQuery、Cloud Storage、データの取り込み費用と権限を含めて設計できるか
アプリの実行環境GKE、Cloud Run、CI/CDどちらを選ぶかの判断と運用の経験
ネットワークVPC、社内やほかのクラウドとの接続接続方式と名前解決を説明できるか
監視と費用管理ログ、指標、予算とアラート費用の増え方を説明して抑えられるか

すべてに深い経験がある必要はありません。ただ、Google Cloudの案件は分野の境目がはっきりしないことが多く、たとえばデータ基盤の案件でもIAMとネットワークの知識が前提になります。軸の分野と、その周りでどこまで対応できるかを分けて説明できるようにしておきましょう。

リソース階層とIAMを設計する力

Google Cloudでは、組織を頂点に、フォルダ、プロジェクト、各リソースの順に階層を作ります。公式ドキュメントでは、最上位を除くすべてのリソースは親を1つだけ持ち、組織やフォルダに付けたロールは配下のすべてのリソースに継承されると説明されています。各リソースで有効になる権限は、そのリソースに直接付けたものと、上位から継承したものを合わせたものです。

この仕組みは便利な反面、上位で広い権限を付けると、配下のプロジェクト全体に効いてしまいます。案件で評価されるのは、次のような判断を説明できる経験です。

  • フォルダを部門で切るか、環境（本番・検証・開発）で切るかを決めた理由
  • 人に直接ロールを付けず、グループ単位で付ける運用にした経緯
  • 事前定義ロールで足りない場面で、カスタムロールを作るか、構成を変えるかの判断
  • サービスアカウントの鍵を配らずに済む仕組みへ切り替えた経験

「権限エラーを解消した」だけでなく、「なぜその階層でその権限が効いていたか」を追いかけた経験は、面談で理解の深さが伝わりやすい部分です。

エージェントベストの見解

Google Cloudの案件をご紹介していると、構築の経験は十分でも、「この権限はどこで付いていたのか」を聞かれて答えに詰まる方を見かけます。反対に、プロジェクトの切り方とグループの設計を自分の言葉で説明できる方は、データ基盤やコンテナ基盤の案件でも頼りにされやすい傾向があります。スキルシートでは、関わった環境のフォルダとプロジェクトの切り方を一行添えることをおすすめします。

BigQueryを費用まで含めて扱う力

Google Cloudの案件では、インフラ担当でもBigQueryに触れる場面が多くあります。求められるのは、SQLを書けることより、使い方によって費用がどう増えるかを読み、抑える仕組みを作れることです。

BigQueryの公式ドキュメント「費用の見積もりと管理」では、費用を抑える方法として次のようなものが挙げられています。

  • クエリを実行する前に、ドライランなどで処理量と費用を見積もる
  • 課金される最大バイト数を設定し、上限を超えるクエリを失敗させる
  • プロジェクトやユーザーごとに、1日に処理できるデータ量の割り当てを設定する
  • 途中の結果をテーブルに書き出し、後のクエリが読む量を減らす
  • 予算とアラート、請求データのBigQueryへのエクスポートで費用を見守る

また、料金の考え方には、処理したデータ量に応じたオンデマンドと、処理能力（スロット）を確保する容量ベースの2つがあり、どちらが合うかは使い方によって変わるとされています。

案件で評価されやすいのは、「費用が急に増えた原因を請求データから特定し、どの対策を入れたか」を順に話せる経験です。分析チームの使い方を変えてもらう必要がある場合は、技術の話だけでなく、相手にどう説明して合意したかも伝えると、外部から入る立場での動き方が伝わります。

アプリの実行環境を選んで運用する力

アプリを動かす環境としては、GKE（Kubernetesのマネージドサービス）とCloud Run（コンテナをサーバーの管理なしで動かすサービス）がよく使われます。

観点GKECloud Run
向いている場面多くのサービスを細かく制御して動かす個々のサービスを手軽に動かす
求められる知識Kubernetesの運用、ノードやネットワークの設計コンテナの作り方、同時実行や起動時間の調整
運用で問われること版の更新、リソースの割り当て、障害時の切り分け外部サービスとの接続、費用の見積もり

案件では、どちらを使ったかより、なぜその環境を選んだか、そしてCloud BuildやGitHub Actionsなどでデプロイをどう自動にしたかが確認されます。Kubernetesの運用経験が深い場合は、SREのスキルの記事で扱っている信頼性の考え方とあわせて整理すると、参画できる案件が広がります。

ネットワークと監視

Google CloudのVPCは、ほかのクラウドと設計の考え方が違う部分があり、ほかのクラウドから移ってきた方がつまずきやすいところです。社内のネットワークやほかのクラウドとの接続、名前解決の設計、外部への通信の制御などは、移行や基盤整備の案件で確認されます。ネットワークを軸にする場合はネットワークエンジニアのスキルの記事もあわせてご覧ください。

監視では、ログと指標の集め方、アラートの条件の決め方に加え、ログの保存量そのものが費用になる点を踏まえた設計ができると評価されます。「何でも保存する」設計から、目的に合わせて保存期間を分けた経験は、費用の見直しの案件で具体的に話せる材料です。

認定資格の位置づけ

Google Cloudの認定資格のうち、入口になるAssociate Cloud EngineerとProfessional Cloud Architectは、GCPエンジニアがフリーランスになるにはで推奨される経験と有効期間を紹介しています。ここでは、分野ごとの専門性を示すProfessionalの認定を整理します（2026年10月時点のGoogle Cloudの案内による）。

認定推奨される経験評価される主な能力
Professional Data Engineer業界経験3年以上（Google Cloudでの設計・管理1年以上を含む）データ処理システムの設計、取り込みと処理、保存、分析用データの準備、ワークロードの維持と自動化
Professional Cloud DevOps Engineer業界経験3年以上（Google Cloudでの本番システムの設計・管理1年以上を含む）組織のブートストラップと維持、SREのプラクティス、CI/CD、オブザーバビリティと費用の最適化
Professional Cloud Network Engineer業界経験3年以上（Google Cloudでの設計・管理1年以上を含む）VPCの設計と実装、ハイブリッド・マルチクラウドの接続、ネットワークのセキュリティ

Professional Data Engineerは、標準試験で取得した場合の有効期間が2年間と案内されています。ほかの認定の有効期間は、更新に関するよくある質問で確認するよう案内されているため、受験や更新の前に公式サイトで最新の内容をご確認ください。

推奨される経験は受験の条件ではありませんが、どの認定を選ぶかの目安になります。案件では、認定の名前より、その分野で何を作り、どう運用したかが問われます。

注意

Google Cloudの認定試験は、製品名の変更や機能の追加にあわせて改訂されることがあります。公式サイトでも、ブランディングの変更などにあわせて内容を更新する予定があるとされ、試験ガイドで最新の製品名を確認するよう案内されています。古い問題集だけで準備すると、出題の範囲とずれるおそれがあります。

スキルシートと面談での示し方

Google Cloudの経験は、使ったサービスを並べるより、誰が何に使う環境を、どういう決まりで作ったかを書くと伝わります。

  • 部門ごとにフォルダを分け、グループ単位でロールを付ける構成に整理した
  • BigQueryの費用の増加を請求データで分析し、処理量の上限と割り当てを設定した
  • Cloud Runで動かしていたサービスを、要件の変化にあわせてGKEへ移した理由と手順
  • 社内ネットワークとの接続で、名前解決の設計を見直した

面談では、「その構成にした理由」と「費用や権限で困ったこと」がよく聞かれます。書き方の詳細はGCPのスキルシートの書き方、報酬との関係はGCPエンジニアの報酬の記事をご覧ください。

エージェントベストの見解

当社では、案件をご案内する前に、稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをお出ししています。Google Cloudの案件は、データ基盤、コンテナ基盤、環境の標準化のどれが中心かで求められる経験が大きく変わるため、軸にしたい分野と、補助として対応できる分野を分けて整理しておくことをおすすめします。

ポイント

  • Google Cloudの案件では、リソース階層に沿ったIAM設計、BigQueryの費用管理、GKEやCloud Runの運用が中心に見られる
  • 上位で付けた権限は配下に継承されるため、階層の切り方を説明できると評価されやすい
  • 認定は分野ごとの専門性の裏付けになるが、実務での判断の経験とあわせて伝える

よくある質問

BigQueryのSQLが書けないとGCPの案件は難しいですか？

インフラの案件では、複雑な分析のSQLまで求められることは多くありません。ただ、費用の調査や権限の確認でBigQueryを使う場面は多く、請求データを集計できる程度のSQLは身につけておくと役立ちます。

AWSの経験はGoogle Cloudの案件で生かせますか？

生かせます。ネットワーク、権限、コンテナ、IaCの考え方は共通する部分が多くあります。一方で、リソース階層とIAMの継承、VPCの設計は考え方が違うため、違いを説明できるようにしておくと面談で伝わりやすくなります。比較はAWSエンジニアのスキルの記事も参考になります。

Professionalの認定はどれから取るとよいですか？

軸にしたい分野に合わせて選ぶのが近道です。データ基盤ならProfessional Data Engineer、運用や信頼性ならProfessional Cloud DevOps Engineer、接続や基盤の設計ならProfessional Cloud Network Engineerが目安になります。設計全般を示したい場合は、Professional Cloud Architectから始める方法もあります。
