組込み・ゲーム・XR

組込みエンジニアのフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい8つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

組込みエンジニアのフリーランス案件を選ぶときは、報酬や稼働日数に加えて、担当の層と構成、開発の局面、実機と機材の環境、出社の条件、品質の手順の重さ、契約の形と不具合の責任、稼働の振れ幅、秘密と掛け持ちの条件の8点を契約前に確かめておくことが大切です。組込みの案件は、同じ「ファームウェア開発」でもこの8点の違いで負担が大きく変わります。

特に見落としやすいのは、自分の作業に必要な実機や計測器を、必要なときに使えるかです。実機が足りない現場では、どれだけ準備しても確かめる作業が進まず、稼働だけが延びていきます。この記事では、組込み案件に固有の確認点を整理します。契約書全般の確認点は業務委託契約書のチェックポイントで解説しています。

組込みの案件選びで差が出る理由

組込みの案件票は「C言語」「RTOS」「車載」のように技術の名前が並ぶことが多く、実際の作業の中身や環境までは書かれていないことがあります。参画してから気づく、よくあるずれは次のようなものです。

  • 新規開発と聞いていたが、実際は古い製品の不具合対応が中心だった
  • 使うマイコンは経験のある系統だったが、社内独自のビルドの手順に慣れるまで時間がかかった
  • 試作基板の到着が遅れ、手待ちが続いたあと、評価の時期に作業が集中した
  • 実機がチームで1台しかなく、使える時間が限られていた
  • リモート中心と聞いていたが、評価の時期は毎日の出社になった

こうしたずれは、面談と条件の確認の段階で聞き方を工夫すれば、多くを防げます。

契約前に確かめたい8つの点

1. 担当の層と構成

最初に確かめたいのは、自分が担う層と、使う構成です。

  • ブート・BSP、ドライバー、RTOS・ミドルウェア、アプリケーションのどこを担うか
  • マイコンやSoCの系統、OSの種類と版、使う開発環境やコンパイラー
  • 新しく書くのか、既存のコードを改修するのか

構成が経験と少し違っても参画はできますが、どこが違い、立ち上がりにどれくらいかかりそうかを自分で見積もっておくと、参画直後に慌てずに済みます。

2. 開発の局面と、この先の見通し

今がどの局面か、この先どう変わるかを確かめます。

  • 試作の何版目か、量産や出荷の予定はいつ頃か
  • 遅れが出ていないか、前任者がいた場合は交代の経緯（答えられる範囲で）
  • 契約期間の中で、局面がどう移る見込みか

遅れのある案件を避ける必要はありません。ただ、状態を知ったうえで受けることが大切です。

3. 実機・評価ボード・計測器の環境

組込みに固有の確認点です。

  • 自分用の実機や評価ボードがあるか、チームで共有か
  • オシロスコープやロジックアナライザー、デバッガーは使えるか
  • 試験装置を使う時間に制限があるか

道具の使い方は組込みエンジニアのスキルの記事でも触れています。

エージェントベストの見解

組込みの案件をご紹介していると、参画後に「聞いていた状況と違った」となりやすいのは、開発の局面と、実機の使える時間の2点です。面談では聞きにくいと感じる方もいますが、作業の段取りを考えるために必要な確認として聞けば、多くの発注元は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

4. 作業の場所と出社の条件

出社の頻度だけでなく、局面によってどう変わるかを確かめます。参画直後や評価の時期は現地が増えることが多いためです。自宅で作業する日がある場合は、機材やソースを自宅で扱ってよいかも合わせて確かめます。傾向は組込みエンジニアのリモートの記事で整理しています。

5. 品質の手順の重さ

車載や産業機器、医療機器などの案件では、コーディング規約、静的解析、レビュー、要求と試験の対応づけ、変更の影響分析の記録が開発の一部になっています。記録の作成にどのくらいの時間を使う現場かを確かめておくと、作業の見積もりがずれにくくなります。分野ごとの決まりは製造業界の規制の記事で扱っています。

6. 契約の形と、不具合の責任の範囲

フリーランスの組込みエンジニアは、多くの場合、準委任契約で参画します。準委任では、ソフトの完成そのものではなく、専門家として通常求められる注意を払って業務を行うことが約束の中身になります。確かめたいのは、書面の書き方がこれと合っているかです。

  • 「製品を完成させる」「不具合をなくす」のように、完成を約束する書き方になっていないか
  • 出荷後に見つかった不具合について、契約終了後も対応や責任を負う定めがないか
  • 成果物の納品が求められる場合、その範囲と受け入れの条件は何か

請負の形で受ける場合は、完成に対する責任を負います。役割と契約の形が合っているかを確かめましょう。違いは準委任契約と請負契約の違いで解説しています。

7. 稼働の振れ幅と精算

組込みの稼働は、試作と評価の日程で大きく振れます。

  • 試作基板の遅れで手待ちが出たとき、稼働はどう扱うか
  • 評価の終盤や量産前に、夜間や休日の作業があるか
  • 精算幅を超えたときと、下回ったときの扱い

手待ちの間に何をするかを事前に決めておくと、稼働が下回る月の心配を減らせます。精算の仕組みは精算幅の記事をご覧ください。

8. 秘密の条件と掛け持ち

発表前の製品を扱う組込みの案件では、秘密保持の条件が細かく決められていることがあります。

  • 試作品や資料の撮影・持ち出しのルール
  • 同じ製品分野の別の会社の案件との掛け持ちに制限があるか
  • 外部のツールや生成AIのサービスにコードを入れてよいか

扱う技術によっては、輸出管理のルールが関わることもあります。秘密保持の考え方は秘密保持契約（NDA）の記事で解説しています。

注意

組込みの現場では、実機の前にいる人に「この試験もついでに」「別の機種も見てほしい」と頼みごとが集まりやすく、参画後に担当の範囲が少しずつ広がることがあります。契約の業務範囲に入っていない作業を頼まれたときは、引き受ける前に範囲と条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容、報酬の額、支払期日、役務の提供を受ける場所などを、書面やメールなどで明示することとされています（2026年10月時点、公正取引委員会の案内による）。明示される事項はフリーランス法で明示される取引条件をご覧ください。

組込みの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、担当する層と作業の範囲（実装、評価の不具合対応など）が書かれているか
  2. 作業の場所と、出社の扱いが聞いた内容と合っているか
  3. 完成や出荷後の不具合の責任を負う書き方になっていないか
  4. 稼働の幅と、超えたとき・下回ったときの精算方法
  5. 契約期間と更新の時期が、開発の局面と合っているか

契約期間については、6か月以上継続して業務を委託している場合、契約を解除したり更新しなかったりするときは、少なくとも30日前までに予告することが求められています（2026年10月時点、公正取引委員会の案内による）。評価の途中で契約の更新時期が来る場合は、見通しを早めに確かめておきましょう。考え方は契約解除・不更新の予告の記事で解説しています。

面談で聞いておくとよい質問は組込みエンジニアの面談でよく聞かれる質問と答え方の逆質問の項目でも紹介しています。一般的な逆質問の考え方は面談で聞いておくべき逆質問をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。組込みの案件で気になりやすい実機の環境や、評価の時期の出社と稼働の扱いなど、書面だけでは読み取りにくい点は、ご質問いただければ確認します。条件に迷う点があれば、契約の前に早めにご相談ください。

ポイント

  • 組込み案件は、同じファームウェア開発でも構成・局面・実機の環境で負担が大きく変わる
  • 担当の層と構成、局面、実機と計測器、出社の条件、品質の手順の重さを面談で確かめる
  • 準委任なのに完成や出荷後の不具合の責任を負う書き方になっていないかを確かめる
  • 稼働の振れ幅と精算、秘密と掛け持ちの条件、契約期間を書面と照らし合わせる

よくある質問

経験のないマイコンを使う案件は避けたほうがよいですか？

避ける必要はありません。近い系統の経験があり、資料を読んで立ち上げた経験があれば対応できることが多くあります。ただし、立ち上がりに時間がかかる可能性を面談で伝え、最初の数週間に期待されている成果を確かめてから受けることをおすすめします。

試作基板の遅れで手待ちになったら、報酬は減りますか？

契約の形と精算の条件によります。稼働の時間で精算する契約では、手待ちの間に別の作業が割り当てられるかどうかで稼働が変わります。手待ちが出たときの扱いを契約前に確かめておくと安心です。

報酬の高い案件と、実機の環境が整った案件で迷ったらどうしますか？

一概には言えませんが、組込みでは実機や計測器を使える時間が足りないと、作業が進まずに稼働が延び、時間あたりの報酬が下がることがあります。報酬の額だけでなく、環境と稼働の見込みを合わせて比べるとよいでしょう。報酬の決まり方は組込みエンジニアの報酬の記事で解説しています。
