モバイルアプリ開発

Androidエンジニアのフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい7つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

フリーランスのAndroid案件を選ぶときは、報酬や稼働日数に加えて、役割と範囲、コードの今の状態、targetSdkなどの要件対応の予定、検証端末の用意、ストアと署名の扱い、稼働の波、契約の形と期間の7点を契約前に確かめておくことが大切です。Androidの案件は、同じ「Androidエンジニア募集」でも、この7点の違いで毎日の負担が大きく変わります。

特に見落としやすいのは、端末とリリースにまつわる仕事を誰が担うかです。案件票には実装の話しか書かれていなくても、参画してみると端末の確認やストアへの提出が当然のように任されることがあります。この記事では、Android案件に固有の確認点を整理します。契約書全般の確認点は業務委託契約書のチェックポイントで解説しています。

Android案件の選び方で差が出る理由

Androidの案件票は、「Kotlin」「Jetpack Compose」「MVVM」のように技術の名前が並ぶことが多く、仕事の中身はそこから読み取りにくいのが実情です。参画してから想定との違いに気づくことが少なくありません。

よくあるずれは次のようなものです。

  • Composeの案件と聞いていたが、実際は古いJavaとViewのコードの保守が中心だった
  • 機能開発のつもりで入ったら、targetSdkの対応の期限が迫っていて、その作業が最優先になった
  • 検証端末が足りず、私物の端末で確認することになった
  • ストアへの提出やリリースの作業まで任され、リリース前の稼働が想定より大きく増えた

こうしたずれは、面談と条件の確認の段階で、聞き方を工夫すれば多くを防げます。案件の種類ごとの働き方はAndroidの仕事内容の記事で整理しています。

契約前に確かめたい7つの点

1. 役割と担う範囲

最初に確かめたいのは、自分が担う範囲です。画面の実装だけか、設計の判断も含むか、レビューを任されるか、リリースの作業まで担うかで、求められる経験も稼働の波も変わります。

面談では、「参画後の最初の1か月で、最も期待されている成果は何か」を聞くと、役割の実態が見えやすくなります。答えが「既存の機能の改修」なら実装が中心、「移行の方針づくり」なら設計の判断が中心です。

2. コードの今の状態

案件票の技術の名前は、目指している姿であることもあります。今のコードの状態を確かめます。

  • KotlinとJavaの比率、ComposeとViewの比率
  • 主なアーキテクチャと、それがどこまで守られているか
  • テストがどの程度書かれているか
  • 古いライブラリや、更新の止まったSDKが残っていないか

古いコードが多い案件を避ける必要はありません。移行の経験は評価にもつながります。ただ、状態を知ったうえで受けることが大切です。

3. targetSdkなどの要件対応の予定

Google Playでは、2026年8月31日以降、新しいアプリとアプリの更新はAndroid 16（APIレベル36）以上を対象にする必要があると案内されています（スマートフォン向けの場合。2026年10月時点のAndroid Developersの案内）。要件を満たさない既存のアプリは、新しいOSの端末を使う新しい利用者に表示されなくなるとも案内されています。

この要件は毎年のように引き上げられてきたため、参画の時期によっては、対応が最優先の仕事になります。次の点を確かめておくと、参画後の優先順位が読めます。

  • 今のtargetSdkと、次の対応の予定
  • 対応を誰が担うか、自分の担当に入るか
  • 組み込んでいるSDKやライブラリの対応の見通し

Google Play以外で配布している業務用のアプリでも、配布の仕組みが変わることがあります。Android Developersでは、開発者の本人確認の仕組みを2027年に世界の対象の端末へ広げる予定と案内されています（2026年10月時点）。業務用端末の案件では、配布の方法と今後の対応を誰が見ているかも聞いておくと安心です。

エージェントベストの見解

Androidの案件をご紹介していると、参画後に「聞いていた状況と違った」となりやすいのは、コードの状態と、要件対応の期限の2点です。面談では聞きにくいと感じる方もいますが、立ち上がりの計画を立てるために必要な確認として聞けば、多くの発注元は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

4. 検証端末の用意と、確認する範囲

Androidならではの確認点です。

  • 検証用の端末は発注元が貸与するか、何台程度あるか
  • 確認する機種とOSの版の範囲を、誰が決めるか
  • 遠隔の実機サービスを使えるか
  • 業務用端末の案件なら、端末をどこで受け取り、どこで使うか

端末の貸与がない案件では、私物の端末での確認を求められることがあります。私物を使う場合は、情報の扱いのルールと、費用を誰が負担するかを確かめておきましょう。リモートとの関係はAndroidのリモート案件の記事で解説しています。

5. ストア・署名・アカウントの扱い

リリースにまつわる作業の担当を確かめます。

  • ストアへの提出や、段階的な公開の操作を誰が担うか
  • ストアの管理画面に自分のアカウントで入るのか、発注元のアカウントを使うのか
  • 署名の鍵をどこに保管し、誰が扱うか

Android Developersでは、アプリの署名の鍵やアップロード用の鍵は秘密にし、安全な場所に保管するよう求められています。新しいアプリをGoogle Playに公開するときは、Play App Signingの設定も必要です（2026年10月時点）。鍵やアカウントの扱いは、トラブルが起きたときの責任の所在にも関わるため、自分の手元に鍵を置かない運用かを確かめておくと安心です。

6. 稼働の波と精算

Androidの稼働は、リリースの周期で波が出ます。

  • リリース前の確認や修正で、稼働が増える時期があるか
  • リリース後の不具合への対応の体制に、自分が入るか
  • 精算幅を超えたときの扱いと、稼働が少ない月の扱い

リリース後のクラッシュの対応や、ストアの審査で差し戻されたときの修正は、予定外の稼働になりやすい仕事です。超過した時間の扱いを確かめておかないと、無償で対応し続けることになりかねません。精算の仕組みは精算幅の記事をご覧ください。

7. 契約の形と期間

フリーランスのAndroidエンジニアは、多くの場合、準委任契約で参画します。新規アプリの開発を受託の形で請け負う場合は、請負契約になることもあります。請負では、完成したアプリを納めることが約束の中身になり、検収や不具合への責任の考え方が変わります。契約の形の違いは準委任契約と請負契約の違いで解説しています。

契約の期間と、アプリの節目が合っているかも確かめます。たとえば、移行の途中や大きなリリースの直前に契約の更新時期が来ると、更新されなかった場合に区切りの悪いところで離れることになります。

注意

Androidの案件では、参画後に仕事が少しずつ広がりやすい傾向があります。iOS版の修正の手伝い、サーバー側のAPIの改修、ストアの掲載情報の作成など、契約の業務範囲に入っていない仕事を頼まれたときは、引き受ける前に範囲と条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容、報酬の額、支払期日などの取引条件を、書面または電子メールなどで明示することとされています（2026年10月時点、公正取引委員会の案内による）。明示される事項の内容はフリーランス法で明示される取引条件をご覧ください。

Androidの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、担う範囲（実装、レビュー、端末での確認、リリースの作業など）が書かれているか
  2. 請負の場合、納めるものと検収の方法が書かれているか
  3. 検証端末や機材の貸与と、返却の扱い
  4. 稼働の幅と、超えたときの精算方法
  5. 契約期間と更新の時期

面談で聞いておくとよい質問はAndroidの面談でよく聞かれる質問と答え方の逆質問の項目、面談の前にそろえておく確認点は案件の面談前に確認しておくべき項目チェックリストでも紹介しています。報酬の決まり方はAndroidの報酬の記事をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。Androidの案件で気になりやすい検証端末の貸与や、リリースの作業の担当など、書面だけでは読み取りにくい点は、ご質問いただければ確認します。

ポイント

  • Androidの案件は、同じ募集でもコードの状態、端末の範囲、リリースの担当で負担が大きく変わる
  • 役割と範囲、コードの状態、要件対応の予定を面談で確かめる
  • 検証端末の用意、ストア・署名・アカウントの扱いはAndroidならではの確認点
  • 稼働の波と精算、契約の形と期間を書面と照らし合わせる

よくある質問

古いJavaのコードが多い案件は避けたほうがよいですか？

避ける必要はありません。移行や保守の経験は、次の案件で評価されやすい経験です。ただし、新しい書き方を使える範囲、移行を進める計画があるか、テストがどの程度あるかを確かめてから受けることをおすすめします。

検証端末を自分で用意するよう言われたら、どうすればよいですか？

まず、確認する機種の範囲と、私物の端末に発注元のアプリや情報を入れてよいかのルールを確かめます。費用を誰が負担するかも、契約の前に決めておきましょう。範囲が広いのに貸与がない場合は、遠隔の実機サービスを使えるかを尋ねる方法もあります。

報酬の高い案件と、コードの状態がよい案件で迷ったらどうしますか？

一概には言えませんが、古いコードが多い案件は、見積もりより作業が膨らみ、稼働が増えて時間あたりの報酬が下がることがあります。報酬の額だけでなく、コードの状態、要件対応の期限、稼働の見込みを合わせて比べるとよいでしょう。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 単価・報酬交渉

精算幅（140〜180時間など）とは｜超過・控除の計算方法

精算幅は、月額報酬のままでよい稼働時間の範囲です。上限を超えると超過分が加算され、下限を下回ると控除されます。超過・控除の単価は上下割か中間割かで変わるため、仮の数字を使って計算方法を整理します。

 スキルシート・面談

業務委託の面談で聞いておくべき逆質問｜参画後のずれを防ぐ確認項目

業務委託の面談の逆質問は、印象づくりより「参画後のずれを防ぐ確認」に使うのが基本です。業務の範囲、体制と指示の流れ、稼働の実態、期間の見込みの4つを確かめておくと、契約後の「話が違う」を減らせます。
