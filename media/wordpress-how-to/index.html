Web制作・デザイン

WordPressエンジニアがフリーランスになるには｜必要な経験と独立までの進め方

公開 2026-10-29　監修：株式会社エージェントベスト

WordPressエンジニアとしてフリーランスになるには、テーマやプラグインをPHPで書いた経験と、運用中のサイトを更新・修正した経験の両方があると、受けられる案件を選びやすくなります。作る経験だけだと構築の請負に偏りやすく、守る経験があると継続の案件にも応募しやすくなるためです。

目安になるのは年数より、一つのサイトを、設計から公開後の更新まで一人で任せてもらえるかです。この記事では、独立前に持っておきたい経験の目安、出身ごとに補うもの、独立までの進め方を整理します。開業届や税金などの手続きは、それぞれの記事にリンクで渡します。

独立前に持っておきたい経験の目安

WordPressの案件で、最初の面談で確かめられやすいのは次の経験です。すべてそろっている必要はありませんが、どこが足りないかを把握しておくと準備の順番を決めやすくなります。

経験目安
テーマの開発既製テーマの調整だけでなく、テンプレートを自分で書いたことがある
カスタム投稿タイプ・カスタムフィールド入力する人が迷わない画面を設計したことがある
プラグインの開発小さくても、フックを使って機能を足すプラグインを書いたことがある
ブロックエディタ既製ブロックでの組み立てに加え、独自ブロックかブロックパターンを作ったことがある
更新と不具合対応本体・プラグイン・PHPの更新で起きた不具合を、原因を調べて直したことがある
サーバードメイン、SSL、バックアップ、PHPの版の切り替えを自分で扱ったことがある

WordPressの公式サイトは、2026年10月時点で推奨環境をPHP 8.3以上、MySQL 8.0以上またはMariaDB 10.11以上、HTTPS対応としています。推奨環境と古い環境の違いを説明できることも、運用中のサイトを任されるうえでの目安になります。

出身ごとに補うもの

制作会社でサイトを作ってきた場合

短い納期で多くのサイトを仕上げてきた方は、構築の段取りと、顧客とのやり取りに慣れていることが強みです。一方で、公開して納めたら手を離れる働き方だと、公開後の更新や障害の経験が少ないことがあります。自社で保守を受けているサイトがあれば、更新作業に加わっておくと、独立後に継続の案件を受けやすくなります。

事業会社でサイトやメディアを運用してきた場合

自社のサイトやメディアを長く運用してきた方は、更新や不具合への対応、入稿する人とのやり取りに慣れています。補いたいのは、ゼロから設計した経験と、社外の発注元に見積もりや範囲を説明する経験です。社内の仕組みを当たり前に使ってきた部分を、社外の人に説明できるか見直しておくと安心です。

デザインやコーディングから広げてきた場合

HTMLとCSSでのコーディングからWordPressに入った方は、見た目を正確に作る力が強みです。WordPressエンジニアとして受けるなら、PHPでテンプレートや機能を書く経験を足すことが近道です。デザインを軸に独立する場合の考え方はWebデザイナーがフリーランスになるにはで扱っています。

Laravelなどの開発からWordPressも担う場合

PHPのフレームワークでの開発経験がある方は、コードの品質やテストの考え方を持ち込めます。一方で、WordPress独自のフックの考え方や、管理画面で設定を変える人がいる前提の作り方には慣れが必要です。PHP全般で独立する場合の進め方はPHPエンジニアがフリーランスになるにはをご覧ください。

エージェントベストの見解

WordPressの案件をご紹介していると、独立したばかりの方がつまずきやすいのは、技術よりも「どこまでが自分の仕事か」の線引きです。構築の案件で公開後の修正をどこまで受けるか、保守の案件で障害時にどこまで動くかを決めないまま始めると、作業が増え続けることがあります。当社では、契約で業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。範囲で迷う点は、ご質問いただければ確認します。

独立までの進め方

1. 経歴を「構築」「機能開発」「保守」に分けて棚卸しする

担当したサイトを並べ、それぞれで「新しく作った」「機能を足した」「更新や不具合に対応した」のどれをしたかを書き出します。件数が多い方は、代表的なものを数件選び、自分が判断したことを中心にまとめます。

2. 手元に検証の環境を持つ

案件ごとに、本番と同じPHPとWordPressの版で動く環境を手元に作れるようにしておきます。更新の前に手元で確かめる習慣は、独立後に一人で作業するときの土台になります。

3. 小さなプラグインかブロックを自分で作る

業務で作ったコードは外に出せないことがほとんどです。小さくてもよいので、自分で作ったプラグインやブロックを手元に持っておくと、面談で書き方を説明しやすくなります。WordPress.orgのプラグインディレクトリに公開する場合、コードや画像などはGPLかGPL互換のライセンスである必要があります（2026年10月時点の公式ガイドライン）。ライセンスの基本はOSSライセンスの記事で扱っています。

4. スキルシートを用意する

WordPressの経験は「WordPress」とひとまとめにせず、何を作り、何を直したかが分かるように書きます。書き方はWordPressエンジニアのスキルシートの記事、全体の構成はスキルシートの基本で解説しています。

5. 受けたい仕事の型と条件を決めて探す

構築の請負を中心にするのか、保守や改修の継続案件を中心にするのかで、探し方と契約の形が変わります。稼働日数、リモートの可否、受ける範囲を先に決めておくと、案件を比べやすくなります。

6. 見積もりと範囲の書き方を用意する

構築の請負を受ける場合は、見積もりと一緒に「何を作り、何を作らないか」を書いた範囲の説明を出せるようにしておきます。テンプレートの数、独自ブロックの数、公開後の修正を何回まで受けるかを分けて書くと、追加の依頼があったときの話がしやすくなります。見積書の書き方は見積書の記事で解説しています。

一人で受ける前に決めておくこと

会社員のときはチームで分けていた責任を、独立後は自分で持つことになります。WordPressの仕事では、とくに次の点を先に決めておくと安心です。

  • バックアップの責任：誰が、どこに、どの頻度で取り、誰が戻すのか
  • アカウントの扱い：管理画面やサーバーのアカウントを自分専用に発行してもらえるか
  • 公開後の対応：公開後の修正を何日・何回まで受けるか
  • 更新の判断：本体やプラグインの更新を、誰の判断で行うのか

注意

発注元のサーバーや管理画面のアカウントを、会社員時代のものや共有のものでそのまま使い続けると、問題が起きたときに誰の操作か分からなくなります。独立後は、案件ごとに自分専用のアカウントを発行してもらい、終了時に返却する流れを確かめておきましょう。

独立直後に受けやすい仕事と注意点

独立したばかりの時期は、実績を作るために小さな構築の仕事を数多く受けたくなることがあります。ただ、構築の請負ばかりが続くと、毎月の収入が案件の切れ目で途切れやすくなります。継続の保守や、既存サイトの改修のように、期間を決めて関われる仕事を一つ持っておくと、収入の見通しを立てやすくなります。

手続きと独立の準備

開業届の出し方は開業届の記事、独立前にそろえておきたいことは独立前の準備の記事で解説しています。最初の案件に入るときの心構えは初めての案件の記事をご覧ください。

エージェントベストの見解

WordPressの面談で評価されやすいのは、作ったサイトの見た目よりも、「入力する人が迷わない管理画面にするために何を考えたか」「更新で困らない作りにするために何を避けたか」を話せる方です。独立前の棚卸しでは、こうした判断を一つずつ言葉にしておくことをおすすめします。

ポイント

  • 独立の目安は年数より、一つのサイトを設計から公開後の更新まで任せてもらえるか
  • 作る経験と守る経験の両方があると、構築と保守の両方の案件を選べる
  • 出身によって補うものが違う。制作会社なら公開後の更新、運用担当なら設計と社外への説明

よくある質問

WordPressの経験は何年あれば独立できますか？

年数の決まりはありません。案件の側が見るのは、テーマやプラグインをどこまで自分で書いたか、更新や不具合にどう対応したかです。一つのサイトを一人で任せてもらえるかを目安に、足りない経験を補ってから独立することをおすすめします。

PHPをあまり書けなくても受けられる案件はありますか？

管理画面での設定や入稿の支援など、コードをあまり書かない仕事もあります。ただ、WordPressエンジニアとして受ける案件では、テーマやプラグインをPHPで書けることが前提になることが多いため、PHPの経験を足しておくと選べる案件が増えます。

会社員のうちに副業で受けてから独立したほうがよいですか？

副業で小さな案件を受けてみると、見積もりや範囲の決め方を実際に経験できます。ただし、勤め先の就業規則で副業が認められているか、同業の仕事を受けてよいかを先に確かめてください。
