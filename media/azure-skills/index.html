Azureのフリーランス案件では、Microsoft Entra IDとAzure RBACで「誰に何を許すか」を設計する力、管理グループとサブスクリプションを使って環境全体の統制を組み立てる力（ランディングゾーンの設計）、社内ネットワークとのハイブリッド接続、Bicepなどで構成をコードにする力が中心に見られます。Azureを使う企業の多くはMicrosoft 365や社内のActive Directoryと一体で運用しているため、Azureの個々のサービスより、組織全体の仕組みの中で設計できるかが問われやすいのが特徴です。

この記事では、Azureの案件で求められるスキルを分野ごとに整理し、認定資格の扱いと、スキルシートや面談での示し方を解説します。独立までの準備や在職中に積みたい実績はAzureエンジニアがフリーランスになるにはにまとめています。

IDと権限：Entra IDとAzure RBAC

Azureの権限は、ユーザーやグループ、アプリの身元（ID）をMicrosoft Entra IDで管理し、Azureのリソースへの操作権限をAzure RBAC（ロールの割り当て）で与える、という二段の仕組みです。案件で問われるのは、この二つを組み合わせて権限を必要な範囲に絞る設計です。

  • ロールをユーザー個人ではなくグループに割り当て、異動や退職の際の管理を楽にした
  • 割り当ての範囲（管理グループ、サブスクリプション、リソースグループ、リソース）を、最小限にとどめた
  • アプリからAzureのサービスに接続するときに、パスワードや鍵を埋め込まず、マネージドIDを使った
  • 強い権限を常に持たせず、必要なときだけ使う運用にした

Entra IDの設定は、Azureだけでなく、Microsoft 365を使う全社員のサインインに影響することがあります。変更の影響範囲を事前に説明できることが、外部の立場で任されるための条件になりやすい部分です。

ランディングゾーンとガバナンスの設計

Microsoftのクラウド導入フレームワーク（Cloud Adoption Framework）では、複数のサブスクリプションからなるAzure環境を統制し、安全に広げていくための構成として「Azureランディングゾーン」を示しています。Microsoft Learnでは、ランディングゾーンは次の2つで構成されると説明されています。

構成要素役割
プラットフォーム ランディングゾーンすべてのワークロードに共通する統制、セキュリティ、共有の資源を集めた土台。多くの組織では、Entra IDのテナントごとに一つ持つ
ワークロード ランディングゾーン各システム（ワークロード）のチームが、土台の決まりの範囲で資源を置いて運用する場所。開発・テスト・本番などの環境を含む

土台の中心になるのが管理グループの階層です。サブスクリプションを階層に並べ、上位に割り当てたAzure Policyを下位に引き継がせることで、決まりをそろえて適用します。新しいワークロードのためにサブスクリプションを払い出す手順を決め、必要に応じて自動化することも、土台の重要な役割とされています。

案件では、次のような経験が評価されます。

  • 管理グループの階層を設計し、本番と開発、社内向けと外部公開向けを分けた
  • Azure Policyで、許可するリージョンやリソースの種類、必須のタグなどを決めて適用した
  • 部署ごとに作られていたサブスクリプションを、ランディングゾーンの考え方に沿って整理した

AWSの複数アカウントの統制と考え方は似ていますが、Azureではテナント、管理グループ、サブスクリプションという単位と、Entra IDとの結び付きが設計の前提になります。AWSのスキルの見られ方はAWSの案件で求められるスキルで解説しています。

エージェントベストの見解

Azureの案件をご紹介していると、面談で評価されやすいのは、個々のサービスを構築した経験より「その環境がどの管理グループやポリシーの下にあり、誰が何を決めていたか」を説明できる方です。構築だけを担当していた方も、決まりを作った側の意図を理解していると、基盤の整備や見直しの案件で話が通りやすくなります。スキルシートには、関わった環境の統制の仕組みを一行添えることをおすすめします。

ネットワークとハイブリッド接続

Azureの案件の多くは、社内のネットワークと切り離せません。ランディングゾーンの参考構成でも、ハブ＆スポーク型とVirtual WAN型のネットワークが示され、接続用のサブスクリプションにファイアウォールやVPN・ExpressRouteのゲートウェイ、DNSを集める形が描かれています。

案件で見られやすいのは次の点です。

  • ハブ＆スポークのどこに何を置き、通信をどの経路で通したか
  • オンプレミスとVPNや専用線（ExpressRoute）で接続し、経路や名前解決の問題を解消した経験
  • Azureのサービスへの通信を、インターネットを通らないプライベートな経路に限定した経験
  • 通信の制御（ネットワークセキュリティグループ、ファイアウォール）のルールを整理した経験

ネットワークの基礎が強い方は、Azureの案件でも頼りにされやすい分野です。ネットワーク側のスキルはネットワークエンジニアの案件で求められるスキルも参考になります。

Bicepなどで構成をコードにする力

Microsoft Learnでは、BicepはAzureのリソースを宣言的に記述してデプロイするための言語と説明されています。主な特徴として、次の点が挙げられています。

  • 新しいリソースの種類やAPIの版にすぐ対応する
  • デプロイ前に、作成・変更・削除されるリソースを確かめる仕組み（what-if）がある
  • 状態はAzure側が持つため、状態ファイルを自分で管理する必要がない
  • モジュールに分けて再利用できる

複数のクラウドを扱う会社ではTerraformを使う案件もあります。どちらを使った場合でも、ポータルで作られた既存環境をコードに取り込んだ経験と、本番に反映する前に差分を確かめる流れを作った経験は評価されやすい部分です。

設計の観点：Azure Well-Architected Framework

Microsoftは設計の指針として、Azure Well-Architected Frameworkを公開しています。信頼性、セキュリティ、コストの最適化、オペレーショナル エクセレンス、パフォーマンス効率の5つの柱で構成され、Azure Advisorの推奨事項もこの柱を基準にしています。設計レビューや改善提案の場面で、どの柱を優先し、何をあきらめたかを説明できると、上流の役割に近い案件で評価されます。

認定資格の扱い

Microsoftの認定資格は、知識の範囲を示す材料になります。2026年10月時点のMicrosoft Learnの案内では、たとえば次の認定があります。

認定試験主な範囲
Azure管理者アソシエイトAZ-104IDとガバナンス、ストレージ、コンピューティング、仮想ネットワーク、監視と保守
Azure ネットワーク エンジニア アソシエイトAZ-700コアネットワーク、接続サービス、アプリケーション配信、Azureサービスへのプライベートな接続、ネットワークのセキュリティ

どちらも更新の頻度は12か月とされています。設計者向けのAzure ソリューション アーキテクト エキスパートの取得条件と更新の方法は、Azureエンジニアがフリーランスになるにはで紹介しています。

なお、Azure セキュリティ エンジニア アソシエイト（AZ-500）は、認定・試験・更新の評価が2026年8月31日に廃止されたと案内されています。すでに持っている方は、スキルシートに書く際に取得時期を添え、学んだ範囲を実務の経験とあわせて説明するとよいでしょう。セキュリティ寄りの案件で求められるスキルはセキュリティエンジニアの案件で求められるスキルで解説しています。

注意

認定資格は廃止や名称の変更が起こります。スキルシートに古い名称のまま書いたり、有効期限が切れた資格を有効なように書いたりすると、確認の段階で行き違いが生じることがあります。書く前に、Microsoft Learnの自分の資格情報で状態と期限を確かめておきましょう。

スキルシートと面談での示し方

Azureのスキルシートでは、プロジェクトごとに次の点を書くと、経験の中身が伝わります。

  • 環境の規模（サブスクリプションの数、利用者の規模など、伏せられる範囲で）
  • 統制の仕組み（管理グループ、ポリシー、権限の付け方）と、自分の関わり方
  • ネットワークの構成とオンプレミスとの接続
  • 使ったIaCのツールとCI/CD
  • 担当した工程と、工夫した点・結果

面談では、構成図を口頭で説明しながら、権限とネットワークの境目をどこに置いたかを話せると、理解の深さが伝わります。書き方はAzureのスキルシートの書き方とスキルシートの基本をご覧ください。Google Cloudとの比較はGCPの案件で求められるスキルも参考になります。

エージェントベストの見解

当社では、案件をご案内する前に、稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをお出ししています。経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せて提案しています。Azureの案件は、IDの整備、基盤の設計、移行、運用のどれが中心かで求められる経験が大きく変わるため、ご希望の仕事の種類もあわせて整理しておくことをおすすめします。

ポイント

  • Azureの案件では、Entra IDとRBACの権限設計、ランディングゾーンによる統制、ハイブリッド接続、構成のコード化が見られる
  • ランディングゾーンは、共通の土台と、各システムが使う場所の2つで構成される
  • Bicepはwhat-ifで変更を事前に確かめられ、状態ファイルの管理が要らない
  • AZ-500は2026年8月31日に廃止。資格は状態と期限を確かめてから書く

よくある質問

Microsoft 365の管理経験はAzureの案件で評価されますか？

Entra IDのユーザーやグループ、条件付きアクセスの管理の経験は、Azureの権限設計に直結するため評価されます。そのうえで、サブスクリプションやネットワークなど、Azureのリソース側の経験を足していくと、参画できる案件が広がります。

ランディングゾーンを一から作った経験がないと不利ですか？

一から設計する案件は限られており、多くの案件は既存の環境の上で構築や運用を行います。大切なのは、自分が関わった環境の統制の仕組みを理解し、その決まりに沿って作業できることです。既存の環境の見直しに関わった経験があれば、十分に伝えられる材料になります。

TerraformとBicepのどちらを学ぶべきですか？

Azureだけを使う会社ではBicepやARMテンプレートが、複数のクラウドを使う会社ではTerraformが使われる傾向があります。応募したい案件の求人票を見て、多く挙がっている方から始めるのが現実的です。どちらでも、既存の環境の取り込みと、デプロイ前の差分確認の考え方は共通しています。
