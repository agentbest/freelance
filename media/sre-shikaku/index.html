SREに資格は必要？フリーランス案件で評価される資格と実務との組み合わせ方

公開 2026-11-04　監修：株式会社エージェントベスト

フリーランスのSRE（サイト信頼性エンジニア）に、資格は必須ではありません。SREの案件の多くは、どの規模の基盤で、障害のときにどんな役割を担い、そこから何を仕組みとして変えたかで参画が決まります。SLOの設計や障害の振り返りといったSREの中心の仕事を、そのまま測る資格はほとんどないためです。

一方で、資格が効く場面ははっきりあります。KubernetesやクラウドなどSREが日々触る基盤の技術を短く示したいとき、インフラ運用やバックエンド開発からSREへ役割を広げたいときです。この記事では、SREにとって評価されやすい資格と効きにくい資格を分け、実務経験とどう組み合わせると効くかを整理します。資格全般の考え方は資格はフリーランスの案件獲得に役立つ？で解説しています。

資格がなくてもSRE案件に入れる理由

SREの仕事は、信頼性の目標を数字で決め、監視と振り返りを回し、手作業をコードに置き換えて、壊れにくく直しやすい基盤にしていくことです。この力は、試験の点数より、本番の環境での振る舞いに表れます。発注元のSREチームのリーダーも障害対応の経験者であることが多く、面談で障害の場面を掘り下げれば力量を測れると考えています。

そのため、案件票の必須条件に資格の名前が入ることは多くありません。必須に並ぶのは「Kubernetesの運用経験」「IaCでの構築経験」「オンコールの経験」のような実務の条件で、資格は「歓迎」の扱いがほとんどです。資格がないことを理由に応募をあきらめる必要はなく、まずはSREのスキルシートで障害対応と改善の経験を伝わる形にすることが先です。

資格が効く4つの場面

場面資格が効く理由
基盤の技術を任される案件Kubernetesやクラウドを一定の水準で扱えることを短く示せる
インフラ運用・開発からSREへ移るときSREとしての経験が浅い部分を、体系的な知識で補える
使ったことのないクラウドの案件別のクラウドの経験を、新しい環境でも生かせる裏付けになる
書類で比べられる段階候補者が並んだとき、技術の幅を短く伝える材料になる

どの場面でも、資格は「この人なら基盤を触らせても大丈夫そうだ」という判断の後押しにはなりますが、それだけで決まることはありません。資格が効くのは、障害対応や改善の実績と並べたときに、技術の裏付けとして働く場合です。

エージェントベストの見解

SREの案件をご紹介していると、資格を多く持っている方でも、面談で評価が分かれるのは障害の場面をどれだけ具体的に話せるかです。一方で、インフラ運用やバックエンド開発からSREの案件に応募するときは、Kubernetesやクラウドの資格が「基盤を体系的に理解している」ことの裏付けになり、書類の段階で目に留まりやすくなる傾向があります。資格は実績の代わりではなく、実績を伝える助けになるものと考えることをおすすめします。

SREにとって評価されやすい資格

CKA（Certified Kubernetes Administrator）

The Linux Foundationが認定する、Kubernetesのクラスタを管理する力を測る資格です。コマンドラインで実際に課題を解く、監督付きのオンライン実技試験で、試験時間は2時間、資格の有効期間は2年間とされています（2026年10月時点、The Linux Foundationの案内による）。選択式ではなく手を動かす試験のため、コンテナ基盤を扱う案件では実務に近い裏付けとして受け止められやすい資格です。受験料は為替や割引で変わるため、公式サイトで最新をご確認ください。詳しくはCKAの記事で解説しています。

クラウドのDevOps系の上位認定

クラウド各社には、運用と開発をつなぐ仕事を対象にした上位の認定があります。

  • Google CloudのProfessional Cloud DevOps Engineer：試験で測る力の一つに「SREの実践を適用すること」が挙げられており、可観測性やCI/CDも範囲に入っています。試験時間は2時間で、日本語でも受験できます（2026年10月時点、Google Cloudの案内による）
  • AWS Certified DevOps Engineer - Professional：AWS上での運用と自動化を対象にした上位の認定で、有効期間は3年間とされています（2026年10月時点、AWSの案内による）

SREの案件はクラウドの上で動くことが多いため、主に使うクラウドに合わせて選ぶと効きやすくなります。クラウドの基礎的な認定はAWSソリューションアーキテクトの記事やGoogle Cloudの認定の記事、Azureの認定の記事で整理しています。

Terraformの認定

IaCで基盤を管理する案件では、Terraformの認定が「コードで基盤を扱える」ことの裏付けになります。トイルの削減や基盤の移行の案件と相性がよい資格です。詳しくはTerraformの認定の記事をご覧ください。

SRE案件では効きにくい資格

資格の価値がないわけではありませんが、SREの案件で参画の判断に直接つながりにくいものもあります。

  • 入門レベルの資格だけ：クラウドの入門的な認定は、SREの案件では前提の知識として扱われ、それだけでは差がつきにくくなります
  • 運用の管理の枠組みの資格：ITILの認定は、運用のプロセスを整える案件では役立ちますが、SLOや自動化が中心の案件では評価の中心になりにくい傾向があります
  • 実務と離れた分野の資格：案件の基盤と関係の薄い製品の資格は、数を並べても技術の深さの証明になりにくくなります

Linuxやネットワークの資格は、基盤の基礎を示す材料として一定の効果があります。LinuCの記事も参考になります。IPAのネットワークスペシャリスト試験などの情報処理技術者試験は、現行の試験制度が2026年度の実施で終わり、2027年度から新しい制度に移る予定です（2026年10月時点、IPAの案内による）。受験を考える場合は、制度の移行をふまえて計画しましょう。

注意

資格を取るために、本業の案件で障害対応や改善の実績を積む時間を削ってしまうのは本末転倒です。SREの案件では、資格より「障害のときに何をして、何を変えたか」が問われます。資格の勉強は、今の案件で使っている技術の理解を深める方向で選ぶと、実績と資格の両方が積み上がりやすくなります。

実務経験との組み合わせ方

資格は、実務の経験と組み合わせたときに効きます。経験に応じた組み合わせの例は次のとおりです。

今の経験足すと効きやすい資格組み合わせのねらい
インフラ運用が中心CKA、Terraformの認定コンテナとIaCを扱えることを示し、自動化の担い手に広げる
バックエンド開発が中心クラウドのDevOps系の認定、CKA基盤と運用の知識を補い、開発と運用をつなぐ役割に広げる
SREの経験がある主に使うクラウドの上位認定別のクラウドの案件にも選択肢を広げる

どの組み合わせでも、資格だけを足すのではなく、資格で学んだことを今の現場で一度使い、その経験をスキルシートに書ける状態にすると効果が上がります。

スキルシートと面談での伝え方

スキルシートでは、資格の欄に名前を並べるだけでなく、取得した年月と、その技術を使った案件を結びつけて書きます。たとえば「CKA取得後、コンテナ基盤の版上げの手順を整えた」のように、資格と実務をつなげると、面談官が経験の深さを想像しやすくなります。

有効期間のある資格は、期限が切れていないかを確かめてから書きましょう。期限が切れた資格は、取得していた時期を書いたうえで「更新なし」と添えるなど、今も有効だと読めない書き方にします。学習中の資格は受験予定の時期とあわせて書くと、学ぶ姿勢が伝わります。

面談で資格について聞かれたときは、試験で学んだことより、その知識を使って現場で何を判断したかを話すほうが評価されます。面談の準備はSREの面談でよく聞かれる質問で解説しています。

エージェントベストの見解

当社では、経歴をご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。資格は、案件の基盤の技術と合っているときに、ご提案の際の材料として生かしやすくなります。どの資格が案件の条件に関係しそうか迷うときは、ご質問いただければ確認します。

ポイント

  • SREの案件は資格がなくても参画できるものが多く、障害対応と改善の実績が中心に見られる
  • 資格が効くのは、基盤の技術を任される場面や、インフラ運用・開発からSREへ移るとき
  • CKA、クラウドのDevOps系の上位認定、Terraformの認定は、SREの実務と結びつけやすい
  • 資格は取得年月と使った案件を結びつけて書き、有効期間を確かめる

よくある質問

SREを目指すなら、最初に取る資格はどれがよいですか？

今の案件や目指す案件で使う基盤に合わせて選ぶのが近道です。コンテナ基盤を扱うならCKA、特定のクラウドが中心ならそのクラウドの認定から考えるとよいでしょう。目指し方の全体はSREがフリーランスになるにはで解説しています。

SREそのものを認定する資格はありますか？

SREの考え方を試験範囲に含む認定はありますが、SLOの設計や障害の振り返りの力をそのまま測る資格はほとんどありません。そのため、資格と並べて、障害対応や改善の実績をスキルシートと面談で示すことが大切です。

有効期間が切れた資格はスキルシートに書いてよいですか？

取得していた事実は書いて構いませんが、今も有効だと読める書き方は避けます。取得した時期と「更新なし」を書き添え、その後に同じ技術を使った実務があれば、あわせて書くと伝わりやすくなります。
