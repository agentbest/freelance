SAP SD/MMコンサルの参画初月にやること｜現場で信頼される進め方

公開 2026-11-04　監修：株式会社エージェントベスト

SAP SD/MMコンサルの参画初月は、担当する業務の流れと設定の現状をつかみ、例外の処理を一覧にし、会計や外部システムとのつなぎ目の持ち主を確かめ、月末に小さな成果を一つ出すところまでを目標にします。最初の1か月で求められるのは、設定を大きく変えることより、この人に販売・購買の流れを任せて大丈夫だと発注側と業務部門が判断できる材料を示すことです。

参画前の契約・環境の準備は参画が決まってから開始日までにやること、職種を問わない最初の1週間の進め方は参画初日から最初の1週間でやることで解説しています。この記事では、SD/MMならではの初月の動き方に絞ります。

初月のゴールを3つに分ける

ゴール中身月末に手元にあるもの
流れと設定をつかむ担当する業務の流れ、組織構造、伝票タイプ、価格条件、アドオン、課題の実態を把握する流れの図に設定を書き込んだ一枚と、例外の処理の一覧
持ち主と決め方をつかむ会計・生産・外部システムとの境目を誰が持ち、どの会議で何を決めるかを知るつなぎ目と相談先の一覧
小さな成果を出す担当のタスクを一つ、設定からテストまで通して完結させる完了したタスクと、設定の記録

この3つを、1週目、2週目、3〜4週目の順に重心を移しながら進めます。

1週目：資料と環境と人から現状を集める

SD/MMとして最初に読む資料

SD/MMは、読む資料が業務とシステムの両方にまたがります。次の順で目を通すと、全体像をつかみやすくなります。

  1. 業務フローと要件定義書：受注から入金まで、購買依頼から支払までの流れ。どこが標準で、どこが作り込みか
  2. 組織構造の設定：販売組織、流通チャネル、購買組織、プラント、保管場所の構成。会社の拠点や部門とどう対応しているか
  3. 伝票タイプと価格条件の一覧：受注・出荷・請求、発注・入庫の伝票タイプ、価格の判定順、承認の条件
  4. アドオンとインターフェースの一覧：追加開発の目的と、EDIや倉庫管理システムとの受け渡しの項目
  5. 課題管理表と直近の議事録：決まっていないこと、業務部門から出ている要望、保留になっている例外

読みながら、「業務フローではこうなっているが、設定は違いそう」「この作り込みの理由が書かれていない」という点を書き留めておきます。この段階では結論を出さず、仮説としてためておきます。

環境を自分で動かす

資料だけでは分かりません。開発や検証の環境で、担当する流れを自分の手で一度通します。受注を登録して出荷と請求まで、発注を登録して入庫と請求書照合まで動かし、価格がどう決まるか、どの勘定に転記されるかを目で確かめます。権限が足りない、テストデータがないといった不足は、1週目のうちに窓口へ伝えます。

関係者と短く話す

発注側の責任者、業務部門のキーユーザー（営業・購買・物流）、FI/COの担当、ABAPの担当、PMと、それぞれ短い時間で話す機会をもらいます。聞くことは次の3つに絞ると、相手の負担になりません。

  • 販売・購買の仕組みで今一番困っていること
  • 「これは変えられない」と思っている運用
  • SD/MMの担当に期待すること

同じ質問を全員にすると、業務部門とシステム側の見方の違いがはっきりします。この違いが、例外の処理の手がかりになります。

2週目：例外を一覧にし、つなぎ目の持ち主を決める

例外の処理を自分から一覧にする

SD/MMでもっとも手戻りを生むのは、後から出てくる例外です。返品、分納、直送、無償出荷、価格の後決め、検収の差異、委託在庫、会社間の取引など、例外の候補を自分から並べ、「この取引はありますか。今はどう処理していますか」と業務部門に確認します。聞かれなければ口に出さない運用を、2週目のうちに引き出します。

つなぎ目の持ち主を名前で確かめる

勘定の決定、在庫の評価、差異の計上先、インターフェースのエラーの再処理など、SD/MMと隣の領域の境目にある項目を一覧にし、誰が設定を持ち、誰が確認するかをFI/COや外部システムの担当者と決めます。ここがあいまいなままだと、統合テストで食い違いが表に出ます。

報告の形を合わせる

発注側の責任者やPMに、どの頻度で、どの粒度の報告がほしいかを確かめ、初回の報告を出します。SD/MMの報告は、設定の進み具合より「業務部門に決めてもらう必要があること」を先に書くと読まれやすくなります。リモート中心の案件での伝え方はSD/MMコンサルのリモートの記事でも触れています。

エージェントベストの見解

SD/MMの案件紹介の現場で、参画後の評価が高い方に共通しているのは、最初の2週間で「例外の処理の一覧」を業務部門と共有していることです。通常の流れを理解しただけでなく、月末だけの請求や特定の得意先だけの直送まで拾い上げていると、業務部門は「自分たちの仕事を分かってくれる人」と早い段階で感じ取れます。初月は、設定を変えることより、例外を見えるようにすることを優先するのをおすすめします。

3〜4週目：小さな成果を一つ完結させる

担当のタスクを設定からテストまで通す

価格条件の追加、承認のルールの変更、帳票の仕様の整理など、担当のタスクを一つ選び、要件の確認、設定、単体の確認、業務部門への説明までを自分で通します。大きさより、一つを最後まで持ち切ることが信頼につながります。

設定の記録を残す

変えた設定の内容、理由、影響する伝票、確認した相手を一行ずつ記録します。移送の番号と対応づけておくと、あとから追えます。この記録は、2か月目以降の自分を助け、契約が終わるときの引き継ぎにもそのまま使えます。引き継ぎの考え方は契約終了時の引き継ぎの進め方で整理しています。

流れの図に設定を書き込む

1〜3週目で集めた情報を、業務の流れの図に「ここで使う伝票タイプ」「ここで決まる価格条件」「ここで会計に渡る」と書き込んだ一枚にまとめます。業務部門にもシステム側にも通じる共通の地図になり、2か月目以降の会話が早くなります。

案件の型によって初月の重心は変わる

同じSD/MMの案件でも、型によって初月に力を入れる場所が違います。

新規導入・要件定義中の案件

まだ設定がない段階で入る場合は、現状の設定を読むより、業務部門の商習慣を聞き取り、標準に寄せるか作り込むかの論点を一覧にすることが初月の中心になります。月末には、論点の一覧と、業務部門に決めてもらう必要があることを出せることを目指します。

ECCからの移行の案件

旧環境の設定とアドオンの棚卸しから始めます。それぞれが、どの伝票でどれだけ使われているかをデータで確かめ、作られた理由を業務部門に尋ねます。初月で全部を読み切れなくても、「分かったもの」「理由が不明なもの」を分けて示せれば十分です。移行の進め方そのものはS/4HANA移行の参画初月にやることで扱っています。

運用保守の案件

問い合わせ対応から入ることが多いため、初月は「伝票とマスタから原因を追う」場数を増やします。月末・期末の締め処理の手順と、過去に起きた障害の記録を先に読んでおくと、最初の締めで慌てずに済みます。

本番稼働の直後に入る案件

出荷や請求の混乱を収める時期です。新しい設計の提案より、止まっている伝票の切り分けと、業務部門の問い合わせへの回答の速さが求められます。課題管理表を自分で整え、優先順位を窓口と合わせることが初月の中心になります。

初月に避けたい動き

避けたい動き起きやすいこと代わりにすること
前任者の設定やアドオンを否定する業務部門が身構え、理由を教えてもらえなくなる事実と使われ方だけを示し、理由は仮説として尋ねる
標準に寄せる提案を一気に出す「現場を知らない人」と見られる例外を一覧にしてから、論点ごとに選択肢で出す
会計の設定を自分で決めてしまうFI/CO担当との境目を踏み越えたと受け取られるつなぎ目の持ち主を先に決め、決めた経緯を残す
検証環境を使わずに設定を変える他の担当のテストを止める変更の影響の範囲を示してから、手順どおりに進める
範囲外の作業（データの整備、説明会など）を抱え込む本来の設定とテストが手薄になる担う範囲を確かめ、外れる依頼は窓口と話す

範囲外の依頼が増えてきたときの扱いは作業範囲が広がったときの契約の扱い、SD/MMがつまずきやすい場面はSD/MMコンサルのフリーランスがつまずきやすい点と対策で整理しています。

注意

稼働直後や移行の山場の案件では、初月から「すぐに設定を直してほしい」と求められることがあります。それでも、その設定がどの伝票で使われ、会計に何を渡しているかを確かめる前に変えると、別の取引や月末の処理が止まることがあります。影響の範囲を確かめてから変える、という進め方を参画の時点で発注側と合意しておくと、後で動きやすくなります。

1か月の終わりに振り返ること

1か月が過ぎたら、次の点を自分で振り返ります。

  • 担当する流れを、自分の手で一度は通せたか
  • 例外の処理の一覧を業務部門と共有できたか
  • 会計・外部システムとのつなぎ目の持ち主が、名前で決まっているか
  • 設定の変更の記録が残っているか
  • 契約で決めた業務の範囲と、実際に担っている仕事がずれていないか
  • 稼働時間の記録が残っているか

ずれている点があれば、2か月目の早い段階で窓口と話しておきます。

エージェントベストの見解

当社では、契約で業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。参画して1か月の間に、聞いていた担当の流れと実際の仕事に違いを感じたときは、早めにご相談ください。契約の内容に関わる点は、ご質問いただければ確認します。

ポイント

  • SD/MMの初月は、流れと設定をつかむ、持ち主と決め方をつかむ、小さな成果を出す、の3つを順に進める
  • 1週目は資料・環境・人から情報を集め、2週目に例外の一覧とつなぎ目の持ち主を決める
  • 3〜4週目に担当のタスクを一つ完結させ、設定の記録と流れの図を残す
  • 前任者の否定、標準への一気の寄せ、会計の設定の踏み越えは避ける

よくある質問

前任者からの引き継ぎがほとんどありません。何から始めればよいですか？

組織構造の設定と伝票タイプの一覧、課題管理表、直近の議事録から読み始め、検証環境で担当の流れを自分で一度通すのが近道です。そのうえで、業務部門のキーユーザーに「今一番困っていること」を聞いてください。引き継ぎの資料がない状態そのものも、現状の報告に含めておくとよいでしょう。

参画初月から本番の設定変更を求められたら、どうすればよいですか？

急ぐ場合でも、その設定がどの伝票で使われているかをデータで確かめ、影響の範囲と確認した相手を記録してから変えます。判断に使った情報と、まだ分かっていない点を明らかにしたうえで、発注側に進めてよいかを決めてもらう形をとると、後で見立てが変わったときにも説明しやすくなります。

業務部門のキーユーザーが忙しく、話を聞く時間をもらえません。

一度に長い時間をもらうより、例外の候補を一覧にして「あるかないか」だけ答えてもらう形にすると、相手の負担が減ります。倉庫や営業所の作業を短時間でも見せてもらえると、質問の精度が上がり、聞く回数も減ります。やり取りの記録は議事録の書き方を参考に残しておくと、あとで確かめられます。

案件の探し方

参画が決まってから開始日までにやること｜契約・事業の手続き・作業環境の準備

参画が決まったら、開始日までに「契約の書面の確認」「他の選考の整理」「請求と事業の手続き」「作業環境」「業務の予習」の5つを進めます。時期ごとのやることと、開始前の作業を頼まれたときの注意点を整理します。

 案件の探し方

参画初日から最初の1週間でやること｜業務委託で立ち上がりを早める進め方

参画して最初の1週間は、成果を急ぐより「任された範囲・依頼の窓口・報告の形」を確かめ、小さな仕事を一つ終えることを優先します。初日から5日目までの進め方と、つまずきやすい点を整理します。

 SAP・ERP

SAP SD/MMコンサルのフリーランスがつまずきやすい点と対策

フリーランスのSAP SD/MMコンサルがつまずきやすいのは、「SD/MM担当」の範囲の広がり、商習慣の例外の聞き漏らし、会計とのつなぎ目の担当の宙づり、切替や締めの稼働超過です。契約・現場・技術・お金の順に対策を整理します。

 SAP・ERP

SAP SD/MMコンサルのフリーランス案件で求められるスキルと経験

SAP SD/MMのフリーランス案件では、価格決定や与信・在庫確認、購買の承認や請求書照合などの設定を自分で組んだ経験と、不具合を伝票とマスタから追う力が見られます。機能別に問われる設定、認定資格の出題範囲、経験の示し方を解説します。

 SAP・ERP

SAP SD/MMコンサルのフリーランスはリモートで働ける？案件の傾向と探し方

SAP SD/MMコンサルは、設定や仕様書の作成、テストを中心にリモートで働ける案件があります。一方で倉庫や工場の業務調査、帳票の印刷確認、取引先とのデータ連携テストでは現地が求められやすくなります。傾向と確認点を解説します。

 SAP・ERP

SAP SD/MMコンサルがフリーランスになるには｜必要な経験と独立までの進め方

SAP SD/MMコンサルとしてフリーランスになるには、受注から請求、購買から支払までの業務の流れを理解し、SDやMMの設定を自分で担った経験が必要です。経験の整理の仕方、面談で問われる論点、独立の手順を解説します。
