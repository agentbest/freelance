バックエンド開発

VBA・Excelマクロ開発者がフリーランスになるには｜必要な経験と独立までの進め方

公開 2026-10-29　監修：株式会社エージェントベスト

VBA・Excelマクロ開発者としてフリーランスになる目安は、自分で作ったマクロだけでなく、他人が作ったマクロを読み解いて直し、仕様と手順を書き残して引き渡した経験があることです。業務委託の現場では、作った人がいなくなったツールを任される場面が多く、「作れる」より「読んで直せる」「引き継げる」ことが先に問われます。

独立までの流れは、経験の棚卸し、足りない経験の補い方、作業の環境づくり、契約の準備の順に考えると進めやすくなります。開業届や税金などの一般的な手続きは、それぞれの記事で扱っています。

出発点によって補う経験が違う

VBAの仕事をしている人の出発点は、大きく3つに分かれます。どこから来たかで、独立の前に足しておきたいものが変わります。

業務部門で自分の仕事を自動化してきた人

経理・営業事務・購買などの部門で、自分や同僚の作業をマクロで楽にしてきた人です。業務の流れが分かり、使う人の言葉で話せることが強みです。

一方で、自分しか使わないツールは、エラー処理や他人が読むための書き方が後回しになりがちです。独立の前に、ほかの人が使う前提のツールを作り、使い方の説明と、困ったときの問い合わせへの対応まで経験しておくと、業務委託の仕事に近づきます。

システム開発から入ってきた人

SIerや開発会社で、ほかの言語での開発を経験してから、VBAの案件を担うようになった人です。設計・テスト・バージョンの管理の考え方を持ち込めることが強みです。

足しておきたいのは、ExcelやAccessの画面の上で動くツールならではの事情です。利用者が勝手にシートを並べ替える、セルの書式が人によって違う、ファイルがメールで回されるといった、きれいに設計できない現実に合わせた作り方を経験しておくと、現場で戸惑いにくくなります。

情報システム部門・社内SEから入ってきた人

社内で作られたマクロやAccessのデータベースの面倒を見てきた人です。社内のファイルサーバー、権限、端末の設定とツールの関係が分かることが強みです。

足しておきたいのは、ツールそのものを設計して作る経験です。問い合わせを受けて直すだけでなく、要望を聞いて一から作り、納めて使ってもらうまでを担っておくと、新規開発の案件も選べるようになります。

独立の目安は「引き継げる形で納めた」経験

経験年数だけでは、任せられる範囲は判断できません。次のような経験があるかで考えます。

  1. 他人のマクロを読み解いた：仕様書のないマクロを調べ、処理の流れを書き起こしたことがある
  2. 壊さずに直した：直す前のファイルを残し、直した後の結果を直す前と比べて確かめたことがある
  3. ほかの人が使う形で納めた：エラーの出し方、入力の確かめ方、使い方の説明を用意したことがある
  4. 書き残して渡した：処理の一覧、ファイルの置き場所、つながっている先を文書にして引き渡したことがある

このうち3つ以上を具体的に話せると、改修や引き継ぎの案件でも検討の材料になります。4つめが弱い人は多いため、今の職場で一度、自分のツールの引き継ぎ資料を作ってみることをおすすめします。

独立前に整えておきたい作業の環境

デスクトップ版のExcelとAccessを手元に

VBAは、デスクトップ版のOfficeで動く仕組みです。会社のパソコンで作ってきた人は、独立した後に自分で検証できる環境を用意しておく必要があります。Accessを使う案件を受けるなら、Accessが含まれる製品かどうかも確かめておきます。

32ビット版と64ビット版の違いを確かめられるように

Microsoft Learnでは、Office 2019とMicrosoft 365からは64ビット版が既定になっていると説明されています。WindowsのAPIを呼ぶDeclareステートメントは、64ビット版で動かすにはPtrSafeキーワードが必要で、ポインターなどを扱う型もLongPtrなどに直す必要があります（2026年10月時点）。発注元の端末が32ビット版のこともあるため、どちらの版で動くかを確かめられる手段を考えておくと安心です。

マクロのブロックを前提にした受け渡し

Microsoft Learnによると、Windows版のOfficeでは、インターネットから取得したファイル（メールの添付やブラウザーでのダウンロードなど）に含まれるVBAマクロは、既定でブロックされます（2026年10月時点）。フリーランスとして外からファイルを納めると、受け取った側でマクロが動かないことがあります。ファイルの受け渡しの方法と、発注元での解除の手順を相談できるように、仕組みを理解しておきましょう。

隣の技術にも触れておく

ExcelのOffice スクリプトは、使うのにMicrosoft 365の法人向けなどのライセンスとOneDrive for Businessが必要です（2026年10月時点のMicrosoft Learnの説明）。個人で試せる範囲は限られるため、会社に在籍しているうちに触れておくと、比べて話せる材料になります。Power Platformの側に広げたい方はPower Platformエンジニアがフリーランスになるには、画面の操作を自動化する方向はRPAエンジニアがフリーランスになるには、スクリプト言語の方向はPythonエンジニアがフリーランスになるにはも参考になります。

エージェントベストの見解

VBAの案件をご紹介していると、面談でつまずきやすいのは、「マクロを作れます」とだけ伝え、どんな業務の、どの規模のツールを、どこまで担ったかが伝わらないケースです。社内向けのツールは成果物を見せられないことが多いため、処理の流れや工夫を言葉で説明できるかが判断の分かれ目になりやすい傾向があります。独立の前に、代表的なツールを2〜3本選び、作った経緯と担った範囲を書き出しておくことをおすすめします。

契約で気をつけること

仕様と検収の条件を書面にする

VBAの仕事は、小さなツールを作って納める請負の形で出されることがあります。請負では、何を作れば完成か、どう確かめて受け取るかがあいまいだと、追加の要望が続いて終わりが見えなくなります。入力・出力・動かす人・動かす時期を書面にし、検収の条件を決めてから作り始めましょう。契約の形の違いは準委任契約と請負契約の違いで解説しています。

作ったものの権利の扱いを確かめる

業務のために作ったマクロは、契約で権利の扱いが決まっていることが多くあります。似た処理を別の発注元で使い回してよいか、自分で作りためた部品を組み込んでよいかは、契約書で確かめておきます。著作物の扱いについては著作者人格権の不行使条項の記事も参考になります。

本番のデータの扱いを決める

マクロのテストには、実際の業務のデータを使いたくなる場面があります。顧客や取引先の情報を含むファイルを手元に持ち出してよいか、加工したテスト用のデータを用意してもらえるかを、最初に決めておきます。

独立までの進め方

  1. 経験を棚卸しする：新規開発・改修・引き継ぎ・移行のどれを、どの規模で担ったかを書き出す
  2. 足りない経験を補う：引き継ぎ資料の作成や、他人のマクロの改修など、弱いところを在籍中に経験する
  3. 手続きとお金の準備：開業届の出し方は開業届の記事、会社を辞める段取りは退職から独立までの流れ、生活費の備えは独立前に用意しておく生活費で扱っています
  4. 案件を探して面談を受ける：いきなり独立せず、副業で小さな案件から始める方法もあります。注意点は会社員の副業で業務委託案件を受けるときの注意点をご覧ください

独立の時期の考え方は独立のタイミングの記事、案件紹介サービスの使い方はフリーランスエージェントの使い方にまとめています。

注意

自分が勤めている会社で作ったマクロを、独立した後に持ち出して別の発注元で使うのは避けてください。会社の業務で作ったものの権利は、会社の側にあることが多いためです。実績として伝えるときも、ファイルやコードではなく、何をどう解決したかを言葉で説明しましょう。

よくある質問

業務部門で自分用のマクロを作ってきた経験だけで独立できますか？

業務の理解は強みになりますが、それだけでは案件の幅が限られます。ほかの人が使う前提のツールを作り、使い方の説明と問い合わせへの対応まで担った経験を足しておくと、業務委託の仕事に近づきます。在籍中に、部署の共有ツールを作る、引き継ぎ資料を書くといった経験を積んでおきましょう。

VBAだけで独立して、案件は続きますか？

VBAの案件は、新規開発に加えて、既存のツールの改修や引き継ぎ、版上げへの対応などがあります。ただ、VBAだけに絞るより、AccessやSQL、Office スクリプト、Power Automateなど隣の技術も扱えるほうが、選べる案件は広がります。広げ方はVBA・Excelマクロ開発者の将来性の記事で扱っています。

資格は独立前に取っておくべきですか？

資格がなくても案件に参画している人はいます。面談では、資格の有無より、どんな業務のツールをどこまで担ったかが問われる場面が多くあります。資格の勉強に時間を使うなら、その前に、代表的なツールの処理の流れと担った範囲を説明できるようにしておくほうが、案件の検討につながりやすくなります。案件で問われる技術はVBA・Excelマクロ開発者のスキルの記事で整理しています。
