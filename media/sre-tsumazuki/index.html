SREのフリーランスがつまずきやすい点と対策

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 現場でのつまずき
  3. 技術でのつまずき
  4. お金でのつまずき
  5. よくある質問

フリーランスのSREがつまずきやすいのは、オンコールの扱いを決めないまま当番に入ること、優先度を決める権限がない立場で改善を押し通そうとすること、仕組みを自分の頭の中に残して属人化させること、障害時の稼働の膨らみです。どれも、正社員なら社内の規程やチームが受け止めてくれた部分を、外部の立場で一人で抱えることから起きます。

対策の基本は、つまずきの種を契約と参画初期の取り決めで小さくし、現場では数字と記録で守ることです。この記事では、契約・現場・技術・お金の4面で、SREならではの場面と対策を整理します。独立前に確かめる項目はSREがフリーランスになるにはで扱っているので、ここでは「実際に起きやすい場面」に絞ります。

契約でのつまずき

オンコールの扱いが契約に書かれていない

SREの契約でもっとも多い食い違いが、当番の扱いです。契約書には「運用改善業務」とだけ書かれ、参画してみると夜間の当番表に名前が入っていた、ということが起きます。待機の時間が稼働に入るのか、呼び出されたときの作業時間をどう数えるのかが決まっていないと、負担だけが増えます。

対策：参画前に、当番に入るかどうか、入るなら頻度、応答までの時間、待機と呼び出しの扱いを言葉で確かめ、契約の内容と照らし合わせます。待機の報酬の考え方は待機報酬の記事、リモートでの当番の確かめ方はSREのリモート案件の記事をご覧ください。

「信頼性の向上」を成果として約束したように読める

契約書や業務説明に「稼働率を〇〇%にする」と書かれていると、達成できなかったときに責任を問われるおそれがあります。準委任契約では、成果そのものではなく、専門家として通常求められる注意を払って業務を行うことが約束の中身です。ただ、書き方によっては成果を約束したように読める場合もあります。

対策：数字の目標は「目指す値」として扱い、達成を約束する文言になっていないかを署名の前に読みます。障害で損害が出たときの責任の範囲は損害賠償の上限の記事で解説しています。判断に迷う場合は弁護士などの専門家にご相談ください。

社員と同じ当番表・作業指示で動くようになる

社員のSREと同じ当番表に入り、作業の手順や時間まで細かく指示されるようになると、準委任の契約と実態がずれてきます。考え方は偽装請負の記事で解説しています。

現場でのつまずき

権限のない立場で「リリースを止めるべき」と言い続ける

SREの考え方では、信頼性が落ちたら新機能より改善を優先します。ただ、外部のSREには、開発の優先度を決める権限がないのが一般的です。正しい主張でも、合意の仕組みがないまま繰り返すと、「開発の邪魔をする人」と受け取られてしまいます。

対策：止めるかどうかを自分で決めようとせず、決める人に判断材料を出す役に徹します。利用者への影響、エラーバジェットの残り、止めない場合に起きそうなことを並べ、決めてもらう形をとります。エラーバジェットの取り決めがない現場では、まず取り決めをつくる提案から始めます。

障害の振り返りが犯人探しになる

障害の後の振り返りで、誰の操作が原因だったかに話が向くと、次から事実が出てこなくなります。外部のSREが振り返りの進行を任されたとき、ここで場を立て直せないと、仕組みの改善につながりません。Googleが公開しているSREの本でも、振り返りは個人やチームを責めずに、仕組みと手順の側の原因を探すものとして説明されています（2026年10月時点、公開ページによる）。

対策：振り返りの文書の型を先に決め、「誰が」ではなく「何がそれを起こしやすくしていたか」を書く欄を設けます。対策は、担当者と期限を決めて課題として追います。

エージェントベストの見解

案件紹介の現場で、フリーランスのSREの方が契約の更新を見送られる理由として耳にしやすいのは、技術力の不足より「開発チームとの関係」です。改善の必要性は正しくても、伝え方が強すぎて開発側との溝が深まる、という場面が続くと、信頼を取り戻すのに時間がかかります。数字を示して決めてもらう形をとることをおすすめします。

当番と改善の両方を抱え込む

少人数の現場では、当番に入りながら改善も期待されることがあります。同じ本では、12時間の当番で扱う障害は2件までを目安とし、当番の体制は1拠点のチームなら8人を最小とする考え方が示されています。これより人数が少なく、呼び出しの多い現場では、改善の時間がほとんど残りません。

対策：当番の対応に使った時間と、改善に使った時間を週ごとに記録し、窓口と共有します。改善が進まない理由を数字で示せると、当番の分担や優先度を見直す相談がしやすくなります。

技術でのつまずき

自分しか分からない仕組みを残す

外部のSREが作った自動化や監視の設定が、本人しか分からない状態で残ると、契約が終わった後に誰も直せなくなります。「辞めたら回らない」状態は、短期的には頼られても、長い目で見ると発注側の不満になります。

対策：仕組みはコードとしてリポジトリに置き、何のための仕組みか、止めたらどうなるか、直し方を短い文書に残します。社内のメンバーに一度作業してもらい、手放せるかを確かめておくと安心です。引き継ぎの進め方は引き継ぎの記事で整理しています。

道具を入れることが目的になる

可観測性の基盤や新しいデプロイの仕組みを入れても、誰も見ない監視画面や、使われないアラートが増えるだけ、ということがあります。

対策：道具を入れる前に、利用者のどんな体験を測りたいのか、アラートが鳴ったら誰が何をするのかを決めます。鳴っても何もしないアラートは減らす、という方針を持っておくと、当番の負担も軽くなります。求められるスキルの中身はSREに求められるスキルで触れています。

本番の権限を広く持ちすぎる

障害対応を早くするために、外部のSREに強い権限がまとめて渡されることがあります。誤った操作の影響が大きくなるうえ、何か起きたときに疑われやすい立場にもなります。

対策：必要な権限を作業ごとに分け、操作の記録が残る形で使います。強い権限が要る作業は、事前に窓口と手順を合わせておきます。

お金でのつまずき

障害対応の稼働超過が精算されない

大きな障害や切り替えの作業では、稼働が延び、精算幅を大きく超えることがあります。超えた分の扱いを決めていないと、報酬に反映されないまま負担だけが増えます。

対策：稼働を日々記録し、精算幅を超えそうな段階で窓口に伝えます。精算の仕組みは精算幅の記事で解説しています。

仕組みが入ったところで契約が終わる

SREの案件は、仕組みが整い社内で回せるようになると役割を終えることがあります。フリーランス法では、6か月以上の業務委託を解除したり更新しなかったりする場合、発注側は少なくとも30日前までに予告することになっています（2026年10月時点、公正取引委員会の案内による）。

対策：引き継ぎの見通しが立った段階で、更新の見込みを窓口に尋ね、次の案件の相談を始めます。契約期間の考え方は契約期間の記事をご覧ください。

注意

夜間の呼び出しが続くと、睡眠が削られたまま翌日の作業に入ることになり、判断の誤りが起きやすくなります。体調を崩してからでは遅いため、体調管理の記事も参考に、当番の上限を自分で決めておいてください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。オンコールの扱いや権限の範囲など、参画前に気になる点はご質問いただければ確認します。

ポイント

  • 契約では、当番の有無と扱い、成果を約束したように読める文言を参画前に確かめる
  • 現場では、止めるかどうかを決める人に材料を出す役に徹し、振り返りは仕組みの原因を探す
  • 仕組みはコードと短い文書で残し、手放せる形にする
  • 稼働は日々記録し、精算幅を超えそうなら早めに伝える

よくある質問

参画してから、当番に入るよう言われました。どうすればよいですか？

まずは契約で決めた業務範囲に当番が含まれているかを確かめます。含まれていない場合は、紹介を受けたエージェントや発注側の窓口に早めに伝え、入るなら頻度と扱いを決めてから引き受けてください。業務範囲が広がったときの考え方は業務範囲が変わったときの記事をご覧ください。

自分の作業が原因で障害が起きたら、損害賠償を求められますか？

準委任契約では、成果そのものを約束しているわけではありません。ただし、契約の内容や、作業の進め方に落ち度があったかどうかで判断が変わることがあります。不安がある場合は、契約書の損害賠償の条項を読み、弁護士などの専門家にご相談ください。

開発チームが改善の提案を聞いてくれません。どうすればよいですか？

改善の必要性を、利用者への影響や障害の件数など、相手が気にしている数字に置き換えて伝えます。そのうえで、決めるのは発注側だという線を守り、示したリスクと決まった内容は記録に残しておくと、後で経緯を確かめられます。

SREがフリーランスになるには｜必要な経験と独立までの進め方

SREとしてフリーランスになるには、SLOの設計や障害の振り返りなど、信頼性を数字で扱い開発チームと改善を進めた経験が必要です。案件の型、独立前に積む実績、外部から参画するときの進め方、オンコールの契約上の注意を解説します。

SREの参画初月にやること｜現場で信頼される進め方

SREの参画初月のゴールは、サービスと障害の現状をつかむこと、当番と権限の線を決めること、小さな改善を一つ形にすることの3つです。週ごとの進め方、案件の型による重心の違い、避けたい動き、月末の振り返りを整理します。

SREのフリーランスはリモートで働ける？案件の傾向と探し方

SREは、可観測性の整備やSLOの導入、リリースの仕組みづくりなどでリモートの案件があります。リモートの条件を大きく左右するのはオンコールです。応答の速さ、待機中の場所の制約、当番の頻度と扱いなど、参画前に確かめる点を解説します。

SREは正社員とフリーランスのどちらがよい？比べるときの観点

SREとして正社員とフリーランスのどちらがよいかは、収入の安定、社会保険、改善の権限とキャリア、オンコールを含む働き方の4つで比べると判断しやすくなります。SREならではの違いと、自分に合う方を確かめる方法を整理します。
