COBOLエンジニアのフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい7つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

COBOLエンジニアのフリーランス案件を選ぶときは、報酬や稼働日数に加えて、環境の系統、案件の目的（保守・運用・移行）、担当工程、夜間や休日の対応、作業場所と端末、契約の形と責任、契約期間と節目の時期の7点を契約前に確かめておくことが大切です。COBOLの案件は、募集の文面が似ていても、この7点の違いで負担と立ち上がりの難しさが大きく変わります。

特に見落としやすいのは、夜間や休日の対応と、立ち上がりにかかる期間です。案件票に短くしか書かれないことが多く、参画してから想定との違いに気づきやすい点です。この記事では、COBOLの案件に固有の確認点を整理します。契約書全般の確認点は業務委託契約書のチェックポイントで解説しています。

COBOLの案件選びで差が出る理由

COBOLの案件票は、「COBOL開発（金融系）」「メインフレーム保守」「マイグレーション案件」のように短く書かれることが多く、仕事の中身が読み取りにくい傾向があります。一方で、扱うシステムは大きく、環境や業務の決まりも現場ごとに違うため、合わない案件に入ると立ち上がりに時間がかかり、評価にも響きます。

よくあるずれは次のようなものです。

  • 開発の案件と思って入ったら、ジョブの監視と障害の調査が中心だった
  • 経験と違う系統のメインフレームで、ジョブの書き方や道具に慣れるまで時間がかかった
  • 移行の案件で、参画した時期がちょうど現新比較の山場で、夜間や休日の作業が続いた
  • リモートを含むと聞いていたが、参画直後の数か月は毎日の出社だった

こうしたずれは、面談と条件の確認の段階で、聞き方を工夫すれば多くを防げます。仕事の種類ごとの働き方はCOBOLの案件の仕事内容で整理しています。

契約前に確かめたい7つの点

1. 環境の系統と、使う道具

最初に確かめたいのは、環境が自分の経験に近いかです。

  • メインフレームかオープン系か。メインフレームならどの提供元の系統か
  • バッチ中心か、オンラインも含むか。使っているDBやファイルの種類
  • ソースの管理や検索、テストに使える道具が整っているか

系統が違う案件を避ける必要はありませんが、立ち上がりに必要な期間を見込んで受けることが大切です。自分の経験との差は面談で正直に伝え、どの程度の期間で慣れる想定かをすり合わせておきましょう。

2. 案件の目的：保守・運用・移行のどれか

同じ「保守」でも、改修が中心なのか、運用と障害対応が中心なのかで仕事が変わります。移行の案件なら、方式（基盤だけを移すのか、言語を書き換えるのか）と、自分が現行の側と移行先の側のどちらを担うのかを確かめます。

面談では、「着任後の最初の1か月で、最も期待されている作業は何か」を聞くと、案件の実態が見えやすくなります。

3. 担当工程と、任される範囲

製造とテストが中心か、影響調査や詳細設計まで任されるか、リードとしてレビューや作業の割り振りまで担うかを確かめます。任される範囲は報酬にも関わります。報酬の決まり方はCOBOLの報酬の記事をご覧ください。

任される範囲が経験より広い場合は、誰がレビューし、誰に相談できるかもあわせて確かめておくと安心です。

エージェントベストの見解

COBOLの案件をご紹介していると、参画後に「聞いていた状況と違った」となりやすいのは、改修と運用の割合と、夜間や休日の対応の2点です。面談では聞きにくいと感じる方もいますが、稼働の見込みを判断するために必要な確認として聞けば、多くの発注元は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

4. 夜間・休日の対応と、障害の当番

COBOLの案件で稼働が読みにくくなる最大の要因です。

  • リリースや本番の切り替えの頻度と、作業の時間帯
  • 障害の連絡を受ける当番に入るか。入る場合の頻度と、連絡を受けたときの対応の範囲
  • 制度対応の施行日や年度末など、稼働が増える時期の見込み

夜間や休日の作業が、精算の対象になる稼働時間にどう含まれるかも確かめます。精算の仕組みは精算幅の記事をご覧ください。

5. 作業場所と端末、出社の日数

閉じたネットワークの中で作業する現場では、作業場所と端末が決まっています。

  • 出社の日数と、参画直後の期間の出社の扱い
  • リモートの日がある場合、使う端末と、資料を手元に置いてよいか
  • 作業場所への入館の手続きや、私物の持ち込みの決まり

リモートの条件は、参画後に変わることもあります。リモートの傾向と確認点はCOBOLのリモート案件の記事で解説しています。

6. 契約の形と、負う責任の範囲

COBOLの案件は、多くの場合、準委任契約で参画します。準委任では、作業そのものを専門家として通常求められる注意を払って行うことが約束の中身になり、システムの完成を約束するものではありません。

確かめたいのは、契約書や発注の書面の書き方が、この考え方と合っているかです。

  • 本番の障害そのものに対する損害賠償の定めがないか
  • 成果物の納品が求められる場合、その範囲は何か（設計書、テストの結果、現行の仕様書など）
  • 移行の案件で、移行の完了を約束する書き方になっていないか

請負の形で受ける場合は、完成に対する責任を負うことになります。契約の形の違いは準委任契約と請負契約の違いで解説しています。また、準委任の契約なのに、発注元の社員から細かな作業の指示や勤務時間の管理を直接受ける働き方は、偽装請負の問題につながるおそれがあります。詳しくは偽装請負の記事をご覧ください。

7. 契約期間と、節目の時期

契約の期間と、プロジェクトの節目が合っているかを確かめます。たとえば、制度対応の施行日や移行の切り替えの直前に契約の更新時期が来ると、更新されなかった場合に最も大事な局面を見届けられません。立ち上がりに時間がかかる現場では、最初の契約期間が短すぎないかも見ておきたい点です。

フリーランス法では、6か月以上継続して業務を委託している場合に、契約を解除したり更新しなかったりするときは、原則として少なくとも30日前までに予告することが求められています（2026年10月時点、公正取引委員会の案内による）。考え方は契約解除と不更新の予告の記事で解説しています。

注意

同じ現場に長くいると、担当外のシステムの調査や、ほかのチームへの説明、若手の育成などを頼まれることが増えやすくなります。契約の業務範囲に入っていない仕事を頼まれたときは、引き受ける前に範囲と条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者は業務を委託したら直ちに、給付の内容、報酬の額、支払期日などの取引条件を、書面またはメールなどの方法で明示することとされています（2026年10月時点、公正取引委員会の案内による）。明示される事項の内容はフリーランス法で明示される取引条件をご覧ください。

COBOLの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、担当する工程とシステムの範囲（保守、運用、移行の現行分析など）が書かれているか
  2. 夜間・休日の作業や当番が業務に含まれるか、含まれる場合の扱い
  3. 稼働の幅と、超えたときの精算方法
  4. 作業場所と、リモートの扱い
  5. 契約期間と更新の時期

面談で聞いておくとよい質問はCOBOLの面談でよく聞かれる質問と答え方の逆質問の項目でも紹介しています。一般的な逆質問の考え方は面談で聞いておくべき逆質問をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。COBOLの案件で気になりやすい夜間の作業や当番の有無、出社の日数など、書面だけでは読み取りにくい点は、ご質問いただければ確認します。条件に迷う点があれば、契約の前に早めにご相談ください。

ポイント

  • COBOLの案件は、環境の系統、保守・運用・移行の別、担当工程で負担と立ち上がりが大きく変わる
  • 夜間・休日の対応と障害の当番、作業場所と出社の日数は、案件票に書かれにくいので面談で確かめる
  • 準委任なのに障害や完成の責任を負う書き方になっていないかを確かめる
  • 契約期間と施行日・切り替えの時期の重なりを見て、書面と照らし合わせる

よくある質問

経験と違う系統のメインフレームの案件は避けたほうがよいですか？

避ける必要はありません。COBOLの読解や影響調査の考え方は共通して生きます。ただし、ジョブの書き方や道具に慣れるまでの期間がかかるため、立ち上がりの期間の見込みと、相談できる人がいるかを確かめてから受けることをおすすめします。

移行の案件と保守の案件は、どちらを選ぶとよいですか？

一概には言えません。移行の案件は、現行分析や現新比較の経験が次の案件の材料になりやすい一方、段階によって稼働の山が大きくなります。保守の案件は、稼働が読みやすく業務の知識が深まりやすい一方、同じ現場が長くなりがちです。今後の方向とあわせて考えるとよいでしょう。将来の見通しはCOBOLの将来性の記事で解説しています。

報酬の高い案件と、夜間の作業が少ない案件で迷ったらどうしますか？

夜間や休日の作業が多い案件では、稼働時間が増えて、時間あたりの報酬が下がることがあります。報酬の額だけでなく、稼働の見込みと精算の方法をあわせて比べるとよいでしょう。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 フリーランス新法・下請法

中途解除の30日前予告｜フリーランス新法のルールと例外

6か月以上の業務委託を発注者が中途解除・不更新にするときは、原則として30日前までの予告が必要です。予告の方法、予告が不要になる5つの例外、理由開示の請求の仕方を、公正取引委員会・厚生労働省の資料をもとに整理します。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

偽装請負とは｜指揮命令の線引きとフリーランスが注意すること

偽装請負は、請負や準委任の契約なのに、実態として発注者が働き手に直接指揮命令している状態です。判断は契約の名前ではなく実態で行われます。フリーランスは「労働者性」の基準と、参画前に確かめたい点を押さえておきましょう。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。
