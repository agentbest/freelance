フリーランスにSalesforce認定資格は役立つ？評価される場面と準備

公開 2026-10-29　監修：株式会社エージェントベスト

Salesforce認定資格は、フリーランスの案件で書類の段階に「どの役割を任せられそうか」を示す目安として見られやすい資格です。ただし、参画を決めるのは実務の経験で、認定がなくても入れる案件はあります。反対に、認定を多く持っていても、実務で担った範囲が狭いと面談で差を指摘されます。

もう一つ大切なのは、Salesforceの認定は取って終わりではなく、年に1回の維持が必要な点です。この記事では、認定が効く場面と効きにくい場面、役割と資格の合わせ方、維持と失効の仕組み、経歴での示し方を整理します（2026年10月時点）。

認定がなくても参画できる案件

Salesforceの案件で発注側が最初に確かめるのは、どのクラウドを、どの工程で、どの立場で扱ったかです。たとえば「Sales Cloudの導入で要件定義から設定まで担当」「Service Cloudの運用保守で、フローの改修とデータの移行を担当」といった経験です。

運用保守や追加開発の案件では、今の環境で手を動かせることが重視され、認定の有無は歓迎条件にとどまることも少なくありません。開発の案件では、ApexやLWCのコードを書いた経験や、テストとリリースの進め方が具体的に問われます。案件で見られるスキルの全体はSalesforceのスキルの記事で整理しています。

認定が効きやすい場面と効きにくい場面

場面認定の見られ方
案件票の必須・歓迎条件に認定の名前がある書類の段階で条件を満たしているかが一目で分かる
新しいクラウドや製品の案件に広げたい実務の経験が少ない領域の知識を補う材料になる
発注側が顧客に体制を説明する必要がある認定を持つメンバーがいることを示しやすい
同じクラウドで長く運用保守を担ってきた人の継続案件実務の実績が先に見られ、認定は補足になる
認定と実務の役割が合っていない面談で経験の深さとの差を確かめられやすい

効きやすい場面に共通するのは、発注側が短い時間で候補者を絞り込む必要があるときです。案件票の条件に認定の名前があれば、持っていることが書類で目に留まりやすくなります。案件票の読み方は案件票の読み方の記事で解説しています。

役割と認定の組み合わせ方

Salesforceには、アドミニストレーター、開発者、コンサルタント、アーキテクトなど、役割ごとの認定があります。認定を選ぶときは、知名度ではなく、次に入りたい案件の役割と同じ系統かで考えます。

  1. 設定と運用が中心の人：アドミニストレーター系の認定が、日々の設定の知識の裏付けになります。上位の役割に広げるときの土台にもなります
  2. 開発が中心の人：開発者系の認定で、Apexやデータの扱いの知識を示せます。実務ではテストクラスやデプロイの進め方も見られるため、資格の範囲だけで準備を終えないことが大切です
  3. 要件定義や業務設計が中心の人：特定のクラウドのコンサルタント系の認定が、そのクラウドの標準機能を業務に合わせて提案できることの目安になります
  4. 全体の設計を担う人：アーキテクト系の認定は、複数の認定を前提にした体系になっているものがあり、取得までの道のりが長くなります

すでに持っている認定と実務が合っていない場合は、無理に認定を増やすより、認定と同じ役割の実務を一つ積むほうが評価につながります。

年1回の維持と、失効の連鎖

Salesforceのヘルプでは、2026年10月時点で次のように案内されています。

  • 維持の頻度：すべての認定で、年に1つの維持用バッジ（メンテナンスバッジ）をTrailheadで完了する必要がある。期限はSpring・Summer・Winterのリリースの周期に沿って決まる
  • 期限を過ぎた場合：そのバッジで維持している認定はすべて失効する
  • 前提の認定の失効：前提になっている認定が失効すると、それを前提とする上位の認定も失効する。たとえばPlatform Administratorが失効すると、それを前提にするSales Cloud Consultantも失効し、Platform Administratorだけを取り直しても他の認定は戻らない
  • 失効した後：直近で失効した場合は復活の審査をサポートに依頼できるが保証はなく、それより前に失効した場合は試験を受け直すのが基本
  • 例外：Foundationsの認定には維持の要件がない。上位の認定を取っても、入門の認定の維持は引き続き必要

Salesforceの公式ブログ（2026年6月）では、古い認定は引退（retire）することがあり、引退した認定は有効なままでも維持の対象ではなくなり、検証用のページには表示されなくなると説明されています。

注意

維持の期限を過ぎると、前提の関係にある認定がまとめて失効することがあります。認定を多く持つほど、期限の管理が大切です。維持の案内はメールでも届きますが、公式のヘルプはメールだけに頼らないよう呼びかけています。期限はご自身のTrailblazerのプロフィールで確かめ、スキルシートに書く前に有効な状態かを必ずご確認ください。

実務経験と組み合わせて示す

認定が評価につながるのは、認定の範囲と実務の範囲が重なって見えるときです。面談では次のような話し方が伝わりやすくなります。

  • 「アドミニストレーターの認定の学習で権限の考え方を体系的に整理し、前の案件ではプロファイルと権限セットの見直しを担当した」
  • 「コンサルタント系の認定の範囲で標準機能を確かめたうえで、要件のうち標準で対応できるものと開発が必要なものを分けて提案した」

認定の範囲で学んだのに実務では触れていない機能は、検証環境で試してから話すと、知識が具体的になります。資格で学んだことと、実務で担ったことを分けて話すと、発注側は任せる範囲を判断しやすくなります。

エージェントベストの見解

案件紹介の現場では、認定の数が多い経歴よりも、認定と同じ系統の実務が経歴欄で具体的に読める経歴のほうが、面談の話が早く進む傾向があります。経歴をご提案するときは、ご本人の了承を得た案件にだけ、氏名や連絡先を伏せた形でお出ししています。認定の状態が変わったときは、提案の前にスキルシートを更新しておくことをおすすめします。

スキルシートでの書き方

資格欄は系統ごとに、状態も添える

資格欄には、認定の正式名称と取得年月を書き、アドミニストレーター系・開発者系・コンサルタント系のように系統ごとにまとめます。維持が必要な認定は、現在も有効な状態かを確かめたうえで書きます。失効した認定は、取得済みの認定と並べず、書く場合は失効していることが分かるようにします。

確かめられる形にしておく

Trailheadには、認定の有効性を確かめられる検証のページがあります。発注側から確認を求められたときに答えられるよう、Trailblazerのプロフィールに認定が正しく表示されているかを見直しておきます。スキルシート全体の組み立てはSalesforceのスキルシートの記事で解説しています。

学習中の認定

受験予定の認定は「学習中」として資格欄とは分けて書くか、面談で今後の方向として話します。取得済みと紛らわしい書き方は避けてください。

取得と維持の準備

フリーランスは、学習と維持の時間を自分で確保する必要があります。準備では次の点を先に考えておきます。

  1. 狙う案件票から選ぶ：入りたい案件の案件票に、どの認定の名前が出てくるかを集めてから決める
  2. 維持の時期を把握する：持っている認定ごとの維持の期限を一覧にし、リリースの周期にあわせて予定に入れる
  3. 前提の関係を整理する：上位の認定を取る前に、前提になる認定の維持が続けられるかを考える
  4. 実務と並行させる：学んだ機能を検証環境で試し、案件で使える形にしておく

学習の時間の作り方は学習時間の作り方の記事をご覧ください。認定をどう選ぶかを職種の視点で考えたい場合は、Salesforceエンジニア・コンサルがフリーランスになるにはも参考になります。

エージェントベストの見解

案件票の認定の条件が「必須」なのか「歓迎」なのか、認定を持つ人が何人必要なのかは、案件票だけでは読み取りにくいことがあります。応募を迷っている案件の条件が分かりにくいときは、ご質問いただければ確認します。案件をご案内するときは、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをお出ししています。

ポイント

  • Salesforce認定は書類の段階で役割の目安として見られやすいが、参画を決めるのは実務の経験
  • 認定は、次に入りたい案件の役割と同じ系統から選ぶ
  • すべての認定で年に1つの維持用バッジが必要。期限を過ぎると失効し、前提の関係にある上位の認定も失効する
  • Foundationsの認定には維持の要件がない
  • スキルシートには正式名称・取得年月・有効な状態を書き、実務の範囲と重ねて示す

よくある質問

認定がないと、Salesforceの案件には応募できませんか？

応募できる案件はあります。多くの案件では、どのクラウドをどの工程で扱ったかが先に見られます。ただし、案件票の必須条件に認定の名前がある場合は、持っていないと書類で見送られることがあるため、条件を確かめてから応募してください。

維持の期限を過ぎてしまったら、どうすればよいですか？

Salesforceのヘルプでは、直近で失効した場合は復活の審査をサポートに依頼できるものの保証はなく、それより前に失効した場合は試験を受け直すのが基本と案内されています。前提の関係にある認定もあわせて失効していないか、Trailblazerのプロフィールで確かめてください。

認定は多く持っているほうが有利ですか？

数が多いことより、案件の役割と同じ系統の認定を持ち、その範囲の実務を説明できることが大切です。認定を増やすほど維持の手間も増えるため、今の仕事と次に狙う案件に関わるものから優先すると、管理しやすくなります。

Salesforceの案件は、認定資格がなくても実務の経験で参画できるものが多くあります。資格が効くのは、役割を広げるときや案件票に名前があるときです。案件の種類別の効き方、効きにくい持ち方、実務との組み合わせ方を解説します。

Salesforceでフリーランスになるには、どのクラウドで、設定・開発・要件定義のどこを自分で担ったかを説明できる経験が必要です。役割ごとの求められ方、経験の整理の仕方、独立の手順を解説します。
