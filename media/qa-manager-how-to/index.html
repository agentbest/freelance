QA・テスト

QAマネージャー・品質保証リードがフリーランスになるには｜必要な経験と独立までの進め方

公開 2026-10-29　監修：株式会社エージェントベスト

QAマネージャー・品質保証リードとしてフリーランスになるには、テストを計画どおりに進めた経験に加えて、品質の基準を決めて関係者と合意した経験、品質の状態を見える形にした経験、不具合の原因から進め方を改善した経験が必要です。業務委託でこの役割を頼む発注側は、テストの人手ではなく、品質について判断と仕組みづくりを任せられる人を探しているためです。

準備は、経験の棚卸し、足りない経験の補強、関わり方の決定、手続きと契約の準備の順に進めます。テストの設計や実行を中心に独立する場合はQAエンジニアがフリーランスになるにはで扱っているので、この記事では管理の立場ならではの点に絞ります。

発注側がQAマネージャーを外部に頼む場面

業務委託のQAマネージャーが求められるのは、社内に品質の責任者がいない、または足りない場面です。主な型は次のとおりです。

場面発注側の困りごと任される仕事
QAの立ち上げ開発者が自分で確かめているが、出してから不具合が見つかるテスト方針、品質の基準、体制の最初の形を作る
立て直しテストはしているのに、リリースのたびに手戻りが続く原因の分析、進め方の見直し、指標の整理
大規模な開発の品質管理複数のチームや外部の会社がテストを担い、全体が見えない横断の計画、品質の報告、受け入れの基準
品質責任者の補佐・代行品質部門の責任者が不在、または手が回らない方針の継続、判定会議の運営、メンバーの育成

どの型でも、「何をもって出してよいとするか」を決め、その根拠を説明する役割が中心にあります。案件の型ごとの仕事の中身はQAマネージャーの仕事内容の記事でくわしく扱います。

独立前に必要な経験の目安

年数より、次の経験があるかどうかで見られます。すべてがそろっていなくても構いませんが、少なくとも1と2は自分の言葉で説明できる状態にしておきたいところです。

  1. 品質の基準を決めた：リリースや受け入れの条件を提案し、開発・事業の責任者と合意した
  2. 品質の状態を報告した：不具合の傾向や残っているリスクを、判断する人に向けてまとめた
  3. 進め方を改善した：不具合の原因を分析し、レビューやテストの入れ方を変えた
  4. 体制を組んだ：テスト担当者の配置や、外部の会社との分担を決めた
  5. 育てた：メンバーのテスト設計をレビューし、任せられる範囲を広げた

テストリーダーの経験が長い方は、1〜3のどれかに当たる場面がすでにあることが多くあります。「リーダーとしてチームを回した」ではなく、「自分で決めたこと」を切り出して書き出すのが最初の作業です。

エージェントベストの見解

QAマネージャーの案件をご紹介していると、面談でつまずきやすいのは、管理の経験を「進捗を管理した」「報告をまとめた」とだけ説明してしまうケースです。評価されやすいのは、なぜその基準にしたのか、反対意見にどう答えたのかまで話せる方です。独立の前に、品質の判断をした場面を3つほど選び、理由とともに言葉にしておくことをおすすめします。

会社員のうちに埋めておきたい穴

独立してから学ぶのが難しい経験は、会社員のうちに機会を作っておくと楽になります。

品質の指標を自分で選ぶ

決められた帳票を埋めるだけでなく、何を測ればリスクが見えるかを考えて、指標を選び直した経験です。不具合の件数だけでなく、見つかった工程、原因の分類、修正までの時間など、判断に使える形に組み替えた経験は、どの現場でも話せます。

開発の進め方の違いを知る

計画を先に固める進め方と、短い間隔で作って確かめる進め方では、品質の仕組みの作り方が違います。片方しか経験がない場合は、もう一方の現場の進め方を学び、品質の考え方をどう変えるかを説明できるようにしておきます。アジャイルの現場での役割の分け方はスクラムマスターのスキルの記事も参考になります。

開発と自動化の言葉を知る

QAマネージャー自身がテストコードを書くことは多くありませんが、自動化をどこまで進めるか、CIでどのテストを回すかの判断には関わります。自動化の担当者と話がかみ合う程度の理解があると、任される範囲が広がります。自動化の担い手の仕事はテスト自動化エンジニアのスキルの記事で扱っています。

知識を共通の言葉で整理する

テストの管理を体系的に学ぶ材料として、JSTQBのAdvanced Level（テストマネージャ）があります。2026年10月時点のJSTQBの案内では、テストマネージャの試験は2025年11月からv3.0のシラバスで実施されています。資格の位置づけはJSTQBの記事で解説しています。

関わり方を決める

QAマネージャーのフリーランスは、関わり方で働き方が大きく変わります。最初に決めておくと、案件選びがぶれにくくなります。

関わり方特徴向いている人
現場に入って体制を回す週の多くを使い、判定会議やチームの運営まで担う大規模な開発の品質管理の経験が長い人
立ち上げ・立て直しを担う期間を区切って方針と仕組みを作り、社内に引き継ぐ複数の組織で仕組みを作った経験がある人
助言・レビュー週数日でテスト方針や指標を見直す特定の業界や開発の進め方に強みがある人

体制を回す型は、稼働が多い分、ほかの案件と並行しにくくなります。立ち上げの型は、期間が終わると次の案件を探す必要があるため、契約の終わりが見えた時点で次の準備を始めます。助言の型は、複数の案件を組み合わせやすい一方、一つひとつの関わりが浅くなりやすいので、成果を説明できる形で残す工夫が要ります。

最初の案件は、これまでの経験に一番近い関わり方を選ぶのが無難です。助言型の案件は、成果物と稼働の関係があいまいになりやすいため、何を渡すかを事前に決めておく必要があります。最初の案件の選び方は最初の案件の記事も参考になります。

独立までの進め方

1. 品質の判断をした場面を棚卸しする

案件ごとに、対象、体制の規模、自分の立場、決めたこと、その結果を書き出します。書き方はQAマネージャーのスキルシートの記事で解説しています。

2. 希望する条件を決める

稼働日数、リモートか出社か、報酬の下限、関わり方を決めます。報酬の決まり方はQAマネージャーの報酬の記事、リモートの傾向はQAマネージャーのリモート案件の記事にまとめています。

3. 手続きを済ませる

退職、年金と健康保険の切り替え、開業届などの手続きは、職種にかかわらず共通です。開業届の提出期限は、国税庁の案内で「事業を始めた年分の確定申告期限まで」とされています（2026年10月時点）。全体の流れは会社員からフリーランスになる手順、書き方は開業届の出し方をご覧ください。税金や保険の判断に迷う場合は、税理士や窓口にご相談ください。

4. 案件を探して面談を受ける

フリーランスエージェント（案件紹介サービス）、以前の同僚や取引先からの紹介、発注元との直接契約などの方法があります。使い方はフリーランスエージェントの使い方で解説しています。

注意

QAマネージャーの案件では、契約の書面に「品質保証業務一式」のような広い書き方だけが並ぶことがあります。範囲があいまいなまま参画すると、テストの実行から採用まで頼まれることになりがちです。フリーランス法では、発注側は業務の内容・報酬の額・支払期日などを書面やメールで明示することとされています。業務の範囲と、判断の権限を誰が持つかを、参画前に確かめましょう。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、業務の範囲・報酬・支払期日・契約期間は個別契約に書いてお渡ししています。経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せて提案しています。体制を回す型か、立ち上げの型か、助言の型か、希望する関わり方が決まっていれば、最初にお伝えください。

ポイント

  • QAマネージャーとして独立するには、品質の基準を決めて合意し、状態を見える形にし、進め方を改善した経験が要る
  • テストリーダーの経験から「自分で決めたこと」を切り出すのが最初の作業
  • 関わり方（体制を回す・立ち上げ・助言）を決めてから案件を探すとぶれにくい

よくある質問

何年くらいの経験があれば独立できますか？

年数で決まるものではありません。品質の基準を決めて合意した経験と、品質の状態を判断する人に向けて報告した経験を、具体的な場面で説明できるかが見られます。年数が短くても、立ち上げや立て直しを担った経験があれば評価されることがあります。

部下を持ったことがなくても、QAマネージャーの案件に入れますか？

入れる案件はあります。業務委託のQAマネージャーは、部下の評価や人事より、品質の方針や基準を決める役割を求められることが多いためです。ただ、外部の会社やテスト担当者に仕事を割り振った経験は見られるので、体制を組んだ場面があれば伝えましょう。

開発エンジニアからQAマネージャーとして独立することはできますか？

開発の経験は、品質の原因を分析する場面で強みになります。ただ、テストの計画や品質の報告を担った経験がないと、マネージャーの案件では説明が難しくなります。まずはQAエンジニアやテストリーダーの立場で品質の仕組みに関わる経験を積むのが近道です。
