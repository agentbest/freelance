COBOLエンジニアのフリーランスはリモートで働ける？案件の傾向と探し方

公開 2026-10-29　監修：株式会社エージェントベスト

COBOLエンジニアのフリーランス案件は、リモートで働ける案件もありますが、ほかの開発言語と比べると常駐や出社が求められる割合が高い分野です。金融・保険・公共の基幹系では、閉じたネットワークや専用の端末でしか作業できない環境が多く、本番に近いデータを扱う作業やリリースでは現地での対応が求められやすくなります。

一方で、オープン系のCOBOLの開発、移行のための現行分析と文書化など、リモートや出社との組み合わせで進めやすい仕事もあります。この記事では、リモートで進めやすい仕事・しにくい仕事を分け、案件の探し方と参画前の確認点を整理します。

COBOLの案件で常駐が多い理由

COBOLの案件で現地での作業が多いのは、言語の問題ではなく、扱うシステムと環境の性質によるものです。

理由中身
閉じたネットワーク開発環境が社外から接続できないネットワークの中にあり、専用の端末からしか入れない
扱うデータの重さ口座、契約、住民の情報など、外に出せない情報を扱う
業界のルール金融や公共では、委託先の作業場所や端末の管理が厳しく決められていることが多い
リリースと障害の対応夜間や休日のリリース、本番の障害対応で現地にいることが求められる
立ち上がりの時期参画直後は環境や業務の説明を対面で受けることが多い

業界ごとのセキュリティのルールは、銀行業界の規制とセキュリティ、保険業界の規制、公共・官公庁の規制とセキュリティで解説しています。

環境の制約は案件ごとに違う

同じ業界でも、リモートでの接続の仕組みを整えている現場もあれば、作業はすべて現地の端末という現場もあります。総務省のテレワークセキュリティガイドライン（2026年10月時点で第5版）が示すように、テレワークでは端末や通信、作業する場所の安全を組織として整える必要があり、その整え方は発注元ごとに違います。リモートの可否は、案件ごとに確かめることが前提です。

リモートで進めやすい仕事・しにくい仕事

COBOLの案件でも、作業の種類によってリモートとの相性が違います。

作業リモートとの相性理由
オープン系COBOLの開発・保守進めやすいことがある開発環境に社外から接続できる仕組みがあれば、ほかの言語と同じように作業できる
現行分析・仕様の文書化進めやすいことがあるソースの閲覧と文書の作成が中心で、接続の仕組みが整っていれば場所を選びにくい
移行後のコードのレビュー進めやすいことがある移行先の環境がクラウドなどにあれば、接続しやすい
設計書の作成・レビュー条件しだい資料を持ち出せるかどうかで変わる
本番に近いデータでのテストしにくいデータを外に出せないため、現地の端末に限られることが多い
リリース・本番の障害対応しにくい現地で関係者と連携して進めることが多い
メインフレームの端末での作業現場しだい接続の仕組みがなければ現地に限られる

「週に何日か出社」の形が多い

COBOLの案件でリモートを含む場合、すべてを在宅で行うより、週に何日かを出社し、残りをリモートにする形が多く見られます。出社の日は、テストやリリース、打ち合わせにあて、リモートの日は文書化や調査にあてる、といった分け方です。

移行の案件は時期によって働き方が変わる

移行の案件では、プロジェクトの段階によって出社の頻度が変わることがあります。現行分析や移行の方式を検討する初めの段階は、文書の作成と打ち合わせが中心で、リモートを組み合わせやすいことがあります。一方、現新比較のテストや本番の切り替えが近づくと、現地の端末での確認や関係者との連携が増え、出社の日が多くなりがちです。参画する時期がプロジェクトのどの段階にあたるかを確かめておくと、働き方の見通しが立てやすくなります。

エージェントベストの見解

COBOLの案件紹介の現場では、リモートを強く希望されると、選べる案件の数が大きく減る傾向があります。リモートの日数と、通える範囲の両方を決めておくと、合う案件を探しやすくなります。当社では、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをご案内しています。

リモートの日に信頼を得る進め方

リモートの日がある案件では、作業の見え方が評価に影響します。COBOLの現場で意識しておきたい点は次のとおりです。

  1. 調査の結果を文書で残す：影響調査や現行分析の結果は、口頭ではなく一覧や文書にして共有する
  2. 出社の日に確かめることを決めておく：現地の端末でしか確かめられないことを、リモートの日に洗い出しておく
  3. 持ち出しのルールを守る：ソースや設計書をどこまで手元で扱えるかを最初に確かめ、迷ったら聞く
  4. 連絡の時間をそろえる：基幹系の現場は勤務時間がはっきりしていることが多く、連絡がつく時間をチームに合わせる

注意

リモートの日に、現地の端末にしかない情報を手元に写して作業したり、私物の端末や個人のクラウドの保存場所を使ったりすると、契約や守秘義務の違反になるおそれがあります。扱ってよい情報と場所は案件ごとに違うため、参画の初日に確かめておきましょう。守秘義務の考え方は秘密保持契約の記事で解説しています。

案件の探し方と確認点

探し方

COBOLのリモートを含む案件を探すときは、次の順に条件を整理すると見つけやすくなります。

  • 案件の種類で探す：保守より、移行の現行分析や文書化、オープン系の開発のほうがリモートを含みやすい
  • 出社の頻度を幅で決める：「フルリモートのみ」より「週何日まで出社可」と幅を持たせる
  • 通える範囲を決める：出社の日がある前提で、通える地域を決めておく

働き方の全体の傾向は、フルリモート案件の記事、常駐案件の記事、地方からの参画の記事で扱っています。

参画前に確かめたいこと

  1. 出社の頻度と時期：週何日か、参画直後だけ出社が多いか
  2. 端末と接続：貸与の端末か、どの環境にリモートから入れるか
  3. 作業の範囲：リモートの日にできる作業と、現地でしかできない作業
  4. 夜間・休日の対応：リリースや障害の対応で現地に行くことがあるか、その扱い
  5. 費用の扱い：出社の交通費や、自宅の通信環境の費用を誰が持つか

フリーランス法では、発注する事業者は、業務の内容や、役務を提供する場所などの取引条件を、書面やメールなどで明示することが求められています（公正取引委員会のフリーランス法特設サイト、2026年10月時点）。作業場所やリモートの条件は、口頭の説明だけで終わらせず、契約の書面で確かめておきましょう。

エージェントベストの見解

当社がご案内する案件では、業務の範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。COBOLの案件は、同じ現場でも時期によって出社の頻度が変わることがあるため、リリースや移行の山場の時期の働き方まで確かめておくことをおすすめします。リモートの条件で迷う点は、ご質問いただければ確認します。

リモートの条件と報酬の関係

リモートを含むかどうかで、応募できる人の数が変わり、条件にも影響することがあります。ただ、COBOLの案件では、環境や業務の経験が合うかどうかのほうが、報酬への影響が大きいことが多くあります。リモートの条件だけで案件を比べるのではなく、担当工程や積める経験とあわせて比べましょう。

また、出社の日がある案件では、通勤の時間と交通費も実質の条件に含まれます。交通費が報酬に含まれるのか、別に精算されるのかで、同じ金額でも手元に残る額が変わります。出社の頻度が高い案件ほど、この点を契約の前に確かめておくことが大切です。遠方から参画する場合は、移動の負担が続けられる範囲かどうかも、案件を選ぶ基準に入れておきましょう。報酬の決まり方はCOBOLエンジニアの報酬の記事で解説しています。

ポイント

  • COBOLの案件は、閉じたネットワークや扱うデータの性質から、常駐や出社の割合が高い
  • 現行分析の文書化、オープン系の開発、移行後のレビューなどは、リモートと組み合わせやすいことがある
  • 出社の頻度、端末と接続、夜間対応の扱いを、契約の書面で確かめる

よくある質問

COBOLのフルリモート案件はありますか？

ありますが、数は多くありません。オープン系のCOBOLの開発や、移行のための現行分析など、社外から接続できる環境が整っている案件に限られることが多い傾向があります。フルリモートだけに絞ると選べる案件が大きく減るため、出社の頻度に幅を持たせて探すと見つけやすくなります。

金融系のCOBOL案件でもリモートで働けますか？

現場の方針しだいです。金融の基幹系は作業場所や端末の管理が厳しいことが多く、現地の端末だけで作業する現場もあります。一方で、接続の仕組みを整え、文書化や調査の作業をリモートで認める現場もあります。案件ごとに、どの作業をどこでできるかを確かめてください。

参画直後からリモートで働けますか？

COBOLの案件では、参画直後の数週間は出社を求められることがよくあります。環境の説明、端末の受け取り、業務の説明を対面で受けることが多いためです。最初の期間の出社の頻度と、その後どう変わるかを、参画前に確かめておきましょう。
