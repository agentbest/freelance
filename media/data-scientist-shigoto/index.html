データ・AI

データサイエンティストのフリーランス案件の仕事内容｜案件の種類と1日・1か月の流れ

公開 2026-11-04　監修：株式会社エージェントベスト

フリーランスのデータサイエンティストの仕事は、依頼者の曖昧な相談を分析できる問いに直し、データで確かめ、判断に使える形で返すことの繰り返しです。ただ、施策の効果を測る案件か、予測モデルをつくる案件か、試しに分析してみる段階の案件か、社内の分析チームを支える案件かで、1日の時間の使い方も、関わる相手も、手元に残る成果物も大きく変わります。

この記事では、データサイエンティストの案件を4つの種類に分け、それぞれの1日と1か月の流れ、関わる相手、成果物を整理します。求められるスキルはデータサイエンティストのスキルの記事、報酬の決まり方は報酬の記事で扱っているので、ここでは「参画したら実際に何をしているか」に絞ります。

仕事の中身は「問いの種類」と「結果の使われ方」で決まる

データサイエンティストの案件は、同じ肩書きでも働き方がかなり違います。違いを生むのは、主に次の2つです。

  • 問いの種類：「やったことに効果があったか」を確かめるのか、「これから何が起きるか」を当てるのか、「そもそも何を分析すべきか」を決めるのか
  • 結果の使われ方：1回の報告で判断に使われるのか、モデルとして業務の仕組みに組み込まれるのか、社内の人が続けて使える形で残すのか

この2つを掛け合わせると、フリーランスの案件はおおむね次の4種類に分けられます。

案件の種類主な相手時間を多く使う仕事
効果検証・施策評価マーケティング・営業・商品企画の担当者比べ方の設計、データの抽出と確認、結果の報告
予測モデルの構築と検証業務部門、データエンジニア、機械学習エンジニア特徴量の検討、精度の評価、業務での使い方のすり合わせ
分析の構想・PoC事業部門の責任者、DX推進の担当者問いの整理、データの棚卸し、試しの分析と報告
社内分析チームの支援（内製化）社内のアナリスト、分析チームの責任者レビュー、手法の助言、勉強会、分析の型づくり

以下では、それぞれの1日と1か月の流れを、典型的な例として紹介します。時間の配分は案件ごとに違うため、目安として読んでください。

効果検証・施策評価の案件

1日の流れ（例）

朝は、前日に流した集計やモデルの結果を確かめ、数字が想定の範囲にあるか、データの欠けや重複がないかを見ます。午前中はSQLでデータを抽出し、施策を受けた群と受けていない群の条件がそろっているかを確かめます。午後は、依頼者との打ち合わせで「何と何を比べるか」「どの指標で判断するか」をすり合わせ、決まったことを分析の設計書に書き足します。夕方は、分析のコードと手順を整理し、翌日に再実行できる形で残します。

手を動かす時間は長いものの、比べ方を決める会話の質が結果の信頼性を左右します。

1か月の流れ（例）

  • 月初：検証したい施策と判断の期限を確かめ、比べ方と指標の案をつくる
  • 毎週：依頼者との定例会議で、データの状況、途中の結果、比べ方の見直しを共有する
  • 月の半ば：本番の分析を回し、結果がどの条件で変わるかを確かめる
  • 月末：報告会で結論と、結論が言える範囲・言えない範囲を示す

成果物

分析の設計書（問い、比べ方、指標、使うデータ）、抽出と分析のコード、結果の報告資料、前提と限界をまとめたメモなどです。効果が「出なかった」結果も、次の施策を決める材料として扱われます。

予測モデルの構築と検証の案件

1日の流れ（例）

需要予測、離反の予測、不正の検知などで、業務の判断を助けるモデルをつくる案件です。午前は特徴量の候補を試し、検証用のデータで精度を確かめます。午後は業務部門の担当者と、予測をどの場面で誰が使うか、外れたときにどう扱うかを話し合います。データの取り込みや本番への組み込みを担うデータエンジニアや機械学習エンジニアとの打ち合わせも入ります。

精度の数字を上げる作業より、業務で使える条件を満たしているかを確かめる時間が意外に長くなります。

1か月の流れ（例）

  • 月初：予測の対象、使う場面、求める精度の考え方を業務部門と合意する
  • 毎週：試したモデルと評価の結果を共有し、次に試すことを決める
  • 月の半ば：最も使えそうなモデルについて、時期や対象を変えても精度が保てるかを確かめる
  • 月末：評価の結果と、運用に乗せる場合の条件（更新の頻度、監視する指標）を報告する

成果物

モデルと学習・評価のコード、評価の報告書、特徴量の定義、運用に渡す場合の引き継ぎ資料などです。本番での運用まで担うかどうかは案件によって違います。運用を担う役割は機械学習エンジニアの仕事内容が参考になります。

エージェントベストの見解

データサイエンティストの案件をご紹介していると、同じ「分析」の募集でも、報告して終わる案件と、モデルを業務に組み込む案件とで、参画後の働き方が大きく違うことに驚く方がいます。前者は依頼者との会話と資料づくり、後者はエンジニアとの調整や運用の条件づくりに時間を使います。応募の段階で、結果を誰がどう使う予定かを聞いておくことをおすすめします。

分析の構想・PoCの案件

参画直後の数週間

「データを活用したいが、何から始めればよいか分からない」という相談から始まる案件です。最初は、分析より問いの整理が仕事になります。事業部門の担当者に業務の流れと困りごとを聞き、どのデータがどこにあり、どの程度使える状態かを棚卸しします。聞き取りと資料の読み込みで1日が埋まることもあります。

試しの分析と報告

問いの候補を絞ったら、手元にあるデータで小さく分析を試し、続ける価値があるかを判断する材料をつくります。PoC（概念実証）の期間は数か月に区切られることが多く、続けるか、やめるか、データを整えてからやり直すかを判断してもらう報告で区切りを迎えます。

成果物

問いの一覧と優先順位、データの棚卸しの結果、試しの分析の報告、次の段階の進め方の案などです。PoCの案件では、分析の結果そのものより、「この先に進むために何が足りないか」を示す資料の重みが増します。

社内分析チームの支援の案件

1日・1か月の流れ（例）

社内に分析チームができたばかりの会社や、アナリストはいるが統計の考え方に不安がある会社で、外部の専門家として支える案件です。1日の中では、社内のメンバーが進めている分析のレビュー、手法の相談への回答、つまずいているコードの確認などをします。1か月の単位では、勉強会の開催や、分析の進め方の型（設計書のひな形、レビューの観点）づくりが入ります。

自分で分析をする時間は短く、他の人の分析を正しい方向に戻す仕事が中心になります。週2〜3日で受けやすい型でもあり、詳しくはデータサイエンティストの週2〜3日・副業案件で解説しています。

成果物

レビューの記録、手法の解説資料、分析の型やチェックリスト、勉強会の資料などです。契約の終わりに、社内のメンバーだけで分析を回せる状態になっているかが問われます。

どの案件にも共通する仕事

種類が違っても、次の仕事はほぼすべての案件にあります。

  1. 問いのすり合わせ：何を明らかにし、結果を何の判断に使うかを、作業の前に言葉にして合意する
  2. データの確認：定義、期間、欠けや重複を確かめ、分かったことを記録する
  3. 再現できる形で残す：コードと手順を残し、同じ数字をもう一度出せるようにする
  4. 結論の範囲を伝える：言えること、言えないこと、前提が崩れたら変わることを分けて報告する

フリーランスならではの仕事として、自分の稼働の記録と報告もあります。月の稼働時間に幅を決めて精算する契約が多いため、データの抽出待ちや追加の集計に使った時間もつけておく必要があります。精算の仕組みは精算幅の記事をご覧ください。

注意

分析の案件では、報告のたびに「ついでにこの切り口でも見てほしい」という追加の依頼が出やすくなります。1つずつは小さくても、積み重なると当初の問いへの結論が遅れ、稼働も膨らみます。引き受ける前に、契約の業務範囲に入るか、当初の問いより優先するかを確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

関わる相手と、その相手に出すもの

データサイエンティストの1日は、誰に何を渡すかで組み立てられています。相手ごとに整理すると、次のようになります。

相手出すもの頻度の目安
事業部門の責任者結論、判断に使える範囲、次に打つ手の選択肢月次、節目ごと
依頼元の担当者途中の結果、比べ方や指標の確認事項週次、随時
データエンジニア必要なデータの依頼、定義の確認随時
機械学習エンジニアモデルの仕様、評価の方法、運用の条件節目ごと
社内のアナリストレビューの結果、手法の助言週次、随時

データの準備をデータエンジニアが担う案件では、分析に集中できます。いない案件では、抽出の仕組みづくりやデータの整形も自分で担うため、1日の多くがデータの準備に使われます。隣の職種の仕事はデータエンジニアの仕事内容やデータアナリストの仕事内容で整理しています。

働く場所については、分析の作業はリモートで進めやすい一方、現場の聞き取りや報告会、社内からしか見られないデータを扱う場面では出社を求められることがあります。詳しくはデータサイエンティストのリモート案件の記事をご覧ください。

エージェントベストの見解

当社では、案件をご案内する前に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをお出ししています。データサイエンティストの案件は、問いの種類と結果の使われ方で毎日の仕事が変わるため、「これまで多く時間を使ってきた仕事」と「避けたい働き方」をあわせてお伝えいただくと、案件を照らし合わせやすくなります。データの準備をどこまで担うかなど、案件票に書かれていない点は、ご質問いただければ確認します。

ポイント

  • 仕事の中身は、問いの種類と、結果が報告で終わるか業務に組み込まれるかで変わる
  • 効果検証は比べ方の設計、予測モデルは業務で使える条件の確認に時間を使う
  • PoCは問いの整理から始まり、続けるかどうかの判断材料をつくる
  • 内製化支援は、他の人の分析のレビューと型づくりが中心になる

よくある質問

フリーランスのデータサイエンティストは、1日中コードを書いていますか？

案件によります。効果検証や予測モデルの案件では手を動かす時間が長くなりますが、それでも依頼者との打ち合わせや報告の準備に一定の時間を使います。PoCや内製化支援の案件では、聞き取り、レビュー、資料づくりの割合が高くなります。

機械学習のモデルをつくる案件ばかりですか？

モデルをつくる案件もありますが、施策の効果を確かめる分析や、分析の構想を整える案件も多くあります。高度なモデルより、比べ方や指標を正しく決められることが求められる場面は少なくありません。

参画して最初の1か月は何をすることが多いですか？

依頼者と問いの確認、使うデータの定義と状態の確認、報告の相手と頻度の確認から始めるのが一般的です。初月の進め方はデータサイエンティストの参画初月にやることで詳しく解説します。
