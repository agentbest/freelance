フロントエンド開発

Angularエンジニアのフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい7つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

Angularエンジニアの案件選びで差が出るのは、今のシステムの版と構成、自分が担う範囲、版上げの予定、チームの決まりとレビューの体制です。同じ「Angularの画面開発」でも、これらによって立ち上がりの早さも、日々の負担も、参画後に増える作業も大きく変わります。

契約の前には、案件票の文面だけで判断せず、面談や事前の確認でこれらの点を聞き、契約の書面と照らし合わせることが大切です。この記事では、Angularの案件で契約前に確かめたい7つの点と、書面との照らし合わせ方を整理します。契約全般の確認点は業務委託契約で確かめたいことで解説しています。

Angularの案件選びで差が出る理由

Angularは業務システムで長く使われることが多く、案件の多くは、すでに動いているシステムへの参画です。新しく作る案件と違い、参画した時点で、版、構成、書き方の決まり、残っている課題が決まっていることになります。

そのため、次のようなずれが参画後に起きやすくなります。

  • 新しい版での開発と聞いていたが、実際は古い版の画面の改修が中心だった
  • 画面の実装で入ったが、版上げやビルドの設定の作業も頼まれた
  • レビューの体制がなく、書き方の決まりもないまま、自分の判断で画面を増やすことになった
  • サポートの期限が近い版を使っていて、参画中に大きな版上げが始まった

案件票に書かれている情報は限られています。案件票の読み方は案件情報の読み方をご覧ください。そのうえで、次の7つの点を契約前に確かめておくと、ずれを減らせます。

契約前に確かめたい7つの点

1. 今の版と構成

最初に確かめたいのは、システムが使っているAngularの版と構成です。版の番号だけでなく、NgModuleとstandaloneのどちらが中心か、変更検知の方式、状態の扱いがRxJS中心かSignalsも使っているかを聞いておくと、自分の経験との近さが分かります。

Angularは2026年10月時点で、メジャー版が年1回の周期になり、各版は通常24か月（Active 12か月とLTS 12か月）サポートされると公式に示されています。公式の一覧では、v2からv19はすでにサポートの対象外です。今の版がサポート中か、期限がいつかを確かめておくと、参画中に何が起きそうかを見込めます。

2. 担う範囲：実装か、設計か、版上げか

同じ募集でも、決まった設計に沿った実装なのか、画面の構成や共通部品の方針を決める立場なのか、版上げや移行を進める役割なのかで、仕事の中身は大きく変わります。レビューを受ける側か、行う側かを聞くと、期待されている立場が分かりやすくなります。

3. 版上げや移行の予定

版上げの予定があるか、あるならいつ、誰が担うかを確かめます。サポートの期限が近い版を使っている場合、参画してから版上げの作業が始まることがあります。版上げに関わりたい人には機会になりますが、画面の実装だけを想定していた人には、作業が増える原因になります。AngularJS（1.x系）の画面が残っているかも、あわせて聞いておくと安心です。

4. チームの体制と書き方の決まり

チームの人数、リーダーや設計担当の有無、コーディングの決まりやレビューの流れ、テストの書き方の決まりを確かめます。決まりやレビューがしっかりしている現場では立ち上がりが早くなる一方、決まりのない現場では、自分で判断する場面が多くなります。どちらが合うかは、経験と好みによって違います。

エージェントベストの見解

Angularの案件をご紹介していると、参画後のずれとして多いのは、版と構成の思い違いと、担う範囲の広がりです。特に、案件票に「最新の版」と書かれていても、実際には古い版の画面が多く残っていることがあります。面談の逆質問で、今の版と構成、版上げの予定、レビューの体制を具体的に聞いておくことをおすすめします。

5. 画面以外に頼まれる作業

画面の開発で入っても、サーバー側のAPIの修正、ビルドや配置の設定、テストの環境づくり、別の画面の調査などを頼まれることがあります。どこまでが担当の範囲か、範囲の外の作業が出たときにどう扱うかを確かめておきましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

6. 契約の形と、負う責任の範囲

業務委託の契約には、作業そのものを引き受ける準委任契約と、完成を約束する請負契約があります。画面の開発をチームの一員として担う案件では準委任契約が多いものの、特定の画面や版上げを成果物として引き受ける請負契約の形もあります。どちらの形かで、完成しなかったときの責任や、不具合への対応の扱いが変わります。違いは準委任契約と請負契約の違いで解説しています。

また、業務委託の契約なのに、発注元の担当者から細かな作業の指示や勤務時間の管理を受ける状態は、偽装請負と見なされるおそれがあります。注意点は偽装請負の記事をご覧ください。

7. 稼働の幅、働く場所、端末の扱い

月の稼働時間の幅と、超えたときや下回ったときの精算の方法を確かめます。リリースの直前や版上げの切り替えの時期は稼働が増えやすいため、その時期の扱いも聞いておくと安心です。精算の仕組みは精算幅の記事をご覧ください。

あわせて、リモートか出社か、貸し出しの端末を使うか自分の端末を使うかも確かめます。機密の多い業務システムでは、指定の端末と場所での作業が求められることがあります。働く場所の傾向はAngularのリモート案件の記事で整理しています。

注意

報酬の金額だけで案件を選ぶと、参画後に版上げや画面以外の作業が増え、稼働の割に負担が大きくなることがあります。反対に、版と構成が自分の経験に近く、担う範囲がはっきりした案件は、立ち上がりが早く、評価も得やすくなります。報酬の決まり方はAngularの報酬の記事で解説しているので、金額と中身を合わせて比べましょう。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者はフリーランスに業務を委託したら直ちに、業務の内容、報酬の額、支払期日などの取引条件を、書面またはメールなどの電磁的な方法で明示することとされています（2026年10月時点、公正取引委員会の案内による）。口頭だけの明示は認められていません。明示される事項の内容はフリーランス法で明示される取引条件をご覧ください。

Angularの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、担う範囲（画面の実装、設計、版上げ、レビューなど）が書かれているか
  2. 画面以外の作業を担う場合、その範囲が業務の内容に含まれているか
  3. 完成を約束する書き方になっていないか（準委任契約の場合）
  4. 稼働の幅と、超えたとき・下回ったときの精算の方法
  5. 契約期間と更新の時期、版上げなどの区切りとの関係

書面の内容が面談で聞いた話と違う場合は、契約の前に確かめましょう。後から「聞いていた話と違う」と言っても、書面の内容が優先されやすくなります。面談で聞いておくとよい質問はAngularの面談でよく聞かれる質問と答え方の逆質問の項目でも紹介しています。一般的な逆質問の考え方は面談で聞いておくべき逆質問をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。Angularの案件で気になりやすい版と構成、版上げの予定、画面以外の作業の扱いなど、書面だけでは読み取りにくい点は、ご質問いただければ確認します。条件に迷う点があれば、契約の前に早めにご相談ください。

ポイント

  • Angularの案件は、版と構成、担う範囲、版上げの予定、チームの決まりで負担が大きく変わる
  • 契約前に、版と構成、担う範囲、版上げの予定、体制、画面以外の作業、契約の形、稼働と働く場所の7点を確かめる
  • 今の版がサポート中か、期限がいつかを確かめると、参画中に起きることを見込める
  • 面談で聞いた内容は、契約の書面と照らし合わせ、違いがあれば契約前に確かめる

よくある質問

サポートの切れた古い版を使っている案件は避けたほうがよいですか？

一概に避ける必要はありません。古い版の案件は、版上げや移行の経験を積む機会になることがあります。ただし、参画中に版上げが始まる可能性が高いため、その作業を誰が担うのか、自分の担当に含まれるのかを確かめてから判断しましょう。

面談で「最新の版を使っていますか」と聞くのは失礼ですか？

失礼にはあたりません。版と構成は、参画後の仕事の中身を左右する大切な情報です。「経験との近さを確かめたい」と目的を添えて聞くと、相手も答えやすくなります。答えられない場合は、参画後に確かめられる範囲を聞いておきましょう。

報酬の高い案件と、版と構成が経験に近い案件で迷ったらどうしますか？

報酬の差だけでなく、立ち上がりにかかる時間、担う範囲の広さ、契約の更新の見込みを合わせて比べることをおすすめします。経験に近い案件で実績を積み、次の案件で条件を相談するという考え方もあります。条件の交渉は単価交渉の記事で解説しています。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 単価・報酬交渉

精算幅（140〜180時間など）とは｜超過・控除の計算方法

精算幅は、月額報酬のままでよい稼働時間の範囲です。上限を超えると超過分が加算され、下限を下回ると控除されます。超過・控除の単価は上下割か中間割かで変わるため、仮の数字を使って計算方法を整理します。

 スキルシート・面談

業務委託の面談で聞いておくべき逆質問｜参画後のずれを防ぐ確認項目

業務委託の面談の逆質問は、印象づくりより「参画後のずれを防ぐ確認」に使うのが基本です。業務の範囲、体制と指示の流れ、稼働の実態、期間の見込みの4つを確かめておくと、契約後の「話が違う」を減らせます。
