データ・AI

データアナリストのフリーランス案件で求められるスキルと経験

データアナリストのフリーランス案件では、SQLで正しい数字を出す力（とくにデータの粒度の理解）、指標を設計する力、施策の結果を誤らずに読む力、可視化して報告する力、依頼を受けて期限内に返す進め方の5分野が見られます。どの分野も、使えるツールの数より、出した数字がなぜ正しいと言えるかを自分で説明できるかが評価の分かれ目です。

この記事では、5分野それぞれの中身と、経験の段階ごとに求められる深さを整理します。独立の目安や準備はデータアナリストがフリーランスになるにはで扱っています。

分野中身面談で確かめられやすいこと

統計モデルや予測、因果推論の手法を深く使う力はデータサイエンティストのスキルの記事で、ダッシュボードの基盤やデータモデルを作る力はBIエンジニアのスキルの記事で扱っています。データアナリストは、その間で事業の問いに対して、速く正しく答えを返すことを期待される職種です。

SQLとデータの理解

データアナリストの案件で最も基本になり、最も差がつくのがここです。

  • テーブルの粒度を確かめる：1行が注文なのか、注文の明細なのか、会員なのかを確かめてから結合する。粒度の違うテーブルを結合すると、件数や金額が水増しされる
  • 重複と欠損を疑う：同じ会員が複数行ある、退会者の行が消えている、といったデータの癖を、集計の前に確かめる
  • 期間と時刻の扱いをそろえる：日付の区切り（タイムゾーン、締めの時刻）を依頼者の感覚と合わせる
  • 検算する：別の集計方法や既存のレポートの数字と突き合わせ、ずれがあれば理由を説明する

ウィンドウ関数を使った順位づけや前回との比較、データ量の多いテーブルで処理の量を抑える書き方も、案件によっては確かめられます。クラウドのデータウェアハウスでは、読み込むデータの量で費用が変わるサービスもあるため、必要な列と期間だけを読む習慣があると安心して任されます。

指標を設計する力

依頼者の「売上を見たい」「会員の動きを知りたい」という言葉を、計算できる指標に置き換える力です。

  • 分解する：売上を、客数・購入回数・客単価のように掛け算や足し算に分け、どこが動いたかを見られるようにする
  • ファネルで見る：訪問から登録、購入までの段階ごとの移り変わりを並べ、どこで離れているかを示す
  • コホートで見る：登録した月ごとに会員を分け、その後の継続を比べる
  • 定義を書き残す：分母と分子、対象から外すもの、計算の時点を文書にする

指標の定義は、決める作業より、関係者の合意をとる作業のほうが時間がかかります。部門ごとに違う数え方をしていた指標を一つにそろえた経験は、指標の管理を任される案件で強い材料になります。

エージェントベストの見解

データアナリストの案件をご紹介していると、面談で評価が分かれやすいのは、集計の速さより「その数字がずれていたときに、どうやって気づいたか」を話せるかどうかです。テーブルの粒度の取り違えや、定義の違いに気づいて直した経験を具体的に話せる方は、少ない説明でも任せやすいと受け止められる傾向があります。

施策の結果を読む力

施策の効果を問われたときに、数字の動きを誤って読まない力です。データアナリストとして求められるのは、高度な手法より基本を外さないことです。

  • 施策の前後を比べるときに、季節、曜日、同時期のほかの施策の影響を考える
  • A/Bテストの結果を見るときに、対象の数が十分か、偶然の範囲の差ではないかを確かめる
  • 期間の途中で結果を何度も見て、都合のよいところで止めない
  • 平均だけでなく、一部の大口の顧客が数字を動かしていないかを確かめる

比較の方法を設計から考える効果検証や、無作為に分けられない場面での推定は、データサイエンティストと分担することもあります。自分で扱える範囲と、専門家に渡す範囲を説明できることも評価されます。統計の考え方を体系的に確かめたい方は統計検定の記事が参考になります。

可視化と報告の力

数字を見た人が、次に何をするかを決められる形にする力です。

  • 最初に結論と、そこからとれる行動を書く
  • 比べたいものに合ったグラフを選ぶ（推移は線、構成は積み上げ、比較は横並びの棒など）
  • 数字の定義と抽出の時点を、グラフのそばに書く
  • 経営層向けと現場向けで、同じ結果の見せ方を変える

BIツールは、既存のダッシュボードを使って分析し、必要な見方を足す使い方を求められることが多くあります。ダッシュボードの設計や運用を広く担う場合は、BIエンジニアの仕事と重なります。

依頼を進める力

フリーランスの案件では、技術と同じくらい、依頼の進め方が見られます。

  • 依頼を受けたら、目的、期限、使い道を確かめる
  • 依頼が重なったときに、優先順位を依頼者と決める
  • 途中で分かったデータの制約を早めに伝える
  • 同じ依頼が繰り返し来るものは、定例のレポートや仕組みにする提案をする
  • 回答した数字ごとに、使ったクエリと抽出の時点を残し、後から聞かれても説明できるようにする

社内の人であれば後から聞き直せることも、外部の立場では契約が終わると説明できなくなります。誰が見ても数字の出どころが分かる形で残す習慣は、継続の判断でも評価されやすい部分です。

経験の段階ごとに求められること

段階任されること求められる深さ
抽出と集計を任される指定された条件の集計、定例レポートの更新粒度の理解と検算、期限を守ること
分析のテーマを任される依頼の意図を聞き直し、原因や打ち手の候補を示す指標の分解、施策の結果の読み方、報告
分析の窓口を任される依頼の優先順位、指標の定義の管理、ほかのメンバーのレビュー関係者との合意づくり、定義の文書化、品質の基準づくり

最初の段階では、SQLの正確さと速さが中心に見られます。段階が上がるほど、依頼者と話して問いを決める力と、ほかの人の数字を見て誤りに気づく力の比重が増えます。

注意

生成AIでSQLの下書きを作る現場は増えていますが、生成されたSQLは、テーブルの粒度や定義を取り違えていても、もっともらしい数字を返します。下書きを使う場合も、結果を別の方法で検算する手順を省かないことが大切です。発注元のテーブル定義や集計結果を外部のサービスに入力してよいかは、事前に発注元の決まりを確かめてください。

資格の位置づけ

資格がなくても参画できる案件は多くあります。知識の整理として使える試験には次のものがあります（2026年10月時点の各公式サイトによる）。

  • 統計検定（統計質保証推進協会）：1級から4級までの区分のほか、データサイエンス基礎・発展・エキスパートの区分があります。データサイエンス基礎は、Excelでのデータの前処理から解析、結果の読み取りまでの一連の力を問うものとされています
  • データサイエンティスト検定 リテラシーレベル（データサイエンティスト協会）：データサイエンス力・データエンジニアリング力・ビジネス力の3つの力について、見習いレベルの実務能力や知識を証明するものとされています

詳しくは統計検定の記事とデータサイエンティスト検定の記事をご覧ください。案件では、資格より実際の分析で数字を正しく扱えているかが問われます。

よくある質問

Pythonは必要ですか？

SQLとスプレッドシート、BIツールで完結する案件も多くあります。Pythonは、定例の集計の自動化や、SQLでは書きにくい加工で役に立ちます。案件の条件に「Python」とある場合は、使う場面がどこかを面談で確かめておくと、求められる深さが分かります。

BIツールはどこまで使えればよいですか？

データアナリストの案件では、既存のダッシュボードから必要な数字を読み取り、分析に合わせて見方を足せることが求められやすい傾向があります。データの接続やモデルの設計、権限の管理まで任される場合は、BIエンジニアに近い役割として条件を確かめましょう。

統計の知識はどの程度必要ですか？

平均とばらつき、偶然の範囲の差かどうかの判断、比較するときの偏りといった基本を、誤らずに使えることが求められます。高度な統計手法を使う場面は、データサイエンティストと分担することもあります。基本に不安がある場合は、統計検定などで体系を学び直しておくと、面談で根拠を持って説明しやすくなります。
