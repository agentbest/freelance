Web制作・デザイン

WordPressエンジニアのフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい6つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

WordPressエンジニアの案件選びで差が出るのは、報酬の額より、作る範囲、サイトの今の状態、本番への反映の方法、保守の範囲と急ぎの対応の扱いです。同じ「保守」「構築」の募集でも、更新が何年も止まったサイトを預かるのか、検証環境が整ったサイトに入るのかで、負担もリスクもまったく違います。

この記事では、WordPressの案件で契約前に確かめたい6つの点と、確かめた内容を書面と照らし合わせる方法を整理します。契約全般の確認点は業務委託契約で確かめたいことで解説しているので、ここではWordPressの案件に固有の点に絞ります。

WordPressの案件選びで差が出る理由

WordPressの案件は、募集の文面だけでは中身が見えにくい職種です。理由は次の3つです。

  • 「WordPressの経験」の幅が広い：管理画面の設定で組み立てる仕事から、独自ブロックやプラグインをコードで書く仕事まで、同じ言葉で募集される
  • サイトの状態が見えない：使われているテーマやプラグイン、PHPの版、本体のファイルを直接書き換えた跡は、入ってみるまで分からないことが多い
  • 保守の範囲があいまいになりやすい：「保守」に、更新だけを含めるのか、小さな修正や問い合わせ、障害の対応まで含めるのかが現場ごとに違う

これらは参画した後に分かると、稼働の見込みや報酬の前提が崩れます。面談と事前の確認で、できるだけ先に聞いておくことが大切です。報酬の考え方はWordPressエンジニアの報酬の記事をご覧ください。

契約前に確かめたい6つの点

1. 作る範囲は、テーマか、機能か、設定か

最初に確かめるのは、仕事の中心が何かです。テーマのテンプレートを組む仕事か、独自ブロックやプラグインを書く仕事か、既製のテーマとプラグインで組み立てる設定の仕事かで、求められる技術も、かかる時間も変わります。デザインを誰が担うか、入力するデータの流し込みや編集者向けの説明が含まれるかも、あわせて聞いておきます。

2. サイトの今の状態

運用中のサイトに入る案件では、次の点を聞いておきます。

  • 使われているWordPressとPHPの版
  • テーマの種類（既製のテーマか、子テーマか、独自のテーマか）
  • 更新が止まっているプラグインや、本体・プラグインのファイルを直接書き換えた箇所の有無
  • 最後に本体やプラグインを更新した時期

WordPressの公式サイトでは、正式にサポートされるのは最新版だけだと説明されています。PHPの公式サイトでは、2026年10月時点でサポートされている版は8.2〜8.5で、8.2のセキュリティサポートは2026年12月31日までとされています。古い版のまま長く運用されてきたサイトでは、更新を始めた途端に不具合が出ることがあり、保守の案件でも実質は改修の仕事になることがあります。

3. 環境と、本番への反映の方法

検証環境があるか、本番への反映をどの方法で行うか（管理画面から、ファイルの転送で、仕組みを使って自動で、など）、反映するのは自分か発注元か、バックアップは誰がどこで取っているかを確かめます。検証環境がなく、本番で直接作業することを求められる案件は、障害が起きたときの責任の線があいまいになりやすい点に注意が必要です。リモートで受けるときの分かれ目はWordPressエンジニアのリモート案件の記事で解説しています。

エージェントベストの見解

WordPressの案件をご紹介していると、参画後に負担が大きくなりやすいのは、報酬が低い案件より、サイトの状態が分からないまま始まった案件です。更新が長く止まっていたサイトでは、最初の更新から不具合の対応が続き、想定の稼働を超えることがあります。面談の段階で、版や最後に更新した時期、検証環境の有無を聞いておくことをおすすめします。

4. 保守の範囲と、急ぎの対応の扱い

保守の案件では、範囲に含まれる作業を一つずつ確かめます。

確かめる点聞いておきたいこと
定期の作業本体・テーマ・プラグインの更新の頻度、バックアップの確認
小さな修正どの程度までを保守に含めるか、件数や時間の目安
問い合わせ誰から、どの手段で来るか、返答の目安
障害の対応稼働日以外や夜間の連絡にどこまで応じるか、応じた時間の扱い
範囲外の依頼新しいページや機能の追加を、別の見積もりにするか

範囲が決まっていないまま始めると、依頼が少しずつ増え、稼働の幅を超えやすくなります。稼働時間の精算は精算幅の記事、範囲が広がったときの考え方は作業範囲が広がったときの契約の扱いをご覧ください。

5. 契約の形と、負う責任の範囲

準委任の契約か、請負の契約かで、負う責任が変わります。構築の案件では、成果物の完成を約束する請負の形になることがあり、公開後の不具合をいつまで、どこまで直すかが問題になります。保守の案件で請負に近い書き方になっていないか、障害が起きたときに損害の責任を負う書き方になっていないかを確かめましょう。契約の形の違いは準委任と請負の違い、不具合の責任の考え方は契約不適合責任の記事で解説しています。

6. コードの権利と、公開してよい範囲

自分で作ったブロックやプラグイン、テーマの権利が、納品後に誰のものになるかを確かめます。手元で作り置きしている部品を案件で使う場合は、その部品の権利をどう扱うかも先に決めておきます。WordPressや多くのプラグインはオープンソースのライセンスで公開されているため、それを組み込んだコードの扱いにも注意が必要です。考え方はオープンソースのライセンスの記事が参考になります。制作の実績として公開してよいかも、このときにあわせて聞いておくと後で困りません。

注意

会員の情報やフォームの問い合わせ、注文の情報を扱うサイトでは、管理画面やデータベースに個人情報が入っています。手元に本番のデータを持ち出してよいか、どの範囲で扱えるかが契約で決められていることがあります。参画前に、個人情報の扱いの取り決めを確かめましょう。考え方は個人情報を扱う業務委託の注意点で解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者はフリーランスに業務を委託したら直ちに、業務の内容、報酬の額、支払期日などの取引条件を、書面またはメールなどの電磁的方法で明示することとされています（2026年10月時点、公正取引委員会の案内による）。明示される事項の内容はフリーランス法で明示される取引条件をご覧ください。

WordPressの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、作る範囲（テーマ、ブロック、プラグイン、設定）や保守の範囲が書かれているか
  2. 稼働日以外の対応や障害の対応の扱いが、書面とずれていないか
  3. 稼働の幅と、超えたときの精算方法
  4. 納品の後に直す範囲と期間（請負の場合）
  5. コードの権利と、実績として公開してよい範囲
  6. 契約期間と更新の時期

面談で聞いておくとよい質問はWordPressエンジニアの面談の記事の逆質問の項目でも紹介しています。一般的な逆質問の考え方は面談で聞いておくべき逆質問をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。WordPressの案件で気になりやすいサイトの版や検証環境の有無、稼働日以外の対応の扱いなど、書面だけでは読み取りにくい点は、ご質問いただければ確認します。条件に迷う点があれば、契約の前に早めにご相談ください。

ポイント

  • WordPressの案件選びで差が出るのは、作る範囲、サイトの状態、反映の方法、保守の範囲
  • 契約前に、作る範囲、サイトの今の状態、環境と反映の方法、保守の範囲と急ぎの対応、契約の形、コードの権利の6点を確かめる
  • 古い版のまま運用されてきたサイトでは、保守の案件でも改修の仕事になることがある
  • 聞いた内容は、フリーランス法で明示される取引条件の書面と照らし合わせる

よくある質問

更新が長く止まっているサイトの案件は避けたほうがよいですか？

避ける必要はありません。版上げや改修の経験を積める案件でもあります。大切なのは、サイトの状態を知ったうえで受けることです。最初の数週間を調査にあてる、改修の作業を保守とは別の範囲にする、といった形で条件をそろえられるかを確かめましょう。

面談でサイトの版や更新の状況を聞くのは失礼ですか？

失礼ではありません。運用中のサイトを任せる発注元にとっても、状態を確かめようとする人のほうが安心できます。答えられる範囲で教えてもらい、分からない点は参画後の最初の作業として調べる、と合意しておけば十分です。

報酬の高い案件と、範囲のはっきりした案件で迷ったらどうしますか？

報酬が高くても、保守の範囲や急ぎの対応の扱いがあいまいな案件は、稼働が膨らんで時間あたりの報酬が下がることがあります。月の稼働の見込みと範囲を並べて比べ、迷う場合は、範囲を書面で確かめられるほうを優先するのがおすすめです。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 業務委託契約の基礎

契約不適合責任とは｜請負で負う責任の範囲と期間、契約書での決め方

契約不適合責任は、請負で引き渡した成果物が種類・品質・数量で契約内容に合わないときに負う責任です。注文者は修補・減額・損害賠償・解除を求められ、民法では不適合を知ってから1年以内の通知が必要です。契約で変わる範囲と期間を整理します。

 業務委託契約の基礎

納品物にOSSを使うときのライセンスの注意点｜義務の違いと契約での扱い

OSSは条件を守れば使えるソフトウェアで、ライセンスごとに表示やソースコード提供などの義務が違います。納品前に、ライセンスの種類と義務、発注者の利用方針、契約の保証や権利の条項との食い違いを確かめ、一覧で共有します。
