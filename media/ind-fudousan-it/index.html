業界別の案件

不動産業界のフリーランスIT案件｜案件の種類と特徴、合う人・合わない人

不動産業界のフリーランスIT案件は、物件・顧客の管理、賃貸の管理、ポータルサイトとの連携や自社サイト、電子契約とオンラインの重要事項説明への対応、不動産テックのデータ活用の5つに大きく分かれます。同じ「不動産」でも、売買の仲介会社、賃貸の管理会社、分譲を行う開発会社では、扱うシステムがまったく違います。

共通する特徴は、宅地建物取引業法などの法令が業務の手順を決めているため、システムの要件にも法令の手順がそのまま入り込むことです。この記事では、案件の種類と特徴、合う人・合わない人を整理します。業務の流れは不動産の業務知識の記事、守るルールは不動産の規制の記事で扱います。建物を建てる側のシステムは建設業界のIT案件の記事をご覧ください。

まず「どの事業のシステムか」で案件を見分ける

不動産会社の事業は、大きく次の形に分けられます。宅地建物取引業法は、宅地や建物の売買・交換と、売買・交換・貸借の代理や媒介を業として行うことを「宅地建物取引業」と定めています（第2条第2号）。これに加えて、賃貸住宅の管理を受託する事業は、賃貸住宅の管理業務等の適正化に関する法律（以下、賃貸住宅管理業法）の対象です。

事業の形主な業務システムで扱うもの
売買の仲介売主・買主の間に入り、物件の紹介から契約までを進める物件情報、顧客と商談の履歴、査定、契約書類
賃貸の仲介部屋を探す人に物件を紹介し、賃貸借契約までを進める物件の空室情報、反響（問い合わせ）、内見の予約、申込み
賃貸の管理オーナーから委託を受け、建物の維持保全や家賃の管理を行うオーナーと入居者、契約の更新、家賃の入出金、修繕の手配
開発・分譲土地を仕入れ、建物を建てて販売する用地の情報、販売の進捗、顧客、引渡し後の対応
自社で保有する物件の運用オフィスや商業施設、住宅を保有して貸す物件ごとの収支、テナント、資産のデータ

1社がいくつもの事業を持っていることも多く、その場合は事業ごとに別のシステムが動いていて、つなぎ込みが案件になることがあります。業務の流れの詳細は不動産の業務知識の記事で説明しています。

案件の種類は大きく5つ

1. 物件・顧客管理（仲介の基幹とCRM）

仲介会社の中心にあるのが、物件の情報と、問い合わせをくれた顧客との商談を管理する仕組みです。パッケージやSaaSの導入、CRMの設定と拡張、既存の自社システムの改修などの案件があります。CRMの経験は、業界が違っても生かしやすい領域です。Salesforceなどの経験が生きる場面はSalesforceのスキルの記事も参考になります。

物件の情報には、所在地、面積、価格や賃料、間取り、設備、法令上の制限など多くの項目があり、物件の種類ごとに必要な項目が違います。データの持ち方を設計する力が問われる領域です。

2. 賃貸管理システム

管理会社向けに、オーナーとの管理受託契約、入居者との賃貸借契約、家賃の請求と入金の消し込み、オーナーへの送金と報告、更新や解約、修繕の手配までを扱うシステムです。お金の流れと契約の期日を正しく回すことが中心になるため、会計や請求のシステムの経験が生きます。

賃貸住宅管理業法は、管理業務を、賃貸住宅の維持保全を行う業務と、それと併せて行う家賃・敷金・共益費などの金銭の管理と定めています（第2条第2項）。賃貸管理システムの機能の多くは、この2つの業務を支えるものです。

3. ポータル連携と自社サイト

物件の情報を不動産ポータルサイトに掲載するための入稿や連携、自社の物件検索サイトの開発、反響を受け付けて顧客管理につなぐ仕組みなどです。一般的なWeb開発やAPI連携の技術が生かしやすく、業界が初めてでも入りやすい領域です。

一方で、物件の広告には業界独自のルールがあり、掲載してよい時期や表示すべき項目、成約済みの物件の扱いなどがシステムの要件になります。中身は不動産の規制の記事で整理しています。

4. 電子契約とIT重説への対応

国土交通省によると、宅地建物取引業法の書面の電子化を可能にする政省令の改正が2022年5月18日に施行されました。重要事項説明書、契約締結時の書面、媒介契約締結時の書面を、相手方の承諾を得たうえで電子書面で提供できるようになっています。テレビ会議などを使った重要事項説明（IT重説）は、賃貸取引で2017年10月1日、売買取引で2021年3月30日から本格運用されています。

これを受けて、電子契約サービスの導入、契約書類を作る仕組みとの連携、承諾の記録、オンラインの説明の予約や録画の管理などの案件があります。法令が求める手順をシステムの流れにどう落とすかが要件の中心です。

5. 不動産テック・データ活用

価格の査定、市場の分析、物件や顧客のデータを集めた基盤づくりなどの案件です。データエンジニアやデータサイエンティストの経験が生きます。データエンジニアのスキルの記事も参考にしてください。

不動産のデータは、住所や地番の表記ゆれで同じ物件かどうかが分かりにくいという課題があります。国土交通省は2022年3月31日に「不動産IDルールガイドライン」を策定し、不動産登記簿の不動産番号13桁と特定コード4桁の計17桁からなる「不動産ID」のルールを示しています。データの名寄せや他のデータとのつなぎ込みに関わる案件では、こうした動きを知っておくと話が通じやすくなります。

このほか、システムの選定や業務の見直しを進めるPMOやDXの支援、社内の情報システムの運用といった案件もあります。

エージェントベストの見解

不動産の案件をご紹介していると、同じ「不動産業界の経験あり」でも、売買仲介の顧客管理をしてきた方と、賃貸管理の家賃まわりをしてきた方では、合う案件がほとんど重なりません。面談でつまずきやすいのは、どの事業の、どの業務のシステムだったかを言えず、不動産の経験を一括りにして話してしまうケースです。事業の形と業務を先に言える準備をしておくことをおすすめします。

不動産の案件に共通する4つの特徴

法令の手順がそのまま要件になる

重要事項の説明は契約が成立するまでに行う（宅地建物取引業法第35条）、契約が成立したら遅滞なく書面を交付する（同第37条）といったように、業務の順番や書類が法令で決まっています。システムの画面の遷移や、帳票、承認の流れにもこの順番が入り込みます。要件定義では、業務部門の担当者の話と法令の手順をつき合わせる作業が多くなります。

繁忙期と月末の締めに左右される

賃貸の仲介や管理では、引越しの多い時期に問い合わせや契約が集中します。家賃の請求や入金の確認、オーナーへの送金は月の決まった日に集中します。リリースや切替の時期がこうした業務の山を避けて決まることが多いため、稼働の予定は案件ごとに確かめておきたい点です。

現場は店舗や現地にある

仲介の店舗、管理物件の現地、モデルルームなど、業務の現場が事務所の外に広がっています。スマートフォンやタブレットでの入力、外出先からの確認など、現場で使う前提の要件が出てきます。システムを使う人のITへの慣れもさまざまなため、分かりやすさへの要求が強くなります。

会社の規模とシステムの成熟度に差がある

大手の不動産会社のように自社でシステムを持つ会社もあれば、パッケージやSaaSを組み合わせて使う会社、紙や表計算ソフトが中心の会社もあります。同じ不動産の案件でも、大規模な基幹の刷新から、小さな業務の電子化まで幅があります。

合う人・合わない人の傾向

合いやすい人合いにくいかもしれない人
業務部門の話を聞き、手順を整理するのが苦にならない技術の話だけに集中したい
契約や請求など、お金と期日を正しく回す仕組みに関心がある法令や書類の細かい決まりを読むのが苦手
現場の使い勝手を考えた画面や運用を作るのが好き社内の利用者との調整を避けたい
パッケージやSaaSの設定と連携を組み合わせて進められるゼロから作る開発だけをしたい

ただし、不動産テックの企業やポータル側の開発では、一般的なWebサービスと同じ進め方をしている現場もあります。「不動産だから紙と手作業が多い」と一律に決めず、事業の形と案件の種類で見ていくのが現実的です。

案件情報を読むときに確かめたいこと

不動産業界の案件情報を見るときは、技術の欄に加えて、次の点を確かめておくと、参画後の行き違いを減らせます。

  1. 事業の形：売買の仲介か、賃貸の仲介か、管理か、開発・分譲か
  2. 対象の業務：物件の登録、顧客の追客、契約、家賃の管理、修繕のどこか
  3. システムの形：自社開発か、パッケージやSaaSの導入・設定か
  4. 関わる法令の手順：重要事項の説明や書面の電子化、広告のルールに関わる要件があるか
  5. 稼働の山：繁忙期や月末に合わせた作業や、リリースの制約があるか

案件で求められる業務知識の中身は不動産の業務知識の記事、経験の書き方は不動産のスキルシートの記事で説明しています。業界知識を強みにするという全体の考え方は業界知識の記事が入り口になります。常駐とリモートの考え方は常駐案件とリモート案件の記事をご覧ください。

よくある質問

不動産業界が初めてでも案件に参画できますか？

技術や役割が案件と合っていれば、業界が初めてでも参画できることはあります。入りやすいのは、Web開発やAPI連携が中心のポータル連携や自社サイト、CRMの設定、データ基盤の案件です。参画後に必要になる業務の流れは、不動産の業務知識の記事を参考に準備しておくと立ち上がりが楽になります。

宅地建物取引士の資格がないと不動産のIT案件には入れませんか？

IT案件の多くは、資格よりもシステムの経験と業務の理解が重視されます。ただ、重要事項の説明や契約書類に関わる要件では、宅地建物取引業法の手順を理解していることが求められます。資格を取るかどうかは別として、法令の手順を押さえておくと要件の話についていきやすくなります。

電子契約の案件では、どんな経験が生きますか？

電子契約サービスの導入や他のシステムとの連携、帳票を作る仕組み、承諾や同意の記録の設計などの経験が生きます。不動産の取引では、書面を電子で提供する前に相手方の承諾を得るなど、法令で決まった手順があります。要件の背景にあるルールは不動産の規制の記事で整理しています。
