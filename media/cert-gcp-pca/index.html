フリーランスにGoogle Cloud認定 Professional Cloud Architectは役立つ？評価される場面と準備

公開 2026-10-29　監修：株式会社エージェントベスト

Google Cloud認定 Professional Cloud Architect（以下、PCA）は、持っていなくても参画できるGoogle Cloudの案件が多い一方で、構成を決める役割に入りたいときや、AWSなど他のクラウドの経験からGoogle Cloudの案件に移るときには裏付けとして効きます。試験はケーススタディを含み、要件から構成を選ぶ考え方が問われるため、面談で設計の判断を話す準備にもつながります。

この記事では、2026年10月時点のGoogle Cloudの案内をもとに、PCAの範囲・形式・有効期間を確かめ、効く場面と効きにくい場面、実務経験との組み合わせ方を整理します。分野ごとのProfessional認定の位置づけはGCPエンジニアのスキルの記事、職種として取る資格の選び方はGCPエンジニアの資格の記事で扱っています。

PCAの試験の範囲と形式

PCAは、Google Cloudが実施する認定です。Google Cloudの技術を使って、組織のためのクラウドの構成を設計・管理する力を確かめるものと位置づけられています。

項目内容（2026年10月時点のGoogle Cloudの案内による）
実施Google Cloud
推奨される経験業界経験3年以上（Google Cloudでの設計と管理の経験1年以上を含む）。受験の必須条件はない
標準試験2時間、50〜60問の多肢選択式。ケーススタディが2つ出題され、試験全体の20〜30%
受験方法遠隔監視のオンライン試験、またはテストセンター
言語英語、日本語
有効期間2年間

評価される能力として、次の6つが挙げられています。

  1. クラウドのソリューションアーキテクチャの設計と計画
  2. クラウドのソリューションインフラストラクチャの管理とプロビジョニング
  3. セキュリティとコンプライアンスに対応した設計
  4. 技術プロセスやビジネスプロセスの分析と最適化
  5. クラウドアーキテクチャの実装の管理
  6. ソリューションとオペレーションの卓越性の確保

技術の範囲だけでなく、ビジネスプロセスの分析や実装の管理まで含まれている点が、PCAの特徴です。

ケーススタディの読み方が問われる

標準試験では、架空の企業の状況と要件を書いたケーススタディが出題され、公開されている4つのうち2つが使われると案内されています。ケーススタディは試験中に画面を分割して確認できます。企業の事業の状況、今の環境、技術とビジネスの要件を読み、どの構成が合うかを選ぶ形です。案件の要件定義で、発注側の資料から制約を拾い出す作業に近いところがあります。

有効期間と3つの更新方法

有効期間は2年間で、更新には次の3つの方法が案内されています。

  • 標準試験を受け直す
  • 短縮版の更新試験を受ける：1時間・25問で、生成AIを活用したソリューションのケーススタディが試験の大半を占める形式。受けるには有効な認定と更新の資格要件が必要
  • Google Skillsで指定のコースやスキルバッジを修了する：有効期間の最後の1年以内に修了したものが対象で、更新後の有効期間は1年間

更新の方法によって次の期限までの長さが変わります。スキルシートに書く有効期限の確かめ方はGCPのスキルシートの記事で紹介しています。

PCAがなくても入れる案件が多い理由

Google Cloudの案件では、BigQueryを中心にしたデータ基盤、GKEやCloud Runでのアプリの実行環境、組織・フォルダ・プロジェクトの階層に沿った権限の設計など、分野ごとの経験が具体的に問われます。データ分析の担当者やアプリ開発の担当者と、どう役割を分けて環境を整えたかを話せれば、PCAがなくても参画が決まることは珍しくありません。

また、PCAは設計全般を広く問う認定です。データ基盤だけを担う案件や、コンテナの運用だけを担う案件では、分野ごとのProfessional認定や実務の経験のほうが先に見られることもあります。

PCAが効きやすい場面

構成を決める役割に入るとき

構築や運用の経験が中心の人が、要件定義や構成の設計を担う案件に応募するとき、PCAは設計の観点を体系的に学んだことの裏付けになります。評価される能力にビジネスプロセスの分析が含まれているため、技術の選定を事業の要件と結びつけて説明する役割と相性がよい認定です。上流の工程に入る考え方は上流工程の案件に入るための記事にまとめています。

他のクラウドからGoogle Cloudの案件に移るとき

AWSやAzureの設計経験がある人が、Google Cloudの案件に応募するときにも効きます。クラウドの設計の考え方は共通していても、リソースの階層やIAMの仕組み、ネットワークの扱いはクラウドごとに違います。PCAがあれば、その違いを学んだうえで応募していることが伝わります。AWSの認定はAWS認定ソリューションアーキテクトの記事で扱っています。

歓迎条件に名前があるとき

Google Cloudのパートナー企業が関わる案件などでは、案件票の歓迎条件に認定名が書かれていることがあります。その場合は、書類の段階で目に留まりやすくなります。

PCAだけでは効きにくい場面

  • 分野を深く掘る案件：データ基盤、ネットワーク、DevOpsなどの専門の案件では、その分野のProfessional認定や実務の経験が先に見られます
  • Google Cloudの実務がまだない場合：推奨される経験にGoogle Cloudでの設計と管理1年以上が含まれているとおり、試験の知識だけでは、設計を任せる判断の材料としては弱くなります
  • 費用の見積もりと管理を問う案件：BigQueryの費用の抑え方など、運用の中で身につく判断は、試験より実務の経験で問われます

エージェントベストの見解

案件紹介の現場では、PCAをお持ちの方の中でも、ケーススタディのように「要件のどこから、その構成を選んだか」を自分の案件で話せる方は、設計寄りの案件の面談で評価されやすい傾向があります。反対に、サービスの名前を並べて構成を説明するだけでは、判断の深さが伝わりにくくなります。取得したら、過去の案件を一つ選び、事業の要件・制約・選んだ構成を3行で書いてみることをおすすめします。

実務経験との組み合わせ方

PCAの6つの能力のうち、自分の経験で裏付けられるものと、試験の知識だけのものを分けておくと、面談での話し方が決まります。

PCAの能力結びつけやすい実務の経験
設計と計画新しい環境の構成案の作成、移行計画
管理とプロビジョニングTerraformでのプロジェクトやネットワークの作成
セキュリティとコンプライアンス組織のポリシー、IAMのロールの整理、監査ログの設定
プロセスの分析と最適化費用の見直し、開発の流れの改善
実装の管理開発チームやデータチームへの環境の引き渡し
オペレーションの卓越性監視とアラートの設計、障害時の対応手順づくり

IaCでの構築は案件で問われることが多く、PCAの範囲だけでは示しにくい部分です。コードで環境を管理する経験はTerraform Associateの記事もご覧ください。

スキルシートでの書き方

資格欄には、正式名称、取得年月、有効期限を書きます。

例：Google Cloud Certified - Professional Cloud Architect（20XX年X月取得、有効期限20XX年X月）

経歴欄では、設計を担った案件に「事業側の要件と費用の制約から構成案を作成」のように、PCAの観点を使った場面を一言添えます。期限が切れた認定は「取得歴」として分けて書きます。

注意

Google Cloudの認定試験は、製品名の変更や新しい機能にあわせて改訂されることがあります。ケーススタディも公開されているものから出題されるため、受験の前に公式ページで最新の試験ガイドとケーススタディを必ずご確認ください。古い問題集だけで準備すると、範囲とずれるおそれがあります。

案件と並行して準備するときの進め方

  1. 公開されているケーススタディを読む：4つのケーススタディを、自分ならどう設計するかを考えながら読みます。案件の要件を読む練習にもなります
  2. 試験ガイドで6つの能力を確かめる：自分の経験で説明できる範囲と、できない範囲に分けます
  3. 検証用のプロジェクトで構成を作る：経験の薄い範囲は、費用の上限を決めた検証環境で確かめます

エージェントベストの見解

他のクラウドからGoogle Cloudの案件に移る方の面談では、前の環境の用語のまま説明してしまい、Google Cloudでどう置き換えるかが伝わりにくくなる場面をよく見かけます。たとえば、アカウントの分け方の話を、組織・フォルダ・プロジェクトの階層でどう表すかまで話せると、PCAで学んだ内容が実務に結びついていることが伝わります。面談の前に、前の案件の構成をGoogle Cloudの用語で一度説明し直してみることをおすすめします。

ポイント

  • PCAがなくても参画できるGoogle Cloudの案件は多く、分野ごとの実務の経験が先に見られる
  • 効きやすいのは、設計の役割に入るとき、他のクラウドから移るとき、歓迎条件に名前があるとき
  • 有効期間は2年。標準試験・短縮版の更新試験・Google Skillsの3つで更新でき、方法で次の期限が変わる
  • ケーススタディの考え方を自分の案件に当てはめ、判断の理由を話せるようにしておく

よくある質問

Associate Cloud Engineerを先に取るべきですか？

PCAに受験の必須条件はありません。Google Cloudの実務がまだ短い人は、構築と運用の範囲を問うAssociate Cloud Engineerから始める方法もあります。推奨される経験はGCPエンジニアがフリーランスになるにはの記事で紹介しています。

日本語で受験できますか？

2026年10月時点のGoogle Cloudの案内では、標準試験も更新試験も英語と日本語で受験できます。言語の扱いは変わることがあるため、申し込みの前に公式ページで確かめてください。

更新は標準試験と更新試験のどちらがよいですか？

更新試験は1時間・25問と短く、生成AIを活用したソリューションのケーススタディが中心です。標準試験より負担は軽い一方で、受けるには有効な認定と更新の資格要件が必要とされています。更新試験を選ぶなら期限が切れる前に受ける必要があるため、期限の半年ほど前に、どの方法で更新するかを決めておくと慌てずに済みます。
