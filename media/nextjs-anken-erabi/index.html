フロントエンド開発

Next.jsエンジニアのフリーランス案件の選び方｜契約前に確かめたい7つの点

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい7つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

フリーランスのNext.js案件を選ぶときは、報酬や稼働日数に加えて、役割の実態、版と書き方、配信先と更新の担当、サーバー側の責任の範囲、コードとテストの状態、契約の形、稼働の振れ幅と契約期間の7点を契約前に確かめておくことが大切です。Next.jsの案件は、同じ「Next.jsエンジニア募集」でもこの7点の違いで、毎日の仕事と負う責任が大きく変わります。

特に見落としやすいのは、画面の担当として入ったのに、サーバー側の入口や配信先の運用まで責任を持つことになっていないかです。この記事では、Next.jsの案件に固有の確認点を整理します。契約書全般の確認点は業務委託契約書のチェックポイント、Reactの案件に共通する点はReactエンジニアの案件の選び方で解説しています。

Next.jsの案件で選び方の差が出る理由

Next.jsは、画面、ルーティング、サーバーでの描画、データの更新、キャッシュ、配信までを一つの枠組みで扱います。そのため、案件票に「Next.js、TypeScript」とだけ書かれていても、実際の仕事の幅は案件ごとに大きく違います。

よくあるずれは次のようなものです。

  • 新しい機能の開発と聞いていたが、実際は古い版の保守と版上げが中心だった
  • 画面の担当のつもりが、Server Actionsでの更新や認証の仕組みまで任された
  • 配信先の設定やセキュリティ更新の適用を、誰が担うか決まっていなかった
  • キャッシュの考え方が現場の中で統一されておらず、古い表示の不具合の調査に追われた

こうしたずれは、面談と条件の確認の段階で、聞き方を工夫すれば多くを防げます。

契約前に確かめたい7つの点

1. 役割の実態は実装か、データの流れまでか、構成の判断か

最初に確かめたいのは、自分が担う役割の実態です。決まった構成に沿ってページと部品を作る役割か、データの取得と更新まで設計する役割か、構成とキャッシュの方針を決める役割かで、求められる経験も稼働の重さも変わります。

面談では、「参画して最初の1か月で、最も期待されている成果は何か」を聞くと、役割の実態が見えやすくなります。

2. 版、ルーター、キャッシュの考え方

使っている版と、App RouterかPages Routerか、キャッシュをどの考え方で扱っているかを確かめます。公式のサポート方針では、2026年10月時点で16.xがActive LTS、15.xはセキュリティ修正が2027年1月31日まで続き、14.x以前はサポートの対象外とされています。

サポートの対象外の版で動いているアプリは、版上げの仕事が近いうちに出てくる可能性が高くなります。古い版の案件を避ける必要はありませんが、版上げが業務範囲に入るのか、その計画は誰が立てるのかを合わせて確かめておきます。

3. 配信先と、セキュリティ更新を誰が適用するか

公式ドキュメントでは、Next.jsはNode.jsのサーバーとDockerのコンテナならすべての機能に対応し、静的な書き出しではサーバーが要る機能が使えず、各プラットフォーム向けのアダプターでは対応が配信先によって変わると説明されています。配信先によって使える機能が違うため、どこに配信しているか、その設定を誰が管理しているかを確かめます。

あわせて、セキュリティ更新の担当も確かめます。Next.jsは2026年7月から、月に1回ほどを目安にセキュリティ更新の予定を公式ブログで事前に告知する運用を始め、急ぎの問題には予告なしの更新も出すと案内しています。告知を読み、更新を適用し、影響を確かめるのが自分の仕事に入るか、入るなら稼働日以外の対応をどうするかを、参画前にはっきりさせておきましょう。

エージェントベストの見解

Next.jsの案件をご紹介していると、参画後に「聞いていた状況と違った」となりやすいのは、使っている版とキャッシュの考え方、そして配信先や更新を誰が担うかの点です。案件票には書かれにくい内容ですが、担当の範囲を判断するために必要な確認として聞けば、多くの発注元は答えてくれます。契約の前に確かめることをおすすめします。

4. サーバー側の責任の範囲

Next.jsの公式ブログでは、"use server"を付けた関数はブラウザから呼び出せる入口になり、関数の最初で権限を確かめ、引数を検証する必要があると説明されています。新しいプロジェクトでは、データへのアクセスを一か所の層にまとめる形も勧められています。

案件を選ぶときは、次の点を確かめます。

  • Server Actionsやデータの取得の層を書くのは自分か、バックエンドの担当者か
  • 認証や権限の仕組みは誰が設計し、レビューは誰が見るか
  • データベースや外部のサービスへの接続の情報を、自分が扱うか

画面の担当の範囲を超えてサーバー側の責任を持つ場合は、その範囲が業務の内容として書面に入っているかが大切です。

5. コードとテストの状態、デザインの受け渡し

既存のアプリに入る場合は、テストがどの程度あるか、レビューの決まりがあるか、デザインはどの形で受け渡されるかを確かめます。テストが少ない現場で版上げやキャッシュの見直しを任されると、変更の影響を確かめる手段を自分で用意することから始めることになります。それ自体は悪いことではありませんが、見込んでいた稼働とのずれにつながります。

6. 契約の形と、負う責任の範囲

フリーランスのNext.jsエンジニアは、多くの場合、準委任契約で参画します。準委任では、仕事の完成そのものではなく、専門家として通常求められる注意を払って業務を行うことが約束の中身になります。

一方、サイトの構築や版上げを「ここまで作って納める」形で受けると、請負の契約になり、完成と不具合への責任を負うことがあります。役割と契約の形が合っているかを確かめましょう。違いは準委任契約と請負契約の違いで解説しています。準委任の契約なのに、発注元の社員から細かな作業の指示や勤務時間の管理を受ける働き方は、偽装請負の問題につながるおそれがあります。詳しくは偽装請負の記事をご覧ください。

7. 稼働の振れ幅と、契約期間の区切り

リリースの前、版上げの切り替えの週、セキュリティ更新が急ぎで出たときなどは、稼働が増えやすくなります。精算幅を超えたときの扱いと、稼働が少ない月の扱いを確かめておきましょう。精算の仕組みは精算幅の記事をご覧ください。

契約期間と、版上げやリリースの区切りが合っているかも確かめます。切り替えの直前に契約の更新時期が来ると、更新されなかった場合に最も大事な局面を見届けられません。フリーランス法では、6か月以上継続して業務を委託している場合に、契約を解除したり更新しなかったりするときは、少なくとも30日前までに予告することが求められています（2026年10月時点、公正取引委員会の案内による）。詳しくは中途解除の30日前予告の記事をご覧ください。

注意

Next.jsの案件では、参画後に担当が少しずつ広がりやすい傾向があります。配信先の設定、認証の仕組み、別のアプリの版上げの相談など、契約の業務範囲に入っていない仕事を頼まれたときは、引き受ける前に範囲と条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容、報酬の額、支払期日などの取引条件を、書面またはメールなどの電磁的な方法で明示することとされています（2026年10月時点、公正取引委員会の案内による）。明示される事項はフリーランス法で明示される取引条件をご覧ください。

Next.jsの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、担う範囲（画面の実装、データの取得と更新、版上げ、配信や更新の適用など）が書かれているか
  2. 準委任の契約なのに、完成や不具合への責任を負う書き方になっていないか
  3. 稼働の幅と、超えたとき、緊急の対応をしたときの精算方法
  4. 契約期間と更新の時期

面談で聞いておくとよい質問はNext.jsエンジニアの面談でよく聞かれる質問と答え方の逆質問の項目でも紹介しています。一般的な逆質問の考え方は面談で聞いておくべき逆質問をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。Next.jsの案件で気になりやすい版上げの扱いや、セキュリティ更新の担当、サーバー側の責任の範囲など、書面だけでは読み取りにくい点は、ご質問いただければ確認します。

ポイント

  • Next.jsの案件は、同じ募集名でも版、キャッシュの考え方、配信先、サーバー側の責任で負担が大きく変わる
  • 役割の実態、版とルーター、配信先とセキュリティ更新の担当を面談で確かめる
  • Server Actionsや認証の責任を持つなら、その範囲が業務の内容に書かれているかを確かめる
  • 契約の形、稼働の振れ幅と精算、契約期間の区切りを書面と照らし合わせる

よくある質問

サポート対象外の古い版の案件は避けたほうがよいですか？

避ける必要はありません。版上げの経験は、次の案件で評価されやすい経験です。ただ、版上げが業務範囲に入るのか、計画を立てる権限があるのか、変更の影響を確かめるテストがあるのかを、参画前に確かめてから受けることをおすすめします。

報酬の高い案件と、構成が自分に合う案件で迷ったらどうしますか？

一概には言えませんが、版やキャッシュの考え方、配信先が経験と離れている案件では、立ち上がりに時間がかかり、稼働が増えて時間あたりの報酬が下がることがあります。報酬の額だけでなく、稼働の見込みと担う範囲を合わせて比べるとよいでしょう。報酬の決まり方はNext.jsエンジニアの報酬の記事で解説しています。

面談で配信先やセキュリティ更新の担当を聞くのは失礼ですか？

担当の範囲を判断するための確認として聞けば、失礼にはあたりません。「参画後に最初に取り組むことを把握したい」という目的を添えると、相手も答えやすくなります。答えられない場合もあるので、その場合は無理に聞き出さず、ほかの確認点で判断しましょう。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 業務委託契約の基礎

偽装請負とは｜指揮命令の線引きとフリーランスが注意すること

偽装請負は、請負や準委任の契約なのに、実態として発注者が働き手に直接指揮命令している状態です。判断は契約の名前ではなく実態で行われます。フリーランスは「労働者性」の基準と、参画前に確かめたい点を押さえておきましょう。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 フリーランス新法・下請法

中途解除の30日前予告｜フリーランス新法のルールと例外

6か月以上の業務委託を発注者が中途解除・不更新にするときは、原則として30日前までの予告が必要です。予告の方法、予告が不要になる5つの例外、理由開示の請求の仕方を、公正取引委員会・厚生労働省の資料をもとに整理します。
