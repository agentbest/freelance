S/4HANA移行の週2〜3日・副業案件｜探し方と受けるときの注意点

公開 2026-11-04　監修：株式会社エージェントベスト

週2〜3日や副業で受けられるS/4HANA移行の案件は、数は限られますが、あります。移行は決まった日に向かって全員が一斉に動く仕事のため、リハーサルや本番切替の時期は週5日どころか休日も含めた体制が組まれます。そのなかで週2〜3日でも成り立ちやすいのは、現行調査やアドオンの棚卸しの期間、方式や計画への助言、変換ルールや照合の設計のように成果物で区切れる仕事、稼働後の問い合わせ対応の特定の曜日などです。

探すときは、「週3日で何でも」ではなく、移行のどの段階の、どの仕事なら稼働日に収まるかを自分から示すことが大切です。この記事では、週2〜3日・副業の移行案件の傾向、探し方、受けるときの注意点を整理します。週3日の働き方全般は週3日の業務委託案件の記事で解説しています。

週2〜3日の移行案件が少ない理由

移行の案件で週5日が中心になるのは、仕事の性質によるものです。

  • 全員が同じ日程に向かう：切替の日が決まっており、工程の遅れが直接その日に響く。不在の日に課題が止まると、ほかのチームの作業も止まる
  • リハーサルと切替は全員拘束：リハーサルの週は長時間になりやすく、本番の切替は夜間や休日をまたぐ。週2〜3日の契約でも、この時期は曜日を選べない
  • 領域をまたぐ課題が多い：会計・販売・購買・基盤の課題が同時に動き、確認の相手が毎日のように変わる
  • テストは業務部門の都合で動く：ユーザーテストは業務部門の空いている日に集中し、その場で切り分ける人が要る

そのため、移行チームの中心の役割を週2〜3日で募集することは多くありません。週2〜3日の案件は、段階と仕事を絞った役割として出てくるのがほとんどです。

現行調査やアドオンの棚卸しは、移行の最初の段階で人手が要る一方、判断の会議はまだ少ない時期です。旧環境を読み解ける経験者が、稼働日にまとめて調査を進める形が成り立ちます。

方式検討や計画への助言は、移行を一度も経験していない発注元が、経験者の目を借りたいときに出てくる案件です。発注元の担当者が責任者となり、フリーランスはベンダーの提案や日程案に対して、「どこで時間がかかるか」「照合の基準が決まっているか」といった観点で意見を出します。経験者ほど向いている型です。

稼働後の問い合わせ対応は、本番切替の後、業務部門からの問い合わせが落ち着くまでの期間に、曜日を決めて窓口に入る形です。旧環境との違いを説明できる人が求められるため、移行の経験者が週2〜3日で受けやすい型の一つです。

エージェントベストの見解

S/4HANA移行の案件をご紹介していると、週2〜3日の希望で決まりやすいのは、「現行調査とアドオンの棚卸しなら、この稼働日数でここまで担える」と、段階と仕事の範囲を自分から示せる方です。反対に、移行チームの中心の役割を週3日で引き受けようとすると、発注元がリハーサルや切替の週の対応に不安を持ち、見送られやすい傾向があります。稼働日数と担える段階をセットで伝えることをおすすめします。

週2〜3日の移行案件の探し方

1. 担える段階と仕事を先に決める

週2〜3日で受けるなら、移行のどの段階の、どの仕事を担い、どの仕事は担わないかを先に決めておきます。たとえば「現行調査と変換ルールの作成は担うが、リハーサルの週の作業と本番の切替は担わない」のように、範囲を言葉にしておくと、案件との照らし合わせが早くなります。

2. 切替の週末をどう扱うかを決める

移行の案件で最も大きな論点は、本番切替の週末です。週2〜3日の契約でも、切替の週だけは曜日を選べないことがあります。「切替の週だけは休日の作業を受ける」「切替には関わらず、その前の段階だけ担う」のどちらで探すかを、先に決めておきましょう。

3. 稼働する曜日と、稼働外の連絡の扱いを決める

移行の案件では、領域をまたぐ定例会議の曜日と稼働日が合うかが大切です。稼働する曜日を固定できるか、稼働日以外にどこまで連絡に応じられるかを決めておきます。曜日を柔軟に選べる人ほど、選択肢が広がります。

4. 週5日の案件の一部を切り出してもらう

週5日で募集されている案件でも、仕事を分ければ週2〜3日で受けられる場合があります。現行調査の期間だけ、特定のデータ領域の変換ルールだけ、特定のアドオンの改修だけ、といった切り出し方を相談する道もあります。ただし、発注元の体制によっては難しいこともあるため、無理に条件を押しつけないことが大切です。

5. 経験の近い段階と役割から選ぶ

稼働日数が少ないほど、立ち上がりの早さが求められます。移行方式、旧環境の版、担当領域が自分の経験に近い案件を選ぶと、短い稼働でも成果を出しやすくなります。リモートで受けられるかどうかも合わせて確かめておきましょう。段階ごとのリモートとの相性はS/4HANA移行のリモートの記事で解説しています。

短い稼働で信頼を得る進め方

週2〜3日の移行案件は、不在の日があることを前提に、仕事の進め方を組み立てる必要があります。

  • 成果物の形を先に合意する：調査の結果の一覧、変換ルールの文書、照合の設計など、何をどの形で出すかを参画時に決め、不在の日にほかの人が使える状態にしておく
  • 課題の持ち主を残さない：自分が持ち主の課題は、稼働日の終わりに期日と状態を更新し、不在の日に止まらないようにする
  • 週の始めと終わりに短く報告する：稼働日の最初に今週の予定、最後に結果と気になる点を文章で残す
  • リハーサルの振り返りに合わせる：リハーサルの翌稼働日に、自分の担当範囲で分かったことと直すことを出す
  • 記録を一か所にまとめる：変換ルールや照合の結果を自分の端末に抱え込まず、関係者が同じ場所で見られるようにする

こうした進め方を面談で具体的に話せると、短い稼働でも任せられるかを発注元が判断しやすくなります。

受けるときの注意点

責任の範囲と稼働日数をそろえる

週2〜3日の案件で最も起きやすいのは、稼働日数は減ったのに、責任の範囲は週5日の担当と同じという状態です。リハーサルが近づくと不在の日にも確認を求められ、結果として稼働日以外に作業が増えていきます。参画前に、担う段階と仕事の範囲、不在の日に代わりに確認する人を確かめておきましょう。

切替の週の稼働と精算を確かめる

リハーサルと本番切替の週は、週2〜3日の約束でも稼働を増やしてほしいと頼まれることがあります。応じられる範囲と、夜間・休日の作業や待機の時間をどう数えるかを、精算の条件と合わせて確かめておきます。精算の仕組みは精算幅の記事をご覧ください。参画後に担う段階が広がった場合の扱いは作業範囲が広がったときの契約の扱いで解説しています。

本番データの扱いと作業の場所を確かめる

データ移行の仕事は、取引先や従業員の情報、価格や原価など、扱いに注意が要るデータに触れます。週2〜3日の参画でも、本番データを決められた環境の中だけで扱う、貸与端末で作業する、といった決まりは同じです。作業の場所と端末の条件を参画前に確かめておきましょう。

注意

複数の案件を掛け持ちする場合、移行の案件はリハーサルや切替の日程がプロジェクトの進み具合で動くため、ほかの案件の予定と重なりやすくなります。日程が動いたときにどちらを優先するかを、先に決めておく必要があります。情報の扱いも、案件ごとに分けなければなりません。掛け持ちの注意点は複数の案件を掛け持ちするときの注意点で解説しています。

会社員の副業で移行案件を受けるとき

会社員が副業で移行の案件を受ける場合は、上の注意点に加えて、次の点を確かめます。

  • 勤務先の就業規則：副業が禁止か、許可制か、届出制か。業務委託が対象に含まれるか
  • 本業との競合：本業がSAPの導入を手がける会社や、SAPを使う企業の場合、同じ業界の顧客や本業の取引先に関わる移行案件は、競業や秘密の扱いで問題になりやすい
  • 時間帯：移行の定例会議やユーザーテストは平日の日中に入ることが多く、本業の時間と重ならないか
  • 切替の週末：本番切替が休日に入る場合でも、本業の繁忙期と重なれば受けられない。その場合は切替に関わらない型で探す

移行の担当者は、本番データと業務の機密に深く触れる立場です。本業で知った設定やデータの扱いを副業の案件で使わないよう、意識して切り分ける必要があります。就業規則の読み方や確定申告などは会社員の副業で業務委託案件を受けるときの注意点と副業禁止の会社で業務委託を受けるリスク、平日の日中に動けない場合の探し方は週末・夜だけの業務委託案件の記事で解説しています。判断に迷う場合は、勤務先の担当部署や専門家にご相談ください。

よくある質問

週2〜3日の案件でも、移行の経験として評価されますか？

担った段階と仕事の中身を具体的に書けば、経験として評価されます。週2〜3日の案件は段階と役割が絞られていることが多いため、スキルシートには稼働日数と担った範囲を正確に書き、本番の切替まで担ったと誤解されない書き方にしておきましょう。役割ごとの週2〜3日の傾向は、SAP FI/COコンサル、SAP Basisエンジニア、SAP ABAPエンジニアの記事でも扱っています。

週3日で始めて、切替の時期だけ週5日に増やすことはできますか？

発注元の体制や予算によっては、段階に合わせて稼働を変える契約にできることがあります。ただし、案件ごとに事情が違うため、増やせる前提で受けるのは避けたほうが無難です。切替の時期に稼働を増やせる意向がある場合は、参画前に伝え、条件を書面で確かめておきましょう。案件を選ぶときの確認点はS/4HANA移行の案件の選び方で整理しています。

平日の夜や週末だけでも移行の案件は受けられますか？

移行の会議やユーザーテストは平日の日中に入ることが多いため、夜や週末だけで受けられる案件はかなり限られます。切替の手順書や照合の基準の点検、変換ルールの文書化のように、成果物や回数で区切れる関わり方なら成り立つことがあります。
