モバイルアプリ開発

React Nativeエンジニアのフリーランス面談でよく聞かれる質問と答え方

公開 2026-11-04　監修：株式会社エージェントベスト

React Nativeエンジニアのフリーランス面談でよく聞かれるのは、担った範囲がJavaScriptの中だけか外まで及ぶか、Expoをどう使っていたか、版上げにどう向き合ったか、iOSとAndroidの差をどう扱ったかの4つです。面談官は、Reactが書けることはスキルシートで分かっているので、「この人に任せたら、ビルドが通らないときやストアで止まったときに一人で片づけられるか」を確かめようとしています。

答えるときは、模範解答を覚えるより、関わったアプリを2〜3本選び、それぞれで詰まった場面を話せるようにしておくのが近道です。面談全般の答え方の型は業務委託の面談でよく聞かれる質問と答え方で解説しているので、この記事ではReact Nativeの面談に固有の質問に絞ります。

React Nativeの面談で面談官が見ていること

面談に出てくるのは、発注元のテックリードやモバイルのチームの責任者、Webの開発の責任者であることが多くあります。相手がネイティブの出身かWebの出身かで聞き方は変わりますが、知りたいことはおおむね次の3点です。

  1. 任せられる範囲：画面だけか、ビルド・ネイティブ・ストア公開まで持てるか
  2. 詰まったときの動き方：JavaScriptの外で問題が起きたとき、何を見て、どう直したか
  3. チームとの相性：Webやネイティブのメンバー、デザイナーとどう分担してきたか

以下の質問は、この3点のどれかを確かめるためのものです。質問の意図が分かれば、答えの中心に何を置くかも決まります。

よく聞かれる質問と答え方の考え方

ここで示す答えの例は、組み立て方を伝えるための架空の例です。そのまま使うのではなく、ご自身の経験に置き換えて準備してください。

1. 「担当したアプリと、あなたの役割を教えてください」

確かめたいのは任せられる範囲です。アプリの種類、チームの人数、React Nativeの担当の人数、自分が担った工程を短く伝えます。画面の実装、ネイティブの設定、ビルド、ストア公開を分けて、どこまでが自分の担当だったかを示すと、後の質問との食い違いが起きません。

架空の例：「会員向けアプリで、React Nativeの担当は2名でした。画面と状態管理に加え、Android側のビルドとPlay Consoleへの公開は私が担当し、iOSの審査への提出は社員の方が行っていました」

2. 「Expoは使っていましたか。どう使っていましたか」

「使っていました」で終わらせず、開発ビルドを使っていたか、ネイティブのフォルダを自分で持つ構成だったか、クラウドのビルドやストアを通さない配信を使っていたかを話します。Expoを使っていない現場の経験なら、その理由と、ネイティブ側の設定を自分でどう管理していたかを話せば十分です。面談官は、選んだ構成の理由を理解しているかを見ています。

3. 「React Nativeの版上げで苦労したことはありますか」

React Nativeは2か月ほどの間隔で新しい版が出ており、公式が保守するのは最新の3つのマイナー系列です（2026年10月時点のReleases Overviewによる）。そのため、版上げの経験は多くの面談で聞かれます。答えは次の順番で組み立てると伝わります。

  • どの版からどの版へ上げたか（覚えていなければおおよそで構わない）
  • 何が壊れたか（ビルド、ライブラリ、画面の動き）
  • どう調べ、何を置き換えたか
  • 作業をどう区切り、チームの開発とどうぶつからないようにしたか

4. 「New Architectureへの対応は経験がありますか」

内部の仕組みを説明できるかより、移行のときに使っているライブラリの対応状況をどう確かめ、対応していないものをどう扱ったかが聞かれます。経験がない場合は、知っている範囲と、案件で必要になったときにどう調べるかを正直に話しましょう。

5. 「iOSとAndroidで動きが違う不具合に、どう対応しましたか」

両OSを一つのコードで扱うReact Nativeならではの質問です。再現の条件をどう絞ったか（機種、OSの版、開発ビルドか本番か）、OSごとに分岐させたか、ライブラリの側の問題だったかを話します。

6. 「ネイティブ側のコードはどこまで書けますか」

「書けません」「全部書けます」の二択で答えず、読める・直せる・一から書けるの段階で伝えます。たとえば「既存のネイティブのモジュールの不具合なら、Swiftのコードを読んで直したことがある」のように、実際の場面とあわせて話すと誇張していない印象になります。

7. 「ストアを通さない配信は、どう使い分けていましたか」

Expoの公式ドキュメントでは、JavaScriptや画像などは配信できる一方、ネイティブのコードや権限、Expo SDKの版を変える変更は新しいビルドが要るとされています。面談では、この線引きを理解したうえで、本番への配信をどう慎重に扱っていたかを話します。配信の経験がなければ、ストアのリリースの周期をどう回していたかを話せば足ります。

8. 「Webのチームとはどう分担していましたか」

Webの画面もReactで作っている会社では、共通にするコードの範囲やレビューの進め方が聞かれます。共通にしてよかった点と、アプリ固有の事情で分けた点を1つずつ話せると、境目を考えてきた人だと伝わります。

エージェントベストの見解

React Nativeの案件をご紹介していると、面談で評価されやすいのは、ビルドが通らない、審査で止まった、特定の機種だけで落ちるといった「JavaScriptの外で詰まった場面」を順を追って話せる方です。反対に、画面の実装の話だけで面談が終わると、ネイティブ側を誰が見るのかを発注元が心配し、見送られやすい傾向があります。担っていなかった工程は、担っていなかったと正直に伝えたうえで、近い経験を添えることをおすすめします。

準備は「アプリごとの詰まった場面」を集める

上の質問は数が多く見えますが、答えの材料は共通しています。準備は次の手順で進めると効率的です。

  1. アプリを2〜3本選ぶ：構成の違うアプリ（Expoかどうか、新規か運用中か）を選ぶ
  2. アプリごとにメモをつくる：版、構成、チームの人数、自分の担当範囲をそろえる
  3. 詰まった場面を書き出す：版上げ、OSの差、審査の指摘、ビルドの失敗など、性質の違う場面を3〜4つ
  4. 2分版と5分版をつくる：最初は短く話し、掘り下げられたら詳しく話せるようにする
  5. スキルシートと照らし合わせる：シートに書いた版と担当範囲が、話と一致しているかを確かめる

スキルシートとの一致は特に大切です。面談官はシートを見ながら質問するため、版や担当範囲がずれると、どちらも信用されにくくなります。書き方はReact Nativeのスキルシートの書き方、冒頭の話し方は面談の自己紹介の記事で解説しています。技術的な課題が出される場合の準備は技術テストの記事をご覧ください。

注意

公開中のアプリの話をするとき、アプリの名前や発注元の社名、未公開の機能、利用者の数などを話してしまいがちです。ストアで公開されているアプリでも、自分が開発に関わったことを話してよいかは契約によって違います。社名やアプリ名は伏せ、規模はチームの人数や期間で伝えましょう。前の現場のコードの批判も、聞き手に悪い印象を与えやすいので避けたほうが無難です。

面談の相手によって重心が変わる

面談の相手重く見られやすい点
モバイルのテックリード（ネイティブ出身）ネイティブ側への理解、ビルドと署名、OSごとの差
Webの開発の責任者Reactの設計、Webとの共通化、レビューの進め方
プロダクトの責任者リリースの回し方、見通しの伝え方、仕様の相談の仕方

ネイティブ出身の面談官には、React Nativeがネイティブ側でどう動いているかの理解を、Web出身の面談官には、アプリ固有の事情をWebのメンバーにどう説明してきたかを中心に話すと、限られた時間を有効に使えます。

React Nativeならではの逆質問

逆質問は、印象づくりより参画後のずれを防ぐ確認に使います。React Nativeの案件では、次の点を聞いておくと判断がしやすくなります。

  • 今のReact NativeとExpoの版、New Architectureへの対応の状況
  • ネイティブのエンジニアがいるか。いない場合、ネイティブ側の変更は誰が担うか
  • ビルドとストア公開の担当と、アカウントの権限の扱い
  • リリースの周期と、ストアを通さない配信の使い方
  • 開発に使うMacと実機は貸与か、自分で用意するか

一般的な逆質問の考え方は業務委託の面談で聞いておくべき逆質問にまとめています。逆質問で聞いた内容は、契約前の確認にもそのまま使えます。確認点はReact Native案件の選び方で整理しています。

エージェントベストの見解

当社では、経歴をご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。React Nativeの案件で、版やネイティブ側の体制など、面談の前に確認しておきたい点があれば、ご質問いただければ確認します。面談で聞きそびれた点が出てきた場合も、契約の前に早めにご相談ください。

ポイント

  • React Nativeの面談では、担った範囲、Expoの使い方、版上げ、両OSの差がよく聞かれる
  • 答えは「何が起きたか→どう調べたか→何を選んだか→どう区切ったか」の順で組み立てる
  • 準備はアプリ2〜3本の「詰まった場面」を集め、スキルシートと版・担当範囲をそろえる
  • 逆質問では、版の状況、ネイティブ側の体制、ストアの権限、端末の扱いを確かめる

よくある質問

Expoしか使ったことがありません。面談で不利になりますか？

不利とは限りません。Expoを使う現場は多く、開発ビルドやクラウドのビルド、ストアを通さない配信を理解して使っていたことは評価の材料になります。ネイティブのフォルダを自分で持つ現場に応募する場合は、ネイティブ側の設定をどこまで触ったかを具体的に話せるようにしておきましょう。

個人で作ったアプリの話をしてもよいですか？

話して構いません。特に、両方のストアに自分で公開した経験は、業務で担っていなかった工程を補う材料になります。業務の経験と区別し、規模や期間を正確に伝えることが大切です。

案件で使っている版を触ったことがない場合、どう答えればよいですか？

触ったことのある版と、版の違いで何が変わるかを知っている範囲で話し、参画後にどう追いつくかを添えます。知らないことを知っているように話すと、掘り下げられたときに答えに詰まります。React Nativeの仕組みの変化はReact Nativeの将来性の記事が参考になります。
