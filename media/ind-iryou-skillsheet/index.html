業界別の案件

医療業界の経験をスキルシートで伝える書き方｜施設・立場・システム・工程をそろえる

公開 2026-10-29　監修：株式会社エージェントベスト

医療業界の経験をスキルシートで伝えるときは、施設の種類と規模、自分の立場、システムと対象の業務、担当した工程の4点をそろえて書くのが基本です。「電子カルテの導入経験あり」だけでは、診療所向けの設定作業なのか、大きな病院の更改のPMOなのかが分かりません。「中規模の病院、ベンダー側、電子カルテと検査部門の連携、データ移行と稼働の立ち会いを担当」まで書くと、合う案件が見えてきます。

同時に、医療の経歴は患者の情報や医療機関の内部の事情に近い分野です。この記事では、4点のそろえ方、書かない情報の線引き、記入例を紹介します。スキルシート全体の構成はスキルシートの基本、守秘義務の一般的な考え方はスキルシートに書いてよいこと・いけないことで扱っているので、ここでは医療の経験に固有の書き方に絞ります。

要約の1行目で「立場」と「領域」を示す

医療の案件では、ベンダー側で製品や導入を担ってきたのか、医療機関側で計画や運用を支えてきたのかで、合う案件が大きく分かれます。要約の1行目で、立場と領域を先に示します。領域の分け方は医療のIT案件の記事で説明しています。

  • 立場と領域（例：電子カルテベンダー側で、病院向けの導入と部門連携）
  • 工程と役割（例：要件の聞き取りから稼働支援まで、後半は導入チームのリーダー）
  • ほかの強み（例：オンライン資格確認への対応の改修、SQLでのデータ移行）

複数の領域を経験している場合は、次に入りたい案件に近い順に並べると、読み手が判断しやすくなります。

プロジェクト欄は4点をそろえる

項目書き方の例避けたい書き方
施設の種類と規模「急性期の中規模病院」「無床の診療所」「複数の病院を持つ法人」病院名、所在地、法人名
立場「電子カルテベンダー側」「医療機関の情報システム部門の支援」「医療系」だけ
システムと業務「電子カルテと検査部門システムの連携」「医事会計のレセプト出力」「病院システム全般」
担当した工程「マスタ設定、データ移行、操作研修、稼働日の立ち会い」「導入」だけ

規模の表し方は、医療法第1条の5の区分（20人以上の入院施設を持つ病院、入院施設がないか19人以下の診療所）を入口にすると書きやすくなります。病院の場合は「中規模」「大規模」程度にとどめ、正確な病床数は書かないほうが特定を避けられます。

業務は「誰が・どの場面で使うか」まで書く

医療のシステムは利用する職種が多いため、「誰のどの業務か」まで書くと、経験の深さが伝わります。

  • 外来の医師の処方オーダーと、薬剤部への連携
  • 病棟の看護記録と、勤務の引継ぎの画面
  • 医事課の月次の請求と、返戻への対応

求められる業務知識の中身は医療の業務知識の記事で整理しています。

稼働を支えた作業も書く

医療の導入案件では、作ることと同じくらい、現場で使える状態にする作業が評価されます。書き忘れやすいので、意識して拾います。

  • 職種ごとの操作研修の計画と実施
  • 切替のリハーサルと、止まっている間の運用手順づくり
  • 稼働日と直後の問い合わせ対応、不具合の切り分け
  • マスタの対応づけと、旧システムからの移行データの検証

エージェントベストの見解

医療の案件をご紹介していると、面談で評価されやすいのは、スキルシートに職種と業務の場面が書かれていて、そこから「現場の要望と製品の仕様が合わなかったとき、どう折り合いをつけたか」を話せる方です。反対に、「電子カルテ導入 5施設」のように件数だけが書かれていると、規模も役割も分からず、合う案件を絞り込みにくくなります。施設ごとの違いと自分の役割を一段細かく書き直すことをおすすめします。

医療の経歴で書かない情報

医療の案件は、地域の病院の数が限られていて、システムの更新が地域で知られていることもあります。一つひとつは問題なくても、組み合わせると施設が特定できることに気をつけます。

書かない情報代わりの書き方
病院名・法人名・所在地施設の種類と規模（「地域の中核となる中規模病院」）
正確な病床数・診療科の構成と稼働の年月の組み合わせ「中規模」「複数の診療科」、時期は年単位
患者の数、症例、画面に写った情報「外来の受付から会計までの流れ」など業務の説明
ネットワークの構成、外部との接続の方式の詳細「院内のネットワークと外部の接続の分離に関わる作業」
障害やセキュリティの事故の日時と内容「障害時の原因調査と復旧手順の見直し」
製品名とバージョン、導入の年月の組み合わせ「病院向け電子カルテパッケージ」など一般的な表現

患者に関わる情報は、特に慎重に扱います。個人情報保護法第2条第3項は、病歴などを含む個人情報を「要配慮個人情報」としています。個人情報保護委員会と厚生労働省の「医療・介護関係事業者における個人情報の適切な取扱いのためのガイダンス」は、患者が亡くなった後も、保存している情報には個人情報と同等の安全管理を求めています。スキルシートに患者の情報を書くことはもちろん、画面の写しや資料を実績の説明に使うことも避けてください。

セキュリティの対策や事故の詳細は、書くこと自体が施設の弱点を示すことになりかねません。どんな対策に関わったかは「ガイドラインに沿った対策の見直し」程度にとどめます。契約で秘密とされた範囲を書かないことが基準で、業務委託契約や秘密保持契約に経歴への記載の定めがある場合は、その定めに従ってください。個人情報を扱う業務の契約の見方は個人情報を扱う業務の記事、守るルールそのものは医療の規制の記事をご覧ください。

注意

会社員時代に医療機関やベンダーで関わった案件は、当時の勤務先の就業規則や退職時の誓約書でも縛られていることがあります。医療機関に勤めていた方は、職員として知った患者や院内の事情も含まれるため、フリーランスになってから書くスキルシートでも、当時の取り決めの範囲を超えないように見直してください。

プロジェクト欄の記入例

以下は書き方を示すための例で、実在の案件や実績ではありません。

例1：電子カルテの更改（ベンダー側）

期間：20XX年〜20XX年（1年3か月）
案件概要：急性期の中規模病院の電子カルテと部門システムの更改
規模・立場：ベンダー側の導入チーム7名（自分は検査・薬剤の部門連携の担当、後半はサブリーダー）
対象の業務：外来・病棟の検査オーダーと処方オーダー、部門システムとの連携
担当した工程：現行運用の聞き取り、マスタの対応づけ、連携テスト、切替リハーサル、稼働日の立ち会い
使用技術：SQL、HL7の連携メッセージ、電子カルテパッケージの設定
工夫・成果：オーダーの取消しと実施済みの扱いを部門ごとに表にまとめ、連携テストの観点の抜けを減らした

例2：国の仕組みへの対応（製品開発）

期間：20XX年〜20XX年（10か月）
案件概要：診療所向けクラウド型電子カルテの、電子処方箋への対応の機能開発
規模・立場：開発チーム6名（自分は処方の送信と結果の取り込みの設計・実装）
対象の業務：医師の処方入力、重複投薬等のチェック結果の表示
担当した工程：国の技術解説書の読み込み、基本設計、実装、結合テスト
使用技術：TypeScript、Java、REST API
工夫・成果：技術解説書の更新の差分を一覧にして影響範囲を共有し、改修の見積もりの手戻りを減らした

例3：医療機関側の支援（PMO）

期間：20XX年〜20XX年（8か月）
案件概要：複数の病院を持つ法人の、次期電子カルテの調達と移行計画の支援
規模・立場：法人の情報システム部門の支援（自分はPMOとして計画と進捗管理を担当）
対象の業務：各部門の要望の取りまとめ、ベンダーの提案の比較
担当した工程：要件の整理、提案依頼書の作成支援、移行計画の作成
工夫・成果：部門ごとの要望を「必須」「代替手段あり」に分け、比較の論点を経営層に説明しやすい形にした

どの例も、施設名、病床数、製品名、患者に関わる情報は書いていません。それでも、立場、業務、工程、工夫が書かれていれば、どの案件に合うかは伝わります。PMOとしての書き方はPMOのスキルシートの記事も参考になります。

面談で深掘りされやすい点

面談全般の準備は面談でよく聞かれる質問の記事で扱っています。医療の案件で聞かれやすいのは、次のような点です。

  1. 医師や看護師など、職種の違う利用者の要望をどう聞き、どうまとめたか
  2. 切替の日や稼働の直後に起きた問題に、どう対応したか
  3. 国の仕組みの仕様の更新に、どう追いついたか
  4. 患者の情報に触れる環境で、どんな決まりに沿って作業したか

4つ目は見落とされがちですが、医療の案件では大事な問いです。決められた手順の中で作業した経験は、そのまま次の案件での安心材料になります。

エージェントベストの見解

当社では、経歴をご本人の了承を得た案件にだけ、氏名・連絡先を伏せてご提案しています。医療の経歴は、施設の規模や地域、時期の書き方で特定されやすさが変わります。提出の前に、組み合わせで施設が推測されないかを見直すことをおすすめします。表現に迷う箇所は、ご質問いただければ確認します。

ポイント

  • 要約の1行目で、ベンダー側か医療機関側かの立場と、領域を示す
  • プロジェクト欄は、施設の種類と規模・立場・システムと業務・工程の4点をそろえる
  • 研修、切替、稼働日の立ち会いなど、現場で使える状態にした作業も書く
  • 施設名、正確な病床数、患者に関わる情報、構成や事故の詳細は書かない

よくある質問

病院名を書かないと、経験の大きさが伝わらないのではありませんか？

施設の種類と規模、自分のチームの人数と役割、担当した工程を書けば、経験の大きさは十分に伝わります。発注側が知りたいのは病院名より、どの立場で、どの業務を、どこまで担ったかです。

医療機関の職員（看護師や医事課など）として働いた経験は書いてよいですか？

書いてよく、医療の案件では強みになります。どの部門で、どんな業務を担い、システムをどう使っていたかを書くと、利用者の立場が分かる人として伝わります。ただし、患者や院内の個別の事情は書かないでください。

診療所向けの導入の経験しかありませんが、病院の案件に応募できますか？

案件によります。診療所の導入で身につけた、マスタの設定、操作の説明、稼働の支援の経験は病院でも生きます。一方で、病院の案件は部門の数や関係者が多いため、その違いをどう埋めるかを面談で話せるようにしておくことをおすすめします。

 スキルシート・面談

スキルシートに書いてよいこと・いけないこと｜守秘義務を守りながら実績を伝える書き方

スキルシートに書いてよいのは、自分の役割・担当工程・使った技術・規模の目安です。取引先の社名、未公開の数値や計画、資料そのものは書きません。業界や幅、増減の方向に置き換えれば、守秘義務を守りながら実績は伝わります。

 業務委託契約の基礎

業務で個人情報を扱うときの契約と注意点｜委託先として求められること

取引先の顧客データなどを扱う業務は、個人情報保護法の「個人データの取扱いの委託」にあたることが多く、取引先には委託先を監督する義務があります。契約に入る安全管理・目的外利用の禁止・再委託・返却と廃棄・事故時の報告の条項と、守るための準備を整理します。
