組込み・ゲーム・XR

組込みエンジニアのフリーランス案件｜報酬の決まり方と単価を上げる考え方

組込みエンジニアのフリーランス案件の報酬は、どの製品分野で、ソフトのどの層を、どの工程から担うかを軸に、ハードウェアを読める度合い、安全や品質の手順に沿って開発した経験、現地での作業の条件が重なって決まります。組込みの単価について公的な統計はなく、金額は案件によって大きく変わります。

単価を上げる近道は、言語の経験年数を積み増すことより、「ハードとソフトの境目を一人で切り分けられる」「決められた手順で品質の証拠を残せる」といった、代わりの人を見つけにくい経験を示せるようにすることです。この記事では、報酬が上下する要素と、交渉で使える材料を整理します。

組込みの報酬は「製品分野×層×工程」で見る

組込みの案件は、同じC言語のファームウェア開発でも、何の製品の、どの層を担うかで中身がまったく違います。報酬もこの組み合わせで変わります。

見る軸主な区分報酬との関係
製品分野家電・住宅設備、産業機器・FA、車載、医療機器、通信機器、計測器安全・信頼性の要求が厳しい分野ほど、手順の経験を持つ人が限られる
ソフトの層ブートローダー・BSP、デバイスドライバー、RTOS・ミドルウェア、アプリケーションハードに近い層ほど、担える人が少なくなりやすい
工程要求仕様・方式設計、詳細設計・実装、評価・検証上流ほど判断の責任が重く、報酬も高めに出やすい

たとえば「家電のアプリケーション層の実装」と「産業機器のデバイスドライバーを方式設計から」では、求められる経験も、応募できる人の数も違います。案件票を読むときは、まずこの3つの軸のどこに当たるかを確かめると、提示額の理由が見えてきます。

報酬を左右する主な要素

1. ハードウェアを読める度合い

組込みの案件で差がつきやすいのが、ハードウェアの資料をどこまで自分で読めるかです。回路図やマイコンのデータシート、リファレンスマニュアルを読んでレジスターの設定を決められるか、信号の不具合をオシロスコープやロジックアナライザーで確かめられるかで、任せられる範囲が変わります。

ソフトの側だけを見て作業する人と、「ソフトの不具合なのか、基板や部品の問題なのか」を切り分けられる人とでは、案件側の期待が違います。切り分けができる人は、評価の終盤や量産前の不具合対応で頼られやすく、報酬の条件にも表れやすくなります。

2. OSの種類

ベアメタル（OSなし）、RTOS、組込みLinuxのどれを扱ってきたかでも、参画できる案件が分かれます。組込みLinuxでは、カーネルやデバイスツリー、ビルドの仕組みまで触れるか、アプリケーションだけかで評価が変わります。RTOSでは、タスクの設計や割り込みとの関係を自分で決めた経験があるかが見られます。

3. 安全・品質の手順の経験

車載や産業機器、医療機器などでは、要求と設計と試験を対応づけて記録する、レビューの証拠を残す、変更の影響を分析するといった手順が開発の一部になっています。こうした手順の中で開発した経験は、ほかの分野から来た人がすぐには身につけにくいため、報酬の差になりやすい要素です。規格や国の基準の中身は、自動車は自動車業界の規制の記事、製造業は製造業界の規制の記事で扱っています。

4. 現地での作業の条件

組込みの開発では、実機、評価ボード、試験装置、計測器を使う作業が多く、開発拠点での作業が前提になる案件が少なくありません。常駐が前提の案件は応募できる人が限られるため、条件に影響することがあります。一方で、通う距離や時間の負担は報酬に入っていないことも多いため、場所の条件は金額とあわせて比べる必要があります。働く場所の傾向は組込みエンジニアのリモートの記事で解説しています。

5. 稼働日数と精算の方法

組込みの案件も、月の稼働時間に幅を決めて精算する準委任の形が多くあります。評価の山場や量産前は作業が増えやすいため、精算幅の上限を超えたときの扱いは事前に確かめておきたい点です。仕組みは精算幅の記事で解説しています。

エージェントベストの見解

組込みの案件をご紹介していると、面談で評価されやすいのは、担当した製品分野とマイコン・OSの組み合わせに加えて、「どの層の不具合を、どの道具で切り分けたか」を具体的に話せる方です。逆に「C言語で制御ソフトを開発」とだけ伝えると、案件の条件と照らし合わせにくくなります。当社では、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをご案内しています。

同じ組込み案件でも提示額が違う理由

似た内容に見える案件で金額が違うときは、次の点が違っていることが多くあります。

  • 求める役割：仕様どおりの実装か、ハードの担当者と仕様を詰める役割まで期待するか
  • 局面：新規開発の設計段階か、評価・不具合対応の段階か、量産後の保守か
  • 発注元の立場：製品メーカーの直下か、部品や基板を作る会社の下か、受託開発の会社の下か。経由する会社の数で手元に届く金額が変わる。考え方は商流の記事を参照
  • 機材の扱い：実機や計測器を発注側が用意するか、自分の環境で作業するか
  • 契約の形：準委任か請負か

提示額は、月額だけでなく、精算の条件、契約期間、支払期日までそろえて比べます。報酬の仕組みの全体像はフリーランスの単価の決まり方でまとめています。

契約の形で変わる報酬のリスク

組込みでは、ファームウェアの一部機能や、評価用ソフトの作成をまとめて請け負う形の案件もあります。請負は成果物の完成と引き渡しに対して報酬が払われるため、準委任とは注意点が違います。

比べる点準委任の案件請負の案件
報酬の対象業務を行ったこと（時間・期間）完成して引き渡した成果物
組込みで起きやすいこと評価の山場で稼働が上限を超える実機の到着が遅れて作業が止まる、ハードの変更で作り直しが出る
事前に決めておきたいこと精算幅、超過時の扱い実機・評価環境の提供時期、ハード変更時の追加報酬、検収の条件

組込みの請負で特に気をつけたいのは、自分では動かせない前提条件です。試作基板の遅れや、部品の変更による回路の修正は、ソフトの側では止められません。こうした場合に納期と報酬をどう扱うかを契約で決めていないと、作業が増えても請求しにくくなります。違いの詳細は準委任契約と請負契約の違いで解説しています。

注意

「評価ボードは自分で用意してほしい」「計測器は手持ちのものを使ってほしい」という条件の案件では、機材の費用が報酬から実質的に差し引かれる形になります。機材を誰が用意し、作業後にどう扱うか（返却・廃棄・保管）を契約前に確かめておきましょう。発注側の試作品や評価ボードを預かる場合は、紛失や破損のときの扱いも確かめておくと安心です。

交渉の材料になるもの

条件の見直しを相談するときは、「経験年数が増えた」より、担った役割の変化を事実で示すほうが伝わります。組込みで材料になりやすいのは次のようなものです。

  1. 担当する層が広がった：アプリケーション層からドライバーやBSPまで任されるようになった
  2. 切り分けを任されるようになった：不具合の原因がハードかソフトかの判断を、自分が最初に担うようになった
  3. 評価の仕組みを作った：試験の自動化や、シミュレーターでの事前確認を整え、実機待ちの時間を減らした
  4. 手順の文書を担った：要求と試験の対応表、変更の影響分析など、品質の証拠を残す作業を任された
  5. ハード担当との窓口になった：仕様の食い違いを、ハードの担当者と直接詰める役割を持った

伝えるときは、どの局面で、何を引き受け、結果として何が変わったかをまとめておきます。時期としては、担当範囲が広がったときと、契約更新の前が話を出しやすいタイミングです。伝え方は単価交渉の記事、考え方の全体は単価を上げるための考え方にまとめています。

エージェントベストの見解

報酬の条件では、月額と同じくらい、稼働時間の幅、精算の方法、契約期間、現地作業の範囲を確かめることが大切です。フリーランス法では、発注する事業者は業務の内容、報酬の額、支払期日、役務の提供を受ける場所などを、書面やメールなどで明示することとされています。当社がご案内する案件では、業務の範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。条件の読み方で迷う点は、参画前にご質問いただければ確認します。

案件を比べるときに確認したいこと

  1. 製品分野と担当の層：何の製品で、ドライバーかミドルウェアかアプリケーションか
  2. 工程と局面：設計から入るか、評価・不具合対応が中心か
  3. ハードとOSの構成：マイコンやSoCの系統、ベアメタル・RTOS・組込みLinuxのどれか
  4. 機材と場所：実機・計測器の置き場所、持ち出しの可否、出社の頻度
  5. 手順の決まり：安全や品質の規格に沿った開発か、文書の量はどの程度か
  6. 契約期間と精算：精算幅、超過時の扱い、更新の判断時期、支払期日

フリーランス法では、取引条件の明示のほか、報酬の支払期日を給付を受け取った日から60日以内のできる限り短い期間で定めることなどが発注する事業者に求められています（2026年10月時点で公正取引委員会のページで確認）。契約の条件に不明な点があれば、署名の前に確かめましょう。

ポイント

  • 組込みの報酬は、製品分野・ソフトの層・工程を軸に、ハードを読む力、安全・品質の手順の経験、現地作業の条件で変わり、案件によって大きく変わる
  • 同じ内容に見えても、役割、局面、発注元の立場、機材の扱い、契約の形で提示額が違う
  • 交渉では、担当する層の広がりや切り分けを任された経験など、役割の変化を事実で示す

よくある質問

組込みエンジニアの単価の相場はいくらですか？

組込みの単価について公的な統計はなく、製品分野、担当の層、工程、現地作業の条件などで大きく変わります。相場の数字を探すより、ご自身の経験が「製品分野×層×工程」のどこに当たるかを整理し、複数の案件で条件をそろえて比べるほうが判断の材料になります。

評価・検証の経験が中心だと報酬は低くなりますか？

評価だけを担う案件は、設計から入る案件と比べて条件が低めに出ることがあります。ただ、試験の自動化や、不具合の原因をハードとソフトの境目まで切り分けた経験は、評価の担当でも強みになります。実装や設計にも関わった経験があれば、あわせて伝えると選べる案件が広がります。

車載の経験があると有利ですか？

車載の案件では、安全や品質の手順の中で開発した経験が見られるため、その経験は車載以外の産業機器や医療機器の案件でも説明の材料になります。ただし、有利かどうかは案件の求める層や工程によります。分野の名前より、どの手順の中で何を担ったかを具体的に伝えることが大切です。
