Unityエンジニアのフリーランス案件の選び方｜契約前に確かめたい8つの点

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい8つの点

  4. よくある質問

Unityエンジニアの案件選びで差が出るのは、同じ「Unityでのクライアント開発」という募集でも、領域と局面、任される役割、端末やライセンスの扱い、契約の形によって、毎日の仕事と負う責任が大きく変わるからです。報酬や稼働日数だけで選ぶと、参画してから「思っていた仕事と違う」となりやすくなります。

契約前に確かめたいのは、役割の実態、版と版上げの予定、端末とライセンス、契約の形と完成の定義、成果物の権利など8つの点です。この記事では、それぞれの確かめ方と、確かめた内容を書面と照らし合わせる方法を整理します。

Unity案件の選び方で差が出る理由

Unityの案件は、案件票の書き方が似ていても、中身の幅が広いのが特徴です。

  • 領域：運営中のモバイルゲーム、家庭用ゲーム機・PCの新規開発、XR、産業・シミュレーション、展示・イベントで、仕事の進め方も話す相手も違う
  • 役割：仕様どおりに作る実装担当か、性能やビルド、版上げまで任されるかで、求められる力と責任が違う
  • 作業の場所と機材：リモートで回せるか、端末や開発機材、ヘッドセット、現場の設備がある場所に行く必要があるか
  • 契約の形：準委任で稼働時間に対して報酬を受けるか、請負で完成したものに対して受けるか

この幅があるため、募集の名前ではなく、中身を一つずつ確かめることが案件選びの中心になります。案件の種類ごとの働き方はUnityエンジニアの仕事内容で整理しています。

契約前に確かめたい8つの点

1. 領域と、開発の局面

どの領域の、どの局面の案件かを確かめます。立ち上げの試作か、量産か、運営か、決まった日に納める制作かで、1日の過ごし方が変わります。運営中のタイトルなら配信の周期、新規開発なら次のマイルストーンの時期を聞いておくと、忙しくなる時期の見当がつきます。

2. 役割の実態

「クライアント開発」の中で、実際に何を任されるかを確かめます。

  • 画面やゲームの仕組みの実装が中心か
  • 性能の調査と改善、ツールづくり、ビルドの自動化まで含むか
  • 構成の判断や、他の人のコードのレビューまで任されるか

役割が重いほど評価の材料になりますが、責任も重くなります。案件票に書かれた役割と、面談で聞いた役割がずれていないかも見ておきましょう。

3. Unityの版と、版上げの予定

使っているUnityの版、レンダーパイプライン（URP・HDRP・Built-In）、主なパッケージを確かめます。Unityの公式の案内では、Unity 6以降、LTS（長期サポート）版は年1回出て2年間サポートされる形で、2026年10月時点でUnity 6.0 LTSのサポートは2026年10月まで、Unity 6.3 LTSは2027年12月までとされています。

古い版で運用しているプロジェクトでは、参画中に版上げの作業が入ることがあります。版上げは、パッケージの更新、描画の設定の見直し、全プラットフォームでの動作確認まで含む大きな仕事です。版上げが予定されているか、その作業が自分の担当に入るかを聞いておきましょう。

エージェントベストの見解

Unityの案件をご紹介していると、参画後に「版上げの作業が思ったより大きく、予定していた機能の開発が進まない」という声を聞くことがあります。版上げの予定は案件票に書かれていないことも多いため、面談で「今の版と、次に上げる予定の時期」を聞いておくことをおすすめします。版上げの経験がある方にとっては、むしろ力を示せる機会になることもあります。

4. 端末・機材とUnityのライセンス

作業に使う機材を、誰が用意するかを確かめます。

  • 開発用のパソコン（貸与か、自分のものか）
  • 検証用のスマートフォン、ヘッドセット、家庭用ゲーム機の開発機材
  • Unityのライセンス（シート）

Unityの公式の案内では、2026年10月時点で、Unity Personalは収入と資金調達の合計が20万ドルまでの場合に無料で使え、それを超える事業者にはUnity Proなどが必要とされています。発注元のプロジェクトでどのライセンスを使うか、シートを発注元が用意するかは案件ごとに違うため、自分で用意する必要があるかを確かめておきましょう。貸与されたパソコンを使うときの注意点は取引先から貸与PCを使うときの注意点で解説しています。

5. 作業の場所と、出社・現地作業の頻度

リモートか、出社か、その組み合わせかを確かめます。開発機材や未発表の情報を扱う案件、XRや産業用途で実物の設備が必要な案件、展示の設置がある案件では、出社や現地作業を求められやすくなります。頻度と、急に呼ばれることがあるかも聞いておくと、稼働の見込みとのずれを防げます。詳しくはUnityエンジニアのリモート案件の記事をご覧ください。

6. 契約の形と、完成の定義

準委任か請負かを確かめます。準委任では稼働の時間に対して報酬を受け、請負では完成したものに対して報酬を受けます。展示やアプリの制作など、請負で受ける案件では、何をもって完成とするか、検収の手順と期間、直しの対応がどこまで含まれるかをはっきりさせておくことが大切です。契約の形の違いは準委任と請負の違い、検収の考え方は検収の記事で解説しています。

7. 成果物の権利と、実績としての扱い

作ったコードやツール、アセットの権利が誰のものになるかを確かめます。自分で作った汎用的な仕組みやライブラリを持ち込む場合は、その扱いも決めておきましょう。あわせて、関わったタイトルやアプリを、公開後に自分の実績として示してよいかも確かめておくと、次の案件で経験を伝えやすくなります。権利の考え方は成果物の著作権は誰のもの？、守秘の範囲は秘密保持契約（NDA）で確認することをご覧ください。

8. 契約期間と、忙しい時期の動き方

契約期間と、更新の判断の時期を確かめます。運営中のタイトルの配信前、新規開発の提出前、展示の設置前など、作業が集中する時期に稼働が増えることがあるかも聞いておきましょう。増えた稼働がどう扱われるかは、精算の決まりとあわせて確かめます。

注意

「Unity経験者歓迎」とだけ書かれた案件では、役割や機材の扱いが決まっていないこともあります。そのまま参画すると、契約の範囲の外にある仕事（素材の調整、サーバー側の改修、他のプロジェクトの手伝いなど）が少しずつ増えることがあります。範囲が広がったときの扱いは作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前のやり取りで確かめた内容は、契約の書面と照らし合わせます。フリーランス法（特定受託事業者に係る取引の適正化等に関する法律）では、発注事業者がフリーランスに業務を委託したときは、給付の内容、報酬の額、支払期日などの取引条件を、書面やメールなどで直ちに示すことが求められています（公正取引委員会の案内、2026年10月時点）。示されるべき事項の詳細はフリーランス新法の取引条件の明示で解説しています。

Unityの案件で、書面と照らし合わせたい点は次のとおりです。

確かめた内容書面で見るところ
役割と担当の範囲業務の内容（給付の内容）
版上げや性能の改善の担当業務の内容に含まれているか
完成の定義と検収検査をする場合の完了日、検収の手順
機材とライセンスの用意貸与物の扱い、費用の負担
成果物の権利と実績としての扱い権利の帰属、秘密保持の条項
契約期間と稼働の数え方契約期間、精算の決まり

面談で聞いたことと書面の内容が違う場合は、署名の前に確かめましょう。契約書全体の見方は業務委託契約書のチェックポイントをご覧ください。面談で何を聞くかはUnityエンジニアの面談の記事の逆質問の部分も参考になります。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。Unityの案件では、版上げの担当や機材の扱いなど、案件票に書かれていない点が働き方を左右することがあります。気になる点は、ご質問いただければ確認します。

ポイント

  • Unityの案件は、同じ募集名でも領域・局面・役割・機材の扱い・契約の形で中身が大きく変わる
  • 契約前に、役割の実態、版と版上げの予定、端末とライセンス、作業の場所を確かめる
  • 請負で受けるときは、完成の定義と検収の手順、直しの範囲をはっきりさせる
  • 確かめた内容は、取引条件の明示の書面と照らし合わせ、違いがあれば署名の前に確かめる

よくある質問

古い版のUnityを使っている案件は避けたほうがよいですか？

一概には言えません。古い版でも安定して運用されているプロジェクトは多くあります。大切なのは、版上げの予定があるか、その作業が自分の担当に入るかを知ったうえで選ぶことです。版上げの経験を積みたい方には、よい機会になることもあります。

Unityのライセンスを自分で用意するよう言われたらどうしますか？

まず、どの種類のライセンスが必要か、その費用を誰が負担するかを確かめましょう。案件の報酬とあわせて考え、自分で負担する場合は、その分を含めて条件を比べることが大切です。取り決めは契約の書面に残しておきましょう。

報酬の高い案件と、役割のはっきりした案件で迷ったらどうしますか？

報酬だけで選ぶと、役割が曖昧なまま範囲の外の仕事が増え、結果として時間あたりの条件が下がることがあります。役割と範囲がはっきりしている案件のほうが、次の案件で話せる経験も残りやすくなります。報酬の決まり方はUnityエンジニアの報酬の記事で解説しています。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

検収とは｜請負で報酬が確定するタイミングと、契約書で確かめる検査の条件

検収は、発注者が納品物を検査して契約どおりと認め、受け入れることです。請負では検収完了を報酬の支払条件にする契約が多いため、検査期間・合格基準・期間内に連絡がないときの扱いを確かめます。フリーランス新法の支払期日との関係も解説します。

 業務委託契約の基礎

成果物の著作権は誰のもの？業務委託の知的財産の扱い

業務委託で作ったプログラムや資料の著作権は、契約で決めなければ原則として作ったフリーランスに残ります。発注者に移す場合は、譲渡の範囲・時期・対価と、以前から持っているコードの扱いを契約で確かめます。

 業務委託契約の基礎

秘密保持契約（NDA）で確認すること｜対象・期間・実績として話せる範囲

NDAで確かめたいのは、秘密情報の範囲と例外、使ってよい目的、守る期間、終了時の返還・廃棄、違反時の責任の5点です。フリーランスは、実績としてどこまで話せるかも署名前に決めておくと安心です。
