モバイルアプリ開発

iOSエンジニアのフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい7つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

フリーランスのiOSエンジニアが案件を選ぶときは、報酬や稼働日数に加えて、アプリの状態と技術の比率、自分の役割と体制、審査とリリースの担当、開発機材とアカウント、契約の形と完成の扱い、稼働の振れ幅、契約期間と成果物の権利の7点を契約前に確かめておくことが大切です。iOSの案件は、案件票の「Swiftでの開発」という一行が同じでも、この7点の違いで負担と責任が大きく変わります。

特に見落としやすいのは、Appleとのやり取りを誰が担うかです。審査への提出、証明書やアカウントの管理を誰が持つのかがあいまいだと、参画後に思わぬ責任を負うことがあります。契約書全般の確認点は業務委託契約書のチェックポイントで解説しているので、この記事ではiOS案件に固有の点に絞ります。

iOS案件の選び方で差が出る理由

iOSのアプリは、Appleの審査を通らなければ利用者に届きません。さらにAppleはアップロードの条件を順に加えており、2026年4月28日からはXcode 26以降とiOS 26などのSDKでのビルドが、2026年9月9日からはiOS 13以降を対象にすることが求められています（2026年10月時点、Apple Developerの案内による）。つまり、コードを書く力に加えて、Appleの仕組みにどこまで責任を持つかで仕事の重さが変わります。

参画後によくあるずれは次のようなものです。

  • 機能追加の案件と聞いていたが、実際は古いコードの書き換えが中心だった
  • 審査の窓口は社員が担うと思っていたら、差し戻しの対応まで任された
  • 自分のMacで開発する前提で、会社の証明書や鍵を個人の端末で扱うことになった
  • 請負の契約で、審査を通ることが完成の条件になっていた

こうしたずれの多くは、面談と条件の確認で防げます。

契約前に確かめたい7つの点

1. アプリの状態と技術の比率

運用中のアプリへの機能追加か、新規の立ち上げか、書き換え・移行か。UIKitとSwiftUIの比率、最低対応OS、Swiftの並行処理への対応の状況も聞いておきます。案件の種類ごとの働き方はiOSエンジニアの仕事内容で整理しています。

面談では「参画後の最初の1か月で、最も期待されていることは何か」を聞くと、状態が見えやすくなります。答えが「既存コードの把握と小さな修正」なら運用寄り、「設計の方針づくり」なら立ち上げ寄りです。

2. 自分の役割と、チームの体制

iOSの担当が自分ひとりなのか、チームの一員なのかで負担は大きく違います。

  • iOSのチームは何名で、リードは誰か
  • 設計の方針を決めるのは誰か
  • コードレビューは誰が担い、自分はレビューする側にも入るか
  • Androidやサーバー側のチームとの仕様のそろえ方

iOSの担当がひとりの案件では、設計からリリースまでを一人で背負うことになりやすく、不在の日の対応も問題になります。

3. 審査とリリースの担当

審査への提出、差し戻しへの対応、リリースの判断を誰が担うかを確かめます。Appleの審査ガイドラインは、プライバシーポリシーの掲示や、アカウント作成ができるアプリでのアプリ内のアカウント削除などを求めています（2026年10月時点、Appleの案内による）。こうした要件への対応を誰が確かめるのかも、あわせて聞いておきましょう。

エージェントベストの見解

iOSの案件をご紹介していると、参画後に「聞いていた状況と違った」となりやすいのは、アプリの状態と、審査・リリースの担当の2点です。面談では聞きにくいと感じる方もいますが、担当範囲を判断するために必要な確認として聞けば、多くの発注元は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

4. 開発機材とアカウント

iOSの開発には、Xcodeが動くMac、検証用の端末、Apple Developer Programのアカウントが必要です。App Storeで配信するためのApple Developer Programは、個人か組織として登録します（2026年10月時点、Appleの案内による）。確かめたいのは次の点です。

  • 開発用のMacと検証用の端末は貸与か、持ち込みか
  • 配信に使うアカウントは発注元の組織のものか
  • 証明書や鍵を、個人の端末でどう扱うか

発注元のアプリを、自分の個人アカウントで配信するような形は、後の引き継ぎや責任の所在で問題になりやすくなります。端末やアカウントの扱いはiOSエンジニアのリモート案件の記事でも解説しています。

5. 契約の形と、完成の扱い

運用中のアプリへの参画は、多くが準委任契約です。準委任では、成果の完成そのものではなく、業務を専門家として通常求められる注意を払って行うことが約束の中身になります。

受託開発などで請負の契約になる場合は、何をもって完成とするかが大切です。審査を通ることそのものを完成の条件にすると、自分では決められないAppleの判断に報酬が左右されます。完成の条件は、納品物と検収の基準で決めておくのが無難です。契約の形の違いは準委任契約と請負契約の違いで解説しています。

6. 稼働の振れ幅と精算

iOSの稼働は、リリースの直前、審査の差し戻し、新しいOSの公開の時期などに増えやすくなります。

  • リリースの前後に夜間や休日の対応があるか
  • クラッシュなどの緊急の対応の連絡体制に、自分が入るか
  • 精算幅を超えたときの扱いと、稼働が少ない月の扱い

超過した時間の扱いを確かめておかないと、無償で対応し続けることになりかねません。精算の仕組みは精算幅の記事をご覧ください。

7. 契約期間と成果物の権利

契約の期間と、リリースの区切りが合っているかを確かめます。大きなリリースの直前に更新の時期が来ると、更新されなかった場合に最も大事な局面を見届けられません。フリーランス法では、6か月以上継続して業務を委託している場合に、契約を解除したり更新しなかったりするときは、原則として30日前までに予告することが求められています（2026年10月時点、公正取引委員会の案内による）。

あわせて、書いたコードの著作権が誰に帰属するか、自分が以前から持っている部品やライブラリを使う場合の扱いも確かめます。考え方は成果物の著作権の記事で解説しています。

注意

iOSの案件では、参画後に「Androidの不具合も見てほしい」「審査の窓口を引き受けてほしい」「別のアプリも手伝ってほしい」と頼まれることがあります。契約の業務範囲に入っていない仕事は、引き受ける前に範囲と条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

フリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容、報酬の額、支払期日、役務の提供を受ける場所などを、書面やメールなどで明示することとされています（2026年10月時点、公正取引委員会の案内による）。明示される事項はフリーランス法で明示される取引条件をご覧ください。

iOSの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、実装・レビュー・審査への提出など、担う範囲が書かれているか
  2. 請負の場合、完成の条件が審査の結果ではなく納品物と検収で決まっているか
  3. 開発機材とアカウントの扱い、作業の場所
  4. 稼働の幅と、超えたときの精算方法
  5. 契約期間と更新の時期、成果物の権利

面談で聞いておくとよい質問はiOSエンジニアの面談でよく聞かれる質問と答え方の逆質問の項目でも紹介しています。報酬の決まり方はiOSエンジニアの報酬の記事をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。iOSの案件で気になりやすい開発機材の扱いや、審査とリリースの担当範囲など、書面だけでは読み取りにくい点は、ご質問いただければ確認します。

ポイント

  • iOS案件は、アプリの状態、審査とリリースの担当、開発機材とアカウントで負担が大きく変わる
  • 体制では、iOSの担当が自分ひとりかどうかを確かめる
  • 請負では、審査を通ることそのものを完成の条件にしない
  • 稼働の振れ幅、契約期間、成果物の権利を書面と照らし合わせる

よくある質問

古いObjective-Cのコードが残るアプリの案件は避けたほうがよいですか？

避ける必要はありません。書き換えや移行の経験は、次の案件で評価されやすい経験です。ただ、置き換えの範囲と期間、回帰テストの体制、移行の判断を誰が担うかを、参画前に確かめてから受けることをおすすめします。

自分のMacで開発してほしいと言われたら、受けてよいですか？

受けることはできますが、情報の扱いと費用の扱いを確かめてからにしましょう。発注元の証明書やソースコードを個人の端末に置く場合の決まり、紛失したときの対応、案件を終えた後のデータの削除の仕方を、契約や取り決めで確かめておくと安心です。

報酬の高い案件と、体制の整った案件で迷ったらどうしますか？

一概には言えませんが、iOSの担当がひとりで審査やリリースまで背負う案件では、稼働が増えて時間あたりの報酬が下がることがあります。報酬の額だけでなく、稼働の見込みと担当範囲を合わせて比べるとよいでしょう。

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

成果物の著作権は誰のもの？業務委託の知的財産の扱い

業務委託で作ったプログラムや資料の著作権は、契約で決めなければ原則として作ったフリーランスに残ります。発注者に移す場合は、譲渡の範囲・時期・対価と、以前から持っているコードの扱いを契約で確かめます。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 単価・報酬交渉

精算幅（140〜180時間など）とは｜超過・控除の計算方法

精算幅は、月額報酬のままでよい稼働時間の範囲です。上限を超えると超過分が加算され、下限を下回ると控除されます。超過・控除の単価は上下割か中間割かで変わるため、仮の数字を使って計算方法を整理します。
