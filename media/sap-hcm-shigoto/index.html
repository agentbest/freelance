SAP HCM・SuccessFactorsコンサルのフリーランス案件の仕事内容｜案件の種類と働き方

公開 2026-11-04　監修：株式会社エージェントベスト

SAP HCM・SuccessFactorsコンサルの仕事は、人事部門の制度と運用を聞き取り、人事・勤怠・給与の仕組みに置き換え、データと計算結果が合っていることを確かめることの繰り返しです。ただし、SuccessFactorsの新規導入か、オンプレミスのHCMからの移行か、給与と連携の構築か、運用保守かで、1日の過ごし方も、向き合う相手も、手元に残る成果物も大きく変わります。

もう一つ、この職種の働き方を決めるのが給与の暦です。毎月の締めと支給日、賞与、年末調整、春の異動や昇給の時期に合わせて、作業の山が来ます。この記事では、案件を4つの種類に分け、それぞれの1日と1か月の流れ、関わる相手、成果物を整理します。報酬の決まり方はSAP HCM・SuccessFactorsの報酬の記事、求められるスキルはスキルの記事で扱っているので、ここでは「参画したら実際に何をしているか」に絞ります。

仕事の中身は「案件の種類」と「給与の暦」で決まる

人事・給与の領域の案件は、肩書きが同じ「HCMコンサル」でも中身がまったく違うことがあります。違いを生むのは、主に次の2つです。

  • 案件の種類：クラウドの新規導入か、旧環境からの移行か、給与と連携の構築か、稼働後の保守か
  • 給与の暦との位置：月次の締めの前後か、賞与や年末調整の時期か、本番の切替の前後か

この2つを掛け合わせると、フリーランスの案件はおおむね次の4種類に分けられます。

案件の種類主な相手時間を多く使う仕事
SuccessFactorsの新規導入人事部門、導入パートナーの他の担当、情報システム部門標準機能との突き合わせ、設定、権限と承認の流れの設計、テスト
オンプレミスHCMからの移行人事・給与の担当、旧環境の保守担当、移行チーム現行の設定の読み解き、データ移行、並行稼働、切替
給与計算と連携の構築給与担当、勤怠や会計の担当、他システムの担当計算の設定と検証、データの受け渡しの設計、差異の説明
運用保守・制度対応人事・給与の担当、社内のシステム担当問い合わせ、制度変更や組織改編への対応、リリースの影響確認

以下では、それぞれの1日と1か月の流れを典型的な例として紹介します。時間の配分は案件ごとに違うため、目安として読んでください。

SuccessFactorsの新規導入の案件

1日の流れ（例）

午前は人事部門との打ち合わせで、発令の種類、組織や職務の持ち方、承認の流れを、標準機能の動きを見せながら確かめます。SuccessFactorsの導入では、標準の機能に業務を合わせる進め方が多く、標準のままで運用できるか、どこを設定で補うかを一つずつ決めていくのが中心です。午後は決まった内容を設計書に落とし、検証環境で設定を進めます。夕方は、権限や業務ルールの設定を自分で動かして確かめ、翌日の打ち合わせの論点をまとめます。

担当する機能は、人事の中心になるEmployee Centralか、採用・入社・評価・目標・育成などのタレント管理の機能かで分かれることが多く、一人で全部を持つことはあまりありません。

1か月の流れ（例）

  • 月初：前月の検討で残った論点を整理し、人事部門と決める順番を合わせる
  • 毎週：機能ごとの定例で、決まったこと・保留・宿題を確かめる。導入パートナーの社内で設定の進み具合をそろえる
  • 月の半ば：設定した範囲を人事部門に画面で見てもらい、認識のずれを拾う
  • 月末：工程の区切りに合わせて、設計の確定やテストの結果を報告する

成果物

要件の一覧、標準機能との差分の整理、設計書（データの項目、発令、業務ルール、承認の流れ、権限）、設定の記録、テストの計画と結果、操作の手順書などです。SAP Learningの説明では、SuccessFactorsの基盤側の設定に入れるのは認定を受けたコンサルタントや導入パートナーに限られるため、フリーランスが担う範囲と、パートナーの社員が担う範囲を参画時に確かめておく必要があります。

オンプレミスHCMからの移行の案件

1日の流れ（例）

旧環境の組織管理・人事管理・勤怠管理・給与計算の設定や、長年積み重なった独自の作り込みを読み解き、新しい仕組みでどう置き換えるかを整理するのが中心です。午前は旧環境の保守担当に、ある手当がどの規則から計算されているかを確かめ、午後は移行するデータの範囲と変換の決まりを人事部門と詰めます。移行のリハーサルの時期は、件数と金額の照合に1日の大半を使います。

1か月の流れ（例）

  • 月初：前月の給与の確定を待って、旧環境の結果を照合の基準として受け取る
  • 毎週：移行チームとの定例で、変換の不具合と照合の差異を確かめる
  • 月の半ば：並行稼働の期間は、旧と新で同じ月の給与を計算し、差異を一件ずつ原因まで追う
  • 月末：差異の説明と、次の回までに直す点を人事・給与の担当に報告する

成果物

現行の設定とアドオンの棚卸し、移行の範囲（在籍者だけか、退職者や過去の履歴まで移すか）、データの変換の決まり、照合の結果、並行稼働の差異の一覧と説明、切替の手順と判断の資料などです。移行先がSuccessFactorsか、S/4HANA上の人事かで作業の中身は変わります。移行先の選択肢は将来性の記事、S/4HANA全体の移行の進め方はS/4HANA移行の仕事内容で解説しています。

エージェントベストの見解

人事・給与の案件をご紹介していると、移行の案件では「旧環境の設定を読めるか」が参画後の働きやすさを大きく左右する傾向があります。新しい仕組みの設定の経験が豊富でも、旧環境の給与の計算の流れを追えないと、並行稼働の差異の説明に時間がかかります。応募の段階で、旧環境の資料がどの程度残っているか、保守担当に話を聞けるかを確かめておくことをおすすめします。

給与計算と連携の構築の案件

人事マスタはSuccessFactors、給与は別の仕組みという構成も増えており、データのつなぎ目を担う案件があります。

1日・1か月の流れ（例）

1日の中心は、計算の設定と検証です。社会保険料、源泉所得税、住民税の控除や、手当・時間外の計算が、規程どおりの結果になるかを、テストのデータで確かめます。あわせて、人事マスタの変更が給与にいつ反映されるか、勤怠の集計がどこから渡るか、給与の結果が会計の仕訳にどう渡るかを、各システムの担当と詰めます。

1か月の単位では、給与の締め日と支給日が作業の区切りになります。締めの前は連携のデータの確認、支給の後は結果の検証と問い合わせへの対応、というように、暦に合わせて作業の重心が動きます。

成果物

計算の設定の一覧、テストのデータと期待値、連携の仕様（項目、タイミング、エラーのときの扱い）、差異の分析の資料などです。会計との受け渡しは、SAP FI/COの仕事内容にある会計側の作業と対になります。

運用保守・制度対応の案件

1日の流れ（例）

人事・給与の担当からの問い合わせを受け、データの誤りか、設定の問題か、運用の誤解かを切り分けます。組織改編や新しい手当の追加など、社内の制度の変更があれば、影響する設定を洗い出して直し、テストしてから本番に反映します。SuccessFactorsの環境では、定期的に提供される新しいリリースの内容を確かめ、取り入れるかどうかの判断の材料をそろえる作業も加わります。

1か月の流れ（例）

  • 締めの前：給与の計算に影響する変更を反映し終える
  • 支給の後：計算結果に関する問い合わせへの対応
  • 月の後半：次の月の制度変更や組織改編の準備、リリースの影響の確認
  • 年の節目：賞与、年末調整、春の異動や昇給の一括反映など、作業が集中する時期がある

成果物

問い合わせの記録と対応の内容、設定変更の記録、テストの結果、リリースの影響の整理、運用の手順書の更新などです。保守の案件は長期になりやすく、週2〜3日の稼働で受けられるものもあります。短い稼働の働き方は週2〜3日・副業の案件の記事をご覧ください。

どの案件にも共通する仕事

種類が違っても、次の仕事はほぼすべての案件にあります。

  1. 制度の聞き取り：規程の文言だけでなく、実際の運用と例外の扱いまで確かめる
  2. 設定とテストの記録：どのデータで何を確かめたかを残し、後から追えるようにする
  3. 個人情報の扱い：従業員の住所、家族、給与の額、評価、マイナンバーなどを、決められた端末と場所で、必要な範囲だけ扱う
  4. 変更の扱い：追加や変更の依頼を受けたら、給与の計算や連携への影響を示し、誰が決めるかをはっきりさせる

個人情報の扱いは作業の場所にも影響します。リモートで進めやすい作業と出社が求められやすい場面はリモート案件の記事で解説しています。フリーランスならではの仕事として、自分の稼働の記録と報告もあります。月の稼働時間に幅を決めて精算する契約が多く、仕組みは精算幅の記事をご覧ください。

注意

人事・給与の案件では、「ついでにこの帳票も」「年末調整の画面の操作を教えてほしい」のように、契約の範囲から外れる頼まれごとが増えやすくなります。また、届出の書類の作成や提出の代行のように、社会保険労務士の業務にあたるおそれのある作業は、資格のない人が報酬を得て行えない場合があります。引き受ける前に契約の業務範囲を確かめ、迷う作業は発注元の担当部署や専門家に確認しましょう。

エージェントベストの見解

当社では、案件をご案内する前に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをお出ししています。人事・給与の案件は、担当する機能と給与の暦によって毎日の仕事が変わるため、「これまで担ってきた機能と工程」と「給与の締めや年末調整の時期にどこまで対応できるか」をあわせてお伝えいただくと、案件を照らし合わせやすくなります。作業の場所や端末の条件など、案件票に書かれていない点は、ご質問いただければ確認します。

ポイント

  • 仕事の中身は、新規導入・移行・給与と連携・運用保守のどれに入るかで大きく変わる
  • 新規導入は標準機能との突き合わせ、移行は旧環境の読み解きと照合、給与と連携はつなぎ目の設計と検証が中心
  • 作業の山は、月次の締めと支給日、賞与、年末調整、春の異動の時期に来る
  • 制度の聞き取り、記録、個人情報の扱い、変更の扱いは、どの案件にも共通する

よくある質問

SuccessFactorsの案件は、設定と打ち合わせのどちらに時間を使うことが多いですか？

導入の前半は、人事部門との打ち合わせと設計に多くの時間を使います。設定が固まる後半からは、検証環境での設定とテスト、操作の説明に重心が移ります。どの工程から参画するかで、1日の配分は大きく変わります。

給与を担当しない人事の案件もありますか？

あります。採用・評価・育成などのタレント管理の機能だけを担う案件や、人事マスタと権限の設計に絞った案件もあります。ただし、人事マスタを担う場合は、データの変更が給与の計算にどう効くかを説明できると、連携の話し合いで役割を果たしやすくなります。

年末調整の時期は、どの案件でも忙しくなりますか？

給与の計算や保守を担う案件では、作業が集中しやすい時期です。新規導入やタレント管理の案件では影響が小さいこともあります。担当範囲に年末の作業が含まれるかは、参画前に確かめておくと稼働の見込みが立てやすくなります。
