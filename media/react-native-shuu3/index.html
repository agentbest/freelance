モバイルアプリ開発

React Nativeエンジニアの週2〜3日・副業案件｜探し方と受けるときの注意点

公開 2026-11-04　監修：株式会社エージェントベスト

週2〜3日や副業で受けられるReact Nativeの案件は、週5日の案件より少ないものの、あります。見つかりやすいのは、運用中アプリの保守と小さな機能追加、版上げを区切って進める作業、Webのチームがアプリも担う現場の補強、立ち上げ前の技術検証などです。React Nativeはリモートで進めやすい技術のため、短い稼働でも成り立つ場面が比較的あります。

探すときは「週3日なら何でも」ではなく、稼働日数に合う役割の案件を選ぶことが大切です。この記事では、週2〜3日・副業のReact Native案件の傾向、探し方、受けるときの注意点を整理します。週3日の働き方全般は週3日の業務委託案件の記事で解説しています。

週2〜3日のReact Native案件が多くない理由

React Nativeの案件で週5日が多いのは、仕事の性質によるものです。

  • 少人数で両OSを持つ：React Nativeの担当が1〜2名という現場が多く、不在の日があると開発が止まりやすい
  • リリースの節目に張りつく必要がある：審査の指摘や公開直後の不具合には、その日のうちに動くことが求められる
  • ビルドの待ちと確認に時間がかかる：両OSでビルドして確かめる作業は、細切れの時間では進めにくい

そのため、アプリの開発を一人で背負う役割を週2〜3日で募集することは多くありません。週2〜3日の案件は、役割の範囲を絞った形で募集されることがほとんどです。

週2〜3日・副業で見つかりやすいReact Native案件

案件の型主な仕事週2〜3日で成り立つ理由
運用中アプリの保守・小さな改修不具合の修正、文言や画面の調整、ライブラリの更新急ぎの少ない作業を稼働日にまとめやすい
版上げ・移行の段階的な作業依存の調査、段階ごとの版上げ、回帰の確認区切りごとに成果を出せ、日々の即応が少ない
Webチームのアプリ補強アプリ固有の部分の担当、Webのメンバーへの助言社員がいて、フリーランスは専門の部分に集中できる
立ち上げ前の技術検証構成の比較、試作、見積もりの材料づくり期間と成果物を区切りやすい
レビュー・相談役設計やコードのレビュー、ビルドの不具合の相談回数や時間で区切れる

運用中アプリの保守は、週2〜3日の案件で最も見つかりやすい型です。Expoを使う現場では、JavaScriptだけの修正をストアを通さずに配信できるため、細かな改修を稼働日にまとめて届けやすくなります。ただし、Expoの公式ドキュメントにあるとおり、ネイティブのコードや権限、Expo SDKの版を変える変更は新しいビルドが要り、ストアの審査を待つ必要があります。

版上げの作業は、段階を区切って進められるため、週2〜3日でも成果を示しやすい仕事です。機能の開発を続ける社員のメンバーと並行して進めることが多く、取り込みの時期をそろえる段取りが求められます。

エージェントベストの見解

React Nativeの案件をご紹介していると、週2〜3日の希望で決まりやすいのは、「この稼働日数なら、保守と版上げのここまでを担える」と役割の範囲を自分から示せる方です。反対に、週5日の案件と同じ役割を週3日で引き受けようとすると、審査の指摘や公開直後の不具合に不在の日はどうするのかを発注元が心配し、見送られやすい傾向があります。稼働日数と担える範囲をセットで伝えることをおすすめします。

週2〜3日のReact Native案件の探し方

1. 担える範囲を先に決める

週2〜3日で受けるなら、どの仕事を担い、どの仕事は担わないかを先に決めておきます。たとえば「保守と版上げは担うが、公開直後の夜間の対応は社員の方にお願いする」のように言葉にしておくと、案件との照らし合わせが早くなります。

2. 稼働する曜日と、稼働外の連絡の扱いを決める

リリースの曜日や定例会議の曜日と、自分の稼働日が合うかが大切です。稼働日以外にどこまで連絡に応じられるかも決めておきましょう。

3. 開発環境と端末を自分で用意できるかを確かめる

短い稼働の案件では、貸与の機器がなく、手元のMacや実機で開発することを求められることがあります。iOSのビルドと確認に使うMac、両OSの実機を用意できるかで、受けられる案件が変わります。リモートでの進め方はReact Nativeのリモート案件の記事で解説しています。

4. 経験の近い構成から選ぶ

稼働日数が少ないほど、立ち上がりの早さが求められます。Expoかどうか、使っている版、状態管理の方式などが自分の経験に近い案件を選ぶと、短い稼働でも成果を出しやすくなります。期間の短い仕事の探し方はスポット案件の記事も参考になります。

短い稼働で信頼を得る進め方

  • 稼働日の最初に予定、最後に結果を残す：何を進め、どこまで終わり、何が残ったかを文章で共有する
  • ビルドと配布を稼働日に終える：確認用のアプリを配るところまで終えて、不在の日に確認してもらえるようにする
  • 不在の日の代わりを決める：審査の指摘や急ぎの不具合が出たときに、誰が判断するかを先に合意しておく
  • 調べたことを残す：OSごとの差やビルドで詰まった点の解決策を記録し、次の稼働日や他のメンバーが追えるようにする

こうした進め方を面談で具体的に話せると、短い稼働でも任せられるかを発注元が判断しやすくなります。

受けるときの注意点

責任の範囲と稼働日数をそろえる

最も起きやすいのは、稼働日数は減ったのに、アプリ全体の責任は週5日の担当と同じという状態です。公開直後の不具合や審査の指摘に不在の日も呼ばれ、結果として稼働日以外の作業が増えていきます。参画前に、担う範囲と、不在の日の対応を誰が担うかを確かめておきましょう。

ストアや開発用アカウントの権限を確かめる

Play Consoleでは、アカウント全体に効く権限と、選んだアプリだけに効く権限を分けて付与でき、招待に有効期限を設けることもできます（2026年10月時点のPlay Console ヘルプによる）。短い期間の参画では、必要な権限だけを付けてもらい、契約が終わったら外してもらう流れを確かめておくと安心です。App Store Connectの権限も同じ考え方で確かめましょう。

稼働時間の記録と精算を確かめる

ビルドの待ちや審査への対応など、見えにくい作業にも時間を使います。稼働日以外に対応した時間をどう扱うかを、精算の条件と合わせて確かめます。精算の仕組みは精算幅の記事、参画後に役割が広がった場合は作業範囲が広がったときの契約の扱いをご覧ください。

注意

複数の案件を掛け持ちすると、リリースの時期や審査の対応が重なったときに、どちらかが後回しになりやすくなります。また、手元のMacや実機に複数の発注元のアプリや検証用のアカウントが入るため、情報の扱いを案件ごとに分ける必要があります。掛け持ちの注意点は複数の案件を掛け持ちするときの注意点で解説しています。

会社員の副業でReact Native案件を受けるとき

会社員が副業で受ける場合は、上の注意点に加えて、次の点を確かめます。

  • 勤務先の就業規則：副業が禁止か、許可制か、届出制か。業務委託が対象に含まれるか
  • 本業との競合：本業と同じ業界のアプリや、本業の取引先に関わる案件は、競業や秘密の扱いで問題になりやすい
  • 時間帯：リリースや定例会議が平日の日中に入ると、本業の時間と重なる
  • 使う機器：本業で貸与されたMacや端末を副業に使わない

厚生労働省は「副業・兼業の促進に関するガイドライン」を公表しており、モデル就業規則にも副業・兼業の規定を設けています（2026年10月時点の厚生労働省のページによる）。ただし、実際の扱いは勤務先の就業規則によって違います。所得が出た場合の確定申告や住民税の扱いは会社員の副業で業務委託案件を受けるときの注意点と副業の所得20万円の考え方、副業が禁止されている場合は副業禁止の会社で業務委託を受けるリスク、平日の日中に動けない場合は週末・夜だけの業務委託案件の記事で解説しています。判断に迷う場合は、勤務先の担当部署や税理士などの専門家にご相談ください。

エージェントベストの見解

当社では、案件をご案内する前に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをお出ししています。週2〜3日のReact Native案件は数が限られるため、稼働できる曜日、稼働日以外の連絡への対応、手元の開発環境と端末、担える範囲をあわせてお伝えいただくと、条件を照らし合わせやすくなります。契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。

ポイント

  • 見つかりやすいのは、保守と小さな改修、版上げの段階的な作業、Webチームの補強、技術検証、レビュー役
  • 担える範囲、稼働する曜日、手元の開発環境を先に決め、責任の範囲と稼働日数をそろえる

よくある質問

週2〜3日の案件でも、React Nativeの経験として評価されますか？

担った範囲と作業の中身を具体的に書けば、経験として評価されます。スキルシートには稼働日数と担った工程を正確に書き、アプリ全体の担当と誤解されない書き方にしておきましょう。

新規アプリの開発を週2〜3日で受けることはできますか？

チームに他の担当がいて、自分は特定の機能や技術検証を担う形なら成り立つことがあります。一人で立ち上げから公開までを担う形は、週2〜3日では進みが遅くなりやすく、募集も少なめです。

平日の夜や週末だけでもReact Nativeの案件は受けられますか？

会議の少ない保守やレビュー、成果物で区切れる作業なら成り立つことがあります。ただし、ストアの審査への対応や発注元との確認は平日の日中に入ることが多く、受けられる案件はかなり限られます。

 副業・複業

週末・夜だけの業務委託案件はある？探し方と会社員が注意すること

週末・夜だけの業務委託案件はありますが、平日日中の稼働を前提にした案件より数は限られます。範囲を区切れる開発や相談・レビューなどで見つかりやすく、勤務先の副業の規定、本業との時間の切り分け、確定申告を確かめておくことが大切です。

 副業・複業

会社員の副業で業務委託案件を受けるときの注意点｜就業規則・契約・税金の確かめ方

会社員が副業で業務委託案件を受けるときは、勤務先の就業規則、本業との競合や秘密の扱い、契約条件、確定申告と住民税の4点を先に確かめます。業務委託は会社員の給与とルールが違うため、受ける前の整理が大切です。

 副業・複業

副業禁止の会社で業務委託を受けるリスク｜就業規則の読み方と許可の求め方

就業規則で副業が禁止・許可制の会社で無断で業務委託を受けると、懲戒などの対象になるおそれがあります。厚生労働省のガイドラインの考え方を踏まえつつ、規則の読み方、許可の求め方、断られたときの選択肢と相談先を整理します。

 副業・複業

副業の確定申告｜所得20万円のルールの正しい理解と、住民税の申告が別に要る理由

副業の所得が20万円以下なら確定申告が不要になるのは、給与を1か所から受け年末調整を受けている人などに限られます。20万円は収入ではなく所得で数え、住民税の申告は別に必要なことがあります。医療費控除などで申告するときは副業分も含めます。

 副業・複業

副業に使える時間の見積もり方｜業務委託を受ける前の計算と契約への落とし込み

副業に使える時間は、1週間の予定から本業・生活・休息を引き、さらに予備の時間を引いて見積もります。業務委託の作業時間は本業の労働時間と通算されないため、自分で管理する必要があります。計算の手順と、契約に残す条件を整理します。
