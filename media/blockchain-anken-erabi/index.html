バックエンド開発

ブロックチェーンエンジニアのフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

ブロックチェーンエンジニアのフリーランス案件を選ぶときは、報酬や稼働日数に加えて、担う領域の実態、鍵と本番操作の責任、検証と監査の体制、契約の形と責任の範囲、発注元の事業の実態、報酬の支払い方、公開と障害時の稼働の7点を契約前に確かめておくことが大切です。

特に見落としやすいのは、取り消せない操作の責任が、誰に、どの手順で置かれているかです。ほかの開発では直せば済む誤りも、チェーンの上では資産の流出につながることがあります。この記事では、ブロックチェーンの案件に固有の確認点を整理します。契約書全般の確認点は業務委託契約書のチェックポイントで解説しています。

ブロックチェーンの案件選びで差が出る理由

ブロックチェーンの案件は、案件票の言葉が「Web3開発」「ブロックチェーンエンジニア募集」のように広く、参画してから想定との違いに気づくことが少なくありません。よくあるずれは次のようなものです。

  • コントラクトの設計を担うつもりが、仕事の大半が周辺のAPIの開発だった
  • 本番の公開や管理用の鍵の操作を、手順が決まらないまま任された
  • 外部の監査を受ける予定がなく、安全の確認が実質的に自分一人に寄っていた
  • 報酬の一部を暗号資産で受け取る話が、契約の後に出てきた

こうしたずれは、面談と条件の確認の段階で多くを防げます。

契約前に確かめたい7つの点

1. 担う領域の実態

最初に、自分が担う仕事の中身を確かめます。コントラクトの設計か実装か、周辺開発か、企業向けの分散台帳か、監査か。チェーンに関わる作業が全体のどのくらいかを聞くと、実態が見えやすくなります。種類ごとの働き方はブロックチェーンエンジニアの仕事内容で整理しています。

2. 鍵と本番操作の責任

  • 管理用の鍵を誰が持ち、どこに保管しているか
  • 本番への公開やアップグレードの操作を誰が行い、誰が承認するか
  • 自分に渡される権限の範囲と、契約が終わったときの返却や削除の手順

フリーランスが本番の操作を担う場合は、手順書と複数人での確認があるかを確かめます。手順がないまま一人で操作する形は、誤りが起きたときの責任が自分に寄りやすくなります。

3. 検証と監査の体制

テストの方針、レビューの体制、外部の監査を受ける予定と時期を確かめます。監査の予定がない案件を避ける必要はありませんが、その場合は安全の確認をどこまで自分が担うのかをはっきりさせておきます。

エージェントベストの見解

ブロックチェーンの案件をご紹介していると、参画後に「聞いていた状況と違った」となりやすいのは、鍵と本番操作の扱いと、検証の体制の2点です。面談では聞きにくいと感じる方もいますが、取り消せない処理を扱う仕事の前提として聞けば、多くの発注元は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

4. 契約の形と、負う責任の範囲

開発の支援は準委任契約で受けることが多く、その場合は成果の完成ではなく、専門家として求められる注意を払って業務を行うことが約束の中身になります。確かめたいのは、契約書の書き方がこの考え方と合っているかです。

  • 「安全なコントラクトを完成させる」のように、完成や無事故を約束する書き方になっていないか
  • 資産の流出などが起きたときの損害賠償の範囲と上限が定められているか
  • 監査の案件で、報告書の納品が求められる場合、対象のコードの範囲と、対象外の事項が書かれているか

監査を請負で受ける場合は、成果物に対する責任を負うことになります。違いは準委任契約と請負契約の違い、賠償への備えはフリーランスの賠償責任保険の記事で解説しています。

5. 発注元の事業の実態

発注元がどんな事業をしていて、その事業に必要な登録などを済ませているかを確かめます。金融庁は、国内で暗号資産と法定通貨の交換サービスを行うには暗号資産交換業の登録が必要だと案内し、登録を受けた事業者の一覧を公開しています（2026年10月時点）。暗号資産の交換などに関わる案件なら、発注元の事業が登録とどう関わるかを確かめておくと安心です。登録の要否などの判断は、発注元や専門家に確かめてください。

6. 報酬の支払い方

報酬を円で受け取るのか、一部でも暗号資産で受け取る話があるのかを確かめます。暗号資産で受け取る場合は、その時点の価格の扱いや税務が複雑になります。考え方はブロックチェーンエンジニアの報酬の記事で扱っています。海外の発注元の場合は、支払いの通貨や手数料の負担も確かめておきましょう。

7. 公開と障害時の稼働

  • 公開の日や移行の作業が、夜間や休日に入るか
  • 障害が起きたときの連絡と待機の体制に、自分が入るか
  • 精算幅を超えたときの扱い

チェーンの上の異常は、時間を問わず起きます。待機や時間外の対応の扱いを決めておかないと、責任感から無償で対応し続けることになりかねません。精算の仕組みは精算幅の記事をご覧ください。

注意

参画後に、別のコントラクトのレビューや、トークンの設計の相談、社内向けの説明資料づくりなど、契約の業務範囲に入っていない仕事を頼まれることがあります。特に、自分が設計に関わっていないコードの安全を確認するよう求められた場合は、責任の範囲が大きく変わります。引き受ける前に範囲と条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。公正取引委員会は、フリーランスに業務を委託した発注事業者は、直ちに書面または電子メールなどで取引条件を明示する義務があると案内しています（2026年10月時点）。報酬の支払期日は、受け取った日から数えて60日以内のできる限り短い期間で定めることとされています。明示される事項はフリーランス法で明示される取引条件をご覧ください。

ブロックチェーンの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、担う範囲（設計、実装、テスト、周辺開発、レビューなど）が書かれているか
  2. 本番の操作や鍵の管理を担うかどうかが、業務の範囲としてはっきりしているか
  3. 完成や無事故を約束する書き方になっていないか、賠償の範囲はどうか
  4. 報酬の額と支払い方（通貨を含む）、支払期日
  5. 契約期間と更新の時期

契約期間は、公開や監査の時期と合わせて見ておきます。公開の直前に契約の更新時期が来ると、最も大事な局面を見届けられないことがあります。なお、6か月以上継続して委託している場合に契約を解除したり更新しなかったりするときは、発注事業者は少なくとも30日前までに予告する必要があります（2026年10月時点、公正取引委員会の案内による）。

面談で聞いておくとよい質問はブロックチェーンエンジニアの面談でよく聞かれる質問と答え方の逆質問の項目で紹介しています。一般的な逆質問の考え方は面談で聞いておくべき逆質問をご覧ください。

ポイント

  • ブロックチェーンの案件は、担う領域、鍵と本番操作の責任、検証の体制で負担が大きく変わる

よくある質問

外部の監査を受けない案件は避けたほうがよいですか？

避ける必要はありません。ただし、その場合は安全の確認をどこまで自分が担うのかがあいまいになりやすいため、テストとレビューの体制、責任の範囲を契約の前に確かめておくことをおすすめします。

本番の鍵の操作を任されそうなときは、どうすればよいですか？

手順書があるか、誰の承認で行うか、複数人で確かめる仕組みがあるかを確かめます。そのうえで、操作を担うことが業務の範囲として書面に書かれているかを確かめましょう。手順が整っていない場合は、まず手順づくりから関わる形を提案する方法もあります。

報酬の高い案件と、体制の整った案件で迷ったらどうしますか？

一概には言えませんが、検証や鍵の体制が整っていない案件では、確認の手間と責任が自分に寄り、稼働が増えやすくなります。報酬の額だけでなく、担う責任の範囲と稼働の見込みをあわせて比べるとよいでしょう。リモートの条件も含めた比べ方はブロックチェーンエンジニアのリモート案件の記事が参考になります。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 共済・将来への備え

フリーランスの賠償責任保険｜IT業務で起きやすい損害と備え方

IT業務のフリーランスが備えたいのは、作業ミスによるシステム障害、情報漏えい、権利侵害などで取引先や第三者に損害を与えた場合です。契約上の責任の範囲を確かめたうえで、補償の対象業務・免責・限度額を見て保険を選びます。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 単価・報酬交渉

精算幅（140〜180時間など）とは｜超過・控除の計算方法

精算幅は、月額報酬のままでよい稼働時間の範囲です。上限を超えると超過分が加算され、下限を下回ると控除されます。超過・控除の単価は上下割か中間割かで変わるため、仮の数字を使って計算方法を整理します。
