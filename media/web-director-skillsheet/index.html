Web制作・デザイン

Webディレクターのスキルシートの書き方｜面談で評価される実績の見せ方

Webディレクターのスキルシートは、制作したサイトの一覧より「何のためのサイトで、どの工程を担い、何を決めたか」を先に読ませるのが基本です。案件ごとに「サイトの目的・規模・体制・担当工程・主な判断・結果」をそろえて書くと、読み手は任せられる範囲をすぐに判断できます。

デザイナーのように作品の見た目で伝えることも、エンジニアのように技術を並べることもできないのが、Webディレクターのシートの難しさです。この記事では、Webディレクターに固有の書き方を、架空の例を使って紹介します。全体の構成はフリーランスのスキルシートの書き方で解説しています。

Webディレクターのシートはどう読まれるか

シートを読むのは、制作会社のディレクションの責任者や、事業会社のWeb担当の管理職であることが多く、読み手自身が制作の流れをよく知っています。そのため「ディレクションを担当」「進行管理を実施」だけでは評価されにくく、次の点を読み取ろうとします。

  • 制作会社の側か、発注する事業会社の側か
  • 要望の聞き取りから入ったのか、決まった設計を引き継いだのか
  • 何人・何社を、直接まとめていたのか
  • 公開後の結果まで見届けたのか

求められるスキルの全体像はWebディレクターの案件で求められるスキルで整理しています。ここでは、それをシートの上でどう表すかに絞ります。

要約欄は「どんなディレクターか」を3行で

要約欄は最も読まれる部分です。経歴を年代順にまとめるより、立場、得意な局面、扱ってきた規模、領域の4つで「どんなディレクターか」を先に書きます。

例（架空）：

  • 制作会社の側で、コーポレートサイトとBtoBの問い合わせ獲得サイトの刷新を、要望の聞き取りから公開まで担当
  • デザイナー・エンジニア・ライターを含む外部の制作メンバーを取りまとめた経験あり
  • 公開後の計測と改善を継続して担い、フォームの導線の見直しなどを提案した経験あり

これは書き方を示すための架空の例です。実際には、応募する案件で求められる型に近い行を一番上に置き、案件ごとに並べ替えます。

案件欄に入れる項目

項目書き方のポイント
期間年月で書く。制作期間と運用期間は分けて書く
サイトの種類と目的業種と目的で書く（例：製造業のBtoBサイト、問い合わせの獲得）。社名やサイト名は書かない
立場制作会社の側か、発注する事業会社の側か。肩書きと実際の役割
規模ページ数のおおよそ、機能（会員、検索、フォームなど）、外部システムとの連携の有無
体制社内外の人数と職種、関わった会社の数、自分が直接まとめた範囲
担当工程要件の整理、構成、デザインの確認、実装の確認、公開、運用・改善のどこを担ったか
使った道具CMS、タスク管理、デザインの確認、解析のツールなど
主な判断自分が決めた、または決定を主導したことを1〜3行で
結果伏せられる範囲での結果（公開の時期、公開後の変化、発注元の評価など）

記入例（架空）

以下は書き方を示すための架空の例で、実在の案件ではありません。

期間：（例）制作8か月、公開後の運用1年
サイトの種類と目的：（例）産業機械メーカーのBtoBサイトの刷新。製品の問い合わせを増やすことが目的
立場：制作会社の側のディレクター。発注元のWeb担当と直接やりとり
規模：約100ページ。製品の検索機能、問い合わせフォーム、CMSの導入
体制：社内のデザイナー2名、外部のエンジニア3名、ライター1名。発注元は広報部と営業部
担当工程：要望の聞き取り、サイト構成、デザインと実装の確認、公開、公開後の改善
使った道具：WordPress、タスク管理ツール、デザインツール、アクセス解析ツール
主な判断：両部門の要望が予算を超えたため、製品検索を優先し、事例ページは公開後の追加に回す案を出して合意を得た
結果：予定の公開日に公開。運用期間中にフォームの項目を減らす改善を提案し、実施された

「主な判断」の行があると、進行を管理しただけでなく、優先度を決めて着地させたことが伝わります。

「主な判断」の書き方

判断の行は、Webディレクターのシートで最も差がつく部分です。次の3つをそろえて書きます。

  1. 状況：何が起きていたか（要望の膨張、素材の遅れ、仕様の変更、関係部署の対立など）
  2. 判断：自分が何を提案し、何を決めたか
  3. 結果：その判断で何が守られ、何が変わったか

「調整した」「対応した」で終わらせず、何と何を比べてどちらを選んだかまで書くと、面談で深く聞かれたときにも話がぶれません。

エージェントベストの見解

Webディレクターの案件をご紹介していると、シートで評価されやすいのは、案件数が多い方よりも、1件ずつ「判断」の行が具体的な方です。制作会社にいた方は、営業や上司が決めたことと自分が決めたことが混ざりやすいので、分けて書くことをおすすめします。経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せて提案しています。

肩書きと実際の役割がずれるとき

Webディレクターは、会社によって肩書きと仕事の中身が違いやすい職種です。シートでは肩書きより実際の役割を優先して書きます。

  • 肩書きは「プロデューサー」だが、進行も自分で回していた：立場の欄に肩書きを書き、担当工程の欄で進行まで担ったことを示す
  • 肩書きは「Webディレクター」だが、更新作業が中心だった：担当工程に「更新作業の手配と確認」と書き、ディレクションの範囲を正直に示す
  • 肩書きはなく、事業会社のWeb担当として外注をまとめていた：立場の欄に「発注する事業会社の側」と書き、まとめた会社の数と判断の範囲を書く

肩書きに合わせて役割を大きく書くと、面談で掘り下げられたときに説明が続かなくなります。逆に、肩書きがなくても実際に担った役割を書けば、評価の材料になります。

運用案件の書き方

公開後の運用を担った案件は、制作と同じ型だと伝わりにくくなります。運用では次の点を書きます。

  • 担った範囲（更新作業の手配、計測、改善の提案、外部の会社への依頼）
  • 見ていた指標と、見る頻度
  • 改善の例を1〜2件（何に気づき、何を変え、どうなったか）

更新作業だけを担っていた場合は、それも正直に書きます。役割を大きく見せると、面談での質問で食い違いが出ます。

公開URLと実績の見せ方

Webディレクターの実績は、公開されているサイトのURLで示したくなります。ただ、制作に関わったことを公表してよいかは、制作会社や発注元との取り決めによって違います。

注意

守秘義務の範囲を確かめずに、社名やサイトのURL、管理画面の画像をシートに載せると、契約違反になるおそれがあります。公表してよいかが分からないものは、業種と目的で説明し、必要なら面談で口頭で補足しましょう。伏せ方はスキルシートでの守秘義務の扱い、実績の示し方はポートフォリオやGitHubは必要かで解説しています。

数字の扱い

ページ数、体制の人数、期間は、おおよその数で書けば十分です。公開後の成果（問い合わせ数の変化など）は、発注元の機密にあたることが多いため、比率や「増えた」「減った」の向きにとどめるのが無難です。数字を書く場合は、自分の施策による変化か、他の要因も含むかを区別しておきます。

提出前に見直したいこと

  • 要約欄の1行目が、応募する案件の型に合っているか
  • 各案件に「立場」「担当工程」「主な判断」があるか
  • 社名、サイト名、URLなど、伏せるべき情報が残っていないか
  • 担当していない工程を、担当したように書いていないか
  • 制作会社の側と発注側の経験が混ざっている場合、案件ごとに立場が分かるか
  • 専門用語が、制作の現場を知らない人事の担当者にも通じる言葉になっているか

シートは、応募する案件ごとに要約欄と案件の並び順を見直すのが基本です。運用改善の案件に応募するなら運用の経験を上に、刷新の案件に応募するなら要件の整理から公開まで担った案件を上に置きます。同じ経歴でも、並べ方で読み手の受け取り方は変わります。

エージェントベストの見解

当社では、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをご案内しています。シートの書き方で迷う点があれば、ご質問いただければ確認します。参画が決まった案件では、業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。

ポイント

  • 制作実績の一覧より、目的・立場・担当工程・主な判断・結果をそろえて書く
  • 「主な判断」は状況→判断→結果の順で、何を選んだかまで書く
  • 運用案件は、見ていた指標と改善の例を書く
  • 公開URLや成果の数字は、守秘義務の範囲を確かめてから載せる

よくある質問

担当したサイトが多い場合、全部書くべきですか？

全部を同じ詳しさで書く必要はありません。応募する案件に近いものを3〜5件選んで詳しく書き、残りは期間・種類・担当工程だけの一覧にまとめると読みやすくなります。

自分でデザインやコーディングもした場合はどう書けばよいですか？

担当工程の欄に分けて書きます。ディレクションと作業を兼ねていたことが分かるように書いておくと、応募先が作業も任せたいのか、ディレクションに専念してほしいのかに合わせて話を進めやすくなります。

事業会社のWeb担当の経験はどう書けばよいですか？

立場の欄に「発注する事業会社の側」と書き、まとめた制作会社や外注先の数、社内で調整した部署、予算や発注の判断にどこまで関わったかを書きます。発注側の経験は、事業会社の側でまとめる案件で評価されやすくなります。面談で聞かれやすい質問は面談でよく聞かれる質問で整理しています。
