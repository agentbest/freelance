Power Platformエンジニアのフリーランス案件の選び方｜契約前に確かめたい7つの点

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい7つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

Power Platformエンジニアのフリーランス案件を選ぶときは、報酬や稼働日数に加えて、作る仕事か統制する仕事か、環境と移送の状態、データの置き場所とライセンス、与えられる権限、既存のアプリやフローの扱い、作ったものの持ち主と引き継ぎ、契約の形と成果物の扱いの7点を契約前に確かめておくことが大切です。

特に見落としやすいのは、任される範囲と、与えられる権限が釣り合っているかです。データポリシーや環境を整えるよう頼まれても、設定を変える権限がなければ進められません。この記事では、Power Platformの案件に固有の確認点を整理します。契約書全般の確認点は業務委託契約書のチェックポイントで解説しています。

Power Platformの案件選びで差が出る理由

Power Platformの案件は、案件票に「Power Apps開発」「業務改善」のように短く書かれることが多く、参画してから中身の違いに気づくことが少なくありません。よくあるずれは次のようなものです。

  • アプリを作る案件として入ったのに、実際は社内で作られた多数のアプリの整理が中心だった
  • 開発とテストの環境がなく、本番の環境で直接作るしかなかった
  • 作りたいものに必要なライセンスが利用者に割り当てられておらず、作り直しになった
  • データポリシーの設定を変える権限がなく、使いたいコネクタが使えないまま進められなかった

Power Platformは作る敷居が低い分、作る前の土台が整っているかで仕事の進めやすさが大きく変わります。こうしたずれは、面談と条件の確認の段階で聞き方を工夫すれば、多くを防げます。

契約前に確かめたい7つの点

1. 作る仕事か、統制する仕事か

最初に確かめたいのは、自分が担う仕事の重心です。アプリやフローを作る仕事が中心か、環境やデータポリシー、作り方の決まりを整える仕事が中心かで、必要なスキルも、話す相手も変わります。

面談では、「参画後の最初の1か月で、最も期待されている成果は何か」を聞くと、重心が見えやすくなります。答えが「この業務のアプリを出すこと」なら作る仕事、「社内のアプリの状況を見える状態にすること」なら統制の仕事です。種類ごとの働き方はPower Platformの仕事内容の記事で解説しています。

2. 環境と移送の状態

開発・テスト・本番の環境が分かれているか、作ったものをソリューションにまとめて移しているか、移送を誰が承認するかを確かめます。

  • 環境が分かれていない場合、分けるところから任されるのか、本番で作る前提なのか
  • 移送の手順や仕組みはすでにあるか
  • 既定の環境に、個人が作ったアプリやフローが多く置かれていないか

環境が整っていない案件を避ける必要はありません。整える経験は評価にもつながります。ただ、整える作業が範囲に入っているかを知ったうえで受けることが大切です。

3. データの置き場所とライセンス

作るものが、SharePointのリストやExcelを使う前提か、Dataverseを使う前提かを確かめます。あわせて、利用者にどのライセンスが割り当てられているかも聞いておきます。

Microsoft Learnのライセンスの概要では、一部のMicrosoft 365のライセンスに含まれるPower AppsやPower Automateの使用権は、Microsoft 365のデータと標準のコネクタを使う場面を対象とし、Premiumのライセンスと同じ権利ではないと説明されています。必要なライセンスは、使う製品、機能、データソース、環境によって変わるとされています（2026年10月時点）。設計の途中でライセンスが足りないと分かると、作り直しや発注元の追加の購入の判断が必要になります。ライセンスを判断し、手配するのは誰かを確かめておきましょう。

エージェントベストの見解

Power Platformの案件をご紹介していると、参画後に「聞いていた状況と違った」となりやすいのは、環境の状態と、ライセンスの割り当ての2点です。どちらも案件票には書かれないことが多い一方、作る前の段階で仕事の進め方を大きく左右します。作業を始める前に確かめたい点として面談で聞けば、多くの発注元は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

4. 与えられる権限

自分がどの権限で作業するかを確かめます。

  • 開発の環境で、アプリやフローを作り、ソリューションを扱える権限があるか
  • データポリシーや環境の設定を変える必要がある場合、誰に依頼し、誰が承認するか
  • 本番の環境への移送は、自分が行うのか、社内の担当者が行うのか
  • テナント全体の管理者の権限を求められていないか

フリーランスが管理者の権限を持つかどうかは、発注元のセキュリティの方針によります。権限が強すぎると、誤った設定が社内の多くのアプリに影響したときの責任が重くなります。必要な範囲の権限だけを受け取り、変更は承認を得てから行う流れになっているかを確かめておくと安心です。

5. 既存のアプリやフローの扱い

社内ですでに作られたアプリやフローがある場合、その保守や整理が範囲に入るかを確かめます。持ち主が異動や退職でいなくなったフローを直す、決まりに合わない作りを見直す、といった作業は、数が多いと想像以上に時間がかかります。

Microsoft Learnでは、これまで棚卸しなどに使われてきたCoEスターターキットは積極的に保守されなくなり、中心の機能はPower Platform管理センターのインベントリや使用状況などに移っていると案内されています（2026年10月時点）。既存の資産の状況を把握する仕組みがすでにあるか、これから整えるのかも、作業の量を見積もる材料になります。

6. 作ったものの持ち主と引き継ぎ

契約が終わったあとに、作ったアプリやフローを誰が持ち、誰が保守するかを確かめます。

  • アプリやフローの持ち主を、社内の担当者にする想定か
  • 接続に使うアカウントを、個人ではなく組織で管理するものにできるか
  • 引き継ぎの説明書や期間は、契約の範囲に入っているか

持ち主と接続の扱いが決まらないまま作ると、契約が終わったあとにフローが止まり、問い合わせが届くことがあります。参画の時点で、引き継ぎまでを仕事に含めておくと、終わり方が整います。

7. 契約の形と成果物の扱い

フリーランスのPower Platformの案件は、多くの場合、準委任契約で参画します。準委任では、アプリやフローの完成そのものではなく、専門家として通常求められる注意を払って業務を行うことが約束の中身になります。

確かめたいのは、契約書や発注の書面が、実際の働き方と合っているかです。

  • 「アプリを期限までに完成させる」のように、完成を約束する書き方になっていないか
  • 請負で受ける場合、完成の基準と検収の方法が決まっているか
  • 作ったアプリやフロー、設計書の権利が誰に帰属するか
  • 自分が以前から持っている部品や作り方の型を使う場合、その扱いが決まっているか

契約の形の違いは準委任契約と請負契約の違い、成果物の権利は業務委託の著作権の記事で解説しています。

注意

Power Platformは、作れると分かると「このフローも」「別の部署のアプリも」と依頼が増えやすい分野です。参画後に範囲が広がったときは、引き受ける前に、契約の業務範囲に入るかと、稼働や報酬の条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。稼働が増えたときの扱いは精算幅の記事をご覧ください。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。公正取引委員会のフリーランス法の特設サイトでは、発注する事業者は業務を委託したら直ちに、業務の内容、報酬の額、支払期日などの取引条件を、書面または電子メールなどの電磁的方法で明示することとされています。報酬の支払期日は、給付を受け取った日から60日以内のできる限り短い期間内で定める必要があります（2026年10月時点）。明示される事項はフリーランス法で明示される取引条件をご覧ください。

Power Platformの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、作るものと統制の作業のどちらが含まれるか
  2. 既存のアプリやフローの保守と整理が、範囲に入るかどうか
  3. 完成を約束する書き方になっていないか、成果物の権利の扱い
  4. 引き継ぎの作業と期間
  5. 稼働の幅と、超えたときの精算方法、契約期間と更新の時期

6か月以上継続して委託を受けている場合に、発注元が契約を解除したり更新しなかったりするときは、原則として少なくとも30日前までに予告することが求められています（2026年10月時点、公正取引委員会の案内による）。詳しくはフリーランス法の契約解除の予告の記事で解説しています。面談で聞いておくとよい質問はPower Platformの面談でよく聞かれる質問の逆質問の項目でも紹介しています。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。Power Platformの案件で気になりやすい環境の状態、ライセンスの割り当て、既存のアプリの扱いなど、書面だけでは読み取りにくい点は、ご質問いただければ確認します。

ポイント

  • Power Platformの案件は、同じ募集名でも役割、環境の状態、権限、既存の資産の扱いで負担が大きく変わる
  • 作る仕事か統制する仕事か、環境と移送、データの置き場所とライセンスを面談で確かめる
  • 必要な範囲の権限か、既存のアプリの保守が範囲に入るか、持ち主と引き継ぎをどうするかを確かめる
  • 完成を約束する書き方や成果物の権利の扱いを、書面と照らし合わせる

よくある質問

環境が整っていない案件は避けたほうがよいですか？

避ける必要はありません。環境を分け、移送の流れを整えた経験は、次の案件で評価されやすい経験です。ただし、整える作業が範囲に入っているか、そのための権限と稼働の見込みがあるかを、参画前に確かめてから受けることをおすすめします。

管理者の権限を渡したいと言われたら、受けてもよいですか？

作業に必要であれば受けることもありますが、必要な範囲を超える権限は、誤った設定をしたときの責任を重くします。どの作業にどの権限が要るかを整理し、変更の前に承認を得る流れを決めてから受けると安心です。発注元のセキュリティの方針もあわせて確かめましょう。

報酬の高い案件と、環境の整った案件で迷ったらどうしますか？

一概には言えませんが、環境やライセンスが整っていない案件では、作る前の準備や作り直しで稼働が増え、時間あたりの報酬が下がることがあります。報酬の額だけでなく、稼働の見込みと任される範囲を合わせて比べるとよいでしょう。報酬の決まり方はPower Platformの報酬の記事で解説しています。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 業務委託契約の基礎

成果物の著作権は誰のもの？業務委託の知的財産の扱い

業務委託で作ったプログラムや資料の著作権は、契約で決めなければ原則として作ったフリーランスに残ります。発注者に移す場合は、譲渡の範囲・時期・対価と、以前から持っているコードの扱いを契約で確かめます。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 フリーランス新法・下請法

中途解除の30日前予告｜フリーランス新法のルールと例外

6か月以上の業務委託を発注者が中途解除・不更新にするときは、原則として30日前までの予告が必要です。予告の方法、予告が不要になる5つの例外、理由開示の請求の仕方を、公正取引委員会・厚生労働省の資料をもとに整理します。
