フロントエンド開発

Vue.jsエンジニアのフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

目次
  1. Vue.js案件の選び方で差が出る理由
  2. 契約前に確かめたい7つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

Vue.jsエンジニアのフリーランス案件を選ぶときは、報酬や稼働日数に加えて、版と書き方、移行の範囲と完了の考え方、担当範囲、仕様とデザインの決まり方、品質の体制、契約の形、稼働と期間の7点を契約前に確かめておくことが大切です。Vue.jsの案件は、同じ「Vue.js開発」の募集でも、この7点の違いで毎日の仕事と負担が大きく変わります。

特に見落としやすいのは、新しく作る仕事か、古いコードを直す仕事かです。案件票の技術名だけでは区別がつかず、参画してから気づくことがあります。この記事では、Vue.js案件に固有の確認点を整理します。契約書全般の確認点は業務委託契約書のチェックポイントで解説しています。

Vue.js案件の選び方で差が出る理由

Vue.jsは、Vue 2とVue 3、Options APIとComposition API、VuexとPinia、Nuxtの有無と版など、同じフレームワークの中に書き方の違いが多くあります。案件票には「Vue.js」「Nuxt」とだけ書かれることが多く、どの組み合わせかは分かりにくくなりがちです。

よくあるずれは次のようなものです。

  • Vue 3の開発と聞いていたが、実際はVue 2の画面の保守が中心だった
  • 画面の担当のはずが、APIの修正やデザインの作成まで頼まれた
  • 移行の案件で、どこまで終われば完了かが決まっておらず、作業が延び続けた
  • デザインが固まっておらず、作り直しが続いた

こうしたずれは、面談と条件の確認の段階で、聞き方を工夫すれば多くを防げます。

契約前に確かめたい7つの点

1. 版と書き方、構成

最初に確かめたいのは、今のコードの姿です。

  • Vue.jsとNuxtの版。Vue 2の画面が残っているか
  • Options APIとComposition APIの割合、TypeScriptを使っているか
  • 状態管理（PiniaかVuexか）、UIライブラリ、ビルドの道具
  • 組み合わせるバックエンド（Laravel、Railsなど）

Vue 2は2023年12月31日にEOLを迎え、セキュリティの修正も含めて更新されていません。Nuxt 3についても、Nuxtの公式ブログでは保守の更新は2026年1月末までと案内されています（いずれも2026年10月時点の公式の案内による）。古い版が残る案件は、近いうちに版上げの作業が出てくる可能性があります。それ自体は悪いことではありませんが、自分が担う仕事にどう関わるかを確かめておきましょう。

2. 移行の範囲と完了の考え方

移行が含まれる案件では、範囲と終わり方を確かめます。

  • 版を上げるだけか、Composition APIへの書き換えまで含むか
  • Vuexから Piniaへの置き換え、周辺ライブラリの更新を含むか
  • テストの追加や、画面ごとの動作の確認は誰が行うか
  • どこまで終われば完了とするか、期限はあるか

「Vue 3に上げる」という目標だけが決まっている案件は、作業量の見込みが大きくぶれます。調査の期間を設けてから計画を決める進め方か、最初から期限が決まっているかでも、負担が変わります。

3. 担当範囲：画面だけか、APIまでか

画面だけを担うのか、APIやデータベースまで触れるのかを確かめます。兼任を求める案件では、どの程度のサーバー側の作業を想定しているか、レビューは誰がするかも聞いておきます。逆に、画面だけの担当でAPIの変更が必要になったとき、誰に頼めば早く進むかも大切です。

エージェントベストの見解

Vue.jsの案件をご紹介していると、参画後に「聞いていた内容と違った」となりやすいのは、Vue 2の画面がどのくらい残っているかと、画面以外の作業がどこまで含まれるかの2点です。面談では聞きにくいと感じる方もいますが、担う範囲を判断するために必要な確認として聞けば、多くの発注元は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

4. 仕様とデザインの決まり方

  • デザイナーがいるか。デザインのデータはどこまで決まっているか
  • 読み込み中やエラーなど、状態ごとの見た目は誰が決めるか
  • 仕様を決めるのは誰で、変更はどう伝わるか

デザインや仕様が固まらないまま実装が始まる案件では、作り直しが増えます。変更を受けたときの扱いと、それが稼働にどう反映されるかを先に確かめておくと安心です。

5. 品質の体制

テスト、型チェック、レビュー、CIがどこまで整っているかを確かめます。仕組みが整っていない案件は、自分で整える余地がある一方で、不具合の確認に時間がかかりやすくなります。どちらの状態かを知ったうえで受けることが大切です。レビューの担当者がいるか、レビューの待ち時間はどのくらいかも、進めやすさを左右します。

6. 契約の形と、負う責任の範囲

フリーランスのVue.jsエンジニアは、多くの場合、準委任契約で参画します。準委任では、完成そのものではなく、専門家として通常求められる注意を払って業務を行うことが約束の中身になります。一方、画面の一式を納める請負の形の場合は、完成に対する責任を負います。

  • 契約書が「◯◯画面を完成させる」のように完成を約束する書き方になっていないか
  • 成果物の納品が求められる場合、その範囲と検収の方法は何か
  • 不具合の修正の扱いと、その期間

役割と契約の形が合っているかを確かめましょう。違いは準委任契約と請負契約の違いで解説しています。準委任なのに、発注元の社員から細かな作業の指示や勤務時間の管理を受ける働き方は、偽装請負の問題につながるおそれがあります。詳しくは偽装請負の記事をご覧ください。

7. 稼働の振れ幅と契約期間

  • リリース前や障害のときに、夜間や休日の対応があるか
  • 精算幅を超えたときの扱いと、稼働が少ない月の扱い
  • 契約期間と、移行や大きなリリースの区切りが合っているか

移行の途中で契約の更新時期が来ると、最も大事な局面を見届けられないことがあります。フリーランス法では、6か月以上継続して業務を委託している場合に、契約を解除したり更新しなかったりするときは、少なくとも30日前までに予告することが求められています（2026年10月時点、公正取引委員会の案内による）。精算の仕組みは精算幅の記事をご覧ください。

注意

Vue.jsの案件では、参画後に担当範囲が少しずつ広がりやすい傾向があります。APIの修正、デザインの作成、別の画面の保守、問い合わせの一次対応など、契約の業務範囲に入っていない仕事を頼まれたときは、引き受ける前に範囲と条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容、報酬の額、支払期日などを、書面またはメールなどで明示することとされています（2026年10月時点、公正取引委員会の案内による）。明示される事項はフリーランス法で明示される取引条件をご覧ください。

Vue.jsの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、担う範囲（画面の開発、移行、APIの修正の有無など）が書かれているか
  2. 完成を約束する書き方や、検収の条件が、契約の形と合っているか
  3. 稼働の幅と、超えたときの精算方法
  4. 契約期間と更新の時期

案件票の読み方は案件情報の読み方、面談で聞いておくとよい質問はVue.jsの面談でよく聞かれる質問と答え方の逆質問の項目で紹介しています。報酬の決まり方はVue.jsの報酬の記事で解説しています。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。Vue.jsの案件で気になりやすい版の構成や移行の範囲、画面以外の作業の有無など、書面だけでは読み取りにくい点は、ご質問いただければ確認します。条件に迷う点があれば、契約の前に早めにご相談ください。

ポイント

  • Vue.js案件は、同じ募集でも版と構成、新規か移行か、担当範囲で負担が大きく変わる
  • 版と書き方、移行の範囲と完了、担当範囲、仕様とデザインの決まり方、品質の体制を面談で確かめる
  • 契約の形と責任、稼働の振れ幅と契約期間を確かめる
  • 聞いた内容を、フリーランス法で明示される書面と照らし合わせる

よくある質問

Vue 2の保守の案件は避けたほうがよいですか？

避ける必要はありません。古いコードを読み、少しずつ直していける経験は、移行の案件で評価されやすい経験です。ただし、移行の予定があるか、自分がそこに関わるかを確かめ、保守だけが長く続く場合の経験の広げ方も考えておくとよいでしょう。

案件票に版が書かれていないときは、どう確かめればよいですか？

面談や事前の確認で、Vue.jsとNuxtの版、書き方、状態管理を聞くのが確実です。「参画後すぐに書き方を合わせたいので」と目的を添えると、相手も答えやすくなります。

報酬の高い兼任の案件と、画面だけの案件で迷ったらどうしますか？

一概には言えませんが、兼任の案件は担う範囲が広い分、稼働が増えて時間あたりの報酬が下がることがあります。報酬の額だけでなく、担当範囲、稼働の見込み、自分が伸ばしたい方向を合わせて比べるとよいでしょう。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 業務委託契約の基礎

偽装請負とは｜指揮命令の線引きとフリーランスが注意すること

偽装請負は、請負や準委任の契約なのに、実態として発注者が働き手に直接指揮命令している状態です。判断は契約の名前ではなく実態で行われます。フリーランスは「労働者性」の基準と、参画前に確かめたい点を押さえておきましょう。

 スキルシート・面談

業務委託の面談で聞いておくべき逆質問｜参画後のずれを防ぐ確認項目

業務委託の面談の逆質問は、印象づくりより「参画後のずれを防ぐ確認」に使うのが基本です。業務の範囲、体制と指示の流れ、稼働の実態、期間の見込みの4つを確かめておくと、契約後の「話が違う」を減らせます。
