C#エンジニアのフリーランス案件の選び方｜契約前に確かめたい8つの点

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい8つの点

  4. よくある質問

C#エンジニアのフリーランス案件を選ぶときは、報酬や稼働日数に加えて、領域と局面、.NETの版と移行の予定、工程と成果物、開発環境、現地作業、商流と指示を出す人、契約の形、稼働の振れ幅と契約期間の8点を契約前に確かめておくことが大切です。C#の案件は、案件票の言葉が同じでも、この8点の違いで毎日の仕事も負担も大きく変わります。

特に見落としやすいのは、.NETの版と、開発環境に入る方法です。どちらも案件票に書かれていないことが多く、参画してから「思っていた技術と違った」「作業の環境が想定と違った」となりやすい点です。契約書全般の確認点は業務委託契約書のチェックポイントで解説しています。

C#の案件選びで差が出る理由

C#は、Webのシステム、Windowsの業務アプリ、装置とつながるアプリ、クラウドのサービスと、使われる場所の幅が広い言語です。そのため「C#エンジニア募集」の一行から読み取れることが少なく、よくあるずれは次のようなものです。

  • 新しい.NETでの開発と聞いていたが、実際は.NET Frameworkの保守が中心だった
  • 新規開発のつもりが、問い合わせの対応と古いコードの調査に多くの時間を使う
  • リモートと聞いていたが、リモートデスクトップの環境が遅く、出社のほうが作業が進む
  • 試験の時期に、想定より多くの現地作業と夜間の作業が入った

こうしたずれは、面談と条件の確認の段階で、聞き方を工夫すれば多くを防げます。案件票の読み方は案件情報の読み方の記事も参考にしてください。

契約前に確かめたい8つの点

1. 領域と局面

最初に確かめたいのは、業務Web、Windowsの業務アプリ、移行、製造・制御系、Azureでのサービス開発のどれか、そして新規開発か、保守か、移行かです。同じ保守でも、改修の依頼を受けて進める仕事と、利用部門の問い合わせに日々答える仕事では、時間の使い方が違います。

面談では「参画後の最初の1か月で、最も多く時間を使う仕事は何か」を聞くと、局面が見えやすくなります。新規と保守の割合も、あわせて聞いておきましょう。

2. .NETの版と、移行の予定

対象のシステムが.NET Frameworkか、新しい.NETか、どの版かを確かめます。あわせて、版上げや移行の予定があるかも聞いておきます。

  • .NET Frameworkの保守なら、今後の移行の計画に自分が関わる可能性があるか
  • 新しい.NETなら、サポートの期限に合わせた版上げを誰が担うか
  • 移行の案件なら、調査から関わるのか、方針が決まった後の書き換えから関わるのか

版と移行の予定は、参画中の仕事の中身だけでなく、その後の経歴の書き方にも関わります。版ごとのサポートの考え方はC#エンジニアの将来性で整理しています。

3. 担当する工程と成果物

設計書を書くのか、実装とテストが中心か、リリースまで担うのかを確かめます。受託の業務Webでは、発注元ごとに決まった型の設計書やテスト仕様書が求められることが多く、その作成にかかる時間は小さくありません。何を成果物として出すのかを、工程ごとに聞いておきましょう。

エージェントベストの見解

C#の案件をご紹介していると、参画後に「聞いていた内容と違った」となりやすいのは、.NETの版と、新規と保守の割合の2点です。面談で聞きにくいと感じる方もいますが、立ち上がりの準備に必要な確認として聞けば、多くの発注元は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

4. 開発環境と、そこに入る方法

C#の案件で特に差が出るのが開発環境です。

  • 貸与の端末か、自分の端末か。自分の端末ならWindowsの環境が必要か
  • 社内の環境にリモートデスクトップで入るのか、手元で開発できるのか
  • Visual Studioなどの開発ツールのライセンスをどちらが用意するか
  • ソースコードの管理とレビューの仕組みは何を使っているか

リモートデスクトップ越しの開発は、通信の状態によって作業の速さが大きく変わります。リモートで働けるかの見分け方はC#のリモート案件の記事で詳しく解説しています。

5. 現地作業と、作業の時間帯

製造・制御系や、利用者のそばで導入する業務アプリでは、現地作業が入ります。確かめたいのは次の点です。

  • 現地作業が入る時期と、おおよその回数
  • 現地までの移動にかかる時間と交通費の扱い
  • 設備の停止に合わせた夜間・休日の作業があるか

現地作業の負担は、報酬の比べ方にも関わります。考え方はC#の報酬の記事で触れています。

6. 商流と、指示を出す人

発注元に直接参画するのか、元請けの会社を通して参画するのかを確かめます。間に入る会社が多いほど、仕様の確認に時間がかかったり、誰に聞けばよいかが分かりにくくなったりします。

あわせて、日々の作業の進め方を誰と相談するのかも確かめます。準委任の契約なのに、発注元や元請けの社員から細かな作業の指示や勤務時間の管理を受ける働き方は、偽装請負の問題につながるおそれがあります。詳しくは偽装請負の記事をご覧ください。

7. 契約の形と、負う責任の範囲

フリーランスのC#エンジニアは、多くの場合、準委任契約で参画します。一方、移行や改修を「動くものの完成」で約束する請負の形になっている案件もあります。古いシステムは仕様書が残っていないことが多く、請負で想定外の作業が増えても報酬が変わらないと、負担が大きくなります。

  • 契約が準委任か請負か。請負なら、完成の基準と検収の条件は何か
  • 移行の案件で、新旧の動きの違いが見つかったときの扱い
  • 不具合の修正を、いつまで、どの範囲で求められるか

違いは準委任契約と請負契約の違いで解説しています。

8. 稼働の振れ幅と、契約期間

稼働の幅と、超えたときの精算方法を確かめます。C#の案件では、リリースの前、試験の時期、障害の対応で稼働が増えやすくなります。精算の仕組みは精算幅の記事をご覧ください。

契約期間と工程の区切りが合っているかも見ておきます。移行の切り替えの直前に契約の更新時期が来ると、最も大事な局面を見届けられないことがあります。フリーランス法では、6か月以上継続して業務を委託している場合に、契約を途中で解除したり更新しなかったりするときは、少なくとも30日前までに予告することが求められています（2026年10月時点、公正取引委員会の案内による）。

注意

保守の案件では、「ついでにこの画面も」「別のシステムの調査も」と、契約の業務範囲に入っていない依頼が少しずつ増えることがあります。引き受ける前に、契約の範囲に入るかを確かめ、外れる場合は条件の見直しを相談しましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容、報酬の額、支払期日などの取引条件を、書面またはメールなどの方法で明示することとされています（2026年10月時点、公正取引委員会の案内による）。明示される事項はフリーランス法で明示される取引条件をご覧ください。

C#の案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、対象のシステムと担う工程（設計、実装、テスト、リリース、問い合わせの対応など）が書かれているか
  2. 作業の場所に、現地作業の可能性が書かれているか
  3. 請負の場合、完成の基準と検収の条件が書かれているか
  4. 稼働の幅と、超えたときの精算方法
  5. 契約期間と更新の時期

面談で聞いておくとよい質問はC#エンジニアの面談でよく聞かれる質問と答え方の逆質問の項目でも紹介しています。一般的な逆質問は面談で聞いておくべき逆質問をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。C#の案件で気になりやすい.NETの版、開発環境に入る方法、現地作業の頻度など、案件票だけでは読み取りにくい点は、ご質問いただければ確認します。

ポイント

  • C#の案件は、同じ「C#開発」でも領域・版・局面・開発環境で負担が大きく変わる
  • 領域と局面、.NETの版と移行の予定、工程と成果物、開発環境を面談で確かめる
  • 現地作業の時期と時間帯、商流と指示を出す人、準委任か請負かを確かめる
  • 稼働の振れ幅と精算、契約期間と工程の区切りを書面と照らし合わせる

よくある質問

.NET Frameworkの保守の案件は避けたほうがよいですか？

避ける必要はありません。古いコードを読み解き、利用部門とやり取りして改修した経験は、移行の案件で頼りにされます。ただし、同じ版の保守だけが長く続くと選べる案件が狭まることがあるため、移行の予定に関われるかや、新しい.NETに触れる機会があるかもあわせて確かめておくとよいでしょう。

報酬の高い案件と、新しい.NETに触れられる案件で迷ったらどうしますか？

一概には言えませんが、現地作業や夜間の作業が多い案件は、時間あたりで比べると差が小さくなることがあります。報酬の額だけでなく、稼働の見込み、働く場所、次の案件で書ける経験を合わせて比べるとよいでしょう。

面談で.NETの版や商流を聞くのは失礼ですか？

参画の準備と、自分が担える範囲を判断するための確認として聞けば、失礼にはあたりません。答えられない場合もあるので、その場合は無理に聞き出さず、契約の前に書面や案件の担当者を通して確かめましょう。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

偽装請負とは｜指揮命令の線引きとフリーランスが注意すること

偽装請負は、請負や準委任の契約なのに、実態として発注者が働き手に直接指揮命令している状態です。判断は契約の名前ではなく実態で行われます。フリーランスは「労働者性」の基準と、参画前に確かめたい点を押さえておきましょう。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 単価・報酬交渉

精算幅（140〜180時間など）とは｜超過・控除の計算方法

精算幅は、月額報酬のままでよい稼働時間の範囲です。上限を超えると超過分が加算され、下限を下回ると控除されます。超過・控除の単価は上下割か中間割かで変わるため、仮の数字を使って計算方法を整理します。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。
