フロントエンド開発

Reactエンジニアのフリーランス案件の選び方｜契約前に確かめたい7つの点

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい7つの点
  3. 案件票の書き方から読み取れること
  4. 確かめた内容を書面と照らし合わせる
  5. よくある質問

Reactエンジニアの案件選びで確かめたいのは、役割の実態、使っている構成と版、コードとテストの状態、仕様を決める人、業務の範囲と責任、稼働と精算、契約期間の7点です。Reactの案件は、案件票に並ぶ技術の名前が同じでも、担う範囲やコードの状態で毎日の負担が大きく変わります。

この記事では、Reactの案件で選び方の差が出る理由と、7つの点を契約前にどう確かめるか、確かめた内容を書面とどう照らし合わせるかを整理します。契約全般の確認点は業務委託契約で確認すべきポイントで解説しているので、ここではReactの案件に固有の点に絞ります。

Reactの案件で選び方の差が出る理由

案件票には「React・TypeScript・Next.js」のように技術の名前が並ぶことが多く、それだけでは中身の違いが見えません。差が出るのは主に次の点です。

  • 担う範囲：決まった画面の実装か、共通部品や設計まで決めるか、チームのレビューまで持つか
  • コードの状態：新しく作るのか、長く使われてきたコードを直しながら進めるのか
  • 仕様の決まり方：仕様書があるのか、実装しながら決めていくのか

参画してから「聞いていた内容と違う」と感じる理由の多くは、この3つのずれです。報酬も担う範囲で変わるため、範囲の確認は条件の交渉にもつながります。報酬の決まり方はReactの報酬の記事で解説しています。

契約前に確かめたい7つの点

1. 役割の実態は実装か、設計か、リードか

募集の名前が「フロントエンドエンジニア」でも、実際の役割は現場で違います。次のように聞くと実態がつかめます。

  • 最初に担当する画面や機能は何か
  • 共通部品や状態管理の方針は誰が決めるか
  • 自分がレビューをする側にも入るか

役割ごとの働き方の違いはReactの案件の仕事内容で整理しています。

2. 使っている構成と版

Reactの版、TypeScriptの有無と型の厳しさ、Next.jsなどのフレームワーク、状態管理やスタイルの書き方を確かめます。今の構成と、版上げの予定の両方を聞いておくと、参画後に移行の作業がどのくらい入るかの見通しが立ちます。自分の経験と離れた構成の場合は、立ち上がりの期間をどう見てもらえるかも確かめておきましょう。

3. コードとテストの状態

新規の開発か、既存のコードの改修かで、仕事の中身は大きく変わります。既存のコードなら、テストがどの程度あるか、古い書き方の部分がどのくらい残っているか、レビューの仕組みがあるかを聞きます。テストが少ないコードの改修は、確かめる作業に時間がかかるため、見積もりの前提に入れておく必要があります。

エージェントベストの見解

Reactの案件をご紹介していると、参画後のずれで多いのは、新規の開発と聞いていたのに既存のコードの改修が中心だった、あるいはその逆、という食い違いです。面談の場で「最初の1か月で触るコードは新しいものか、既存のものか」を聞いておくと、ずれを防ぎやすくなります。案件票に書かれていない点は、ご質問いただければ確認します。

4. 仕様を決める人と、デザインの受け渡し

仕様を誰が決め、デザインをどんな形で受け取るかを確かめます。デザイナーがいるか、デザインのデータに画面の状態（読み込み中・エラー・データが空のとき）まで描かれているか、決まっていない点を誰に聞けばよいか。仕様を決める人がはっきりしない現場では、判断を求められる場面が増え、作業量が読みにくくなります。

5. 契約の形と、負う責任の範囲

業務委託には、作業そのものを引き受ける準委任と、成果物の完成を約束する請負があります。Reactの案件で請負の形をとる場合は、何をもって完成とするか、不具合が見つかったときにいつまで直す責任を負うかを確かめます。違いは準委任と請負の違いで解説しています。

あわせて、バックエンドやインフラの作業が範囲に入るかも確かめます。Next.jsのようにサーバー側の処理まで同じコードで扱う構成では、範囲があいまいなまま作業が広がりやすくなります。広がったときの扱いは作業範囲が広がったときの契約の扱いをご覧ください。

6. 稼働の振れ幅と精算

月の稼働時間の幅と、幅を超えたときや下回ったときの精算の方法を確かめます。リリースの前に稼働が増えやすいか、夜間や休日の対応があるかも聞いておきましょう。精算の仕組みは精算幅の記事で解説しています。

7. 契約期間と、更新の見通し

最初の契約期間と、更新を判断する時期を確かめます。開発の区切り（リリース、移行の完了）と契約期間がどう対応しているか、区切りの後に保守や次の開発が続く予定があるかを聞くと、見通しを立てやすくなります。

注意

面談で「指示は現場のリーダーから直接受けて、始業と終業の時刻も決まっている」といった話が出た場合は注意が必要です。業務委託でありながら、働く時間や作業の進め方を細かく指示される状態は、偽装請負にあたるおそれがあります。気になる点があれば、契約の前に確かめましょう。考え方は偽装請負の記事で解説しています。

案件票の書き方から読み取れること

案件票の言葉にも、確かめるべき点の手がかりがあります。次のような書き方を見かけたら、面談で中身を聞いておきましょう。

  • 「フロントエンド全般」「幅広くお任せ」：範囲が決まっていない可能性がある。最初の担当と、範囲を決める人を聞く
  • 「スピード感のある開発」：仕様が実装の途中で変わりやすい可能性がある。仕様を決める人と、変更の受け方を聞く
  • 「リプレイス」「モダン化」：既存のコードの読み込みと段階的な置き換えが中心になりやすい。テストの状態と移行の順番を聞く
  • 「Next.js歓迎」：サーバー側の処理まで範囲に入るかどうかで仕事が変わる。データの取得と配信の担当を聞く

どれも悪い案件という意味ではありません。書き方の裏にある働き方を確かめ、自分の希望と合うかで判断することが大切です。

確かめた内容を書面と照らし合わせる

面談や事前の説明で確かめた内容は、契約の書面と照らし合わせます。公正取引委員会のフリーランス法の特設サイトでは、発注事業者が明示すべき取引条件として、給付の内容、報酬の額、支払期日、業務委託をした日、役務の提供を受ける日や場所などが挙げられています。明示は書面か、電子メールなどの電磁的方法で行うこととされ、口頭は認められていません。項目の詳しい読み方はフリーランス法で明示される取引条件で解説しています。

Reactの案件で特に照らし合わせたいのは次の点です。

面談で確かめたこと書面で見る箇所
担当する画面や機能、レビューの有無業務の内容（給付の内容）
バックエンドやインフラの作業の有無業務の範囲、除外される作業
稼働時間の幅と精算の方法報酬の額と精算の条件
作業の場所、リモートの可否役務の提供を受ける場所
契約期間と更新の時期契約期間、更新の条件

面談で聞いた内容と書面が合わないときは、署名の前に確かめます。口頭で「範囲は柔軟に」と言われた点ほど、書面に何が書かれているかを見ておくことが大切です。面談で何を聞くかはReactの面談の記事と業務委託の面談で聞いておくべき逆質問が参考になります。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。Reactの案件は、構成やコードの状態で負担が変わるため、案件票と個別契約の内容を照らし合わせ、気になる点は署名の前にご質問いただくことをおすすめします。

ポイント

  • Reactの案件は、技術の名前が同じでも、担う範囲・コードの状態・仕様の決まり方で負担が変わる
  • 役割、構成と版、コードとテスト、仕様を決める人、範囲と責任、稼働と精算、契約期間の7点を確かめる
  • バックエンドやインフラの作業が範囲に入るかは、Next.jsの案件では特に確かめる
  • 確かめた内容は書面と照らし合わせ、合わない点は署名の前に確かめる

よくある質問

古い書き方のコードが多い案件は避けたほうがよいですか？

一概に避ける必要はありません。既存のコードを少しずつ新しい形に置き換える経験は、刷新や版上げの案件で評価されることがあります。ただ、テストが少ないと確かめる作業に時間がかかるため、作業量の見積もりと稼働の条件が合っているかを確かめてから判断しましょう。

報酬の高い案件と、構成が自分に合う案件で迷ったらどうしますか？

報酬だけで選ぶと、立ち上がりに時間がかかり、評価を得るまでの負担が大きくなることがあります。構成が近い案件で成果を出し、次の更新や次の案件で条件を上げるという考え方もあります。どちらを選ぶ場合も、担う範囲と報酬が釣り合っているかを確かめることが大切です。

Next.jsの案件を選ぶときに、Reactだけの案件と違って確かめることはありますか？

サーバー側の処理やデータの取得、配信の設定まで範囲に入るかを確かめます。サーバー側の不具合の対応を誰が担うかもあわせて聞いておきましょう。詳しくはNext.jsの案件の選び方で解説しています。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 業務委託契約の基礎

偽装請負とは｜指揮命令の線引きとフリーランスが注意すること

偽装請負は、請負や準委任の契約なのに、実態として発注者が働き手に直接指揮命令している状態です。判断は契約の名前ではなく実態で行われます。フリーランスは「労働者性」の基準と、参画前に確かめたい点を押さえておきましょう。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 スキルシート・面談

業務委託の面談で聞いておくべき逆質問｜参画後のずれを防ぐ確認項目

業務委託の面談の逆質問は、印象づくりより「参画後のずれを防ぐ確認」に使うのが基本です。業務の範囲、体制と指示の流れ、稼働の実態、期間の見込みの4つを確かめておくと、契約後の「話が違う」を減らせます。
