ノーコード・ローコード開発者のフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい7つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

ノーコード・ローコード開発者のフリーランス案件を選ぶときは、報酬や稼働日数に加えて、担う工程、既にある環境の状態、拡張の量、ツールの費用と契約の名義、契約の形と完成の定義、依頼の受け付け方、引き継ぎの範囲を契約の前に確かめることが大切です。同じ「業務アプリの開発」という募集でも、この7点の違いで、参画後の負担と、終わったあとに残る実績が大きく変わります。

この記事では、この職種で案件選びの差が出る理由と、契約の前に確かめたい7つの点、確かめた内容を書面とどう照らし合わせるかを解説します。契約全般の確認点は業務委託契約で確認することにまとめています。

案件選びで差が出る理由

ノーコード・ローコードの案件は、募集の名前と実際の仕事がずれやすい分野です。理由は主に3つあります。

  • 作るのが速いため、範囲が広がりやすい：試作を見せるたびに要望が増え、契約した範囲の外の作業が少しずつ積み上がる
  • 既にある環境の状態が見えにくい：社内でアプリが増えた会社では、新しく作る前に、重なったアプリや権限の整理が必要になることがある
  • 費用と名義が後回しになりやすい：プラグインや連携サービスの契約が、作り手の個人のアカウントに依存してしまうことがある

どれも、案件票だけでは分からないことが多く、面談や契約の前の確認で差がつきます。

案件票から読み取れることと、読み取りにくいことを分けておくと、面談で何を聞けばよいかが決まります。

案件票から読み取りやすいこと案件票から読み取りにくいこと
使うツールの名前、稼働日数、リモートの可否既にあるアプリの数と、整理の要否
募集の名前（構築、改修、内製化支援など）業務部門との打ち合わせの頻度と相手
必須・歓迎のスキル拡張の量と、契約後の保守の担い手
契約期間の目安ツールの費用の負担と契約の名義

右の列は、面談の逆質問や、事前のやり取りで確かめる項目です。逆質問の組み立て方は逆質問の記事、ノーコード・ローコードの面談の準備は面談の記事をご覧ください。

契約前に確かめたい7つの点

1. 担う工程はどこからどこまでか

業務の聞き取りと設計から任されるのか、決まった仕様で構築するのか、利用者への説明や運用の支援まで含むのかを確かめます。「構築」として募集されていても、実際には業務部門との打ち合わせが多い案件もあります。逆に「業務改善の支援」として募集されていても、構築だけを求められることもあります。打ち合わせの相手と頻度を聞くと、実態がつかみやすくなります。

2. 既にある環境の状態

既にツールを使っている会社なら、アプリの数、利用者の数、誰が作ってきたか、作成や変更のルールと管理者が決まっているかを聞きます。整理されていない環境では、新しく作る前の調べ物と整理に想像以上の時間がかかります。その時間が見積もりや稼働の想定に入っているかも確かめましょう。

3. 拡張と連携の量

標準の機能で組む想定か、JavaScript や API による拡張、基幹システムや会計などとの連携があるかを確かめます。拡張が多いほど、ツールの更新で動かなくなったときの対応や、障害時の切り分けの責任が重くなります。拡張の部分を誰が保守するのか、契約が終わったあとも問い合わせが来る前提になっていないかも聞いておきます。

エージェントベストの見解

ノーコード・ローコードの案件をご紹介していると、参画後に負担が大きくなりやすいのは、既にある環境の状態を確かめずに「新規の構築」として受けたケースです。面談の段階で、今あるアプリの数と、作成や変更のルールの有無を聞いておくと、整理にかかる時間を見込みやすくなります。こうした質問は、発注側にも準備のよい人として受け止められやすい傾向があります。

4. ツールの費用と契約の名義

ツールのライセンス、プラグイン、連携サービスの費用を誰が負担するか、契約の名義が発注側になっているかを確かめます。作り手のアカウントで契約したサービスに業務が依存すると、契約が終わったときに引き継げなくなります。作業に使うアカウントを誰が用意し、どこまでの権限が与えられるかもあわせて聞きます。

5. 契約の形と、完成の定義

この分野の案件には、アプリを作って納める請負の形と、稼働時間に応じて報酬が決まる準委任の形があります。

  • 請負の場合：何をもって完成とするか、検査の方法と期間、納めたあとの修正をどこまで受けるか。納めたものに問題があったときの責任の考え方は契約不適合責任の記事で解説しています
  • 準委任の場合：月の稼働時間の幅と、超えたときや足りないときの扱い。仕組みは精算幅の記事をご覧ください

どちらの形か分からないまま進めると、修正の依頼が続いても報酬が変わらない、といった行き違いが起きます。違いは準委任契約と請負契約の違いで整理しています。

6. 依頼の受け付け方と、範囲の外の依頼の扱い

改修や追加の依頼を、チケット、チャット、口頭のどれで受けるのか、優先順位を誰が決めるのかを確かめます。契約の範囲を超える依頼が来たときに、誰と条件を相談するのかも聞いておくと、範囲が広がったときに慌てずに済みます。考え方は作業範囲が広がったときの契約の扱いをご覧ください。

7. 引き継ぎの範囲と、作ったものの扱い

契約が終わったあと、社内の誰が保守を担うのか、設計の記録や手順書を成果物に含めるのかを確かめます。引き継ぎの資料づくりが作業の範囲に入っていないと、最後に時間が足りなくなります。あわせて、作ったアプリや拡張のコードの権利をどう扱うかも確かめておきましょう。考え方は成果物の著作権の記事で解説しています。

顧客や従業員の個人情報を含むデータを扱う場合は、本番のデータを触るか、手元に保存してよいかなど、取り扱いの条件も確かめます。業務で個人情報を扱うときの契約と注意点もご覧ください。

注意

「ノーコードだからすぐできる」という前提で、短い期間や少ない稼働の見積もりが先に決まっている案件があります。業務の聞き取りや既存の環境の整理、利用者への展開の時間が入っていないと、参画後に稼働が膨らみます。期間と稼働の想定が、どの工程を含んだものかを契約の前に確かめましょう。

確かめた内容を書面と照らし合わせる

面談や事前のやり取りで確かめた内容は、契約の書面と照らし合わせます。フリーランス法では、発注側は業務を委託したときに、給付の内容、報酬の額、支払期日などの取引条件を、書面またはメールなどの電磁的な方法で直ちに明示する必要があり、口頭での明示は認められていません（2026年10月時点、公正取引委員会の案内による）。明示される事項の詳しい中身はフリーランス法で明示される取引条件で解説しています。

照らし合わせるときは、次の表のように、確かめたことが書面のどこに書かれているかを一つずつ見ます。

確かめたこと書面で見る場所の例
担う工程、作るアプリの範囲業務の内容（給付の内容）
請負か準委任か、完成の定義契約の形、検査の方法と期日
稼働時間の幅と精算報酬の額と計算の方法
ツールの費用の負担費用の負担に関する条項
引き継ぎの資料、権利の扱い成果物、知的財産権に関する条項
個人情報の扱い秘密保持、個人情報の取り扱いの条項

口頭で「大丈夫です」と言われたことが書面にない場合は、書面に入れてもらうか、メールで確認の記録を残しておくと安心です。書面の解釈や、個別の契約の判断に迷う場合は、専門家にご相談ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。案件をご案内するときは、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをお出ししています。担う工程、ツールの費用の負担、既にある環境の状態など、案件票だけでは分からない点は、ご質問いただければ確認します。

ポイント

  • ノーコード・ローコードの案件は、作るのが速いぶん範囲が広がりやすく、既存の環境の状態も見えにくい
  • 担う工程、既存の環境、拡張の量、費用と名義、契約の形、依頼の受け付け方、引き継ぎの7点を確かめる
  • 確かめた内容は、明示された取引条件や契約の書面と一つずつ照らし合わせる
  • 口頭の約束は、書面かメールの記録に残す

よくある質問

報酬の高い案件と、担う工程のはっきりした案件で迷ったらどうしますか？

報酬だけで選ぶと、範囲の広がりや整理の手間で、時間あたりの負担が想定より重くなることがあります。担う工程がはっきりした案件は、設計や定着までやり切った実績として残しやすい面もあります。稼働の想定と、終わったあとに話せる実績の両方で比べることをおすすめします。

面談で、ツールの費用や名義を聞くのは失礼になりませんか？

失礼にはなりません。費用と名義は、契約が終わったあとの引き継ぎに関わる大事な点で、発注側にとっても決めておくべきことです。「引き継ぎのときに困らないよう確かめたい」と理由を添えて聞くと、受け止められやすくなります。

独立して最初の案件は、どの種類を選ぶのがよいですか？

これまで扱ったツールの種類と、近い業務の案件を選ぶと立ち上がりで苦労しにくくなります。既にある環境の整理を含む案件より、範囲のはっきりした構築や改修の案件から始めるのも一つの方法です。考え方は独立後の最初の案件の選び方で解説しています。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

契約不適合責任とは｜請負で負う責任の範囲と期間、契約書での決め方

契約不適合責任は、請負で引き渡した成果物が種類・品質・数量で契約内容に合わないときに負う責任です。注文者は修補・減額・損害賠償・解除を求められ、民法では不適合を知ってから1年以内の通知が必要です。契約で変わる範囲と期間を整理します。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 単価・報酬交渉

精算幅（140〜180時間など）とは｜超過・控除の計算方法

精算幅は、月額報酬のままでよい稼働時間の範囲です。上限を超えると超過分が加算され、下限を下回ると控除されます。超過・控除の単価は上下割か中間割かで変わるため、仮の数字を使って計算方法を整理します。
