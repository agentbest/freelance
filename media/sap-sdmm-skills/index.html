SAP・ERP

SAP SD/MMコンサルのフリーランス案件で求められるスキルと経験

SAP SD/MMのフリーランス案件では、価格決定、与信、在庫の確認、購買の承認、請求書照合といった機能の設定を自分で組んだ経験と、不具合が起きたときに伝票とマスタから原因を追える力が見られます。業務の流れを知っていることは前提で、そのうえで「どの設定を、なぜそう組んだか」を説明できるかが、任される範囲を分けます。

この記事では、SDとMMで案件によく出る機能ごとに、問われやすい設定と論点を整理し、認定資格の位置づけと経験の示し方を解説します。業務の流れに沿った経験の棚卸しや独立の手順はSAP SD/MMコンサルがフリーランスになるにはで扱っています。

SDで深さを問われやすい機能

SDは、受注から出荷、請求までを扱うモジュールです。案件の面談では、次の機能について、設定をどこまで自分で組んだかを聞かれることが多くあります。

機能問われやすい設定・論点説明できると強いこと
価格決定条件タイプ、アクセス順序、価格決定表の組み立て得意先別・品目別の値引きを、どの順番で判定させたか
与信管理与信限度の確認の方法、超過時の止め方止めた受注を誰がどう解除する運用にしたか
在庫の確認受注時に引き当てる在庫の範囲と考え方納期回答の考え方と、足りないときの扱い
出荷出荷ポイントの決め方、ピッキング・出庫の流れ分納や直送をどう組んだか
請求請求の伝票タイプ、請求のまとめ方と分け方締め日でまとめる請求をどう実現したか
返品・訂正返品、赤伝・黒伝、値引きの後付け会計への影響を含めて流れを説明できるか
出力納品書・請求書などの帳票の出し分け取引先ごとの帳票や送付方法の違いの扱い

価格決定は「なぜその順番か」まで話す

SDの面談で特によく問われるのが価格決定です。条件タイプを並べた手順の中で、どの価格を優先するか、値引きを積み上げるのか上書きするのか、端数をどう扱うかは、取引先との契約や商習慣によって変わります。設定の名前を言えることより、「得意先ごとの特別価格を先に探し、なければ標準価格を使う」のように、判定の順番とその理由を業務の言葉で説明できることが評価されます。

請求は会計とのつなぎ目

請求の処理は、売上の仕訳を作る起点です。どの売上の勘定に計上されるか、値引きや運賃がどこに入るかは、FI/COの担当と一緒に決める論点です。会計側の設定は担当外でも、SDの請求から会計伝票までの流れを追えると、統合テストで頼られます。会計側のスキルはSAP FI/COコンサルのスキルで扱っています。

MMで深さを問われやすい機能

MMは、購買と在庫を扱うモジュールです。製造業・流通業の案件で、次の機能の経験がよく見られます。

機能問われやすい設定・論点説明できると強いこと
購買の基礎データ購買情報レコード、供給元の一覧、契約同じ品目を複数の仕入先から買うときの決め方
発注の承認承認の段階と条件（金額・品目グループなど）社内の権限規程をどう設定に写したか
在庫の管理移動タイプ、入庫・出庫・振替、棚卸独自の移動タイプを作った理由と影響の範囲
在庫の評価移動平均か標準原価か、評価の単位原価計算の担当とどう決めたか
請求書照合発注・入庫・請求の三者の照合、差異の許容範囲差異が出たときの保留と解除の運用
所要量の計算発注点、所要量計算の結果から発注への流れ計画の担当者が結果をどう使っていたか
特殊な調達外注、委託在庫、直送、会社間の取引通常の購買と何が違い、どこでつまずいたか

請求書照合は差異の扱いで差がつく

MMの面談で深く聞かれやすいのが請求書照合です。発注の数量・単価、入庫の数量、仕入先の請求の三つがそろわないことは日常的に起こります。どこまでの差異なら自動で通し、どこから止めるのか、止めた請求書を誰が確認して解除するのかを、購買部門と経理部門の両方の事情を踏まえて決めた経験は、具体的に話す価値があります。

在庫の評価は会計とのつなぎ目

在庫の評価方法は、入庫や出庫のたびに作られる仕訳の金額を左右します。移動平均と標準原価のどちらを使うか、評価の単位をプラントにするかなどは、原価計算の考え方と一緒に決まります。MMの立場から、どの取引でどの勘定が動くかを説明できると、FI/COの担当との会話がかみ合います。

エージェントベストの見解

SD/MMの案件紹介の現場では、面談で「その不具合を、どこから調べて原因にたどり着いたか」と問われる場面をよく見ます。評価されやすいのは、伝票の流れをさかのぼり、マスタの値と設定の条件を一つずつ確かめた手順を順に話せる方です。設定を担当した経験があっても、原因の調べ方を説明できないと、保守や統合テストの局面で任せられるかが伝わりにくくなります。

SDとMMをまたぐ力

SDとMMは在庫を通じてつながっています。受注で在庫を引き当て、足りなければ購買や生産で補い、出荷で在庫が減ります。両方の担当が分かれているプロジェクトでも、次のような論点はまたいで話せることが求められます。

  • 会社間の取引：グループ会社の間で販売と購買が対になる取引。片方の受注が、もう片方の発注になる
  • 直送：仕入先から得意先へ直接届ける取引。発注、入庫の扱い、請求のタイミングをそろえる必要がある
  • 在庫の移動：プラントや倉庫の間の移動。出荷の仕組みを使うかどうかで手順が変わる
  • 返品：得意先からの返品を、仕入先への返品や廃棄までつなげる

どちらか一方が専門の場合も、こうした取引でもう一方の伝票がどう動くかを説明できると、チームの中での役割が広がります。

設定の外で求められる技術的なスキル

SD/MMのコンサルタントは、プログラムを書くことは少なくても、次のような技術的なスキルが評価されます。

  1. 追加開発の仕様を書く力：標準の機能で足りない部分を、開発者が迷わない粒度で仕様書にする。入力・出力・例外の処理・テストの観点まで書けるか
  2. データを調べる力：伝票やマスタのデータを照会し、件数や値の偏りを確かめる。移行や不具合の調査の基本になる
  3. テストを設計する力：受注から請求、発注から支払までを通す統合テストのシナリオを作り、例外のパターンを漏らさない
  4. 外部とのつなぎを理解する力：EDIや倉庫管理のシステムとの間で、どの項目がどう対応しているかを読み解く

特に、追加開発の仕様書は、成果物として見せられない分、面談で「どんな項目を書いたか」を説明できるようにしておくと、設計の工程から入れる人として伝わります。

認定資格の位置づけ

SAPは、SDとMMに対応する認定資格を用意しています。2026年10月時点のSAP Learningの公式ページでは、それぞれ次のような出題範囲が示されています。

認定試験コード出題範囲（比重の大きい順）
SAP Certified - Implementation Consultant for SAP S/4HANA Cloud Private Edition, SalesC_TS462販売（31〜40%）、請求（21〜30%）、価格決定（21〜30%）、出荷（11〜20%）、ビジネスパートナー（10%以下）
SAP Certified - SAP S/4HANA Cloud Private Edition, Sourcing and ProcurementC_TS452調達から支払までの流れ（21〜30%）、特殊な調達・マスタ・供給元の決定・設定（各11〜20%）、契約・在庫管理・所要量計算（各10%以下）

いずれも、指導を受けながらプロジェクトに参加するコンサルタントを想定した資格とされており、Salesのページでは入門の位置づけと説明されています。案件では認定より実務の設定経験が重視されますが、出題範囲は自分の知識の抜けを確かめる一覧として使えます。名称や範囲は見直されることがあるため、受験の前に公式ページで最新の内容をご確認ください。

注意

SDかMMの「担当」と書くだけでは、どの機能を深く扱ったかが伝わりません。保守で問い合わせに答えていた期間と、導入で設定を組んだ期間が混ざっていると、設計から任せる案件を紹介されて、参画後に負担が大きくなることがあります。機能ごとに「設定を組んだ」「設定を直した」「使い方を知っている」を分けて書いておきましょう。

スキルシートと面談で伝えたいこと

SD/MMの経験は、機能と工程の組み合わせで書くと伝わります。プロジェクトごとに次の点をそろえておきましょう。

  • 業種と、販売・購買の形の特徴（受注生産か在庫販売か、直送や委託在庫の有無など）
  • バージョン（ECCかS/4HANAか）とプロジェクトの種類（導入、移行、保守など）
  • 担当した機能（上の表の言葉で）と、自分で設定を組んだ範囲
  • 追加開発の仕様書、統合テストのシナリオなど、自分が作った成果物の種類
  • つまずいた例外の処理と、どう解決したか

S/4HANAへの移行案件で問われる論点はS/4HANA移行のフリーランス案件で求められるスキル、書き方の詳細はSAP SD/MMのスキルシートの書き方をご覧ください。

エージェントベストの見解

当社では、先に稼働日数・リモートの希望・ご希望の金額を伺い、合う案件だけをご案内しています。ご経歴は、ご本人の了承を得た案件にだけ、氏名・連絡先を伏せて提案しています。SD/MMの案件は、同じモジュールでも求められる機能が案件ごとに違うため、上の表の機能の単位で経験を書き出しておくことをおすすめします。

ポイント

  • SDでは価格決定・与信・請求、MMでは承認・在庫の評価・請求書照合の設定の深さがよく問われる
  • 不具合を伝票とマスタから追う手順を話せると、保守やテストの局面でも任されやすい
  • 認定資格の出題範囲は、知識の抜けを確かめる一覧として使える

よくある質問

SDとMMのどちらか一方の経験だけでも案件はありますか？

あります。案件の募集は、SDまたはMMのどちらかを主に担う形のものも多くあります。そのうえで、会社間の取引や直送など、両方にまたがる取引でもう一方の伝票がどう動くかを説明できると、参画できる案件が広がります。

ABAPの知識は必要ですか？

プログラムを書くことを求める案件は多くありませんが、追加開発の仕様を書くときや、不具合の原因を調べるときに、プログラムの動きを読める知識があると役立ちます。開発者と話すときの共通の言葉として、基本的な仕組みを知っておくとよいでしょう。

認定資格を持っていれば経験が浅くても参画できますか？

認定資格だけで参画が決まることは多くありません。案件では、実際のプロジェクトで設定を組んだ経験が重視されます。資格は、学んだ範囲を示す材料として、実務の経験とあわせて伝えることが大切です。

SAP SD/MMコンサルのフリーランスはリモートで働ける？案件の傾向と探し方
