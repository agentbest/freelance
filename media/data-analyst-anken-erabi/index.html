データ・AI

データアナリストのフリーランス案件の選び方｜契約前に確かめたい7つの点

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい7つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

フリーランスのデータアナリスト案件を選ぶときは、報酬や稼働日数に加えて、依頼の来方と優先順位を決める人、データの準備状態、作業の環境と権限、データの扱いの決まり、成果物と契約の形、応答の期待と稼働の振れ幅、契約期間の区切りの7点を契約前に確かめておくことが大切です。データアナリストの案件は、募集の文面が同じ「データ分析業務」でも、この7点の違いで負担と働き方が大きく変わります。

特に見落としやすいのは、分析に入る前の段階にどれだけ時間を取られるかです。テーブルの定義書がない、権限が届かない、指標の数え方が部門ごとに違う、といった状態の案件では、期待されていた分析にたどり着く前に稼働が消えていきます。この記事では、データアナリスト案件に固有の確認点を整理します。契約書全般の確認点は業務委託契約書のチェックポイントで解説しています。

データアナリスト案件の選び方で差が出る理由

エンジニアの案件なら、使う言語や担当する工程で仕事の中身がある程度読めます。データアナリストの案件は、案件票に「SQL」「BIツール」「データ分析業務全般」のような書き方が並びやすく、依頼の量やデータの状態は書かれないことが少なくありません。

参画してから気づきやすいずれは次のようなものです。

  • 施策の分析を任されると思っていたが、実際は事業部門からの抽出の依頼に1日中答える仕事だった
  • テーブルの定義書がなく、数字の意味を確かめるだけで最初の数週間が過ぎた
  • 権限の申請が通るまで、データに入れない日が続いた
  • 週5日の契約なのに、月初の締めや経営会議の前は夜まで依頼が続いた

こうしたずれは、面談と条件の確認の段階で、聞き方を工夫すれば多くを防げます。

契約前に確かめたい7つの点

1. 依頼の来方と、優先順位を決める人

最初に確かめたいのは、仕事がどう届くかです。

  • 依頼は誰から、どの経路（チャット、受付表、定例会議）で届くか
  • 1日や1週間に、どのくらいの依頼が来ているか
  • 依頼が重なったときに、優先順位を決めるのは誰か
  • 定例レポートとテーマを持つ分析の割合はどのくらいか

複数の部門から直接依頼が届く形で、優先順位を決める人がいないと、すべての依頼を同時に抱えることになります。決める人が明確になっているかが、依頼対応型の案件で最も差が出る点です。面談では「着任後の最初の1か月で、最も期待されている成果は何か」を聞くと、依頼対応が中心か、分析のテーマが中心かが見えやすくなります。

2. データの準備状態

分析に使うデータがどこまで整っているかを確かめます。

  • 分析用のテーブルは整っているか。複数のシステムからつなぎ合わせるところから始まるか
  • テーブルの定義書や、主な指標の定義書はあるか
  • 「売上」「会員」などの指標の数え方は、部門の間でそろっているか
  • データの取り込みや不具合の対応を担う人（データエンジニアなど）はいるか

データが整っていない案件を避ける必要はありません。指標の定義をそろえる経験は、次の案件で評価されやすい経験です。ただ、状態を知ったうえで受けることが大切です。整っていない場合は、整備にかける期間と、その間に求められる成果を合わせて確かめておきます。データの整備そのものが中心の案件は、データエンジニアやBIエンジニアの役割と重なります。

エージェントベストの見解

データアナリストの案件をご紹介していると、参画後に「聞いていた状況と違った」となりやすいのは、依頼の量と、テーブルや指標の定義がどこまで整っているかの2点です。面談では聞きにくいと感じる方もいますが、立ち上がりの見込みを立てるために必要な確認として聞けば、多くの発注元は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

3. 作業の環境と権限

データアナリストの仕事は、データの置かれた環境に入れなければ始まりません。

  • 作業は手元のパソコンか、貸与の端末か、仮想デスクトップか
  • データウェアハウスやBIツールの権限は、参画のいつから使えるか
  • 読める範囲（どのテーブル、どの期間、どの項目）に制限はあるか
  • 処理の量で費用がかかるサービスの場合、使い方の決まりはあるか

権限の申請に時間がかかる会社では、参画初日から作業できないことがあります。その間に何をしていればよいかを確かめておくと、最初の週を無駄にせずに済みます。在宅での作業の条件はデータアナリストのリモート案件の記事で解説しています。

4. データの扱いの決まり

会員の属性や購買履歴など、個人に関わるデータを扱う案件は多くあります。

  • 個人に関わる項目をどこまで見てよいか。行単位のデータをダウンロードしてよいか
  • 少ない人数の集計など、個人が推測できる結果をレポートに載せてよいか
  • SQLや集計の結果を、生成AIなど外部のサービスに入力してよいか
  • 契約が終わったときに、手元のデータや資料をどう返し、どう消すか

客先の個人データを預かって扱う立場での注意点は業務で個人情報を扱うときの契約と注意点、契約終了時の扱いは契約終了後のデータの返却・削除の記事をご覧ください。

5. 成果物と契約の形

フリーランスのデータアナリストは、多くの場合、準委任契約で参画します。準委任では、分析の結論そのものではなく、分析の業務を専門家として通常求められる注意を払って行うことが約束の中身になります。

確かめたいのは、契約書や発注の書面の書き方が、この考え方と合っているかです。

  • 「売上が伸びる要因を特定する」のように、分析の結論を約束する書き方になっていないか
  • レポートやダッシュボードなど、提出物がある場合は、その範囲と頻度が書かれているか
  • 「分析業務全般」のように、範囲が広く書かれすぎていないか

分析は、やってみるまでどんな結果が出るか分かりません。結論ではなく、作業と提出物で約束しておくと、期待との行き違いを防げます。契約の形の違いは準委任契約と請負契約の違いで解説しています。

6. 応答の期待と稼働の振れ幅

データアナリストの稼働は、事業の節目で振れます。

  • 依頼への返答は、その日のうちを期待されているか、数日でよいか
  • 月初の締め、経営会議の前、大きな施策の前後に、依頼が集中するか
  • 稼働日以外や夜間に依頼が来たときの扱い
  • 精算幅を超えたときの扱いと、稼働が少ない月の扱い

即応の期待が強い案件では、短い回答が1日に何度も入り、実際に使った時間が見えにくくなります。応答できる時間帯と、超過した時間の扱いを確かめておかないと、無償で対応し続けることになりかねません。精算の仕組みは精算幅の記事をご覧ください。

7. 契約期間と仕事の区切り

契約の期間と、仕事の区切りが合っているかを確かめます。たとえば、施策の分析を任される案件で、結果が出る前に契約の更新時期が来ると、最後まで見届けられないことがあります。定例レポートの整備を任される案件では、手作業を減らして仕組みにした後に、外部に任せる理由が薄くなることもあります。区切りの後にどんな役割を期待されているかを聞いておくと、更新の見通しを立てやすくなります。

フリーランス法では、6か月以上の業務を委託している場合に、契約を解除したり更新しなかったりするときは、少なくとも30日前までに予告しなければならないとされています（2026年10月時点、公正取引委員会の案内による）。詳しくは中途解除の30日前予告の記事をご覧ください。

注意

データアナリストの案件では、参画後に役割が少しずつ広がりやすい傾向があります。ダッシュボードの作り込み、データの整備、広告の運用レポート、社員向けの勉強会など、契約の業務範囲に入っていない仕事を頼まれたときは、引き受ける前に範囲と条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者は業務を委託したら直ちに、給付の内容、報酬の額、支払期日などの取引条件を、書面またはメールなどで明示することとされています。報酬の支払期日は、給付を受け取った日から数えて60日以内のできる限り短い期間内で定めることとされています（いずれも2026年10月時点、公正取引委員会の案内による）。明示される事項の内容はフリーランス法で明示される取引条件をご覧ください。

データアナリストの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、担う範囲（定例レポート、依頼対応、施策の分析、指標の整備など）が書かれているか
  2. 分析の結論を約束する書き方になっていないか
  3. 提出物がある場合は、その範囲と頻度
  4. 稼働の幅と、超えたときの精算方法
  5. データの扱いと、契約終了時の返却・削除
  6. 契約期間と更新の時期

面談で聞いておくとよい質問はデータアナリストの面談でよく聞かれる質問と答え方の逆質問の項目でも紹介しています。一般的な逆質問の考え方は面談で聞いておくべき逆質問をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。データアナリストの案件で気になりやすい依頼の量や、データの扱いの決まりなど、書面だけでは読み取りにくい点は、ご質問いただければ確認します。条件に迷う点があれば、契約の前に早めにご相談ください。

ポイント

  • データアナリスト案件は、依頼の来方とデータの状態で負担と働き方が大きく変わる
  • 依頼の来方と優先順位を決める人、データの準備状態、作業の環境と権限を面談で確かめる
  • データの扱いの決まりと、分析の結論を約束しない契約の書き方を確かめる
  • 応答の期待と稼働の振れ幅、契約期間の区切りを書面と照らし合わせる

よくある質問

テーブルの定義書がない案件は避けたほうがよいですか？

避ける必要はありません。定義をそろえて文書にした経験は、次の案件で評価されやすい経験です。ただし、整備にかける期間、その間に求められる成果、整備の作業が業務範囲に入っているかを、参画前に確かめてから受けることをおすすめします。

依頼対応型と分析テーマ型の案件で迷ったらどうしますか？

一概には言えませんが、今後伸ばしたい経験で選ぶのが基本です。依頼対応型は事業のデータに早く慣れられる一方、自分の分析テーマを持ちにくい面があります。テーマ型は結果の説明まで任されるぶん、事業の理解が求められます。報酬の考え方はデータアナリストの報酬の記事で解説しています。

面談で依頼の量やデータの状態を聞くのは失礼ですか？

立ち上がりの見込みを立てるための確認として聞けば、失礼にはあたりません。「着任後に最初に取り組むべきことを把握したい」という目的を添えると、相手も答えやすくなります。答えられない点がある場合は無理に聞き出さず、ほかの確認点で判断しましょう。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 フリーランス新法・下請法

フリーランス新法の取引条件の明示｜受け取るべき8項目と確認のしかた

フリーランス新法では、発注者は業務委託をしたら直ちに、業務の内容・報酬の額・支払期日など8項目を書面かメール等で明示しなければなりません。口頭だけは不可です。受け取るべき内容と、未定事項や共通事項の扱いを整理します。

 フリーランス新法・下請法

中途解除の30日前予告｜フリーランス新法のルールと例外

6か月以上の業務委託を発注者が中途解除・不更新にするときは、原則として30日前までの予告が必要です。予告の方法、予告が不要になる5つの例外、理由開示の請求の仕方を、公正取引委員会・厚生労働省の資料をもとに整理します。

 業務委託契約の基礎

業務で個人情報を扱うときの契約と注意点｜委託先として求められること

取引先の顧客データなどを扱う業務は、個人情報保護法の「個人データの取扱いの委託」にあたることが多く、取引先には委託先を監督する義務があります。契約に入る安全管理・目的外利用の禁止・再委託・返却と廃棄・事故時の報告の条項と、守るための準備を整理します。

 業務委託契約の基礎

契約終了後のデータの返却・削除の義務｜何を返し、何を消し、何を手元に残すか

契約終了時のデータの返却・削除は、主に契約の秘密保持や個人情報の条項で義務づけられます。個人データなら取引先には委託先を監督する義務もあります。保存場所を洗い出し、指示どおりに返却・削除し、報告と自分の事業の記録を分けて残すのが基本です。
