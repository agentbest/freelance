SAP・ERP

SAP FI/COコンサルのフリーランスがつまずきやすい点と対策

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 現場でのつまずき
  3. 技術でのつまずき
  4. お金でのつまずき

フリーランスのSAP FI/COコンサルがつまずきやすいのは、契約に書かれた範囲と現場の期待のずれ、経理部門との言葉の食い違い、他モジュールとのつなぎ目で責任が宙に浮くこと、ECCの知識のままS/4HANAを語ること、決算期や切替期の稼働の膨らみです。どれも、会社員のコンサルなら社内のリーダーや品質管理の仕組みが受け止めてくれた部分を、外部の立場で一人で抱えることから起きます。

対策の基本は、つまずきの種を契約と参画初期の取り決めで小さくしておき、現場では設定の記録と数字の説明で守ることです。この記事では、契約・現場・技術・お金の順に、FI/COならではの場面と対策を整理します。契約で確かめる項目の一覧はFI/COコンサルがフリーランスになるにはで扱っているので、ここでは「実際に起きやすい場面」に絞ります。

契約でのつまずき

「FI/CO設定支援」と現場の期待がずれる

契約書には「FI/CO領域の設定支援」とだけ書かれ、現場では経理部門との要件定義の進行、他モジュールとの調整、帳票の仕様づくりまで期待されていた、という食い違いはよく起きます。FI/COは会計のすべてに関わるため、引き受けた範囲が少しずつ広がりやすいのが特徴です。

対策：参画前に、担当する機能（FI-GL、FI-AA、CO-PAなど）と工程（要件定義、設定、テスト、移行、稼働後の支援）を言葉で確かめ、担わないもの（アドオンの開発、経理部門の業務設計そのものなど）も書き出しておきます。範囲の外の依頼が来たときの扱いは作業範囲が広がったときの記事と追加の依頼の断り方をご覧ください。

稼働後の決算支援まで含むのかがあいまい

本番切替で契約が終わるのか、稼働後の初回決算や四半期決算の支援まで含むのかが決まっていないと、切替の直後に「このまま決算まで残ってほしい」と頼まれ、次の案件の予定と重なることがあります。逆に、決算の支援を見込んでいたのに切替で契約が終わり、収入の予定が狂うこともあります。

対策：契約期間と、プロジェクトの稼働予定日・会計年度の節目を並べて見ておきます。稼働後の支援を含むなら、その期間と稼働日数を契約に書いてもらいます。契約期間の考え方は契約期間の記事で解説しています。

設計書やテストの「完成」を約束する文言が入っている

準委任で参画するつもりが、契約書に設計書やテスト結果の完成と検収を約束するように読める文言が入っていることがあります。移行のデータが合わなかった、テストで不具合が残った、という場面で責任の範囲が広く読まれるおそれがあります。

対策：署名の前に、成果物の完成や検収を前提とした条項がないかを読みます。気になる文言は、エージェントや発注側に確かめてください。判断に迷う場合は弁護士などの専門家に相談するのが安全です。

指揮命令の形が社員と変わらなくなる

発注側のリーダーの下で、勤務時間や作業の手順まで細かく指示されるようになると、準委任の契約と実態がずれてきます。FI/COは経理部門の中に机を置いて働くこともあり、この状態に気づきにくい職種です。考え方は偽装請負の記事で解説しています。

現場でのつまずき

経理部門とシステムの言葉で話してしまう

経理の担当者に「伝票タイプの設定で」「転記キーが」と説明しても伝わらず、要件の確認が進まないことがあります。逆に、経理の「仮受消費税の消込」「配賦の二次配賦」といった言葉を取り違えると、設定が要件とずれたまま進みます。

対策：経理には「どの帳簿のどの数字がどう変わるか」で説明し、設定の名前は添える程度にします。要件を聞いたら、自分の言葉で言い換えて確かめ、議事録に会計の言葉と設定の言葉の両方で残します。求められる会計知識の範囲はFI/COで求められるスキルで触れています。

他モジュールとのつなぎ目で責任が宙に浮く

入庫・請求書照合で使う勘定の決め方、出荷から作られる売上の仕訳、製造実績から作られる原価差異の扱いは、MM・SD・PPの担当とFI/COの担当のどちらが決めるのかがあいまいになりやすい部分です。統合テストで数字が合わなかったとき、「会計側の設定の問題だ」と押し付けられることもあります。

対策：参画の初期に、つなぎ目ごとに「どちらが設定を持ち、どちらが確認するか」を一覧にして、両方のリーダーと確かめます。不具合が出たときは、どのモジュールのどの設定が原因かを切り分けた記録を残します。

前の現場の勘定体系や設計を持ち込みすぎる

前の案件でうまくいった勘定体系、原価センタの階層、帳票の設計を、参画してすぐに持ち込むと、経理部門の反発を招きやすくなります。会計の方針は会社ごとに違い、監査人との合意の積み重ねの上に成り立っているためです。

対策：最初は現行の設計とその理由を聞き、困っている点が見えてから提案します。提案するときは、現行の方針を否定せず、「標準の機能ならこう収まる」という形で選択肢として出します。

ユーザー企業側で「ベンダーに言えば済む人」と見られる

ユーザー企業の側に支援として入る案件では、経理部門の要望をそのままベンダーに伝えるだけになると、「間に入るだけの人」と見られ、契約の更新が見送られることがあります。

対策：要望を伝える前に、標準の機能で足りるか、運用で補えるか、会計方針の変更が要るかを自分で整理し、経理部門が判断できる形にして出します。

エージェントベストの見解

案件紹介の現場で、フリーランスのFI/COの方が契約の更新を見送られる理由として耳にしやすいのは、設定の技量より「数字の説明」と「範囲の踏み越え」です。テストで出た差異の理由を自分の言葉で説明できない、あるいは経理部門が決めるべき会計方針を先に決めてしまう、という場面が続くと、信頼を取り戻すのに時間がかかります。差異は原因を切り分けて早めに伝え、方針は決めてもらう形をとることをおすすめします。

技術でのつまずき

ECCの知識のままS/4HANAを語る

S/4HANAでは、FIとCOの伝票が一つの仕訳にまとまり、原価要素は勘定として持つ形になりました。顧客・仕入先のマスタも取引先として統合されています。ECCの感覚で「COの伝票を後で照合する」「原価要素を別に作る」と説明すると、設計の前提からずれ、移行の判断を誤ります。

対策：自分の担当機能について、ECCとS/4HANAで何が変わったかを一覧にしておきます。経験がない部分は「学んで説明できる範囲」として正直に伝え、設定で確かめながら進めます。

設定の変更を記録に残さない

FI/COの設定は、会計の数字に直接影響します。どの設定を、どの要件のために、いつ変えたかの記録がないと、テストで差異が出たときに原因を追えず、監査人への説明もできなくなります。移送の依頼と設定の変更が結び付いていないと、本番に反映されたものが分からなくなります。

対策：設定の変更一覧を自分で持ち、移送の番号と要件の番号を結び付けておきます。発注側に記録の決まりがあればそれに従い、なければ自分の一覧を共有します。

本番環境の権限と統制を軽く見る

本番の設定を直接変えられる権限を持ったまま、口頭の依頼で変更してしまうと、内部統制の評価で問題になり、自分の責任が問われることがあります。上場企業では、設定の変更に承認の記録が求められるのが一般的です。

対策：本番の設定を誰がどの手順で反映するかを参画の初期に確かめ、権限を持っていても承認の記録なしには変えないようにします。確かめる項目はFI/COのリモートの記事でも触れています。

数字の差異を説明できない

移行後の残高が旧システムと合わない、配賦の結果が経理の想定と違う、というとき、「設定は合っているはず」で止まると、経理部門の信頼を失います。

対策：差異が出たら、換算レートの取り方、配賦の順番、期間の切り方など、原因になりやすい点を順に確かめ、分かったところまでを短く報告します。原因が分からない段階でも、何を確かめたかを伝えるほうが信頼されます。

お金でのつまずき

決算期・切替期の稼働超過が精算されない

本番切替の週末、稼働後の初回決算、年度決算の時期には稼働が延びやすく、精算幅を大きく超えることがあります。超えた分の扱いを決めていないと、報酬に反映されないまま負担だけが増えます。

対策：稼働を日々記録し、精算幅を超えそうな段階で窓口に伝えます。切替や決算の時期に休日の作業が見込まれるなら、その扱いを契約の前に確かめておきます。精算の仕組みは精算幅の記事で解説しています。

工程の区切りで契約が突然終わる

要件定義の終わり、本番切替、初回決算の終わりといった節目で、契約が更新されないことがあります。フリーランス法では、6か月以上続く業務委託を解除したり更新しなかったりする場合、発注側は原則として30日前までに予告することになっています（2026年10月時点、公正取引委員会の案内による）。

対策：契約期間とプロジェクトの工程、会計年度の節目を並べて見ておき、更新の見込みを早めに確かめます。移行の案件では、移行後の運用まで関わるのか、移行の工程だけなのかを参画前に確かめておくと、区切りを読みやすくなります。

支払期日と取引条件を確かめていない

フリーランス法では、発注側は業務の内容、報酬の額、支払期日などを書面やメールで明示し、報酬は給付を受け取った日から60日以内のできるだけ短い期間で支払期日を定めることとされています（2026年10月時点、公正取引委員会の案内による）。口頭の約束だけで参画すると、範囲や支払いの食い違いを後から正せません。

対策：参画前に、明示された取引条件と契約書の内容を照らし合わせます。受け取るべき項目はフリーランス法の取引条件の明示で整理しています。

守秘情報の扱いで損害の責任を問われる

FI/COは、決算発表前の業績や取引先ごとの残高など、扱いに注意が要る情報に触れます。自宅の作業環境や資料の持ち出しが秘密保持の条項に反すると、損害の責任を問われるおそれがあります。

対策：秘密保持の条項を読み、作業場所と資料の扱いの決まりを参画前に確かめます。読み方は秘密保持契約（NDA）の記事をご覧ください。

注意

切替や決算の時期は、深夜や休日の対応が続くことがあります。稼働の記録が残っていないと、精算の相談も体調の管理も難しくなります。体調を崩してからでは遅いため、体調管理の記事も参考に、稼働の上限を自分で決めておいてください。

エージェントベストの見解

当社では、契約で業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。担当する機能と工程の範囲、稼働後の決算支援の有無、切替期の稼働の扱いなど、参画前に気になる点はご質問いただければ確認します。参画後に範囲が広がってきたと感じたときも、早めにご相談ください。

ポイント

  • 契約では、担当する機能と工程、稼働後の決算支援の有無、成果物の完成を約束する文言の有無を参画前に確かめる
  • 現場では、経理には会計の言葉で話し、他モジュールとのつなぎ目の責任を一覧にし、前の現場の設計を持ち込みすぎない
  • 技術では、S/4HANAの変化点を押さえ、設定の変更と移送を記録に残し、差異は切り分けて早めに報告する
  • 稼働は日々記録し、決算期・切替期の超過は精算幅を超える前に伝える

よくある質問

参画してから、聞いていた機能や工程と違うと気づきました。どうすればよいですか？

まずは、何が違うのかを機能と工程で具体的に書き出し、契約で決めた業務範囲と照らし合わせます。そのうえで、紹介を受けたエージェントや発注側の窓口に早めに伝えてください。我慢して続けると、範囲外の作業が当たり前になり、後から戻しにくくなります。案件を選ぶ段階で確かめたい点はFI/COの案件の選び方で整理しています。

移行後の残高が合わず、責任を問われそうです。どうすればよいですか？

準委任契約では、成果そのものを約束しているわけではなく、専門家として通常求められる注意を払って業務を行うことが約束の中身です。まず、差異の原因を切り分けた記録と、設定の変更の記録を整理して、発注側に経緯を説明してください。契約の内容や、業務の進め方に落ち度があったかどうかで判断が変わることがあるため、不安がある場合は契約書の損害賠償の条項を読み、弁護士などの専門家にご相談ください。

経理部門と設計の方針で意見が対立したときは、どうすればよいですか？

FI/COコンサルとしての見立てと、標準の機能・運用・会計方針の変更という選択肢を示したうえで、最終的に決めるのは発注側の経理責任者だという線を守ります。決まった内容と、自分が示した懸念は議事録に残しておくと、後で経緯を確かめられます。参画初期の進め方はFI/COコンサルの参画初月にやることをご覧ください。
