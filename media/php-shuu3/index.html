PHPエンジニアの週2〜3日・副業案件｜見つかりやすい型と探し方、受けるときの注意点

週2〜3日や副業で受けられるPHPエンジニアの案件は、ほかの職種と比べると見つかりやすい部類に入ります。PHPは小規模なWebサービスやCMS・ECサイトに広く使われており、機能の追加や改修を単位で切り出しやすいためです。中心になるのは、小さな自社サービスの機能追加、既存システムの保守と改修、CMS・ECサイトの構築、技術的な相談役といった案件です。

ただし、週5日の開発チームの一員として募集される案件を、そのまま週3日で受けるのは難しいことが多く、稼働日数に合う役割の案件を選ぶことが大切です。この記事では、週2〜3日・副業のPHP案件の型、探し方、短い稼働で信頼を得る進め方、受けるときの注意点を整理します。週3日の働き方全般は週3日の業務委託案件の記事で解説しています。

PHPで週2〜3日の案件が比較的多い理由

PHPの案件に週2〜3日のものがある程度あるのは、仕事の性質によるものです。

  • 作業を単位で切り出しやすい：機能の追加や画面の改修は、プルリクエスト単位で区切れるため、稼働日にまとめやすい
  • 小さな会社の案件が多い：社内にエンジニアが1〜2名、または専任がいない会社では、週5日分の仕事がなく、週2〜3日で足りる
  • 保守の需要が続く：動いているサイトやシステムを直す仕事は、月に数日あれば回ることがある
  • リモートで完結しやすい：コードの管理とレビューがオンラインで済むため、稼働日を分散しても進められる

一方で、週5日が前提の案件もあります。立ち上げ期の自社サービスで毎日仕様が動く案件、受託の新規開発で工程に沿って進む案件、障害対応の当番がある運用の案件などです。これらは、不在の日に進まないことが問題になりやすく、週2〜3日では成り立ちにくくなります。

小規模な自社サービスの機能追加は、社内の担当者が日々の運用を回し、フリーランスが機能の実装を担う形です。社内にPHPを読める人がいるかどうかで、相談のしやすさと、自分が抱える範囲が変わります。

技術的な相談役は、社内のエンジニアが少ない会社で、設計の方針やコードの質を外から支える役割です。実装の量は少ない一方、設計と運用の経験が求められるため、PHPでの開発と運用の経験が長い方に向いています。

CMS・ECサイトの案件は、短い期間の制作や、月に数日の保守契約が多く、複数の案件を掛け持ちする働き方につながります。PHPの案件の型ごとの働き方はPHPエンジニアの仕事内容で詳しく解説しています。

エージェントベストの見解

PHPの案件をご紹介していると、週2〜3日の希望で決まりやすいのは、「この稼働日数なら、ここまでを担える」と役割の範囲を自分から示せる方です。たとえば「機能の実装とレビューは担うが、障害の一次対応は社内にお願いしたい」のように言葉にできると、発注元も任せる範囲を決めやすくなります。反対に、週5日の案件と同じ役割を週3日で引き受けようとすると、不在の日の対応に不安を持たれ、見送られやすい傾向があります。

週2〜3日のPHP案件の探し方

1. 担える範囲と、担わない範囲を先に決める

週2〜3日で受けるなら、どの仕事を担い、どの仕事は担わないかを決めておきます。「機能の実装と版上げは担う」「本番の障害の一次対応と、稼働日以外の問い合わせは担わない」のように範囲を言葉にしておくと、案件との照らし合わせが早くなります。

2. 稼働する曜日と、稼働外の連絡の扱いを決める

開発チームの案件では、計画や振り返りの会議の曜日と、自分の稼働日が合うかが大切です。曜日を固定できるか、稼働日以外にチャットの返信にどこまで応じるかを決めておきましょう。会議の曜日は案件ごとに違うため、曜日を柔軟に選べる人ほど選択肢が広がります。

3. 成果物や期間で区切れる仕事を選ぶ

CMSの構築、版上げ、性能の改善のように、ゴールがはっきりした仕事は、稼働日数が少なくても評価されやすい形です。逆に、「チームの一員として何でも」という募集は、週5日を前提にしていることが多いため、稼働日数の相談ができるかを先に確かめます。

4. 経験の近い案件から選ぶ

稼働日数が少ないほど、立ち上がりの早さが求められます。使っているフレームワークの版、データベース、開発環境が自分の経験に近い案件を選ぶと、短い稼働でも成果を出しやすくなります。リモートで受けられるかどうかも合わせて確かめておきましょう。PHPのリモートの働き方はPHPのリモート案件の記事で解説しています。

短い稼働で信頼を得る進め方

週2〜3日のPHPエンジニアは、不在の日があることを前提に、仕事の進め方を組み立てる必要があります。

  • 環境構築を最初の稼働日で終える：ローカルの環境が動かないまま日を空けると、立ち上がりが大きく遅れる。手順書がなければ、自分で作って残す
  • プルリクエストを小さく保つ：レビューの待ち時間が稼働日をまたぐため、大きな変更は分けて出す。レビューの依頼は稼働日の早い時間に出す
  • 本番への適用の日を稼働日に合わせる：リリースの直後に不在になると、問題が起きたときに誰も直せない。リリースは稼働日の前半に行い、同じ日に確かめる
  • 不在の日の連絡の扱いを決める：急ぎの不具合が出たときに誰が対応するか、自分はいつまでに返事をするかを、発注元と先に合意しておく
  • 稼働日の終わりに短く報告する：進んだこと、残っていること、次の稼働日に判断してほしいことを文章で残す

こうした進め方を面談で具体的に話せると、短い稼働でも任せられるかを発注元が判断しやすくなります。

受けるときの注意点

責任の範囲と稼働日数をそろえる

週2〜3日の案件で最も起きやすいのは、稼働日数は減ったのに、責任の範囲は週5日のエンジニアと同じという状態です。特に保守の案件では、不在の日に本番の障害が起きたときの対応を求められ、結果として稼働日以外に作業が増えていきます。参画前に、障害対応を担うかどうか、担う場合の連絡の方法と時間の扱いを確かめておきましょう。

契約の形と、稼働外の作業の扱いを確かめる

月単位で稼働する準委任の契約か、サイトや機能を納品する請負の契約かで、作業の扱いが変わります。準委任なら、稼働日以外に対応した時間をどう精算するかを確かめます。精算の仕組みは精算幅の記事をご覧ください。請負なら、修正の回数や検収の方法を決めておかないと、追加の依頼が続いて稼働に見合わなくなります。参画後に役割が広がった場合の扱いは作業範囲が広がったときの契約の扱いで解説しています。

2024年11月に施行されたフリーランス法では、業務を委託する事業者は、業務の内容、報酬の額、支払期日などの取引条件を、書面またはメールなどで直ちに明示することとされています（2026年10月時点、公正取引委員会の案内による）。週2〜3日の案件や小さな会社の案件では、口頭やチャットだけで始まりやすいため、条件を書面やメールで受け取ることを意識してください。

掛け持ちの情報の扱いを分ける

週2〜3日の案件を複数受ける場合、会議や障害の対応が重なりやすくなります。情報の扱いも、案件ごとに分ける必要があります。コードや資料を別の案件の端末や環境に持ち込まない、同じ業界の競合に当たる案件を同時に受けない、といった線を自分で引いておきましょう。掛け持ちの注意点は複数の案件を掛け持ちするときの注意点で解説しています。

注意

CMSやECサイトの保守を月に数日の契約で受ける場合、CMS本体やプラグインの更新を怠ると、脆弱性が放置されてサイトの改ざんや情報の流出につながることがあります。更新作業を契約の範囲に含めるか、含めない場合は誰が担うかを、参画前にはっきりさせておきましょう。「保守」という言葉の中身は案件ごとに違います。

会社員の副業でPHPの案件を受けるとき

会社員が副業でPHPの案件を受ける場合は、上の注意点に加えて、次の点を確かめます。

勤務先の就業規則

副業が禁止か、許可制か、届出制か、業務委託が対象に含まれるかを就業規則で確かめます。厚生労働省は「副業・兼業の促進に関するガイドライン」を公表しており、モデル就業規則からは「許可なく他の会社等の業務に従事しないこと」という規定が削除され、副業・兼業に関する規定が設けられています（2026年10月時点、厚生労働省の案内による）。ただし、勤務先の規則が実際にどうなっているかは会社ごとに違うため、自分の勤務先の規則を読んでから動いてください。就業規則の読み方は会社員の副業で業務委託案件を受けるときの注意点と副業禁止の会社で業務委託を受けるリスクで解説しています。

本業との競合と情報の扱い

本業と同じ業界のサービスや、本業の取引先に関わる案件は、競業や秘密の扱いで問題になりやすくなります。本業で書いたコードや設計を副業の案件で使わない、逆も同じ、という線を引いておきましょう。

時間帯

PHPの開発案件でも、計画や振り返りの会議は平日の日中に入ることが多くあります。夜や週末だけで受ける場合は、会議への出席を求められない案件か、成果物や期間で区切れる仕事を選びます。探し方は週末・夜だけの業務委託案件の記事で解説しています。

確定申告と住民税

国税庁の案内では、給与を1か所から受けている人で、給与所得と退職所得以外の各種の所得金額の合計額が20万円を超える人は、確定申告が必要とされています（2026年10月時点）。副業の報酬から経費を引いた所得がこの額を超えるかどうかで、申告の要否が変わります。住民税の扱いも含め、詳しくは副業の所得が20万円以下のときの扱いと副業の住民税の記事で解説しています。個別の判断は、税理士などの専門家にご相談ください。

よくある質問

週2〜3日の案件でも、PHPエンジニアとしての経験として評価されますか？

担った範囲と判断の中身を具体的に書けば、経験として評価されます。週2〜3日の案件は役割が絞られていることが多いため、スキルシートには稼働日数と担った範囲を正確に書き、チーム全体を担っていたと誤解されない書き方にしておきましょう。

週3日で始めて、あとから週5日に増やすことはできますか？

発注元の体制や予算によっては、稼働を増やせることがあります。ただし、小さな会社では週5日分の仕事がないことも多いため、増やせる前提で受けるのは避けたほうが無難です。将来の希望がある場合は、参画前に伝えておくと話がしやすくなります。

平日の夜や週末だけでもPHPの案件は受けられますか？

CMSの構築や小さな改修のように、成果物で区切れる仕事なら成り立つことがあります。一方、開発チームの一員として会議に出る案件は、平日の日中が前提になることが多く、夜や週末だけでは難しくなります。会議への出席が求められるかどうかを、応募の前に確かめましょう。
