SAP・ERP

SAP BTPエンジニアのフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

  2. 契約前に確かめたい8つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

SAP BTPエンジニアのフリーランス案件を選ぶときは、報酬や稼働日数に加えて、担う領域と判断の範囲、つなぐ先と相手先の体制、接続と権限の分担、環境と配布の手順、稼働後の保守の担い手、契約の形と責任、稼働の振れ幅、契約期間と局面の区切りの8点を契約前に確かめておくことが大切です。BTPの案件は、案件票の書き方が似ていても、この8点の違いで負担と責任が大きく変わります。

特に見落としやすいのは、作ったものを誰が動かし続けるのかです。開発だけのつもりで入ったのに、稼働後のエラー対応や問い合わせまで担うことになる案件は少なくありません。この記事では、BTPの案件に固有の確認点を整理します。契約書全般の確認点は業務委託契約書のチェックポイントで解説しています。

BTPの案件選びで差が出る理由

BTPは、拡張アプリの開発、システム連携、ローコード・自動化、AIの組み込み、環境の管理といった、性質の違う仕事をまとめて呼ぶ言葉です。連携の領域だけを見ても、SAP Learningでは、Integration Suiteの機能としてCloud Integration、API Management、Event Mesh、Integration Advisor、Migration Assessmentなどが挙げられています（2026年10月時点）。案件票に「SAP BTP」「Integration Suite」とあるだけでは、どの仕事をどの深さで担うのかが読めません。

よくあるずれは次のようなものです。

  • 設計から任されると聞いていたが、実際は決まった設計どおりにフローを作る作業が中心だった
  • 開発の案件だったが、オンプレミスとの接続の設定や障害の調査まで求められた
  • つなぐ先の相手先の準備が遅れ、テストの待ちが続いて計画が崩れた
  • 稼働後の保守の担い手が決まっておらず、問い合わせが自分に集まった

こうしたずれは、面談と条件の確認の段階で、聞き方を工夫すれば多くを防げます。案件票の読み方の基本は案件票の読み方の記事で解説しています。

契約前に確かめたい8つの点

1. 担う領域と、判断の範囲

最初に確かめたいのは、自分が担う領域と、どこまで判断を任されるかです。

  • 拡張開発・連携・ローコード・AI・環境の管理のうち、どれが中心か
  • 拡張をS/4HANAの中に置くかBTPの上に置くか、連携を同期・非同期・イベントのどれにするかを、自分が決めるのか、決まったものを作るのか
  • 設計のレビューを誰が行うか

面談では、「着任後の最初の1か月で、最も期待されている成果は何か」を聞くと、役割の実態が見えやすくなります。答えが「既存の連携の一覧と方式の見直し案」なら設計の役割、「決まった連携の実装」なら実装の役割です。報酬との関係はSAP BTPエンジニアの報酬の記事で整理しています。

2. つなぐ先と、相手先の体制

連携や拡張の難しさは、つなぐ先で大きく変わります。

  • つなぐ先はS/4HANAのクラウド版か、オンプレミス版か、旧来のSAP ERPか、他社のSaaSか
  • つなぐ先の数と、それぞれの担当者が誰か
  • 相手先とのテストの日程を、誰が調整するか

相手先の担当が別の会社の場合、テストの準備や不具合の対応の速さは、自分では動かせません。相手先の体制の弱さが、自分の遅れとして見られることがないよう、調整の窓口が誰かを確かめておきましょう。

3. 接続と権限の分担

オンプレミスとの接続の設定、利用者のロールの設計、社内のID管理との連携、資格情報の管理は、BTPの仕事と基盤の仕事の境目にあります。

  • これらの設定を、自分が担うのか、Basisやインフラの担当が担うのか
  • 本番の環境に入る権限を持つのか、作業を依頼する立場か
  • 権限の申請や承認にかかる期間

分担があいまいなまま始まると、接続の問題で作業が止まったときに、誰が調べるのかで時間を使います。基盤の側の確認点はSAP Basisエンジニアの案件の選び方も参考になります。

エージェントベストの見解

BTPの案件をご紹介していると、参画後に「聞いていた状況と違った」となりやすいのは、接続と権限の分担と、稼働後の保守の担い手の2点です。面談では聞きにくいと感じる方もいますが、担う範囲を判断するために必要な確認として聞けば、多くの発注元は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

4. 環境の構成と、配布の手順

  • 開発・検証・本番の環境がどう分かれているか
  • 本番への配布を誰が、どの手順で、どの頻度で行うか
  • ソースの管理と、レビューの決まりがあるか

配布の手順が整っていない案件では、手作業での配布や、環境ごとの設定の違いの調査に時間を取られます。それ自体が仕事の範囲になっているのかを確かめておきましょう。

5. 稼働後の保守の担い手

作ったアプリや連携を、稼働後に誰が動かし続けるのかを確かめます。

  • 監視とエラーの再処理を誰が担うか
  • 利用者からの問い合わせの窓口はどこか
  • 自分の契約が終わった後の引き継ぎ先はあるか

保守の担い手が決まっていない案件は、作った人に問い合わせが集まりやすくなります。引き継ぎ先がある場合は、引き継ぎの期間と手順書の範囲が業務に含まれるかも確かめておきます。

6. 契約の形と、負う責任の範囲

BTPの案件は、月単位の準委任契約で稼働することが多い一方、アプリや連携フローの納品を約束する請負の形もあります。

  • 準委任なのに、「連携を期日までに完成させる」のように完成を約束する書き方になっていないか
  • 請負の場合、何をもって完成とするか、稼働後の不具合への対応をいつまで、どこまで負うか
  • 損害賠償の定めに上限があるか

連携の不具合は、出荷や請求などの業務の停止につながることがあるため、責任の範囲の書き方は特に確かめておきたい点です。契約の形の違いは準委任契約と請負契約の違い、損害賠償の考え方は損害賠償の条項の記事で解説しています。

7. 稼働の振れ幅と精算

BTPの稼働は、テストと切り替えの時期に大きく振れます。

  • 結合テストや本番の切り替えで、夜間や休日の作業があるか
  • 障害が起きたときの連絡の体制に、自分が入るか
  • 精算幅を超えたときの扱いと、稼働が少ない月の扱い

切り替えの当日の作業や、障害の対応で稼働の上限を超えやすい職種です。超過した時間の扱いを確かめておかないと、無償で対応し続けることになりかねません。精算の仕組みは精算幅の記事をご覧ください。

8. 契約期間と、局面の区切り

契約の期間と、プロジェクトの局面の区切りが合っているかを確かめます。たとえば、移行の切り替えの直前に契約の更新時期が来ると、更新されなかった場合に最も大事な局面を見届けられません。検証から始まる案件では、検証の後に本番の開発が続く見込みがあるかも聞いておきたい点です。

フリーランス法では、6か月以上継続して業務を委託している場合に、契約を解除したり更新しなかったりするときは、原則として少なくとも30日前までに予告することが求められています（2026年10月時点、公正取引委員会の案内による）。詳しくは中途解除の30日前予告の記事、契約期間の決め方は契約期間の記事で解説しています。

注意

BTPの案件では、参画後に担当が少しずつ広がりやすい傾向があります。利用部門が作ったアプリの手直し、別の連携の調査、新しい機能の検証など、契約の業務範囲に入っていない仕事を頼まれたときは、引き受ける前に範囲と条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容、報酬の額、支払期日などを、書面またはメールなどで明示することとされています（2026年10月時点、公正取引委員会の案内による）。明示される事項の内容はフリーランス法で明示される取引条件をご覧ください。

BTPの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、担う領域と工程（設計、実装、テスト、切り替え、保守など）が書かれているか
  2. 接続や権限の設定、障害の対応が業務に含まれるかが分かるか
  3. 完成を約束する書き方や、稼働後の不具合の責任を期限なく負う書き方になっていないか
  4. 稼働の幅と、超えたときの精算方法、夜間や休日の作業の扱い
  5. 契約期間と更新の時期

面談で聞いておくとよい質問はSAP BTPエンジニアの面談でよく聞かれる質問と答え方の逆質問の項目でも紹介しています。出社の条件や端末の扱いなど、リモートの確認点はSAP BTPエンジニアのリモート案件の記事をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。BTPの案件で気になりやすい接続と権限の分担や、切り替えの時期の稼働の扱いなど、書面だけでは読み取りにくい点は、ご質問いただければ確認します。条件に迷う点があれば、契約の前に早めにご相談ください。

ポイント

  • BTPの案件は、同じ「BTP」でも領域・局面・分担で負担と責任が大きく変わる
  • 担う領域と判断の範囲、つなぐ先と相手先の体制、接続と権限の分担を面談で確かめる
  • 稼働後の保守の担い手と、完成や不具合の責任の書き方を確かめる
  • 稼働の振れ幅と精算、契約期間と局面の区切りを書面と照らし合わせる

よくある質問

検証やPoCから始まる案件は避けたほうがよいですか？

避ける必要はありません。新しい機能を早く試せる経験は、次の案件で話せる材料になります。ただし、検証の後に本番の開発が続く見込みがあるか、検証の期間だけで契約が終わる可能性があるかを、参画前に確かめてから受けることをおすすめします。

移行の案件で、旧環境の資料がほとんどないと言われました。受けてよいですか？

資料が少ない移行は、読み解きと聞き取りに時間がかかります。受ける場合は、現状の棚卸しにかける期間が計画に入っているか、旧環境に詳しい担当者に話を聞けるかを確かめておきましょう。棚卸しの結果で作業量が増えたときの扱いも、あわせて確認しておくと安心です。

報酬の高い案件と、分担のはっきりした案件で迷ったらどうしますか？

一概には言えませんが、BTPの案件では、接続や保守の分担があいまいなまま範囲が広がると、稼働が増えて時間あたりの報酬が下がることがあります。報酬の額だけでなく、稼働の見込みと担う範囲を合わせて比べるとよいでしょう。報酬の決まり方はSAP BTPエンジニアの報酬の記事で解説しています。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

損害賠償の条項｜上限の考え方とフリーランスが確認するポイント

損害賠償の条項では、責任を負う場合（帰責事由）、賠償の範囲、上限額、請求できる期間の4点を確認します。民法には上限の定めがないため、上限は契約で決めることになります。読み方と相談の仕方を整理します。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。

 単価・報酬交渉

精算幅（140〜180時間など）とは｜超過・控除の計算方法

精算幅は、月額報酬のままでよい稼働時間の範囲です。上限を超えると超過分が加算され、下限を下回ると控除されます。超過・控除の単価は上下割か中間割かで変わるため、仮の数字を使って計算方法を整理します。

 スキルシート・面談

業務委託の面談で聞いておくべき逆質問｜参画後のずれを防ぐ確認項目

業務委託の面談の逆質問は、印象づくりより「参画後のずれを防ぐ確認」に使うのが基本です。業務の範囲、体制と指示の流れ、稼働の実態、期間の見込みの4つを確かめておくと、契約後の「話が違う」を減らせます。
