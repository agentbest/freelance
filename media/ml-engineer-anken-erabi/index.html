データ・AI

機械学習エンジニアのフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい8つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

フリーランスの機械学習エンジニアの案件を選ぶときは、報酬や稼働日数に加えて、担う工程、データの状態、評価の基準と検証の終わり方、計算資源と費用、成果物の権利、外部のAIサービスの扱い、本番の運用の責任、契約の形の8点を契約前に確かめておくことが大切です。機械学習の案件は、同じ「モデル開発」の募集でも、この8点の違いで負担と責任が大きく変わります。

特に見落としやすいのは、データがそろっているかと、精度の達成を約束する形になっていないかです。データが届かないまま期間が過ぎたり、届かない精度の責任を問われたりすると、どれだけ働いても状況を動かせません。この記事では、機械学習の案件に固有の確認点を整理します。契約書全般の確認点は業務委託契約書のチェックポイントで解説しています。

機械学習の案件選びで差が出る理由

一般的な開発の案件なら、作る機能と使う技術で仕事の中身がある程度読めます。機械学習の案件は、結果がデータの質と量に左右され、やってみないと分からない部分が残ります。案件票には「AIモデルの開発」「需要予測の高度化」のように抽象的に書かれやすく、参画してから想定との違いに気づくことが少なくありません。

よくあるずれは次のようなものです。

  • モデル開発の案件と聞いていたが、実際はデータの収集とラベル付けの整備が中心だった
  • データの提供が遅れ、最初の数週間は実験ができなかった
  • 検証の終わり方が決まっておらず、「もう少し精度を上げて」が続いた
  • 学習に使えるGPUがなく、費用の負担が誰にあるかもあいまいだった
  • 本番の監視まで任され、夜間の障害の連絡が届くようになった

こうしたずれは、面談と条件の確認の段階で聞き方を工夫すれば、多くを防げます。

契約前に確かめたい8つの点

1. 担う工程はどこからどこまでか

データの準備・学習・評価・推論の組み込み・運用と監視のうち、どこを担うのかを確かめます。面談では「着任後の最初の1か月で、最も期待されている成果は何か」を聞くと、工程の実態が見えやすくなります。答えが「データの整理」なら前の工程寄り、「推論のAPIの公開」なら組み込みの役割です。工程ごとの働き方は機械学習エンジニアの仕事内容で整理しています。

2. データの状態と、アクセスできる時期

確かめたいのは次の点です。

  • 学習に使うデータはすでにあるか、これから集めるのか
  • ラベルは付いているか。付いていない場合、誰がどう付けるのか
  • データにアクセスできるようになる時期と、権限の申請にかかる時間
  • 個人情報や機密の情報が含まれるか。含まれる場合の扱いのルール

データがそろっていない案件を避ける必要はありません。ただ、データの整備も業務に含まれるのかを確かめ、含まれるならその前提で期間と稼働を見積もってもらうことが大切です。

3. 評価の基準と、検証の終わり方

どの指標で、何と比べて、どこまで届けば次に進むのかを確かめます。あわせて、届かなかったときにどうするか（検証の報告で終わるのか、期間を延ばすのか）と、それを決めるのは誰かも聞いておきます。終わり方が決まっていない検証は、期待だけが膨らみやすくなります。

エージェントベストの見解

機械学習の案件をご紹介していると、参画後に「聞いていた状況と違った」となりやすいのは、データの状態と、検証の終わり方の2点です。面談では聞きにくいと感じる方もいますが、担う範囲と期間を判断するために必要な確認として聞けば、多くの発注元は答えてくれます。案件票だけでは分からない点は、契約の前に確かめることをおすすめします。

4. 計算資源と、費用の負担

  • 学習や推論に使う計算資源（GPUなど）は、どこに、どのくらい用意されているか
  • クラウドの利用料は誰の負担で、どのアカウントで使うか
  • 費用の上限はあるか。超えそうなときに誰に相談するか

自分のアカウントや私物の機器で学習を回すよう求められた場合は、費用の負担とデータの持ち出しの両面から、事前に取り決めておく必要があります。計算資源の環境とリモートの関係は機械学習エンジニアのリモート案件の記事で解説しています。

5. 成果物の範囲と権利

学習済みのモデル、学習と推論のコード、実験の記録、報告書のうち、何を成果物として渡すのか、その権利を誰が持つのかを確かめます。自分が以前から使っている汎用のコードやライブラリを持ち込む場合は、その扱いも決めておきましょう。オープンソースの学習済みモデルを使う場合は、利用の条件が業務での使い方に合うかも確かめておくと安心です。権利の考え方はフリーランスの著作権の記事で解説しています。

6. 外部のAIサービスとデータの扱い

発注元のデータを外部のAIサービスに入力してよいか、コードの補完などのAIツールを使ってよいかは、会社ごとにルールが違います。使ってよいサービスと、使ってはいけないデータの範囲を、作業を始める前に確かめます。契約の終了時にデータや学習済みのモデルをどう返し、どう消すかも決めておきましょう。考え方はAIツールの利用と業務委託契約の記事と契約終了時のデータの返却の記事をご覧ください。

7. 本番の運用と障害対応の責任

モデルを本番に出したあと、監視や再学習、障害の対応を誰が担うのかを確かめます。

  • 監視の仕組みは誰が持ち、異常に気づいたら誰に連絡が来るか
  • 夜間や休日の障害の連絡の体制に、自分が入るか
  • 稼働時間外に対応したときの精算の扱い

組み込みまでの契約のはずが、なし崩しに運用まで担うことになると、稼働の上限を超えやすくなります。

8. 契約の形と、約束する中身

機械学習の検証やモデル開発は、事前に結果が読めないため、業務を行うことに報酬が支払われる準委任契約で進むことが多くあります。確かめたいのは、契約書や発注の書面の書き方がこの考え方と合っているかです。

  • 「精度◯%を達成する」のように、結果を完成の条件にする書き方になっていないか
  • 精度が届かなかったこと自体に対する損害賠償の定めがないか
  • 精度に連動した報酬を提案された場合、届かなかったときの扱いがどうなっているか

請負の形で受ける場合は、完成に対する責任を負うことになります。役割と契約の形が合っているかを確かめましょう。違いは準委任契約と請負契約の違い、精度に連動した報酬の考え方は機械学習エンジニアの報酬の記事で解説しています。

注意

機械学習の案件では、参画後に役割が少しずつ広がりやすい傾向があります。別のテーマの検証の相談、社内向けの勉強会の講師、データ基盤の整備など、契約の業務範囲に入っていない仕事を頼まれたときは、引き受ける前に範囲と条件を確かめましょう。考え方は作業範囲が広がったときの契約の扱いで解説しています。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者は業務を委託したら直ちに、業務の内容、報酬の額、支払期日などの取引条件を、書面またはメールなどで明示することとされています。報酬は、成果物などを受け取った日から60日以内のできる限り短い期間で定めた支払期日までに支払うこととされ、6か月以上継続して委託している契約を解除したり更新しなかったりするときは、少なくとも30日前までに予告することが求められています（2026年10月時点、公正取引委員会の案内による）。明示される事項の内容はフリーランス法で明示される取引条件をご覧ください。

機械学習の案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、担う工程（データの整備、学習、評価、組み込み、運用など）が書かれているか
  2. 精度の達成を完成の条件にする書き方になっていないか
  3. 成果物の範囲と権利の帰属、持ち込むコードの扱い
  4. 計算資源と費用の負担、データの返却と消去
  5. 稼働の幅と、超えたときの精算方法、契約期間と更新の時期

面談で聞いておくとよい質問は機械学習エンジニアの面談でよく聞かれる質問と答え方の逆質問の項目でも紹介しています。一般的な逆質問の考え方は面談で聞いておくべき逆質問、近い職種の案件の選び方はデータサイエンティストの案件の選び方やMLOpsエンジニアの案件の選び方もあわせてご覧ください。個別の契約の判断に迷う場合は、弁護士などの専門家にご相談ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。機械学習の案件で気になりやすいデータの状態や計算資源の負担、成果物の権利など、書面だけでは読み取りにくい点は、ご質問いただければ確認します。

ポイント

  • 機械学習の案件は、データの状態と評価の基準、契約の形で負担と責任が大きく変わる
  • 担う工程、データ、評価と検証の終わり方、計算資源と費用を面談で確かめる
  • 成果物の権利、外部AIサービスの扱い、本番の運用の責任を参画前に決めておく
  • 精度の達成を完成の条件にする書き方になっていないかを、書面と照らし合わせる

よくある質問

データがそろっていない案件は避けたほうがよいですか？

避ける必要はありません。データの整備から関わった経験は、次の案件で評価されることもあります。ただし、データの整備が業務に含まれるか、アクセスできる時期はいつか、その前提で期間と稼働が見積もられているかを、参画前に確かめてから受けることをおすすめします。

精度の目標を契約書に書きたいと言われたらどうしますか？

目標として共有すること自体は、進め方をそろえるうえで役に立ちます。問題になりやすいのは、目標を完成の条件や報酬の条件にする書き方です。目標は「目指す値」として扱い、届かなかったときの進め方（報告で終える、期間を延ばすかを協議する）を書面に残す形を相談するとよいでしょう。

報酬の高い案件と、条件のはっきりした案件で迷ったらどうしますか？

一概には言えませんが、機械学習の案件では、データや評価の基準があいまいなまま進むと、手戻りが増えて稼働が膨らみ、時間あたりの報酬が下がることがあります。報酬の額だけでなく、データの状態、検証の終わり方、運用の責任の範囲を合わせて比べるとよいでしょう。

業務委託契約の基礎

業務委託契約書のチェックポイント｜署名前に確かめたい10項目

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

成果物の著作権は誰のもの？業務委託の知的財産の扱い

業務委託で作ったプログラムや資料の著作権は、契約で決めなければ原則として作ったフリーランスに残ります。発注者に移す場合は、譲渡の範囲・時期・対価と、以前から持っているコードの扱いを契約で確かめます。

 業務委託契約の基礎

業務での生成AIの利用に関する契約条項｜禁止・承認制・条件付き許可の読み方

生成AIの利用に関する条項は、禁止・事前承認・条件付き許可の3つの型に分かれます。確かめたいのは、使ってよいサービス、入力してよい情報、出力の権利と保証、利用の報告の4点です。定めがない場合は使う前に書面で確かめます。

 業務委託契約の基礎

契約終了後のデータの返却・削除の義務｜何を返し、何を消し、何を手元に残すか

契約終了時のデータの返却・削除は、主に契約の秘密保持や個人情報の条項で義務づけられます。個人データなら取引先には委託先を監督する義務もあります。保存場所を洗い出し、指示どおりに返却・削除し、報告と自分の事業の記録を分けて残すのが基本です。

 業務委託契約の基礎

秘密保持契約（NDA）で確認すること｜対象・期間・実績として話せる範囲

NDAで確かめたいのは、秘密情報の範囲と例外、使ってよい目的、守る期間、終了時の返還・廃棄、違反時の責任の5点です。フリーランスは、実績としてどこまで話せるかも署名前に決めておくと安心です。
