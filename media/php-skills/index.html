PHPのフリーランス案件では、Laravelを「動かせる」だけでなく設計の意図まで理解して使えるか、SQLとデータベースの力、Webのセキュリティを自分で守れるか、古いコードを壊さずに直せるかが中心に見られます。PHPは書き始めやすい言語のぶん、経歴の書き方だけでは力の差が伝わりにくく、面談ではこの4点を具体的に聞かれることが多くあります。

独立までの進め方はPHPエンジニアがフリーランスになるにはで扱っているため、この記事では、案件で求められるスキルの中身と、それをどう示すかに絞って整理します。

PHPの案件で見られるスキルの全体像

PHPの案件で確認されやすいスキルを、分野ごとにまとめると次のようになります。

分野具体的なスキル面談での見られ方
フレームワークLaravelの各機能、層の分け方、キューやイベントの使い方機能の名前より、どこに処理を置いたかの判断
データベーステーブル設計、インデックス、実行計画、トランザクション遅いSQLをどう見つけ、どう直したか
セキュリティ入力値の扱い、認証・認可、脆弱性への対策対策を「フレームワーク任せ」にしていないか
保守・移行静的解析、テスト、バージョンアップ古いコードを安全に変えた手順
周辺技術フロントとの連携、Docker、クラウド、CI/CD一人でどこまで完結できるか

すべてを深く持っている必要はありません。ただ、上の2つ（フレームワークとデータベース）は、ほとんどの案件で前提として扱われます。

Laravelを設計の意図まで理解しているか

機能を使えることと、使い分けられることは別

Laravelの案件では、ルーティング、Eloquent、バリデーション、マイグレーションを使えることはスタートラインです。差がつくのは、次のような使い分けを説明できるかどうかです。

  • 入力のチェックをコントローラーに書くか、フォームリクエストに分けるか
  • 権限の判定をポリシーやゲートにまとめているか、画面ごとに散らばっているか
  • 時間のかかる処理（メール送信、外部APIの呼び出し、集計）をキューに回しているか
  • 処理をサービスクラスなどに分けるとき、どこまで分けるかの基準

運用中のサービスに入る案件では、コントローラーやモデルに処理が集まり、読みにくくなっているコードに出会うことがよくあります。そうしたコードを、一度に作り直すのではなく、テストを足しながら少しずつ分けていった経験は、高く評価されやすい部分です。

Eloquentの便利さと引き換えになるもの

Eloquentは書きやすい反面、気づかないうちにSQLが大量に発行される「N+1」の問題を起こしやすい仕組みでもあります。一覧画面で関連するデータを読み込むときにどう対策したか、発行されるSQLをどう確認したかを話せると、Laravelの理解が深いことが伝わります。

CakePHP・Symfony・独自フレームワークの経験

既存システムの改修では、Laravel以外のフレームワークや、社内独自の仕組みで作られたコードを扱うこともあります。フレームワークが違っても、MVCの考え方、DIコンテナ、ミドルウェアといった共通の仕組みを理解していれば、読み解く速さに差が出ます。経歴では、フレームワーク名とあわせて、その中で何を担当したかを書いておきましょう。

SQLとデータベースの力

PHPの案件の多くは、MySQLなどのリレーショナルデータベースと一緒に使われます。フレームワークがSQLを隠してくれる場面が多いぶん、SQLそのものを書けるか、読めるかで力の差が出ます。

  1. テーブル設計：正規化をどこまで行い、どこで崩したか。外部キーや制約をどう使ったか
  2. インデックスと実行計画：遅いクエリを見つけ、実行計画を読んで、どの列にインデックスを張ったか
  3. トランザクションとロック：在庫や残高のように同時に更新されるデータを、どう守ったか
  4. 大量データの処理：数百万件規模のテーブルの変更や、一括処理をどう分割したか

特に、本番のデータベースに対して列の追加やデータの移し替えを行った経験は、運用中のサービスの案件で頼りにされます。止められないサービスで、どの順番で作業し、どう戻せるようにしたかを説明できるようにしておきましょう。

エージェントベストの見解

PHPの案件をご紹介していると、「Laravelで開発◯年」と書かれた経歴でも、面談でSQLの改善や本番のデータ移行について聞かれると、答えが浅くなる方を見かけます。反対に、遅い画面の原因をSQLまでたどって直した経験を、数字や手順を交えて話せる方は評価されやすい傾向があります。フレームワークの経験とデータベースの経験は、分けて整理しておくことをおすすめします。

Webのセキュリティを自分で守れるか

PHPはWebサービスの画面やAPIを直接作る言語です。そのため、脆弱性への対策を理解しているかが、ほかの言語以上に問われやすい傾向があります。

脆弱性案件で確認されやすい点
SQLインジェクションプレースホルダーを使っているか。生のSQLを書くときの扱い
クロスサイトスクリプティング出力時のエスケープ、テンプレートでのエスケープを外す場面の判断
クロスサイトリクエストフォージェリトークンの仕組みを理解し、API側でどう守るか
認証・認可の不備ログインの仕組みと、他人のデータを見られないようにする確認
ファイルのアップロード拡張子・中身の確認、保存場所、公開範囲

Laravelには多くの対策が最初から組み込まれています。ただ、古いコードや独自の仕組みでは、それが効いていないこともあります。「フレームワークが守ってくれるから大丈夫」ではなく、どの仕組みが何を守っているかを説明できることが大切です。脆弱性診断の指摘を受けて直した経験があれば、具体的に書き出しておきましょう。

古いコードとバージョンアップに向き合う力

サポートの期限から仕事が生まれる

PHPの公式サイトによると、2026年10月時点でサポートされているのは8.2〜8.5で、8.2と8.3はセキュリティ修正のみの段階です。8.2のセキュリティサポートは2026年12月31日、8.3は2027年12月31日までとされています。Laravelは、バグ修正が18か月、セキュリティ修正が2年という方針で、Laravel 12のセキュリティ修正は2027年2月24日までと案内されています。

期限が近づくと、バージョンを上げる作業がまとまって発生します。経験を積んだ手順はPHPエンジニアの独立の記事でも触れていますが、スキルとして見られるのは、次のような「安全に変えるための道具」を使えるかです。

  • 静的解析：PHPStanなどで型の不整合や使われていないコードを見つけ、レベルを段階的に上げた
  • 自動テスト：PHPUnitなどで、変更前の動きを固定するテストを先に書いた
  • 段階的な移行：一度に上げず、非推奨の警告を一つずつ解消しながら進めた

型を書く習慣

PHPは型を書かなくても動きますが、引数や戻り値に型を付けておくと、静的解析とテストの効き目が大きく変わります。型のない古いコードに、少しずつ型を足していった経験は、保守の案件で強みになります。

周辺技術で一人で完結できる範囲を広げる

PHPの案件では、バックエンドだけでなく周辺の作業まで任されることがあります。

  • フロントエンドとの連携：APIを設計してVue.jsやReactの画面に渡す、またはLaravelの仕組みで画面とつなぐ。フロント側の基礎はVue.jsの案件で求められるスキルやTypeScriptの案件で求められるスキルも参考になります
  • 開発環境とデプロイ：Dockerで開発環境をそろえ、GitHub ActionsなどでテストとデプロイをCIに乗せる
  • クラウドでの運用：AWSなどでアプリを動かし、ログや監視を見て障害を切り分ける

WordPressの案件では、テーマやプラグインの開発に加えて、サーバーの設定、表示の速さ、更新による不具合への対応が求められます。Laravel中心の案件とは見られる経験が違うため、経歴を分けて書いておくと案件との合い具合が伝わりやすくなります。

資格の位置づけ

PHPには、PHP技術者認定機構が実施する資格があります。公式サイトでは、PHP8初級試験、PHP8上級／準上級試験、PHP技術者認定ウィザードのほか、ウェブ・セキュリティ基礎試験とウェブ・セキュリティ実務知識試験が案内されています（2026年10月時点）。

案件では実務の経験が優先されるため、資格だけで参画が決まることは多くありません。ただ、上級やセキュリティの試験は、言語仕様やセキュリティの知識を体系的に持っている裏付けになります。独学でPHPを身につけてきた方や、制作中心の経歴からサービス開発に移りたい方には、知識の抜けを確かめる材料として役立ちます。

注意

「PHP・Laravel・MySQL・AWS・Docker」と技術名だけを並べたスキルシートは、PHPの案件ではよく見かけるため、かえって差がつきにくくなります。技術名ごとに「何をしたか」を一行添えるだけで、読み手の受け取り方は大きく変わります。書き方はPHPのスキルシートの記事で詳しく解説しています。

スキルシートと面談での示し方

PHPのスキルは、次のように「状況・判断・結果」で書くと伝わります。

  • 一覧画面の表示が遅い問題を、発行SQLの確認からインデックスの追加とN+1の解消で改善した
  • 型のないコードにPHPStanを入れ、警告を段階的に解消してからPHPのバージョンを上げた
  • 脆弱性診断の指摘を受け、ファイルのアップロード処理の確認と保存場所を見直した

面談では、バージョンの数字や機能の名前を並べるより、そのときの制約（止められないサービス、テストのないコード、少ない人数）と、自分が選んだ方法の理由を話すほうが評価につながります。面談でよく聞かれる質問は面談でよく聞かれる質問と答え方にまとめています。報酬との関係はPHPエンジニアの報酬の記事をご覧ください。

よくある質問

Laravelの経験がないとPHPの案件は難しいですか？

Laravelの経験を条件にする案件は多いものの、CakePHPやSymfony、独自のフレームワークで作られたシステムの改修案件もあります。フレームワークが違っても、MVCやDIの考え方、SQL、セキュリティの理解は共通して評価されます。新しい開発の案件を狙う場合は、Laravelでの開発経験を足しておくと選択肢が広がります。

セキュリティの経験はどう書けばよいですか？

脆弱性診断の指摘に対応した経験、認証・認可の仕組みを作った経験、入力値やファイルの扱いを見直した経験などを、守秘義務に触れない範囲で書きます。「セキュリティに配慮」とだけ書くより、どの種類の対策を、どの画面や機能で行ったかを書くほうが伝わります。

PHPの資格は取っておいたほうがよいですか？

必須ではありません。実務の経験が十分にある方は、経験の整理を優先したほうが案件探しに役立ちます。一方、知識に自信のない分野がある方や、経歴の厚みを補いたい方には、上級やセキュリティの試験が知識を確かめる材料になります。
