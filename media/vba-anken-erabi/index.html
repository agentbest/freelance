VBA・Excelマクロ開発者のフリーランス案件の選び方｜契約前に確かめたいこと

公開 2026-11-04　監修：株式会社エージェントベスト

目次

  2. 契約前に確かめたい7つの点
  3. 確かめた内容を書面と照らし合わせる
  4. よくある質問

VBA・Excelマクロ開発者のフリーランス案件を選ぶときは、報酬や稼働日数に加えて、仕事の種類と残っている資料、ツールの規模とつながる仕組み、Officeの版と配布の方法、データの扱いと作業する場所、契約の形と検収、稼働の波と問い合わせの範囲、作ったものの権利の7点を契約前に確かめておくことが大切です。

VBAの案件は、案件票に「Excelマクロの改修」としか書かれていないことが多く、参画してから中身の重さに気づきやすい仕事です。特に見落としやすいのは、ツールがどれだけ業務に組み込まれていて、止まったときに誰が困るかです。この記事では、VBA案件に固有の確認点を整理します。契約書全般の確認点は業務委託契約書のチェックポイントで解説しています。

VBA案件の選び方で差が出る理由

VBAのツールは、部署の中で長い年月をかけて少しずつ育てられてきたものが多く、外から見えるのはブックの画面とボタンだけです。その裏で、複数のブックやAccessのデータベース、基幹システムから出力したファイル、ほかの部署の共有フォルダがつながっていることがあります。

よくあるずれは次のようなものです。

  • 「1本のブックの改修」と聞いていたのに、実際は5本のブックとAccessが連動していた
  • 仕様書がなく、作った人にも話を聞けず、読み解きに想定の何倍もの時間がかかった
  • 自分の端末では動くのに、利用者の端末ではマクロがブロックされて動かなかった
  • 請負で受けたのに、完了の条件が決まっておらず、修正の依頼が続いた

こうしたずれは、面談と条件の確認の段階で、聞き方を工夫すれば多くを防げます。

契約前に確かめたい7つの点

1. 仕事の種類と、残っている資料

最初に確かめたいのは、新規開発か、改修か、引き継ぎか、版への対応や移行かです。改修や引き継ぎなら、次の点も聞いておきます。

  • 仕様書や手順書が残っているか
  • 作った人に話を聞けるか（異動先にいる、退職している、など）
  • 直近で誰がどこを直したかの記録があるか

資料がない案件を避ける必要はありません。読み解きの経験は評価にもつながります。ただ、資料がないと分かったうえで、読み解きの期間を見込んで受けることが大切です。

2. ツールの規模と、つながる仕組み

対象のツールの数と、つながる仕組みを確かめます。

  • 対象のブックの数、モジュールのおおよその量
  • Accessや外部のデータベース、基幹システムの出力ファイルとつながっているか
  • Outlookでのメール送信や、Wordへの差し込みなど、ほかの製品を操作しているか
  • ほかの部署のフォルダや、ほかのツールの出力を読んでいるか

つながる仕組みが多いほど、1か所を直したときの影響を確かめる手間が増えます。報酬の決まり方との関係はVBA・Excelマクロ開発者の報酬の記事で解説しています。

3. Officeの版と、配布の方法

ツールが動く環境を確かめます。Microsoft Learnによると、Office 2019とMicrosoft 365からは64ビット版が既定で、古いマクロのDeclareステートメントは、PtrSafeを付け、型をLongPtrなどに直さないと64ビット版では正しく動きません（2026年10月時点）。Office 2016とOffice 2019は2025年10月14日にサポートが終了しています。

  • 利用者の端末のOfficeの版と、32ビット版か64ビット版か
  • 版が混在していないか、版の切り替えの予定があるか
  • ツールをどこに置き、どう配布しているか

Windows版のOfficeでは、インターネットから取得したファイルのマクロが既定でブロックされ、信頼できる場所に置いたファイルや、信頼された発行元のデジタル署名があるマクロは許可されると説明されています（2026年10月時点）。信頼できる場所や署名の運用を誰が決めるかを確かめておかないと、作ったツールが利用者の端末で動かないまま止まることがあります。

エージェントベストの見解

VBAの案件をご紹介していると、参画後に「聞いていた状況と違った」となりやすいのは、つながっている仕組みの多さと、利用者の端末の環境の2点です。面談では、ツールの画面を見せてもらうだけでなく、どのファイルやデータベースとつながっているか、利用者のOfficeの版は何かを聞いておくことをおすすめします。案件票だけでは分からない点は、契約の前に確かめることが大切です。

4. データの扱いと、作業する場所

VBAのツールは、取引や個人に関わるデータを扱うことが少なくありません。

  • 本番のデータに触れるか、テスト用のデータを用意してもらえるか
  • 作業は自分の端末か、貸与端末か、出社か
  • ファイルの受け渡しの方法（共有フォルダ、クラウドのストレージなど）

データの扱いは、秘密保持の取り決めと合わせて確かめます。考え方は秘密保持契約の記事、リモートで受けられる条件はリモート案件の記事をご覧ください。

5. 契約の形と、完了・検収の決め方

VBAの案件は、稼働時間で精算する準委任の形と、成果物を納める請負の形の両方があります。

  • 準委任なら、月の稼働時間の幅と、超えたときの精算方法
  • 請負なら、何を納めれば完了か、検収の方法と期間
  • 請負で納めた後に不具合が見つかったとき、どこまで直す責任を負うか

請負では、納めたものが契約の内容に合っていない場合の責任を負うことがあります。検収の考え方は検収の記事、責任の範囲は契約不適合責任の記事、形の違いは準委任契約と請負契約の違いで解説しています。

6. 稼働の波と、問い合わせの範囲

業務のツールは、締めの時期に使われることが多くあります。

  • 月末・月初・期末に、問い合わせや立ち会いの対応があるか
  • 保守の窓口を担う場合、どの時間帯に、どこまで応じるか
  • 新しい開発の依頼が来たとき、保守の範囲で受けるのか、別の契約にするのか

問い合わせが業務範囲のどこまでかを決めておかないと、小さな依頼が積み重なって稼働が膨らみます。精算の仕組みは精算幅の記事、範囲が広がったときの扱いは作業範囲が広がったときの契約の扱いをご覧ください。

7. 作ったものの権利と、部品の再利用

作ったツールの権利が発注元に移るのか、自分が以前から使っている汎用的な部品はどう扱うのかを確かめます。権利が発注元に移る契約なら、同じものをほかの発注元に渡すことはできません。考え方は著作権と著作者人格権の扱いの記事で解説しています。

注意

VBAのツールは、利用者が自分でコードを書き換えられることが多い仕組みです。納めた後に利用者が直した箇所で不具合が起きたとき、誰が責任を負うかが曖昧になりがちです。引き渡しのときの版を残しておき、納めた後の変更をどう扱うかを契約の前に決めておきましょう。

確かめた内容を書面と照らし合わせる

面談や事前の確認で聞いた内容は、契約の前に書面と照らし合わせます。フリーランス法では、発注する事業者は業務を委託したら直ちに、給付の内容、報酬の額、支払期日などを、書面またはメールなどの方法で明示することとされています（2026年10月時点、公正取引委員会の案内による）。明示される事項の内容はフリーランス法で明示される取引条件をご覧ください。

VBAの案件では、特に次の点が書面に反映されているかを確かめます。

  1. 業務の内容に、対象のツールと、改修・保守・資料づくりなど担う範囲が書かれているか
  2. 請負なら、納める物と完了の条件、検収の方法が書かれているか
  3. 稼働の幅と、超えたときの精算方法、問い合わせ対応の扱い
  4. 作ったものの権利の扱い
  5. 契約期間と更新の時期

フリーランス法では、6か月以上継続して業務を委託している場合に、契約を解除したり更新しなかったりするときは、少なくとも30日前までに予告することが求められています（2026年10月時点、公正取引委員会の案内による）。保守の案件のように長く続く契約では、更新の時期もあわせて確かめておきましょう。

面談で聞いておくとよい質問はVBA・Excelマクロ開発者の面談でよく聞かれる質問と答え方の逆質問の項目でも紹介しています。一般的な逆質問の考え方は面談で聞いておくべき逆質問をご覧ください。

エージェントベストの見解

当社では、取引先の会社の実態と支払条件を確かめた案件を扱い、契約では業務範囲・報酬・支払期日・契約期間を個別契約に書いてお渡ししています。VBAの案件で気になりやすい対象のツールの数、利用者のOfficeの版、締めの時期の対応など、書面だけでは読み取りにくい点は、ご質問いただければ確認します。条件に迷う点があれば、契約の前に早めにご相談ください。

ポイント

  • VBAの案件は、同じ「マクロの改修」でも、ツールの状態・つながる仕組み・動かす環境で負担が大きく変わる
  • 仕事の種類と資料、規模と連携先、Officeの版と配布を面談で確かめる
  • データの扱いと作業場所、契約の形と検収、稼働の波と問い合わせの範囲、権利を契約の前に決める
  • 確かめた内容は、フリーランス法で明示される取引条件と照らし合わせる

よくある質問

仕様書がない引き継ぎの案件は避けたほうがよいですか？

避ける必要はありません。資料のないツールを読み解き、仕様を書き起こした経験は、次の案件で評価されやすい経験です。ただし、読み解きにかける期間を見込み、準委任の形で稼働に応じて精算できるかを確かめてから受けることをおすすめします。

請負と準委任、VBAの案件ではどちらが多いですか？

案件によって違います。小さなツールを1本作る仕事は請負、改修や保守を継続して担う仕事は準委任になりやすい傾向があります。どちらの形かで負う責任が変わるため、仕事の中身と契約の形が合っているかを確かめましょう。

報酬の高い案件と、環境がはっきりした案件で迷ったらどうしますか？

一概には言えませんが、つながる仕組みや利用者の環境が分からないまま受けると、読み解きや検証に時間がかかり、時間あたりの報酬が下がることがあります。報酬の額だけでなく、稼働の見込みと確かめられた環境を合わせて比べるとよいでしょう。仕事の種類ごとの働き方はVBA・Excelマクロ開発者の仕事内容で整理しています。

業務委託契約書は、契約形態・業務範囲・報酬と精算・支払期日・契約期間と解除・知的財産・秘密保持・損害賠償などを署名前に確認します。フリーランス新法で発注者が明示すべき事項と照らし合わせると、抜けに気づきやすくなります。

 業務委託契約の基礎

準委任契約と請負契約の違い｜フリーランスが知っておくべきこと

準委任は「業務を行うこと」、請負は「仕事を完成させること」に報酬が払われる契約です。責任の範囲・報酬の条件・途中でやめるときの扱いが違うため、契約書で何を約束しているかを確かめることが大切です。

 業務委託契約の基礎

契約不適合責任とは｜請負で負う責任の範囲と期間、契約書での決め方

契約不適合責任は、請負で引き渡した成果物が種類・品質・数量で契約内容に合わないときに負う責任です。注文者は修補・減額・損害賠償・解除を求められ、民法では不適合を知ってから1年以内の通知が必要です。契約で変わる範囲と期間を整理します。

 業務委託契約の基礎

検収とは｜請負で報酬が確定するタイミングと、契約書で確かめる検査の条件

検収は、発注者が納品物を検査して契約どおりと認め、受け入れることです。請負では検収完了を報酬の支払条件にする契約が多いため、検査期間・合格基準・期間内に連絡がないときの扱いを確かめます。フリーランス新法の支払期日との関係も解説します。

 業務委託契約の基礎

著作者人格権の不行使条項とは｜意味と署名前に確かめたい範囲

著作者人格権は譲渡できないため、発注者が成果物を改変・公表できるよう「行使しない」と約束する条項が置かれます。確かめたいのは、誰に対して、どの成果物の、どんな利用について行使しないのかの3点です。

 業務委託契約の基礎

作業範囲が広がったときの契約の扱い｜追加の報酬と変更の残し方

契約で決めた業務範囲を超える作業は、原則として当初の報酬に含まれません。追加するなら、作業内容・報酬・期限を決め直して書面やメールで合意します。フリーランス新法の不当な給付内容の変更の考え方と、変更を合意する手順を整理します。
